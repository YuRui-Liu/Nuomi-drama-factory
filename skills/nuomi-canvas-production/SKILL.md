# Nuomi canvas production

Codex is the production entry point. Read the user's constraints, project settings, and named local references before drafting. The Nuomi canvas shows the current core artifacts; project-local documents hold external source material and working notes. Use the public CLI and shared canvas services so web edits, Codex edits, and task history stay in sync.

Before paid media generation, read [first-pass-production.md](references/first-pass-production.md). Prepare the full input before one submission: actual style and model tier, target-frame composition, per-shot entities and causal states, and the real queued workflow/reference selection. Reuse successful media; do not use repeated paid calls to discover missing preparation. Read-only checks reduce preventable failures but do not guarantee provider compliance.

Use this skill for both a supplied complete screenplay and an idea-to-screenplay workflow. Keep user-provided text and facts distinct from Codex-created material. Never label invented connective writing or dialogue as the user's original. For the detailed source-to-screenplay path, see [creation.md](references/creation.md).

For the full input → method → real operation → artifact → check flow, read [stage-contracts.md](references/stage-contracts.md). At the start of a new production, configure the episode's existing progress policy before changing its canvas. Use [voice-and-audio.md](references/voice-and-audio.md) for voice references, explicit voice-candidate adoption, dubbing, and supported track handling; use [editing-and-delivery.md](references/editing-and-delivery.md) before mixing or exporting.

Keep exactly one editable screenplay source per episode. First inspect the episode's existing screenplay-node binding and, for a formal script handoff, `script` in the director-workspace response. A node with `documentRef` uses the project-local `ProductionDocuments` path; a node with `documentId`/`documentRevisionId` uses the formal `script_creation.DocumentStore`. These stores have different APIs: `canvas documents` reads/writes project-local files, while `script documents` reads/writes immutable formal document revisions. Never copy a formal DocumentStore screenplay into `ProductionDocuments` as another editable screenplay. For a bound formal screenplay, direct save, restore, and accepted revision-bound rewrite proposals all use the same source-sync policy: advance Episode Source only through the already-confirmed handoff for that exact document and episode, and only while its source revision/hash still match. A conflict or incomplete review preserves the saved formal revision and leaves Episode Source unchanged; resolve the reported status before production. The formal handoff receipt is an immutable progress artifact, not an edit target. See [creation.md](references/creation.md), [stage-contracts.md](references/stage-contracts.md), and [cli.md](references/cli.md) for the two source workflows and checks.

When the current Codex is asked to author episode semantics and director groups, prepare both from one `screenplay-semantics/source-context` snapshot and import the supplied content through the external-draft routes in [cli.md](references/cli.md). Those routes bind and validate the draft without invoking an internal model. Reuse the returned source hash and revision IDs through semantic activation, manual director review/activation, and production-graph materialization; do not add a parallel approval flow.

Put outlines, continuity notes, experience provenance, and production logs in project-relative documents, not extra planning nodes. Build the visible graph from the ten core artifact kinds only: idea, screenplay, asset, storyboard table, grid, shot, director, dubbing, music, and composition.

Use [cli.md](references/cli.md) for current commands and [recovery.md](references/recovery.md) before resuming work. Use [h3-experience.md](references/h3-experience.md) for local case retrieval, H3 preparation, and track choices. Follow [visual-continuity.md](references/visual-continuity.md) for reference assets and visual checks. Use [professional-references.md](references/professional-references.md) for role-based asset, spatial, camera, performance, dialogue, and voice methods, plus the limits of external H3 prompt examples.

For a 360-degree scene, read [scene-360.md](references/scene-360.md) before any paid call. Prepare the whole spatial/projection input first, submit once with a stable request ID, and inspect the sphere. Do not discover missing back walls, topology, or projection through repeated paid generations. Judge usability against the user's current purpose; record accepted local defects and continue with the existing result when the user permits them. Stop automatic paid retries for an unusable panorama and diagnose the cause. Reuse completed media and resume verification/projection failures without regenerating it.

Use [cinematic-direction.md](references/cinematic-direction.md) to turn story causality into visible evidence and structured director inputs. It is a decision guide, not a required prompt template; missing scene, camera, performance, continuity, or sound facts stay unknown.

Before turning a storyboard table into grid images, apply [storyboard-direction.md](references/storyboard-direction.md). Author shared scene blocking, camera-axis continuity, lighting, expressions, and prop states first; compile selected stills from those decisions. A table copied into panel descriptions is not director preparation. Resolve the selected catalog style to the supported node field and verify its actual compiled fragment in request preview. Use [roles/asset-design.md](references/roles/asset-design.md) when writing or reviewing asset briefs, and [professional-references.md](references/professional-references.md) for external production rules.

The default episode policy is `review`: reuse its three existing review points after screenplay, assets, and storyboard. The storyboard checkpoint is complete only when both its table and grid are saved. Show each result before continuing and approve only the current `approval_hash`; do not create a parallel approval flow. `auto` skips those review gates; `stop_after` remains a deliberate stop even in auto mode. Progress belongs to an episode, so batch work can pause or recover one episode without replaying successful work in another.

Before creating or running nodes, read `canvas capabilities` and `canvas director capabilities`; use only operations marked available. Apply graph changes in one atomic `canvas patch`, then read the canvas back and check its revision and parameters. Do not create visible planning, agent, or execution-plan nodes. For video, prepare structured director input through the shared H3 preview/compiler and submit only the returned, validated preparation through the existing attempt queue. The runtime capability response is authoritative; do not infer T2VA or L2VA support from older notes.

Treat retrieved experience as optional advice. Preserve case IDs, links, provenance, and the segment where an idea was applied. User facts and constraints outrank examples; examples cannot change dialogue, character identity, references, timing, or route validation. If the catalog is unavailable or has no match, continue without it.

Before audio and composition, inspect the prepared H3 result and saved timeline. By default, create dialogue as a separate dubbing track using each character's voice profile, or reuse an existing external independent dubbing track when it matches the current dialogue. Mute or replace dialogue embedded in the video to prevent doubled voices; retain its environmental sound when available and intended. Reuse dialogue embedded in the original video only when the user explicitly chooses that audio route. A segment with no dialogue needs no dubbing. Add music only where intended and pass each audio track once to composition. Dubbing is independent by default and does not require lip-sync animation; only plan visible mouth movement when the user requests it and the supported route can provide it. Review the generated video as a continuous clip against the story cause, visible evidence, and declared start/end states. When a segment fails, revise the input responsible for that evidence and rerun only the affected segment through the supported workflow. Check segment order, missing video/audio, duration, and playback before marking the episode complete. A successful task or export alone is not content acceptance.
