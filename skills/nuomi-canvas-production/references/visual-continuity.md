# 风格与人物设计检查

这是 Skill 的人工视觉检查步骤，当前编排服务尚未提供自动视觉审核门禁。不得声称后端已自动保证风格或人物一致性。

## 制作前

- 读取项目当前视觉风格、已有角色设定和已选设计图。用户明确指定优先于项目默认；既无设定也无明确偏好时，提出具体候选设计供用户选择，不凭姓名猜性别或外形。
- 保存本次风格基准：风格 ID、实际风格描述、参考图（如有）、色彩与光照规则。所有人物、场景、道具、分镜和视频提示词必须使用同一基准；不能只在节点标题写“写实”。
- 每个角色建立独立、可复用的人物设计：性别表达、年龄、脸型、发型与发色、体型、服装版型和配色、鞋及关键配饰。区分剧本明确设定与补充设计，不把补充设计冒充原文。
- 优先复用已有选定的人物设计图。新设计图应清楚表现同一人的正面、侧面、背面全身及脸部细节，使用简单背景、统一服装；避免用带其他人物的剧情截图代替设计图。

## 先验资产，再执行整集

1. `plan` / `apply` 后检查所有资产提示词，使用公开 CLI 更新入口补齐风格与设计；当前自动规划可能只有泛化描述，不可直接视为已定稿。
2. 先对人物资产节点分别执行 `run --target NODE_ID`。使用本地图片查看工具或网页打开真实产物，不能只读状态码、尺寸或哈希。
3. 逐项检查：与角色设定相符；多视图是同一个人；发型、衣服、配饰一致；全身信息足够；不同角色可区分；与项目风格一致。任何一项失败，记录原因并修正该资产，禁止直接执行下游整集。
4. 保存通过检查的节点 ID、图片 URL、产物哈希和检查记录。每个叙事组的分镜与视频都引用相同版本的角色设计图，同时传递全片风格描述；检查实际连线与请求输入，不能只检查 `referenceOrder` 文本。
5. 检查首个叙事组的实际分镜，再扩大到剩余组。视频完成后仍需检查跨组脸型、发型、服装、画风与声音连续性。

参考图发生变化时，原有下游产物不能自动继承“已通过”结论。只重做受影响的依赖，避免重复生成已通过且未受影响的资产。

## 已知真机反例

2026-10-05，验收画布 `canvas-episode-acceptance-20261004-final` 的项目配置为 `realistic`，但人物资产出现摄影风格和动漫风格混用，且产物是场景肖像而非设计图。三个人物提示词没有锁定完整外形。即使图片解码与哈希校验成功，这些资产也没有通过人物设计和风格验收，不能据此宣称整集可用。
