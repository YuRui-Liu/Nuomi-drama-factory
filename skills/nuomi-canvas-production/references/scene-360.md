# 360 场景：准备完整后一次提交

适用于用户要求可环视场景、全景背景或 360° 场景资产。2:1 是文件比例要求，不是全景合格证明。一次提交策略保证不自动重抽，不代表模型必然一次合格。

## 付费前必须完成

1. 从当前正式剧本和场景 brief 固定空间：四壁及其邻接、唯一门窗、家具数量、人物活动区、相机位置、主光世界方向。未见背面属于美术补充，记录后再准备，不能让模型随意复制正面。
2. 先检查现有场景、正反面参考和已保存 3D 调度数据。能复用的输入直接复用。不要为每次全景任务另买正面、反面或所谓试验图。
3. 准备覆盖整球的几何投影底图，或已验证的完整球面场景。底图必须真实表示 360×180°，四周完整、左右边缘相接、天顶和地底连续。用本地几何渲染准备这类空间约束不需要图像模型调用；简化几何只作投影约束，不当作最终美术成品。
4. 正反面图只提供身份、材质和光线依据。仅有一张正面图、纯色拓扑条或“360/equirectangular”提示词，不足以通过此准备检查。不得把普通宽幅图包装为底图。
5. 通过公开画布图像入口，把球面底图作为编辑基图，其他图作为材质参考；先核对当前运行时真实支持的模型、编辑操作、尺寸、参考图数量和费用。没有受支持的组合就报告缺口，不改走直连供应商脚本。
6. 读取保存后的节点：实际请求比例为 `2:1`；模型、风格、全部参考图顺序、基图与负面约束齐全；风格片段只注入一次。正式剧本用确认的 handoff receipt 做 `--document` 来源校验。图像节点没有通用请求预览时，不虚构已调用预览。

前置材料不完整时，不提交付费生成，也不先买一张看看。

## 一次提交与恢复

- 从确切模型、尺寸、风格、提示词、参考图版本/哈希形成稳定输入指纹，以 `pano-<指纹>` 作为 `--request-id`。提交前查看当前画布已有 run；相同输入已有成功产物就直接恢复使用。
- 一次只提交一张候选。保存 `run_id`、原始 attempt、provider task 和产物路径；不以新的随机 request ID 重抽相同任务。
- 提交结果未知时先查询原任务，不能重试。任务已成功但校验或画布回写阻断时，只使用 `canvas resume RUN_ID` 恢复原任务；随后查询终态。不能把 resume 的 HTTP 成功当作实际校验完成。
- 产物已完整且请求语义未变，但编辑器默认字段导致错误的过期标记时，修复默认值归一化并恢复已有产物，不买新图。
- 视觉验收失败时，保留失败证据并停止自动生成。先修正对应准备或执行链路；后续付费重做须有用户明确要求，并沿用其预算。不能把同义提示词轮换当作修复。

## 球面验收

把真实产物连到内置 `pano360ViewerNode`，不要只看展开图。检查前、后、左、右、天顶、地底和首尾接缝：

- 四个方向组成同一个完整房间，后半球不是重复的正面或被压成狭窄条带。
- 门窗、案台和其他唯一物件不重复；转向后位置、邻接和尺度合理。
- 接缝没有墙面错位、重复门窗、明显明暗断带。
- 天顶和地底没有黑洞、截断、拼贴边框或严重放射拉伸。
- 场景身份、材质、风格和主光与已确认设计一致。

保存各方向的实际截图和检查结论，以当前创作用途判断是否可用，不要求每处纹理完美。四周空间成立、主要调度区域可用时，局部天顶或地底瑕疵可以记录为限制；用户明确接受后，采用已有产物并继续下游，不反复生成。房间缺面、主体重复或主要调度空间错误仍应说明并停止自动重抽。用户要求先完成全景且尚未接受当前结果时，下游保持暂停；用户后续明确允许继续时，以最新指示为准。

本轮已发现的反例：仅文字要求、单正面参考，以及正反面加抽象拓扑条，均可能产生貌似全景的宽幅图；不得把这些路径记为已验证的一次成片方案。几何约束方法也必须完成球面实测后才能记录为通过。
