# H3 提示词链路修复与验证

## 原因

E1 第 1 组操作固定阀门，旧 QC 却只接受人物、手持道具或自然运动白名单。第 2 组 ACTION 已列出本子、铅笔、纸牌和桶，PHYSICS 正文也描述了这些对象，但重复列表漏列道具，导致严格集合相等检查失败。第 6 组只返回 06a，漏了 06b；原逻辑在进入修复前即缓存失败。

这些是视频调用前的应用校验，不是 Minimax 视频模型拒绝。原错误中的物理术语不完整、缺少引用数量约束已经是 warning。

## 已实现

- 编译前从动作派生运动主体索引，从结构化人物、引用、持物事实派生数量索引；动作与物理正文不因此重写。
- 固定装置、环境运动不因词汇白名单缺项就被硬拦截；静止保持、纯音频事件不被迫填写运动主体。它们保留建议记录。
- 官方六段 Ref2VA 输出与真实引用、身份、时长、对白、风格检查继续执行。
- 合法部分规划返回缺片段时，只请求缺失 ID 一次。重复 ID、未知 ID、错误剧集与版本不做猜测映射。补齐仍不完整则失败并保留预算记录。
- 对明确被拒绝的风格字段允许采用修复结果，再按真实项目风格校验，避免把错误旧值合并回来。
- QC 版本 12、提示词配置版本 20，使旧规则缓存与新规则输入区分。

- [官方 Ref 指南](https://github.com/MiniMax-AI/MiniMax-H3/blob/main/skills/h3-prompt-writing/references/ref-en.txt)：身份参考与具体首帧／构图参考用途不同；不能因为提供了一张身份图就把它当首帧。
- [drama-skills 分镜](https://github.com/zenstory-ai/drama-skills/blob/main/skills/short-drama-storyboard/SKILL.md)：起点—主要动作—终点，持物接触与落点、跨镜连续性、画外与画内区分。
- [真实案例库](https://github.com/stimQQ/stunning-minimax-h3-prompts/blob/main/README.zh-CN.md)：读取 README 案例摘要和经验总结。采用明确引用用途、动作时间线、同步声音、风格锁定。作者原文索引和 AI 反推不能等同，未重跑案例视频；不把“必须运镜”“只能一个动作”或通用负面词模板变成硬规则。
