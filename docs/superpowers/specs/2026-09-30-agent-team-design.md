# 创作工作室：Agent 团队设计

日期：2026-09-30
状态：讨论方案已确认；书面规格待用户审阅。本文不代表功能已经实现。

## 1. 目标与范围

在创作工作室新增「Agent 团队」，汇总不同制作流程实际使用的 Agent、Prompt、Skill 和参考资料，让用户知道创作方法在哪里生效，并能替换、试跑、启用和回退。

采用固定流程、岗位创作方法可替换的方案。团队模板跨项目复用，项目引用固定模板版本，并按字段覆盖。首版不支持新增岗位、改动流程顺序、并行编排、多 Agent 内部流程编辑、执行程序替换或工具权限自定义。

岗位是面向用户的职责入口，不承诺每个岗位都是独立 Agent。一个岗位可以包含多个现有调用点；每个调用点必须有真实绑定，不能只展示配置而不进入执行链路。

## 2. 现有系统依据

- 工作室入口：`frontend/src/features/studios/studio-page.tsx`。
- 导演方法配置：`frontend/src/features/studios/director-studio.tsx`；现有本地建议仅修改运镜与构图，AI 规划将配置快照送入导演规划。
- 剧本创作：`src/novelvideo/script_creation/prompts.py` 组合阶段约束、创作资料与用户要求。
- 语义解析、导演规划：`src/novelvideo/screenplay_semantics/`、`src/novelvideo/director_plan/`。
- 现有 Agent：`src/novelvideo/agents/`，包括规划、改写、资产编译、审查、修复及提示词生成等。
- 画布技能契约：`src/novelvideo/freezone/skill_registry.py`；不得因名称相似就假定画布技能与任意岗位可互换。
- 模型路由：`src/novelvideo/text_task_runtime/`；视频提示词方法分布于 `src/novelvideo/media_capabilities/video/` 等模块。

这些位置用于建立接入清单，不对现有执行器做无关重构。实现计划须逐调用点确认输入、输出、模型能力及资源加载方式。

## 3. 信息结构与前端

### 3.1 入口与总览

新增工作室页签「Agent 团队」。顶部展示项目、当前团队模板及版本、项目覆盖岗位数、可用模板更新；提供更换模板、比较更新、创作资源库入口。

主区采用左侧流程岗位总览、右侧岗位编辑。左侧按创作、解析、分镜、资产、视频组织；岗位卡显示职责、实际作用环节、配置来源、启用版本及草稿状态。流程顺序表达依赖关系，不表示自动执行全部步骤。

初始职责目录包括编剧、剧本审查、剧本解析、分镜导演、分镜审查、资产设计、资产审查、视频导演。此目录是展示分组：只有存在已验证调用适配器的岗位才可启用自定义；其余显示「尚未接入」，禁止启用，不能将其包装为已完成能力。

多调用点岗位在详情中列出子任务。例如编剧包含大纲、人物、分集剧本；配置按子任务区分，不将同一个 Prompt 无差别套到全部任务。卡片展示覆盖摘要，详情显示准确作用范围。

### 3.2 岗位详情

顶部展示输入、输出、调用位置、生效范围；分为「创作方法」「试跑对比」「版本记录」。支持展开为宽编辑视图，保留所选岗位、页签和草稿。窄屏使用列表到详情的导航，返回时恢复位置。

创作方法分开编辑模型、创作 Prompt、Skill 引用和参考资料。每项标明继承来源或项目覆盖，可单独恢复继承。模型沿用已有模型选择与能力约束，不在此保存凭据。

岗位输入结构、输出协议、工具范围和必要校验规则为只读。用户可替换创作指令，不允许覆盖这些接口约束。导演方法的结构化字段保留，不能退化成两处互不一致的文本。

### 3.3 资源库与模板管理

资源库按 Prompt、Skill、参考资料分类，支持查看内容、创建自定义版本、编辑草稿和查看引用岗位。内置资源通过复制创建自定义版本，保留原始版本。首版 Skill 指被现有岗位加载器支持的方法资源，不执行用户上传的任意程序。

模板管理通过顶部模板入口进入，支持从现有模板复制、编辑岗位配置、保存并发布固定版本。已发布版本不可变；项目配置可另存为新模板。模板引用的资源同样固定版本。

资源使用列表展示模板及项目引用位置。已引用版本不得直接删除；停用后仍可用于历史任务追溯。

### 3.4 状态与交互

明确区分未保存修改、已保存草稿、当前启用、历史版本、尚未接入。保存不等于启用。离开有未保存修改的详情时提供保存或放弃选择；保存失败保留输入，版本冲突展示服务器版本与本地草稿，不能静默覆盖。

试跑、保存、启用均显示独立状态和错误。空列表、无可用模型、无试跑输入、资源不可用分别显示原因及可执行操作。卡片、页签和编辑控件支持键盘操作、焦点可见及非纯颜色状态提示。

## 4. 配置与版本规则

### 4.1 模板与覆盖

项目绑定固定模板版本。有效配置由该模板版本及项目字段覆盖合成。覆盖键缺失表示继承；显式空内容表示清空，仅在该字段允许为空时有效。资源列表作为完整字段覆盖，避免隐式拼接导致引用不确定。

模板发布新版本不改变现有项目。升级比较展示旧模板、新模板和项目覆盖：覆盖字段默认保留；继承字段经确认升级。恢复某字段继承会移除该字段覆盖，产生草稿，待启用后生效。

### 4.2 保存、启用与回退

保存产生可编辑草稿。启用前检查调用适配器、引用资源、模型能力、必需变量和输出接口要求，展示变更及受影响岗位/环节。静态检查通过不承诺创作质量，也不替代生成结果校验。

启用原子性地切换项目有效版本；失败保持原版本。回退使用相同兼容性检查与确认流程。配置升级、恢复继承、切换模板都不自动重生成已有产物。

## 5. 运行接入与追溯

职责分为四个边界：

1. 岗位目录与适配器：描述职责、子任务、输入输出协议、可替换字段及真实执行入口。
2. 配置与资源存储：维护不可变发布版本、草稿、项目覆盖及并发版本检查。
3. 配置解析器：根据项目、岗位、子任务合成有效配置并冻结依赖；不负责模型调用。
4. 现有任务执行器：消费冻结配置，通过既有模型路由和结果校验运行；正式任务与试跑使用同一解析和调用路径。

任务提交时冻结有效配置，记录模板版本、项目启用版本、岗位/子任务、Prompt 内容或可恢复快照、Skill/参考资料快照、模型路由解析结果、输入版本及内容摘要。项目模型和项目资料即使配置为跟随项目，也在提交时冻结。排队和重试不得悄悄读取后来修改的配置。

任务记录实际执行模型及已有路由策略下的变更，不能只记录用户期望值；不额外引入静默模型回退。凭据通过原有安全配置读取，不进入方法快照。

结果页提供「本次创作方法」追溯入口。未接入岗位继续原有行为并明确标记，不声称使用了统一配置。

## 6. 试跑对比

用户选择岗位及子任务、已保存输入版本，固定输入后分别运行当前启用版与草稿。提交前展示运行范围、两次运行及可能费用；无可靠估价时不伪造金额。结果展示输出、差异、耗时、模型与费用；未回传费用显示未提供。

试跑候选存储与正式制作产物分离，不启用导演方案、不写入正式剧本或替换资产，不触发后续自动制作。首版用于方法评价，用户认可后启用方法，再通过原有生产入口生成正式结果。

某一侧失败时保留另一侧结果和失败原因，可明确重试失败侧；不自动重复两侧付费运行。支持既有任务系统的运行状态、取消能力与幂等提交。重复点击不创建重复付费任务。

## 7. 导演自定义整合

「导演自定义」与分镜导演岗位共用同一份版本化创作方法，任一入口编辑均形成同一草稿。启用版供后续导演 AI 规划使用，入口均显示有效版本与项目范围。

原有对单镜头、叙事组或整集的本地运镜/构图建议继续保留；这是方案编辑操作，不等同于全岗位方法替换。建议展示使用的方法版本，采纳仍需走原有方案审阅与启用。

已有导演配置不在迁移时自动启用。作为可选择的项目方法候选导入；用户明确选择并启用后进入统一配置。原有导演配置不会因打开新页面而失效。

## 8. 错误、权限与兼容

沿用现有项目访问控制和任务提交权限。项目编辑者可编辑/启用项目覆盖；模板写入须校验模板所有者或现有授权，不因能访问某个项目就允许修改共享模板。

资源失效、模型不支持岗位输入、必填项缺失、协议不兼容均阻止启用并定位字段。运行失败保留配置快照、已产生候选与任务错误，不改变当前启用版。

原有岗位的固定协议和结果校验仍执行；不允许通过创作 Prompt 绕过。项目未选择团队时沿用当前行为，不能迁移即改变生成质量或默认模型。

## 9. 验收标准

- 同一模板的两个项目互不影响；只覆盖 Prompt 时模型和 Skill 仍继承固定模板版本。
- 保存不改变正式任务行为；启用后，新任务确实使用新方法，排队和历史任务仍可恢复原快照。
- 模板升级、恢复继承及回退有逐字段差异，覆盖内容不被静默清除。
- 每个可替换岗位至少有真实调用集成测试，验证注入配置影响对应调用且不破坏输出接口。未接入岗位不能启用。
- 同输入的双版本试跑候选隔离，无正式剧本/方案/资产写入；单侧失败和重复提交不导致重复运行成功侧。
- 导演两个入口编辑同一方法，版本状态一致，单镜头操作不误改项目全局方法。
- 前端验证宽窄屏、键盘操作、未保存提示、并发冲突、无模型/无素材、运行失败、版本对比和启用范围提示。
- 任务结果能追溯实际配置及模型；引用资源更新后仍能读取历史内容。
