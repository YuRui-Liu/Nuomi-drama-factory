日期：2026-10-01。状态：用户已确认，实施中。用户已确定三层架构，并选择「全量案例入库，各题材手法同时发布」。直接在当前分支实施，保留其他任务改动。

## 1. 目标与方案

在已有共享手法库和画布视频导演节点上增加可重复执行的案例吸收流程：固定上游版本 → 全量案例索引 → 去重与出处标注 → 原创手法提炼 → 目录发布 → 用户选卡与 AI 改写。

采用批量索引、精选提炼、版本化发布。相比每个案例自动变成一张卡，这能减少重复和剧情专用内容；相比生成时实时检索外部仓库，它可以离线使用、追溯版本，并避免外部故障影响生成。三个仓库均进入本次范围，所有题材同步发布，不按短剧分期。

## 3. 第一层：案例库

### 全量的含义

枚举固定版本的所有案例条目，建立可追溯索引。没有公开提示词的案例也保留，标记缺失；不能从标题编造提示词。教程和 Skills 单独归为指导资料，不混入视频案例计数。全量索引不等于下载第三方视频、缩略图或打包第三方提示词全文。

案例记录包括稳定 ID、标题、原创摘要、题材标签、输入模式原始声明、时长原始声明、作者、原始发布链接、收录仓库与文件位置、提交 SHA、提示词出处状态、媒体来源链接、关联手法 ID、导入时间。上游验证声明与本项目实测状态分别保存；默认本项目未实测。

提示词状态至少区分：官方公开、作者公开、反推、未公开、出处不明。授权状态独立记录，不从公开可读推定可再分发。延续现有产品规则：展示原创摘要、可验证元数据和来源链接；外部全文及视频不进入产品包。分析中读取的材料仅作为提炼依据。

### 去重与更新

原始来源 URL 规范化，X/Twitter 同一帖子按帖子 ID 识别。单条帖子可能含多条视频，不能仅按帖子 URL 把多个案例强制合一：使用显式媒体/案例标识辅助判断，无法区分时保留关联候选。相同素材的多仓库收录保留全部出处；提示词版本冲突同时记录，不静默覆盖。

适配器输出统一记录后，由独立归并器处理稳定 ID 和多来源关联。原始来源缺失时使用仓库加上游 ID 作为保守标识，不按相似标题自动合并。重跑同一版本结果幂等。后续更新保持案例 ID、既有卡片引用和旧快照可解析。

本次提供维护用导入命令和报告，不新增定时任务或自动联网后台。发布数据使用可审查的本地版本文件，查询接口无需访问 GitHub。

## 4. 第二层：跨题材手法库

首批同步覆盖六类用途：电影叙事、人物表演与关系、动作与空间调度、广告与产品、音乐与节奏、风格化与转场。用途与摄影技术分开：一张「环绕揭示」可以同时适用于人物和产品。

提炼目标是首批不少于 24 张有区别、有出处的可复用手法，包含既有 8 张；每类用途至少覆盖 2 张。不能为凑数量复制近义卡或虚构依据。若证据不足，报告具体缺口而不宣称达成。

每张卡包含：原创名称和效果摘要、动作节拍、人物/主体表现、镜头调度、结尾构图、避免事项、用途标签、关联案例及提炼依据、适用输入条件。移除案例专有角色、台词、品牌和剧情。时长与模式限制由本项目能力和手法需求推导，不能把案例片长误当模型硬限制。

卡片内容与来源可追溯；原文案例、反推案例的依据分别标注。仅有视频且未实际观察的案例可索引，但不能作为已观察镜头动作的证据。Skills 用于参考写作结构，不接管生成指令或运行时配置。

生成相关字段变动必须新增版本，保留旧版定义。展示标签和关联案例信息独立于生成投影，不因追加出处而改变历史生成哈希。收藏仍按 ID 跟随最新活动版本，片段仍绑定精确版本。需要当前工作流不具备的参考视频、音频等能力的手法，可浏览并说明条件，不能伪装成可应用。

## 5. 浏览入口

沿用独立手法库弹窗，提供「手法」与「案例」浏览入口。手法模式沿用分类、搜索、收藏和详情，增加用途筛选与关联案例列表；卡片使用原创镜头示意，缺示意时明确文字回退。

案例模式显示可分页搜索的标题、摘要、用途、提示词出处状态、来源与关联手法；不自动播放或下载外部媒体。可从案例进入已发布手法详情。片段入口打开案例后，也只有选择已发布且适用的手法才修改草稿。案例自身没有「直接应用全文」按钮。

数千条案例使用服务端分页、搜索与筛选，不把全部案例塞进首屏或模型上下文。卡片仍支持无项目全局浏览与跨项目收藏。目录和案例加载失败分别显示重试，不清空原选择。

## 6. 第三层：视频节点复用

用户选择一张手法 → 冻结 `id@version` 与生成投影 → 运行时结合当前图片、人物、剧情、时长改写 → 既有 H3/Ref 工作流生成。图片及剧情事实优先，手法只指导兼容的动作和镜头表达。

模型只接收所选手法的结构化原创指导及当前片段上下文，不接收全部案例、外部网页、Skills 指令或整段第三方提示词。沿用每片段一张卡、无参考图切换普通 H3、生成时冻结图片等既有行为。

不增加生成时的 QC 闸门。导入校验、资料整理和发布检查发生在离线维护阶段，不阻断用户既有生成任务。本次不触发付费视频测试，不宣称卡片已提升实际视频质量；真实效果仍需后续独立验证。

## 7. 失败处理与验收

- 三个来源都有适配器和固定版本清单。枚举完整性、解析失败、重复候选及来源冲突均可核对；失败不能伪装成空仓库或全量成功。
- 网络、解析或字段异常保留当前已发布库；候选数据验证后整体发布，避免半导入覆盖。重跑不产生重复案例。
- 验证同一帖多媒体不误合并、跨仓库同一案例多出处、反推不冒充原文、无提示词不补写、来源字段安全展示。
- 用例覆盖所有用途，检查卡片差异、出处、可解析版本、当前能力适配、收藏、搜索分页和节点投影。
- 既有后端导演测试和前端选卡测试继续通过；增加导入适配、去重、发布回退、案例查询、跨题材浏览及旧版本回归测试。
- 浏览器验收全局案例检索、手法关联、片段应用、不兼容提示、窄屏和回焦。导入报告区分索引完成、提炼完成、发布完成及未实测状态。
