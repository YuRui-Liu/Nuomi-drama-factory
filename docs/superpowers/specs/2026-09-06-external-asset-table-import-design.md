# 外部资产表导入设计

## 背景

当前项目会从剧本文本推导角色、场景和道具。目标行为是将“剧本摄入”和“资产构建”彻底解耦：导入剧本时不自动创建或补全任何角色、场景、道具；用户需要资产时，可以继续主动使用已有的角色“自动提取”、场景/道具“从知识图谱构建”，也可以在对应资产面板导入外部资产表。

首版外部文件仅支持 `.md` 和 `.txt`。参考输入包括：

- `墨骨辨冤/manuscript/04_人物表.md`
- `墨骨辨冤/manuscript/05_场景与道具.md`

## 目标

1. 剧本导入不隐式触发角色、场景或道具构建。
2. 角色、场景、道具面板分别支持导入外部表格并推导本领域字段。
3. 导入前提供字段级预览，用户确认前不修改项目数据。
4. 导入只新增资产或补全空字段，绝不覆盖已有非空数据和生成资产。
5. 保留现有显式“自动提取”和“从知识图谱构建”能力。
6. 导入过程可审计、有证据、原子提交，并能应对预览后的并发编辑。

## 非目标

- 首版不支持 `.docx`、`.pdf` 或表格工作簿。
- 不从文件路径或文件名猜测资产内容。
- 不因导入混合文件而一次修改多个资产域。
- 不自动创建场景变体或道具状态分身。
- 不从剧本或知识图谱补充外部表未提供的信息。
- 不改变现有显式资产构建按钮的业务语义。

## 总体架构

系统保留四条彼此独立的入口：

```text
剧本导入
  -> 保存、分段并构建剧本/剧集资产
  -> 不创建或补全角色、场景、道具

角色面板 -> 导入人物表 -> 仅解析角色 -> 预览 -> 确认
场景面板 -> 导入场景表 -> 仅解析场景 -> 预览 -> 确认
道具面板 -> 导入道具表 -> 仅解析道具 -> 预览 -> 确认

角色面板 -> 自动提取（保留现有显式能力）
场景/道具面板 -> 从知识图谱构建（保留现有显式能力）
```

外部表导入采用“共享导入框架 + 领域适配器”：

- `AssetImportService`：负责文件校验、临时预览、差异计算、确认幂等、审计和原子提交。
- `CharacterSheetAdapter`：识别角色条目、推导角色字段、验证角色级证据。
- `SceneSheetAdapter`：识别场景条目、推导场景字段、验证场景级证据。
- `PropSheetAdapter`：识别道具条目、推导道具字段、验证道具级证据。

每个适配器只依赖统一的候选输入/输出协议，不了解其他领域的存储细节。共享服务通过领域仓储接口读取当前资产并提交合并结果。

## 文件接收与内容边界

### 文件校验

- 仅接收一个 `.md` 或 `.txt` 文件。
- 接受 UTF-8 和带 UTF-8 BOM 的文本，并统一换行符。
- 拒绝空文件、无法解码的文件、超出既有上传安全上限的文件和不支持的扩展名。
- 服务端不能只依赖客户端扩展名校验。

### 章节和条目识别

适配器支持 Markdown 标题、字段列表、Markdown 表格和结构明确的普通文本。混合文件由当前入口决定解析范围：

- 从场景入口上传 `05_场景与道具.md` 时，只读取场景表和可明确归属于场景的连续性内容。
- 从道具入口上传同一文件时，只读取道具表、道具红线及可明确归属的稳定字段。
- 其他资产章节被忽略，在预览摘要中说明，不作为错误。

角色适配器导入所有被独立定义的具名个体，包括标题角色和表格行角色。分类标题、人物信息边界等说明段落中仅被提及且没有独立定义的人名，不创建为角色。

## 解析、推导与证据

解析采用“结构规则优先、模型归纳兜底”：

1. 规则层确定目标章节、条目边界、名称、编号和显式键值。
2. 领域模型在单个条目的完整资料块内映射、压缩和保守推导字段。
3. 每个候选字段必须关联来源片段；无证据字段不进入待写结果。
4. 不得根据名称猜测性别、地域、阶层、外貌或关系。
5. 单个候选失败不阻断其他候选预览，但失败项必须形成警告。

模型不可用或整个文件无法形成任何有效候选时，解析失败且不产生可确认的半成品预览。

### 角色字段

- 角色名 -> `name`
- 身份/职业 -> `occupation`、`social_identity`
- 前史 -> `biography`
- 核心缺陷、价值逻辑、语言习惯等 -> `personality`
- 功能、对主角的阻力、人物弧线、关键选择等 -> `dramatic_function`
- 视觉锚点 -> `description`，同时作为后续外观设计约束
- 明确年龄和性别 -> 标准化后的年龄段和性别
- 明确别名和关系 -> `aliases`、`relationships`
- 目标、能力、恐惧等可以保守归纳进人物简介或小传，但不得创造剧情事实
- 版权/形象风险保留为生成约束，禁止写入真实演员或公众人物外观

表格中的简略角色只填写表格实际支持或可保守归纳的字段。

### 场景字段

- 场景名 -> `name`
- 内/外 -> `scene_type`
- 常用时段 -> `time_of_day`
- 长期视觉特征 -> `environment_prompt`
- 故事功能、首次出现、连续性约束 -> `description` 或 `notes`
- 明确别名 -> `aliases`

外部表默认创建基础场景，不推导 `base_scene_id` 或 `variant_id`。明确描述的状态变化首版仅进入备注预览，不自动创建派生场景。

### 道具字段

- 道具名 -> `name`
- 初始持有人 -> `owner`
- 来源/权利、首次出现、状态变化、回收窗口、使用红线 -> `description` 或 `notes`
- 明确的材质、尺寸、颜色和结构 -> `visual_prompt`
- 明确别名 -> `aliases`
- 有充分证据时保守归类 `prop_type`，否则使用 `object`

状态变化保留为叙事资料，不自动创建多个道具资产。

### 编号和全局规则

`L001`、`P001` 等编号作为来源编号和审计信息保留，不替代资产显示名称。连续性、红线或稳定字段只有在能明确归属于单个资产时才进入其 `notes`；无法归属的全局规则仅保留在导入审计和预览警告中。

## 合并规则

### 名称匹配

三类资产均通过规范化名称匹配现有记录。规范化只处理空白、全半角和无语义边界标点，不进行模糊语义合并。明确别名可作为辅助匹配依据；出现多个可能归属时必须标记冲突，不自动选择。

单个文件中重复定义同一资产时，先在候选层合并。字段值互相冲突时，该字段不进入待写结果并显示警告。

### 仅补空字段

- 资产不存在：创建新资产并写入全部有效候选字段。
- 资产已存在：只写当前为空的字段。
- 非空字符串、非空数组、图片路径、引用图、生成结果和设计数据均不可覆盖。
- `extraction_locked` 不因导入改变；用户明确发起的外部表导入可以为锁定角色补空字段，但不能覆盖已有值。
- 技术默认值若不代表用户选择，可视为空值。例如新道具默认的 `prop_type="object"` 可被有证据的更具体分类替换；哪些默认值属于“技术默认”必须由领域适配器显式列举，不能用通用真假值判断。

确认时服务端重新读取当前记录并重算差异。预览后由用户或其他任务填入的字段视为最新非空值，自动跳过并在最终结果中报告。

## 预览与确认协议

### 接口

```text
POST /api/v1/projects/{project}/asset-imports/{asset_type}/preview
POST /api/v1/projects/{project}/asset-imports/{asset_type}/{import_id}/confirm
```

`asset_type` 仅允许 `character`、`scene`、`prop`。

预览请求接收文件，返回：

- `import_id`
- 文件元数据和内容哈希
- 新增资产及待写字段
- 已有资产的空字段补全
- 因已有值而保持不变的字段
- 冲突、证据不足、无法归属的内容
- 被忽略的其他资产章节摘要
- 新增、补全、跳过和警告计数

确认请求不重新接收或信任客户端候选数据，只引用服务端保存的 `import_id`。服务端重新计算合并结果并一次性提交，返回实际新增、补全、跳过和警告明细。

### 临时预览状态

- 预览按项目、用户和资产类型隔离。
- 设置明确有效期，只能成功确认一次。
- 已过期、已确认或作用域不匹配的预览必须拒绝。
- 预览本身不修改正式资产表。

## 前端交互

角色、场景、道具面板各自增加对应的“导入人物表”“导入场景表”“导入道具表”按钮，复用同一套导入对话框外壳。

流程为：

1. 选择或拖入 `.md` / `.txt` 文件。
2. 上传并显示解析状态。
3. 展示当前资产类型的只读差异预览。
4. 用户确认或取消。
5. 确认成功后刷新当前资产列表并显示实际新增、补全和跳过数量。

预览逐资产、逐字段展示：

- `新增`：准备创建的资产和字段。
- `补全`：`当前为空 -> 准备写入`。
- `保持不变`：已有非空字段及不会覆盖的说明。
- `警告`：重复定义、相互矛盾、证据不足或无法识别的内容。

场景入口和道具入口即使上传同一个混合文件，也需要分别预览、分别确认，任何一次确认都不能修改另一资产域。

## 原子性、审计与安全

- 一次确认中的正式数据写入必须位于单个数据库事务中；任何写入失败都整批回滚。
- 审计记录包含项目、用户、资产类型、来源文件名、内容哈希、创建时间、确认时间、解析结果摘要和最终合并结果。
- 字段证据引用外部表的原文片段及位置，不伪装成剧本证据。
- 外部表不写入剧本 source/chunk，不改变剧本导入 manifest。
- 日志不得写入完整上传内容，只记录必要元数据、计数和安全截断后的错误。

## 错误处理

- 格式不支持、文件为空、无法解码：不创建预览。
- 没有明确目标资产定义：返回可理解的错误，不写入数据。
- 个别候选失败：其他候选仍可预览，失败项进入警告。
- 同名或别名匹配歧义：不自动合并，进入冲突警告。
- 模型不可用：解析失败，不允许确认不完整结果。
- 预览过期、已确认或作用域错误：要求重新上传。
- 数据库确认失败：整个事务回滚，预览保留为未确认状态以便安全重试；只有成功提交后才标记已确认。

## 与现有流程的关系

剧本导入任务需要停止自动调用角色、场景和道具构建步骤，但继续完成剧本文本、章节、剧集及其他非资产摄入职责。

现有能力继续保留并且只能由显式操作触发：

- 角色“自动提取”仍从剧本来源分析角色。
- 场景“从知识图谱构建”仍按当前流程构建场景。
- 道具“从知识图谱构建”仍按当前流程构建道具。

外部表、自动提取和知识图谱构建是并列来源。它们共享“不覆盖已有用户数据”的保护语义，但审计来源必须可区分，且任何来源均不得隐式触发另一个来源。

## 测试策略

### 后端单元与契约测试

- `.md`、`.txt`、UTF-8 BOM 和不同换行符均可处理。
- 拒绝空文件、错误扩展名和无法解码内容。
- `04_人物表.md` 能识别标题角色和表格角色，不把说明段落提及的人名创建为角色。
- `05_场景与道具.md` 在场景模式只产生场景，在道具模式只产生道具。
- 字段映射、证据定位、重复候选合并和冲突警告正确。
- 已有非空标量、数组、设计数据、图片和生成结果不被覆盖。
- 空字段及显式允许的技术默认值能够补全。
- 锁定角色可补空字段且锁定状态保持不变。
- 预览不写正式资产；确认原子写入；重复确认被拒绝。
- 预览后的并发编辑在确认阶段受到保护。
- 事务失败整批回滚，预览不被错误标记为已确认。
- 项目、用户和资产类型作用域不可串用。

### 现有流程回归测试

- 剧本导入完成后不创建或补全角色、场景、道具。
- 角色“自动提取”仍能由用户手动启动。
- 场景和道具“从知识图谱构建”仍能由用户手动启动。
- 三种显式构建来源互不隐式触发。

### 前端测试

- 三个面板显示各自的导入入口和正确文案。
- 上传、解析、预览、确认、取消、过期和错误状态可用。
- 预览正确区分新增、补全、保持不变和警告。
- 混合文件只显示当前资产类型，并说明忽略的其他章节。
- 确认后只刷新当前资产列表，并显示服务端返回的实际结果。

## 验收标准

1. 仅导入剧本后，项目已有角色、场景和道具保持原状，也不会新增三类资产。
2. 用户仍可主动运行原有的角色自动提取与场景/道具知识图谱构建。
3. 用户在角色面板上传 `04_人物表.md` 时，所有独立定义的具名角色进入预览；确认后只新增角色或补全空字段。
4. 用户分别从场景和道具面板上传 `05_场景与道具.md` 时，两次预览和确认只影响各自资产域。
5. 任意导入均不覆盖已有非空字段、图片、生成结果或设计数据。
6. 所有正式写入均经过用户确认、可审计、具备字段证据并保持事务原子性。
