# Agent、节点与画布创作工作空间设计

日期：2026-10-13

分支：`feat/canvas`

状态：各设计章节已获用户确认；书面规格待审阅，尚未进入实现。

## 1. 目标与已确认决策

将短剧／漫剧创作统一到每集画布。用户与主 Agent 共同操作画布，主 Agent 按任务调用专业 Agent，通过不同题材策略和技能支持不同创作。项目共享跨集资产，每集一张主画布，集内自由创建、连接、分组和编辑节点，不设置必须顺序完成的制作阶段。

本分支面向新项目，不迁移旧项目，不维护两套创作路径。删除旧分页流水线及其专属逻辑，但不删除本地已有项目文件。旧格式项目不得被新工作空间自动转换或写入；入口清晰标识不支持，并提供创建新项目的路径。

沿用当前产品视觉风格、画布交互与大部分节点，保留资产中心、手法库和风格库。此前独立重画的交互草图已被用户否决，不作为界面实现依据。布局细节须基于现有界面校验，不据此规格自行重做主题、节点卡片或专业编辑器。

## 2. 方案比较与选择

选择画布为主、Agent 侧栏协作：产物持续可见，手动操作与局部委托自然衔接。对话主导方案会削弱直接操作节点的效率；对话／画布双模式会增加上下文切换。项目共享资产、每集一张画布控制内容规模，场景分组仅用于组织，不承担固定执行阶段。

竞品调研的公开依据：

- 小云雀官方教程中心：https://xyq.jianying.com/tutorials 。公开目录介绍对话与画布协作、资产引用、角色和场景节点、节点编辑等能力。
- Seko 官方首页：https://seko.sensetime.com/ 。公开入口提供创作 Agent、无限画布、空白画布和提示词批量上传。

以上仅作为交互方向参考，未进行登录后的完整实测，不推断竞品内部实现。

## 3. 工作空间与交互

进入项目后选择集数，直接打开该集画布。剧本、分镜、视频、音频、合成不再构成顺序切页路径。保留必要的项目与集管理、账户、模型配置等支撑入口，不将这些管理入口误删为创作流水线。

主 Agent 使用现有侧栏，允许收起。未选择节点时上下文为当前集；选择节点后显示明确的引用范围，用户可委托局部操作。专业 Agent 的状态由主 Agent 汇总，并能定位其输入、输出和待确认对象，不要求用户管理多个聊天窗口。

自由添加节点、上传参考、拖入共享资产、连线、分组、调整布局及节点内编辑延续现有交互。节点专业参数和图像、视频、音频、3D 等编辑能力保留。预览与合成从现有节点工具展开，不另外设计一套大型剪辑产品。

资产中心保留跨集资产管理能力。手法库、风格库保留管理和浏览入口，同时支持节点与 Agent 引用。将画布产物保存为共享资产使用明确的发布操作；普通节点生成不会自动覆盖项目共享资产。

## 4. 本体语义模型

采用类型、关系和操作契约实现 Ontology 思想，首版无需图数据库、通用本体编辑器或向用户展示本体术语。

| 单元 | 职责和主要约束 |
| --- | --- |
| 创作对象 | 项目、集、剧情片段、角色、场景、分镜、媒体产物、风格、手法具有稳定对象 ID 和明确类型 |
| 对象版本 | 保存创作内容和来源；生成锁定具体输入版本，历史版本不被静默替换 |
| 关系 | 明确属于、引用、采用、由其生成、选用版本等语义；关系两端校验类型和作用域 |
| 画布节点 | 对象的展示或创作操作实例；保存位置、尺寸、分组、对象引用或操作配置 |
| 操作与运行 | 描述受支持的对象操作、输入输出、前置条件和运行记录 |
| 确认记录 | 关联提案、对象版本、授权范围和用户决定 |

对象 ID 与节点 ID 分离，同一角色在多集出现仍指向同一资产身份，但各集可绑定不同版本。自由文本、上传和临时生成节点无需先入资产中心；对象类型按能力声明确定，纯布局分组不强制成为业务对象。

语义对象及版本是创作内容的权威来源，画布负责展示与操作组织，资产中心等库负责相应对象的管理。现有节点字段通过适配层读写统一契约，避免节点、资产库和 Agent 各存一份不一致的内容。

连线区分执行输入、素材引用和来源追溯。追溯线不触发重新执行；分组和画布坐标不决定依赖或成片顺序。合成顺序以显式时间线为准。执行依赖拒绝循环，非执行关系按其业务规则校验。

## 5. Agent 与执行数据流

用户意图 → 主 Agent 解析目标与范围 → 查询对象、版本和可用能力 → 委托专业 Agent → 提案或可执行操作 → 关键确认 → 统一操作服务 → 现有任务后端与媒体能力 → 验证产物 → 新对象版本／产物与关系 → 更新画布视图。

手动节点操作进入同一操作服务。Agent 使用受支持的领域工具，不能绕过接口直接写存储、伪造生成结果或另建不可见的执行链。

主 Agent 负责上下文、题材策略、任务分解、委托范围与进度汇总；专业 Agent 负责具体创作任务，返回结构化提案、操作或产物引用。专业能力及其工具权限按目录声明，用户不必先配置一个复杂的 Agent 团队。

每次操作携带项目、集、目标对象／节点、预期版本、输入版本、请求幂等键与授权范围。业务服务校验对象作用域，不能仅靠提示词限制跨集修改。共享资产更新与创建本集变体必须使用不同的显式操作。

例如“把林舟换年轻一些，只调整第二集”：创建角色形象版本并调整第二集引用，列出本集受影响的产物；其他集继续绑定原版本。

## 6. 创作确认与版本影响

Agent 默认自动推进，在剧本方向、角色形象、分镜方案等对作品有实质影响的决定处提交确认。确认依据实际任务，不设置所有作品必须经过的硬编码阶段。明确授权后不重复询问同一范围与同一版本。

确认卡展示决定内容、关联节点、采用版本及下一步执行范围；支持认可、提出修改和直接编辑。确认后内容发生变化，旧确认失效。若用户已授权按明确范围继续完成，记录授权并在范围内推进。

输入版本变化后标记依赖产物可能过期，保留可播放的已有结果。用户或 Agent 选择重做范围，默认不自动启动新的付费生成。资产中心发布新版本也不静默替换各集已选版本。

## 7. 可靠性、冲突和撤销

- 节点运行至少区分等待、运行中、成功、失败、阻塞、取消请求及取消；提交状态不明单独标记并先对账。
- 运行、供应商任务映射和结果必须持久化，关闭网页不丢任务；重新打开按已有任务恢复状态。
- 输入快照、请求幂等与结果应用幂等共同避免重复提交、重复落图。供应商能力不足时不承诺恰好执行一次，不盲目重发状态不明的请求。
- 独立分支可继续，失败仅阻塞依赖它的部分。重试复用有效产物，仅执行失败或经授权需要更新的部分。
- Agent 操作携带预期对象版本；用户修改同一内容时不能被覆盖，Agent 结果保留为候选并提示冲突。用户布局变动与内容结果通过字段范围合并。
- 取消停止新提交，并尽可能取消正在执行的任务；无法取消的任务继续对账、保留产物，但不自动继续下游。
- 撤销恢复创作内容或引用，采用新的版本记录，不删除历史生成证据；已提交的外部生成和已发生费用不能由撤销逆转。

## 8. 模块边界与现有代码映射

| 模块 | 职责 | 现有基础／依赖 |
| --- | --- | --- |
| 集创作工作空间 | 集切换、画布、Agent 侧栏、库入口 | `frontend/src/features/freezone/FreezoneShell.tsx`、`features/canvas`、`features/superchat` |
| 节点与能力适配 | 延续节点 UI，声明操作、端口和语义映射 | `canvas/domain/canvasNodes.ts`、`nodeRegistry.ts`、现有节点组件 |
| 语义对象服务 | 对象身份、版本、关系、作用域与影响查询 | 现有项目／资产存储，经明确适配统一访问 |
| Agent 协作服务 | 上下文、专业委托、提案和确认 | `src/novelvideo/chat`、现有 Agent 运行时 |
| 画布执行服务 | 依赖、调度、幂等、取消、恢复、结果更新 | `src/novelvideo/freezone/orchestration`、任务后端 |
| 库适配 | 共享资产、风格、手法的查询、引用与发布 | 现有资产中心、`features/technique-library`、风格库 |

对象服务不依赖界面组件；Agent 依赖公开操作契约；调度器依赖能力目录与执行适配器；画布通过查询与操作结果呈现状态。具体文件拆分、存储表结构和删除文件清单在实现计划中依据引用关系明确。

当前节点目录包含 19 种节点：上传、图像编辑、图像生成、图片结果、剧情上下文、文本注释、分组、分镜拆分、分镜生成、视频、视频导演、音频、视频故事、视频合成、音乐工作台、剧本、全景查看、3D 世界和 Skill。以保留这些能力为基线。旧主线耦合节点先改为独立画布语义；节点删除必须在计划中列明理由，不能以简化设计为由批量替换。

## 9. 保留与删除边界

保留：现有视觉与基础画布交互、大部分节点及专业编辑器、资产中心、手法库、风格库、模型和供应商接入、媒体任务、持久化及必要的账户／配置／项目管理能力。

删除目标：旧剧本、分镜、视频、音频、合成等阶段专属页面与导航，固定阶段推进、旧规则流水线执行器，以及画布与旧主线之间专属的素材投影、提交回填、状态同步接口和测试。不得仅隐藏导航后继续把旧流程作为创作的实际执行引擎。

旧路由中被节点或库依赖的通用能力先抽取或重新挂接，再删除旧消费者。叙事分组可以作为 Agent 的创作策略，但不能继续充当所有创作的强制生产单位或阶段门禁。仓库旧生产说明随实际删除范围同步更新。

删除业务代码不等于清理用户文件，不删除旧项目素材。当前工作区包含大量已有未提交修改，实现前需按改动归属梳理，禁止用整体还原或清理覆盖这些工作。

## 10. 验收与测试

1. 新建短剧项目与两集，进入各集直接打开独立画布，集内可任意添加节点和引用素材，无旧阶段前置条件。
2. 资产中心创建角色并在两集引用；第二集采用新形象版本，第一集的引用与产物保持原版本。
3. 手法库和风格库仍可管理、浏览和引用；人工与 Agent 引用解析到同一对象版本。
4. 主 Agent 从创作意图搭建可编辑节点，调用专业 Agent，关键方案在关联节点确认，确认后继续限定任务。
5. 选中局部节点要求修改，仅目标和经授权的依赖范围发生变化；所有输出可追溯到输入和运行记录。
6. 人工编辑与 Agent 同时修改同一对象，触发版本冲突并保留候选；布局编辑不被生成回写覆盖。
7. 单节点失败、提交超时、重复请求、取消、重启服务与关闭页面均有对应恢复测试，不重复产生逻辑输出；对账与不明提交覆盖供应商限制。
8. 端到端完成一段短剧内容并在画布内合成、播放和导出真实产物。单元测试和模拟供应商通过不能替代最终真实链路验收。
9. 基于当前界面截图验证视觉延续、节点编辑能力和库入口，测试画布选择、引用、自由添加、侧栏协作及错误定位。
10. 检查已删除路径的路由、调用方与测试，不留隐藏的旧阶段引擎；验证旧项目文件不被修改或自动迁移。

测试分层：对象与关系规则单元测试，操作契约和持久化集成测试，运行恢复与作用域测试，核心交互测试，以及一条真实制作验收。只针对改动范围验证，避免无关的大规模重测。

## 11. 实施顺序与非目标

在同一目标下分阶段实施：现状与删除依赖清单 → 语义契约及现有能力适配 → 集画布与库引用 → 主 Agent 协作及确认 → 切断并删除旧流程 → 核心链路与视觉验收。各阶段服务同一个闭环，不扩大为多个独立产品。

不在本次范围：旧项目迁移、视觉主题重做、全部节点重写、图数据库引入、通用本体编辑器、Agent 市场、多人实时协作、通用视频编辑器重建和计费体系重构。
