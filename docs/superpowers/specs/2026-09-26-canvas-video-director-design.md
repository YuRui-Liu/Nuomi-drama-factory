# 资产库多图选择与画布视频导演台需求规格

日期：2026-09-26。状态：分节设计已获用户确认，书面规格待用户审阅；尚未进入实现。

## 1. 目标与范围

在自由画布新增独立的「视频导演台」节点，支持共享主体参考、多片段编排、视频模型选择、runtime 自动改写及 RunningHub 视频生成。同时增强现有资产库，使用户能进入角色并选择基础图片和变体图片。

首期视频模型为 MiniMax H3 系列，保留新增其他视频模型的扩展接口。“模型选择”指视频生成模型，不是生成首尾帧图片的模型。首尾帧由用户提供，本期不增加自动生图子流程。

用户正文及本次确认是需求依据；截图仅作为现有资产库界面参考。项目历史文档、工作流导出和 skill 中的检查策略属于参考资料，不能覆盖本需求明确的“不做 QC”和优化失败处理约定。

## 2. 已确认的产品决策

1. 新增专门的导演台视频节点，保留现有普通视频节点。
2. 一个导演台支持多个有序片段，各段设置提示词、时长及首尾帧，共享主体参考素材。
3. 选择 MiniMax 后，有主体参考图使用 H3 Ref；无主体参考图、只有首尾帧时使用普通 H3。首尾帧不被当成主体参考图。
4. 首期包含纯主体参考生成：有主体参考图时，片段可以没有首尾帧。
5. 点击生成后自动运行提示词优化，成功即提交；不增加用户审批优化结果的步骤。
6. 优化失败暂停本次生成并允许重试，禁止回退原始提示词直接提交。
7. 改写遵循项目已吸收的 MiniMax H3 提示词规则；不增加 QC 评分、质量审核或反复修稿闸门。
8. 同一角色的基础图和多张变体图可同时选择，按实际图片张数计算参考图数量。
9. 采用「节点摘要 + 展开导演台」布局。

## 3. 交互设计

### 3.1 画布节点与展开面板

节点展示视频预览、所选视频模型、实际工作流（H3 / H3 Ref）、片段数、预计总时长、生成状态，以及“打开导演台”“生成”入口。生成成功后成片回填本节点，并沿用画布视频预览和连接能力。

展开导演台采用大面板：顶部为模型及全局参数，中部为共享主体参考区，下方为有序片段编辑区。片段支持添加、复制、删除和排序；每段包含原始提示词、期望时长、首帧槽位及尾帧槽位。复制片段生成新的稳定片段 ID，排序不改变既有 ID。

关闭面板、刷新页面后草稿仍可恢复。生成使用点击时的输入快照；生成中的草稿编辑只影响下一次生成。展示结果时区分对应的生成版本，旧任务完成不得覆盖较新任务的结果。

### 3.2 资产库

角色卡片作为进入图片列表的入口。二级列表标明基础图、变体图及已有的状态/服装名称；跨角色、多图选择可以累积，返回上级不清空选择。界面显示角色的已选图片数量，总数按图片而非角色计数。

共享参考入口使用多选，确认后加入有序主体参考列表，允许删除及调整顺序。同一具体图片去重；同一角色不同图片保留。首帧或尾帧入口使用单选，只填入当前片段的对应槽位，不顺带增加共享主体参考。

选择结果需要保留资产 ID、角色 ID（存在时）、图片 ID、基础/变体类别、变体说明及图片地址，不能只返回角色封面 URL。人物图片列表来自现有角色资产数据，不以重新生成图片为前提。无可用图片时展示空态；素材失效时提示重新选择。

道具、场景及上传图片继续沿用现有资产入口。本期不新增道具或场景的变体编辑系统。

### 3.3 状态和历史

状态按实际阶段显示为：草稿、优化中、提交中、排队中、生成中、完成或失败。失败信息说明发生在优化、提交、供应商执行还是下载阶段，并提供对应重试入口。

历史记录保存输入快照、原始提示词、优化结果、规则版本、参数、工作流身份、供应商任务 ID 与结果地址。优化结果可展开查看；不要求用户二次确认。历史内容不得被后续草稿编辑覆盖。

## 4. 模型路由与能力边界

模型选择以用户可理解的视频模型为单位。MiniMax 适配器根据共享主体参考图是否为空解析到普通 H3 或 H3 Ref，不要求用户手动在这两个工作流之间切换。

| 共享主体参考 | 片段帧输入 | 处理规则 |
| --- | --- | --- |
| 无 | 首帧 | 普通 H3，首帧模式 |
| 无 | 首帧和尾帧 | 普通 H3，首尾帧模式 |
| 有 | 无首尾帧 | H3 Ref，纯主体参考模式，首期必须支持 |
| 有 | 首帧或首尾帧 | H3 Ref，按已验证的组合能力提交 |
| 无 | 无首尾帧 | 本期不扩展纯文生视频，提示添加首帧或主体参考图 |
| 任意 | 只有尾帧 | 本期不开放仅尾帧控制，提示补充首帧或移除尾帧 |

所有片段在同一次请求中保持顺序。全局选择了主体参考后，不允许某段静默绕过参考图去普通 H3。某组合不受实际工作流支持时明确指出对应片段，不能删除参考图、忽略首尾帧或切换工作流后继续。

纯主体参考是确定需求，不得套用旧叙事组适配器“每段必须有首帧”的限制。Ref 与首尾帧的混用属于开发前必须核实的能力：现有本地适配字段并不等于线上已验证支持。若实际工作流不支持，应如实展示不可用状态，并报告需求与供应商能力差异；不得宣称混合模式已完成验收。

后续模型通过能力描述和适配器扩展：声明多段、主体参考、首尾帧、画幅、分辨率和参数限制，并提供对应的优化及提交实现。仅在注册表增加模型名不足以构成支持；不支持当前草稿的模型应显示原因且保留草稿。

## 5. H3 参数设计

以下范围依据仓库现有配置和适配代码，不构成对当前线上工作流的实测声明。开发前须核对所配置工作流的实际定义、版本及参数绑定。

| 参数 | 首期界面 | 系统责任 |
| --- | --- | --- |
| 视频模型 | 用户选择，首期 MiniMax | 根据能力配置扩展其他模型 |
| 实际工作流 | 只读显示 H3 / H3 Ref | 根据主体参考自动解析 |
| 画幅 | 9:16、16:9 | 整次生成统一，映射到实际像素 |
| 分辨率 | 720p、1080p | 使用项目尺寸预设，并同步工作流细化节点尺寸 |
| 每段时长 | 用户填写秒数 | 换算合法帧数，显示实际预计时长和总时长 |
| 主体参考 | 全局有序多图 | 读取当前模型/项目限制，首尾帧不占此数量 |
| 首尾帧 | 每段独立选择 | 根据模式和验证过的组合能力传递 |
| 帧率 | 不开放编辑 | 现有 H3 时间线为 24 fps |
| seed、cfg、采样及细化参数 | 首期不开放编辑 | 使用适配器和工作流配置，并保存有效参数 |

现有 H3 尺寸映射：720p 竖屏为 736×1280、横屏为 1280×736；1080p 竖屏为 1088×1920、横屏为 1920×1088。产品档位与实际像素分别记录，不伪称精确 720 或 1080 高度。

时长复用项目的合法帧数规则（24 fps、17k+5），不得静默把用户时长替换为供应商默认值。可输入时长、片段数与总帧数上限从核实后的适配能力中提供，前后端使用同一约束来源，不凭界面习惯编造常量。

现有项目主体参考上限默认 5、设置范围 1–10。新节点读取实际生效配置并与工作流能力取兼容范围，不能把截图中的 9 当成 H3 固定上限。基础图与变体各占一张；首尾帧单独计算。

## 6. runtime 提示词改写

使用项目配置的文本任务 runtime，不在节点内绑定某一家文本服务。输入包含片段稳定 ID、顺序、原始提示词、实际帧数、首尾帧、共享参考清单及相邻片段上下文。输出按片段 ID 关联优化结果，不能改变片段顺序或自行增删用户片段。

改写规则优先复用项目吸收的 H3 规则集及格式编译器：

- `src/novelvideo/media_capabilities/video/h3_prompt_profile.py`：H3 模式、动作容量、运镜、主体/场景一致性、首尾帧衔接、对白和声音规则；当前检查版本为 17。
- `src/novelvideo/media_capabilities/video/h3_prompt_compiler.py` 与 `h3_wire.py`：将结构化内容转为 H3 实际提示词格式。
- `docs/plans/2026-08-29-minimax-h3-codex-prompt-generator-design.md`：记录已吸收的官方 `h3-prompt-writing` 规则来源，作为历史依据。

复用规则不等于原样复用旧执行链。现有规则包含硬质量失败表述，旧优化器也关联质量检查：新节点必须拆开提示词写作指导、可提交格式校验与主观质量检查。遵循写作指导，但不调用 QC 评分、质量门禁、循环审稿修复或生成后质量审批。不得要求导入完整叙事组、导演计划或不存在的角色事实才能使用画布节点。

保留身份、服装、场景、道具、运镜方向和实际首尾画面约束；对白保留原文及说话人，不擅自编造人物、台词或素材。中文输入可转为 H3 需要的描述格式，身份标识和对白内容不因描述语言转换而改变。

同一角色的多张图片仍对应同一个角色身份；保留各图的变体含义，不能把每张图片都写成一个新角色，不能把互斥服装自动融合。片段明确指定变体时遵循指定；未指定时保留素材标签与用户原意，不新增 QC 关卡要求人工审批。

必要校验仅用于形成有效请求，例如必填内容、结构可解析、片段 ID 对齐、图片可读取、参考数量、时间线及工作流支持范围。业务质量评分不能伪装成格式错误。若结构化输出不能形成有效请求，则属于优化失败，保留输入并允许重试。

## 7. 职责与数据流

| 单元 | 职责和边界 |
| --- | --- |
| 资产查询与选择 | 提供角色及其图片列表；返回稳定图片身份和元数据；不负责视频生成 |
| 导演台节点与面板 | 编辑及持久化草稿、显示状态和结果；不直接调用 RunningHub |
| 导演台任务编排 | 冻结输入、调用 runtime、管理阶段状态、重试和历史 |
| 模型能力与路由 | 声明可用参数和输入组合，解析具体模型/工作流 |
| H3 优化与编译适配 | 应用项目 H3 写作规则，编译格式；不执行 QC |
| RunningHub 执行与结果接收 | 上传素材、提交、查询和下载结果，使用现有并发管理 |

流程：草稿 → 必要输入校验 → 冻结生成快照 → runtime 改写 → 格式编译 → 提交一个有序多段工作流任务 → 查询 → 下载完整视频 → 记录历史并回填节点。

草稿至少包含模型选择、全局参数、有序共享参考与片段列表。生成快照另外保存草稿版本、素材身份/内容指纹、规则版本、实际参数、解析后的工作流及优化结果。供应商凭据留在现有服务端配置中。

优先复用现有任务、素材上传、并发和视频展示能力；不把新多段编辑器继续堆入大型 `VideoNode.tsx`，不进行与此需求无关的重构。

## 8. 失败恢复

1. 优化调用失败或输出无法编译：不提交供应商，保留草稿和错误；重试优化使用相同快照。用户修改输入后启动新版本。
2. 优化成功但提交明确失败：保留优化结果，可重新提交相同快照，不重复改写。输入、素材内容或相关规则发生变化后不得复用过期优化缓存。
3. 提交响应超时、是否受理不明：先通过已有记录和供应商能力确认任务状态，不能直接重发。无法确认时明确显示状态未知。
4. 已获取任务 ID：刷新或重新打开面板后继续查询该任务，不创建重复任务。
5. 供应商执行失败：保留失败任务历史，用户重试创建新的生成尝试。下载失败先重试获取已有结果，不重新付费生成。
6. 输出为空或文件不可读取属于交付失败；不以审美、演技、提示词评分等 QC 结果拦截已取得的视频。
7. 运行中的草稿编辑不改动快照；旧任务回调只更新自身历史，不覆盖较新任务状态。

## 9. 验收标准

- 资产：点击角色可查看基础图与变体；同角色多图、跨角色选择、返回保留、去重、图片计数及首尾帧单选均正确；重新同步不产生重复图片身份。
- 界面：新增独立节点；展开多段面板可增删、复制、排序、保存并恢复；节点正确显示摘要及成片。
- 路由：有主体参考选 H3 Ref，无主体参考且有首帧选 H3；首尾帧本身不会误触发 Ref；不支持的输入组合明确报错且不丢素材。
- 纯 Ref：无任何首尾帧的多段请求可经 H3 Ref 生成，不被旧适配器首帧必填校验拦截。
- 提示词：确实通过所配置 runtime 及项目 H3 规则改写；片段 ID、参考身份、对白和顺序保持正确；原文与优化结果可追溯。
- 无 QC：质量评分低或主观检查意见不会触发阻断或反复修稿；必要协议错误仍有清晰提示。
- 恢复：优化失败不提交原文；提交失败可复用优化结果；有任务 ID 不重复提交；未知受理状态不盲目重发；下载失败不重新生成。
- 参数：画幅、像素、合法时长、总帧数、参考上限与实际请求一致；尺寸不得被细化节点默认值覆盖。
- 多段输出：按用户顺序生成完整视频，保留模型产生的音轨；不追加未经要求的 ASR 或付费 QC。
- 扩展：新增模型必须有能力定义和对应实现，不能只出现可选名称；切换不兼容模型时保留草稿并说明差异。

验证分为聚焦的前后端回归、工作流契约核对和实际生成验收。纯 Ref、普通 H3 首尾帧、多段输出及 Ref 混合控制分别记录证据；本地测试和历史工作流样例不替代供应商验收。此次仅编写规格，没有运行付费生成或声称线上验收通过。
