# 画布视频导演节点图片输入改版设计

日期：2026-09-30。状态：交互、数据流及验收范围已获用户分节确认；书面规格待审阅。

## 1. 问题与目标

现有「视频导演」节点的大块预览区在尚无结果时只显示“尚无视频”。首帧、尾帧和主体参考图入口藏在展开面板中，用户无法在画布上判断图片该放在哪里，也无法直接把本地图片或上游图片节点用于生成。

本次改版让用户在节点卡片上就能完成第一段的图片和提示词输入，并保留多段导演台。图片支持资产库、本地上传或拖入、画布图片节点连线三种来源。MiniMax H3 Ref 是新节点的默认引导；有主体参考图时走 H3 Ref，没有参考图而有首帧时自动走普通 H3。任何生成仍经过现有 runtime 提示词优化，不增加 QC 门禁。

截图仅用于定位现有交互问题。项目既有规格和代码说明当前能力；用户在本次讨论中确认的 Ref 优先和三种图片入口是本设计的需求依据。

## 2. 已确认的产品决策

1. 采用「节点卡片内直接填写」布局。卡片显示当前片段的主体参考图、首帧、尾帧、简短提示词、片段位置与生成入口；完整编排仍在展开面板。
2. 图片可从资产库选择、本地上传或拖入，也可由画布图片节点连线提供。
3. 新节点默认突出主体参考图。拖到卡片未指定槽位的第一张图作为主体参考图；拖到有明确名称的槽位始终填该槽位。
4. 没有主体参考图、选择首帧时自动使用普通 H3；主体参考图存在时使用 H3 Ref。没有任何图片时不提交纯文生视频。
5. 画布连线在草稿中实时跟随上游图片，点击生成时冻结本次素材和提示词快照。
6. 参考图与各片段首尾帧分别保留；切换当前使用方式不删除另一组输入，实际请求仅包含当前启用的图片。
7. 当前画布适配器只声明普通 H3 的首帧/首尾帧以及 H3 Ref 的纯参考图可用。参考图与首尾帧混用不宣称可生成，不通过静默忽略图片或偷偷切换工作流绕过能力限制。
8. 错误显示在具体图片槽位，并指明恢复动作；不增加主观质量检查、QC 审核或二次审批。

## 3. 节点和展开面板

节点空态用图片输入区替代“尚无视频”占据的大块空白。顶部显示视频模型和当前路线；尚无有效图片时将路线标为「Ref 引导，待输入」，不能暗示已可提交。主体参考图为默认主入口，首帧和尾帧入口同时可见，并清楚标明切换后生效的输入。当前片段的提示词可直接在卡片编辑。片段切换控件只改变卡片展示的片段，不改变片段顺序；添加、复制、删除、排序以及完整参数继续在展开面板操作。

点击图片槽位提供「从资产库选择」和「本地上传」。槽位支持拖入本地图片和已有画布素材；上传成功后才写入草稿，不能把临时 `blob:` URL 当作可供后端读取的图片。已填槽位显示缩略图、来源、替换/移除动作。多张主体参考图显示缩略图、数量和当前能力上限，保留原有顺序及去重规则。卡片与展开面板使用同一组槽位组件与更新逻辑，避免两处显示和提交不一致。

直接拖到卡片空白处按当前主入口处理：Ref 方式下增加主体参考图；普通 H3 方式下先填空首帧，首帧已占用时弹出目标选择，避免覆盖或把图片误判为参考图。拖到显式槽位不再猜测用途。本地上传失败不改变原槽位，并显示错误；不可用文件类型、失效图片和数量超限在发生处提示。

节点生成成功后仍能查看和播放结果，同时保留返回输入区的显眼入口。结果预览不得覆盖草稿或妨碍下一次编辑；显示生成状态、对应草稿版本和当前输入是否已在结果之后更改。

## 4. Ref 优先与输入模式

`activeInputMode` 在新节点中默认为 `ref`，并持久化在节点数据中。Ref 方式使用全局有序参考图，可不设置首尾帧；普通 H3 方式使用各段首帧和可选尾帧。用户在无参考图时选择首帧，界面自动转入普通 H3；在已有首尾帧时选择参考图，明确提示改用 Ref 并保留帧输入。最后一张参考图被移除后，若存在可用首帧则自动转为普通 H3；若没有任何可用图片，显示添加参考图或首帧的引导，不提交请求。

两组输入都可在草稿中保留，但只有当前方式的图片进入生成请求。未启用图片在界面标明「已保留，当前不参与生成」；切换回来可恢复。预检、路线标签和生成快照都使用同一个有效输入投影，不能出现界面显示 Ref、请求却发送首尾帧的状态。参考图与首尾帧混用的能力需另行验证；本期不改 RunningHub 供应商契约，也不把本地工作流示例当作线上混用成功证据。

## 5. 画布连线与素材身份

画布图片节点连到视频导演时，出现一次目标选择：全局主体参考图，或指定片段的首帧/尾帧。绑定记录源节点身份、目标片段稳定 ID 与槽位；一张上游图片可被多个槽位引用，一个首帧或尾帧槽位只能有一个有效绑定。主体参考图继续按图片身份去重，并受模型能力上限限制。非图片节点或尚无可用图片输出的连接不能伪装为有效输入。

绑定在草稿中解析上游当前图片，缩略图和生成预检随之更新。上游图片失效时标出对应槽位，不以曾经的旧图悄悄提交；只有当前启用方式中的失效输入会阻止本次生成。断开连线清除这条绑定提供的图片，其他手动选择的图片不受影响。用户刷新画布后，连线与目标槽位仍可恢复；上游重新产生图片时重新解析。

资产库选择和本地上传沿用现有素材身份。角色基础图与变体图保留图片 ID、资产 ID、角色 ID、变体身份和图片地址；本地图片先取得后端可读取的持久地址。连接图片节点时保留绑定身份与当次解析的图片身份，不用单一 URL 代替来源关系。

## 6. 数据流与职责

| 单元 | 职责 |
| --- | --- |
| 图片槽位组件 | 展示、选择、上传、拖入及槽位级错误；卡片和展开面板共用 |
| 节点草稿 | 保存当前方式、两组图片、片段和手动素材；切换时不丢失未启用输入 |
| 画布连线绑定 | 保存源节点到目标槽位的关系，解析实时图片和失效状态 |
| 有效输入投影 | 从当前方式与绑定结果形成可提交 `DirectorDraft`，供预检、路线标签和生成共用 |
| 现有任务编排 | 点击生成时冻结投影，调用 runtime 改写、RunningHub 提交和历史记录 |

生成步骤为：编辑草稿及连线 → 解析当前图片 → 能力与素材预检 → 冻结有效输入快照 → runtime 优化提示词 → 现有 H3/H3 Ref 适配器提交 → 结果回填。运行中上游图片变化只影响下一次生成，不改写已冻结快照。现有后端 `DirectorDraft` 和任务历史继续表示实际提交的输入；仅前端节点草稿需要保存未启用图片与连线绑定，不把未启用素材传给供应商。

## 7. 错误处理与验收

- 空节点明确提示先添加主体参考图，或使用首帧切换普通 H3；无有效图片不能直接生成。
- 图片上传失败、来源失效、图片不可读取、参考图超限和目标槽位冲突均就地显示。生成入口给出可操作的缺项提示，并将展开面板定位到出错片段。
- Ref 纯参考模式与普通 H3 首帧/首尾帧按现有能力预检；未验证的混用输入不提交，不丢失用户已选图片。
- 从资产库、上传/拖入、画布连线三条路径填入图片，均能在卡片和展开面板看到相同来源、缩略图与身份；替换、移除、断线、刷新后状态正确。
- 多片段切换不串槽；同一角色多变体和跨角色参考按实际图片计数、去重且不超限。
- 上游图片改变时当前槽位更新，已运行任务快照和历史不变；上游失效时阻止当前有效输入的提交。
- 在 Ref 与普通 H3 之间切换后，未启用图片仍可恢复；最终请求的图片、工作流路线、提示词优化上下文和界面预检一致。
- 完成聚焦的交互测试、草稿及连线恢复测试、请求契约测试与前后端构建。实际付费出片属于工作流能力验收，不以本次界面测试代替；本次改版不新增 QC。

## 8. 范围边界与现有依据

本期不新增视频模型，不生成首尾帧图片，不接入未验证的 Ref+首尾帧混合请求，不改项目其他视频生产链。可复用现有 `AssetLibraryModal` 的图片选择/上传、`VideoDirectorPanel` 的草稿编辑、画布连线与 `useVideoDirectorTask` 的冻结请求。当前 `directorValidation.ts` 和后端 `capabilities.py` 都拒绝 Ref 与首尾帧同时作为有效输入；有效输入投影必须与这些能力约束一致。

原型保存在 `.superpowers/brainstorm/` 的本次会话中，展示了 A 布局和 Ref 优先状态。它是讨论材料，不是已实现界面。
