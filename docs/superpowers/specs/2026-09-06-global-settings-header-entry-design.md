# 全局设置顶部入口恢复设计

## 背景与根因

项目管理中心右上角缺少设置按钮。Header 当前同时对设置按钮和 `SettingsDialog` 使用 `ceRuntime` 条件渲染；当 `/api/v1/config` 返回 EE 运行时后，两者会被主动卸载。截图中的积分入口只在 EE 显示，也与该判断一致。因此问题不是图标颜色、屏幕宽度或响应式布局，而是版本门控隐藏了全局设置入口。

## 目标

- CE 与 EE 均在顶部动作区显示设置按钮。
- 首页和项目内页面使用同一 Header，因此设置入口在两类页面都可用。
- 设置按钮继续位于通知按钮左侧，保持现有图标、尺寸、交互和可访问名称。
- 点击按钮后，两种运行时均可打开现有 `SettingsDialog`。

## 非目标

- 不移动设置入口到账户菜单，也不创建重复入口。
- 不修改设置弹窗的页面、字段、保存逻辑或后端接口。
- 不改变积分、通知、伙伴和账户入口。
- 不改变 CE 专属的未配置警告判定。

## 方案

采用始终渲染顶部设置按钮与 `SettingsDialog` 的方案，移除这两个 UI 节点外层的 `ceRuntime` 条件。

保留 `ceRuntime` 在以下数据与状态逻辑中的用途：

- `useModelGatewayConfig(ceRuntime)` 仍仅在 CE 请求网关状态。
- `hasSettingsWarning` 仍要求 `ceRuntime` 为真。
- 设置警告气泡在 EE 中不会出现。

这样 EE 可以进入全局设置（包括已存在的任务并发设置），同时不会因 CE 专属配置状态产生错误告警或额外的 Header 级查询。

## 数据流

1. Header 在任意运行时渲染设置按钮。
2. 用户点击按钮，`settingsOpen` 设为 `true`。
3. 始终挂载的 `SettingsDialog` 接收 `open={settingsOpen}` 并展示。
4. 弹窗内部按现有逻辑在打开后加载对应设置数据。
5. CE Header 继续加载网关摘要用于警告；EE Header 不加载该摘要。

## 测试策略

先修改 Header 测试并确认旧实现失败：

- 模拟 CE，断言设置按钮存在。
- 模拟 EE，断言设置按钮同样存在。
- 在 EE 点击设置按钮，断言 `SettingsDialog` 收到打开状态。
- 保留或增加断言，确保 EE 不触发 CE 网关状态查询/警告。

随后最小修改 `header.tsx`，运行 Header 定向测试、TypeScript/ESLint 对应检查及 `git diff --check`。

## 验收标准

- 用户截图所示的 EE 项目管理中心顶部重新出现设置按钮。
- CE 与 EE 点击按钮都能打开设置弹窗。
- 按钮位置仍在通知入口左侧。
- EE 不显示 CE 未配置警告。
- 没有设置页或后端接口变更。
