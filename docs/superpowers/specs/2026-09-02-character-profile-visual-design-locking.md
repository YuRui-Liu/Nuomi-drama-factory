# 角色叙事档案、视觉提案与提取锁定设计

## 背景与根因

当前结构化角色抽取只允许提取剧本明确写出的角色名、职业和可见事实。对没有直接描写五官的剧本，角色的 `description`、`body_type`、`face_prompt` 会保持为空，这是事实层的正确行为。

故障出在后续链路尚未完成：资产中心没有依据人物小传生成视觉提案，肖像生成却允许绕过未确认的 CharacterVisualBible，退回到“姓名、性别、年龄段、职业，请模型自行设计”的通用提示词。真实项目 `test2` 中，周禾的肖像任务正是使用这一兜底，因此生成大众化 AI 脸。

本设计补齐既有三层模型，不把剧情推导伪装成剧本明确外貌：

1. `CharacterNarrativeProfile`：有来源依据的人物叙事档案。
2. `CharacterDesignProposal`：由模型生成、明确标注为创意设计的外貌方向。
3. `CharacterVisualBible`：用户选择、编辑并确认的生产级视觉身份。

## 目标

- 自动提取后，每个有效角色都获得可读、可复盘的人物小传。
- 即使剧本没有明确描写五官，也能生成三套符合人物功能、时代地域和项目风格的视觉提案，并推荐一套。
- 面部设计具备稳定、可复现、与同剧其他角色可区分的身份锚点，减少大众化 AI 脸。
- 未确认视觉身份不得消耗图片额度生成正式肖像。
- 用户可以锁定角色；再次提取时锁定角色不发送给模型、不更新、不删除。
- 未锁定角色可通过再次提取补齐或刷新自动字段，但不能覆盖人工确认内容和已生成资产。

## 非目标

- 不从角色姓名直接推断长相。
- 不把人物小传、剧情句或对白保存成 `face_prompt`。
- 不在重新提取时自动删除未再次识别到的角色。
- 不覆盖肖像、身份图、服装图、声线、参考音频或生成历史。
- 不允许模型修改已确认 CharacterVisualBible。

## 数据分层

### 1. 人物叙事档案

人物档案从完整剧本、场次语义和剧集关系图中综合生成，字段包括：

- 姓名、别名、年龄范围、性别、职业、社会身份；
- 人物经历和当前处境；
- 欲望、目标、困境、行为方式；
- 关键关系、性格、戏剧功能；
- 跨集状态变化；
- 每条明确事实的原文范围、证据、置信度和 `explicit/inferred` 标记。

人物小传是对上述叙事信息的紧凑总结，建议 80～180 个中文字符。小传可以归纳剧情，但不得成为可见外貌约束。

### 2. 视觉设计提案

提案输入只包括：人物叙事档案、剧本明确可见事实、时代地域、职业阶层、人物气质、戏剧功能、项目视觉风格，以及同剧其他角色已选或已确认的视觉摘要。

每个角色生成三套低成本纯文字方向，并选出一套 `recommended`。每套包括：

- 设计标题和设计理由；
- 脸部轮廓与骨骼结构；
- 眉眼、鼻、口等局部结构；
- 发际线、发型与发质；
- 年龄质感、肤质和生活痕迹；
- 体型和姿态倾向；
- 标志性特征；
- 默认服装状态；
- 3～6 个跨镜头必须保持的身份锚点。

提案属于创意设计，不能回写为剧本明确事实。

### 3. 反大众脸质量规则

每套推荐提案必须通过文字质量门：

- 至少覆盖脸部轮廓、眉眼、鼻口、发际线/发型四类结构中的三类；
- 至少包含一个非夸张的不对称或角色专属识别点；
- 至少包含三个可在近景重复观察的身份锚点；
- 禁止以“帅气、漂亮、精致、自然五官、标准脸”等审美空词替代结构描述；
- 禁止明星姓名、在世人物肖像和仅靠姓名联想的外貌；
- 与同剧已选角色做碰撞检查，不能共享高度相似的脸型、眉眼、发型和专属特征组合；
- 不合格时只重做文字提案，不调用图片模型。

## 人物锁定

### 锁定语义

角色新增 `extraction_locked`，默认 `false`。资产中心角色卡和详情页提供显式“锁定/解锁”操作，并显示锁定状态。

锁定后：

- 角色不进入再次提取任务的模型上下文或候选集合；
- 不更新基础字段、人物小传、剧本事实、视觉提案或推荐项；
- 不删除角色；
- 不触碰 VisualBible、肖像、身份、服装状态、声线、参考音频和历史版本。

解锁后，下一次提取允许刷新自动字段和未确认提案。界面必须提示“解锁后重新提取可能更新自动生成内容”。

### 更新策略

再次提取采用按角色 upsert，而不是当前的“已有角色全部跳过”：

- 新角色：新增档案和视觉提案。
- 未锁定已有角色：更新自动提取字段、事实和未确认提案。
- 锁定已有角色：完全跳过。
- 已确认 VisualBible：无论是否锁定都不自动覆盖；未锁定角色可生成新的候选提案，但不能替换已确认版本。
- 本轮未识别到的已有角色：保留并标记为“本轮未出现”，不自动删除。

锁定名单在任务入队时形成快照，并在提交事务前再次检查，防止提取运行期间用户刚锁定角色仍被覆盖。

## 工作流与界面

“自动提取”调整为以下文本任务链：

1. 读取锁定角色快照并从提取范围排除。
2. 从完整剧本构建或更新未锁定角色的叙事档案。
3. 提取带证据的剧本明确事实。
4. 为新增和未锁定角色生成三套视觉提案。
5. 执行提案质量门和全阵容差异检查。
6. 在单一事务中写入新增/更新结果；提交前重新检查锁。

资产中心依次展示：

- 人物小传；
- 剧本明确事实及来源；
- 三套视觉提案和推荐标记；
- 可编辑的视觉身份设定；
- 服装与剧情状态；
- 高级诊断中的系统编译提示词。

用户选择或编辑提案并确认后形成新的 CharacterVisualBible。正式“生成肖像”按钮只有在存在已确认 VisualBible 时可用；否则提示先确认视觉身份，不再使用通用兜底提示词。

## API 与持久化边界

- 角色列表/详情返回 `extraction_locked`。
- 提供幂等锁定接口，重复锁定或解锁不会产生错误。
- 构建角色任务结果返回 `added`、`updated`、`locked_skipped`、`not_seen_preserved`、`proposal_failed` 计数。
- 锁定状态持久化在角色正式数据中，不放在前端本地状态。
- CharacterVisualWorkspace 继续独立存放叙事档案、提案和 VisualBible，避免污染旧角色字段。
- 肖像任务结果保留最终 `prompt_snapshot` 和 `visual_bible_revision`，方便复盘。

## 错误处理

- 小传生成失败：该角色不写入半成品更新，保留旧数据并在任务结果中列出。
- 提案质量不通过：最多执行受控文本重试；仍失败则保留人物档案，将角色标记为“视觉提案待处理”。
- 提取期间角色被锁定：提交阶段跳过该角色并计入 `locked_skipped`。
- 缺少已确认 VisualBible：阻断肖像生成，不调用图片供应商，不计图片额度。
- 角色重名或别名冲突：不静默合并，保留候选并要求人工处理。

## 测试与验收

### 后端

- 剧本没有五官描写时，人物小传仍可生成，但明确视觉事实保持为空。
- 三套提案均标记为创意设计，推荐提案满足身份锚点质量规则。
- 同剧角色视觉碰撞会触发文本重做或失败状态。
- 锁定角色不会进入提取输入，且再次提取后所有字段和资产引用逐字节不变。
- 未锁定角色能够补齐人物小传和未确认视觉提案。
- 提取运行中途锁定角色时，事务提交仍不会覆盖它。
- 没有确认 VisualBible 的肖像任务在 transport 前失败，`transport_called=false`。
- 有确认 VisualBible 时，编译提示词包含身份锚点和版本号，不包含剧情句或通用兜底。

### 前端

- 角色列表和详情均能锁定/解锁，并立即显示状态。
- 锁定角色在再次提取结果中显示“已锁定，跳过”。
- 人物小传、事实、三套提案、推荐项和确认状态均可见。
- 未确认 VisualBible 时肖像按钮禁用并给出明确原因。
- 诊断区可查看实际系统编译提示词和 VisualBible 版本。

### 真实验收

使用 `test2` 再次提取：

- 周禾、梁真、赵凯、陈卫国均获得人物小传和三套视觉提案；
- 四人的推荐方案具有明显不同的面部结构与身份锚点；
- 锁定周禾后再次提取，周禾所有数据和资产保持不变，其他未锁定角色可更新；
- 未确认提案前不能再次调用 GRSAI 生成周禾肖像；
- 确认后生成任务的 `prompt_snapshot` 来自该 VisualBible，且不再出现旧通用兜底文本。
