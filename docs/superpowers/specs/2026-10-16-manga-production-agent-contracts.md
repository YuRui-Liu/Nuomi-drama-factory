# 漫剧全链路：专业 Agent 与制作交接契约

日期：2026-10-16。状态：专业细化规格；本轮已确认产品决定以[主 PRD 第 15 节](2026-10-13-agent-canvas-prd.md)为准，整合规格已获用户确认。用户明确要求覆盖从创意到可播放漫剧的全链路，并补齐创意师、主笔、分镜、站位、灯光、动作、表情、MiniMax 执行等专业岗位。本文件细化 [PRD](2026-10-16-professional-agents-script-handoff-prd.md)，不表示这些 Agent 或执行链路已经实现。

## 1. 交付目标决定任务终点

主创接到“做成一集漫剧”的目标后，应在约定的范围、预算、重试权限和共享内容修改权限内持续协调，直到交付可播放、可导出的成片，或给出定位到具体内容的阻塞。不能完成分镜文字后就用“建议下一步生成视频”代替用户要求的成片。

“只整理剧本”“只调整表情”“只试两个造型”等局部任务仍按用户指定终点交付；局部完成不触发整集生产。用户已有剧本或资产时复用有效产物，不强制重新经历创意或主笔环节。

全链路表达真实依赖，而不是必须逐页审批的线性工作台。角色、节点、内容组与成果留在统一画布；用户可随时直接编辑和局部委托。一次有效授权范围内不重复确认，新的任务范围、费用上限或采用替换权限才需要展示差异。

## 2. 责任分工

专家拥有对应节点的直接操作能力；通过与人工相同的受支持操作服务，固定输入版本、范围及授权，取回实际结果。MiniMax 执行师是模型适配与故障处理专家，不是所有视频生成的强制中转。下表的职责划分不禁止其他已获授权专家调用适用节点。五项配置（方法、节点能力、交付要求、参考示例、协作规则）复用已有版本管理，不能自行扩大权限。

| 岗位 | 核心职责 | 不应越界的行为 |
| --- | --- | --- |
| 主创／制片统筹 | 维护目标、任务图、分工、预算、进度与交付缺项；持续推进已授权依赖 | 把提交成功当成成片交付；为凑齐岗位强制调用每个 Agent |
| 创意师 | 题材、核心冲突、看点、观众体验和视觉创意候选 | 擅自把未选创意写成项目硬设定 |
| 主笔 | 故事圣经、人物弧、分集梗概、逐场剧情与对白；维护叙事因果 | 把镜头建议当成已生成画面；覆盖人工剧本 |
| 剧本编辑 | 检查动机、节奏、因果与可拍性，提出修订 | 默改已锁定事实或把审美偏好设为生产硬门槛 |
| 导演 | 叙事组划分、戏剧目标、专业方案融合与冲突裁决 | 把画布布局顺序直接当剪辑顺序；自行扩大任务 |
| 分镜师 | 视觉节拍、景别、机位、切点、镜头作用、组内时序与参考关系 | 把每格分镜自行拆成独立付费生成任务 |
| 站位师 | 人物/物件位置、轴线、视线、进出方向、路线、遮挡与空间连续性 | 仅写“站位合理”，却没有可执行空间关系 |
| 摄影师 | 构图、镜头视点、运动、景别变化、焦点与剪接视点 | 覆盖站位与动作的空间约束；承诺模型精确执行物理镜头参数 |
| 灯光师 | 主光方向、光源动机、冷暖、对比、场内变化与跨镜头连续性 | 无理由改变时段、天气、人物外观或场景事实 |
| 动作师 | 动作起点、过程、落点、反应、接触与道具交互，安排时间节拍 | 输出互相冲突、超出组时长或无法衔接的动作指令 |
| 表情师 | 情绪动机、克制程度、视线、微表情、反应时机与对白表演 | 与角色目标矛盾；默认夸张表情；将细节不可辨当必重生成 |
| 美术／资产师 | 角色身份、造型变体、场景、道具与风格参考；取得实际可用资产 | 仅有文字资产说明却声称媒体引用已准备完成 |
| 连续性师 | 检查组间人物状态、空间、光向、道具、剧情和声音衔接 | 默认逐帧深审或发起额外付费质检；无限扩大返工 |
| 分镜图执行师 | 将融合方案转成实际整组分镜图并绑定引用与版本 | 绕过支持入口、跳过必需引用、重复购买已有合格图 |
| MiniMax 执行师 | 模型适配、提示词编排、模式与引用校验、预算内提交、状态查询、整组视频交付 | 自行改剧情、台词或已锁定动作；静默换模型、模式或拆组 |
| 声音师 | 对白表演与音色、环境声、动作声、配乐、音量和同步方案及音频产物 | 对已有可用原生音频无条件重配，或重复生成不需要的声音样本 |
| 剪辑师 | 组视频顺序、节奏、衔接、音轨、字幕、画幅与导出；反馈补镜需要 | 将缺关键组的片段拼接后宣称整集完成；自行购买补镜 |
| 交付检查 | 最小必要检查：文件可播放、必需内容齐全、声音字幕符合目标、导出可取回 | 仅凭任务状态或存在 URL 判定成功；默认追加 ASR 或付费复检 |

以上岗位必须可以独立配置职责、方法和输入范围；复用底层模型和工具，不要求独立服务或每组固定运行十八次。主创根据任务调度必要岗位，未调用的岗位不能伪造执行记录。导演负责融合专业意见，主笔负责已确认叙事事实，制片负责范围和成本，执行师负责按冻结方案调用工具；不能让最后一个写提示词的人隐式裁决全部冲突。

## 3. 全链路产物与接收条件

下表是设计期逻辑契约，不预设数据库字段或要求另建一套任务系统。每份产物复用项目现有稳定身份和版本机制；显示名称不是跨系统唯一标识。

| 交接产物 | 生产者 → 接收者 | 必要内容 | 接收条件 |
| --- | --- | --- | --- |
| 创作简报与选定创意 | 用户／创意师 → 主笔、主创 | 目标受众、题材、核心冲突、风格、篇幅或时长、交付范围、未决项 | 选定方向与候选分开；未知项不冒充事实 |
| 故事与剧本包 | 主笔／编辑 → 导演、美术、声音 | 故事圣经、人物动机、场次、对白、必要事件、已锁定事实、原文修订 | 能定位剧情和台词来源；主线因果可用于制作 |
| 角色场景资产包 | 美术／资产 → 专业方案与执行师 | 基础身份、状态变体、场景空间、道具、实际媒体引用及用途 | 必需媒体可访问、版本可查；缺项明确阻塞或按授权补齐 |
| 叙事组与分镜方案 | 导演／分镜 → 各专业岗位、执行师、剪辑 | 组身份、剧情范围、戏剧目标、镜头作用、时序、时长、台词与声音位置、引用 | 整组表达完整叙事意图；组内物理分段与独立任务明确区分 |
| 专业表演与视听方案 | 站位／摄影／灯光／动作／表情／声音 → 导演 | 空间图或明确关系、动作节拍、表情动机、运镜、光线、声音；硬约束与偏好 | 与已确认事实不冲突；冲突提交导演融合，不拼接互斥文本 |
| 融合后的导演方案 | 导演 → 分镜图／MiniMax 执行师 | 被采用的专业方案、保留约束、未采纳建议及原因、引用和版本 | 有可执行的统一方案；执行师不能悄悄补改关键剧情 |
| 整组分镜图 | 分镜图执行师 → MiniMax 执行师、导演 | 实际图像、对应组/分镜关系、版本、参考绑定、已存在的有效验收状态 | 图像可访问；保留必需身份和场景信息；软问题不自动变硬门槛 |
| 整组视频与执行回执 | MiniMax 执行师 → 声音、剪辑、交付检查 | 实际视频、任务身份、冻结请求、引用、模型/模式、输入输出版本、费用状态 | 不是仅有子片段；整组可播放；未知提交先对账，不盲重发 |
| 音轨与字幕包 | 声音／剪辑 → 合成与交付检查 | 台词来源、音轨用途、时间位置、字幕文本/时间、采用版本 | 已有有效原生声音可复用；避免重复对白、明显错位与混音冲突 |
| 成片与交付清单 | 剪辑／检查 → 用户 | 可播放文件、下载入口、实际时长/画幅、必要声音字幕、来源清单、未满足项 | 满足本次目标；缺关键组不得标整集完成；产物可取回 |

## 4. 共用上下文与版本责任

所有专业 Agent 接收同一份本次任务快照：用户目标、当前范围、项目硬约束与偏好、已采用剧本修订、人物/场景/状态变体、必要前后组上下文、已有产物、目标画布和授权范围。只传必要上下文，不把整个项目无差别塞给每个角色。

专业产物记录作者 Agent 配置版本、输入版本、影响对象、输出类别、候选/采用状态、工具或模型执行身份。人类编辑优先受到保护：运行中的 Agent 仍使用原快照，返回结果成为候选，不能覆盖用户并发修改。

同一事实出现冲突时，定位到对应内容继续处理不受影响的组。站位与摄影冲突由导演协调；剧情与动作冲突先保持锁定剧情，再改表现方式；来源事实改变必须显示影响，不允许执行师用提示词改写掩盖。空间、动作、表情、灯光的逻辑字段留给专业展开面板；默认画布先呈现作品和成果。

## 5. 站位、动作、表情与灯光怎样落到执行

以虚构“雨夜巷口对质”为例，以下均为设计示例，不是已生成或已验证的作品：

- 站位师：林夏在巷口、陈默在巷内；主视线轴沿两人连线；林夏从画面左侧靠近，把信递入两人之间；车从巷口外经过。
- 动作师：追近后停步，递信，等待；陈默看向日期并停住，不接信。记录起始姿态、接触或无接触、结束姿态和节拍。
- 表情师：林夏压住怒意，以直视和短促质问表现；陈默由回避转为短暂停顿。表情变化与看见日期的事件同步，避免无理由一直愤怒。
- 摄影师：先交代空间关系，再靠近证据与反应；明确景别、视点和运动。若切反打，应服从已采用轴线。
- 灯光师：主要照明来自巷口路灯；经过车灯是短暂变化，不能把整个场景变成白天或持续逆光。
- 分镜师与导演：把上述内容组织为该叙事组内的可见节拍，指出关键因果是“信上日期→他提前知情→沉默”，保留台词原文及必要反应。
- MiniMax 执行师：用当前模型支持的方式表达融合结果和参考用途。若组时长或参考组合不支持，返回明确适配问题，由支持的组计划处理，不自行拆成逐镜头付费循环。

验收看关键剧情和可见结果是否满足目标，不要求模型机械兑现每一个微小摄影参数。只有明确身份、动作、事实冲突或无法播放等硬问题需要阻断相应产物；已通过有效检查的内容应复用。

## 6. MiniMax 执行师必须具有真实执行能力

这不是“MiniMax 提示词专家”的改名。完成标准包括：读当前支持能力与保存设置，检查引用和计划修订，编排请求，按授权提交，追踪任务，取回并关联实际整组视频，处理失败与未知状态，向剪辑交付。

| 动作 | 要求 |
| --- | --- |
| 模型与模式选择 | 从当前能力描述和保存配置读取；不把研究日的时长、分辨率、参考上限硬编码成所有模型规则 |
| 提示词编排 | 保存原意、融合方案、模型适配稿、实际提交稿；增强处理新增关键语义时可追溯，不能篡改锁定台词与剧情 |
| 引用绑定 | 明确身份、场景、状态、动作、首尾帧或其他用途；校验当前模式允许的组合与可访问媒体 |
| 提交前冻结 | 使用现有执行合同记录实际生效模型、模式、画幅、参数、引用、方案和设置修订；参数来源与实际生效值区分 |
| 提交与恢复 | 关联原任务/组身份，读取已保存并发；提交未知先查询，重复网络请求不能重复购买 |
| 失败返工 | 区分配置/引用错误、技术失败、结果不满足目标；只恢复失败组，遵守原预算和重试授权，不循环生成到自认满意 |
| 回传产物 | 实际视频、媒体版本、执行回执、费用或结算状态、可定位问题回到同一画布与任务 |

现有叙事组视频执行合同不意味着统一画布节点已经全部使用同一合同；这是必须核实和补齐的适配点。现有供应商工具有能力，也不等于专业 Agent 已获得该工具的受限执行接口。

本地现有 H3 路径通过 RunningHub 托管工作流执行，而非直接调用 MiniMax 官方 API。MiniMax 执行师必须同时记录用户选择的模型能力与实际执行平台/工作流，不把品牌名称当成供应商传输实现。未来若增加其他执行适配器，仍使用同一任务、引用和冻结合同责任边界。

## 7. 生产调度与统一画布的衔接

本节叙事组约束描述当前生产路径，不规定所有未来节点任务的固定顺序或唯一调度器。目标架构复用共享能力并删除旧阶段引擎；具体迁移先明确支持入口和恢复语义并同步操作说明，不提前绕过现有约束。

当前生产执行遵守仓库 [nuomi-production](../../../skills/nuomi-production/SKILL.md)：读策略和保存并发，按活动方案中的叙事组出整组分镜图、整组视频，最后合成集。Ref 模式改变引用方式，不改变生产单位。组内因模型限制产生的物理片段由支持的服务端计划处理；Agent 不另写供应商脚本或逐镜头/片段循环。

新产品需把专业产物、授权、实际执行、状态回传和成片映射接到统一画布的任务图；这是开发范围。不能只在新画布贴一个旧阶段工作台，也不能通过保留旧阶段门禁满足“全链路”。迁移时复用专业能力、版本和可靠任务机制，按上位 PRD 逐项替换旧流程专属控制；本次不宣称迁移已完成。

同组准备存在依赖：实际分镜图就绪后才能进入相应组视频制作；独立组按保存并发推进。一个组失败不暂停其他独立组，但缺关键组的集不能作为完整成片交付。批次可交付已完成集，同时列出受阻集和原因。

剪辑需要补镜时，将需求回传到相关叙事组和主创任务范围，先显示最小影响。授权覆盖时继续；超出范围或预算时再明确选择。不能因一个表情问题无条件重做整场或全片。

## 8. 端到端完成判定

角色与能力分开标记：定义完成、可执行、产物可追溯、链路验收通过。只有真实集成用例满足目标，才可将全链路标为可用。目录里有十八个名字、手工拼好的演示视频或模拟任务均不能作为验收替代。

验收样片由项目配置决定长度、画幅和声音字幕要求；可以选一个可控成本的短集作验证，但本文件不代替用户授予生成费用。至少覆盖：

1. **从创意起步出片：** 创意、主笔、导演、资产、专业方案、整组分镜图、MiniMax 视频、声音字幕和剪辑交付均有实际产物或明确复用来源，最终文件可播放并可取回。
2. **从已有剧本出片：** 不重写已确认剧本，场次/台词/人物来源能够追踪到最终组视频和成片，关键剧情无明显遗漏。
3. **专业能力有作用：** 站位、灯光、动作、表情方案进入导演融合与实际请求，不只是侧栏聊天；被修改或未采用的建议有原因。
4. **失败与中断恢复：** 有一组失败时其他独立组继续；恢复复用成功产物，不重复购买，不交付缺关键组的“成功整集”。
5. **局部返工：** 改一处表情或动作，能定位受影响组/产物、保留其他成果，并保护人工编辑；实际重生成范围受支持能力和授权限制。
6. **完成条件：** 必要组和声音字幕满足本次目标，成片顺序正确、可播放、可下载；如只完成无声片或缺少一组，应如实标为部分完成并指出缺项。

核验以任务结果、明显剧情遗漏、必要音画与最终播放为主，不默认添加逐帧深审、ASR 或重复付费质量检查。产品可运行不意味着所有模型都能保证人物、动作、口型或灯光完全准确；不确定性必须表现为具体能力或结果边界。

以下是本轮只读核查，不是端到端运行结果。不可将“字段存在”或“API 接受参数”当成专业 Agent 或成片能力已完成。
