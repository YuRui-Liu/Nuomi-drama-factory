# 叙事组画幅选择器设计

## 背景

叙事组生成链路已经能够接收 `9:16` 和 `16:9`，但叙事组页面没有直接的画幅入口。用户需要返回其他页面修改项目画幅，而且页面上的 `split` 分支仍可能漏传画幅，导致横屏项目回落到默认竖屏。结果是组图、拆分单镜和组合视频的画幅行为不透明，也容易出现上下游不一致。

## 目标

在叙事组页面标题栏增加一个始终可见的 `9:16 / 16:9` 分段选择器，并让选择成为该项目后续叙事组媒体操作的统一画幅来源。

具体目标：

1. 用户无需离开叙事组页面即可切换项目画幅。
2. 选择立即保存到项目设置，刷新页面后保持。
3. 生成、重生成、拆分和组合视频均使用同一画幅值。
4. 明确说明画幅切换只影响后续操作，不自动改写既有媒体。
5. 用组件测试锁定显示、保存、传参与无障碍状态。

## 非目标

- 不在本次修改中新增 `1:1`、`4:3` 或自由尺寸。
- 不自动重绘、裁切或删除已经生成的组图、单镜图片和视频。
- 不把画幅变成叙事组级别的独立配置；它仍是项目级配置。
- 不复制一套仅供前端使用的临时画幅状态。

## 方案选择

采用方案 A：在叙事组页面标题栏放置分段选择器。

未采用的方案：

- 设置弹层：占用空间少，但关键生成参数隐藏，生成前不容易确认。
- 每个阶段分别配置：灵活性更高，但会造成组图、拆分和视频画幅互相冲突。

标题栏方案让当前画幅持续可见，并保持一个项目只有一个权威值。

## 交互设计

标题栏右侧显示“目标画幅”和两个互斥按钮：

- `9:16`：对应项目的 portrait orientation。
- `16:9`：对应项目的 landscape orientation。

行为规则：

1. 初始选中项来自项目当前 `aspect_ratio`。
2. 点击非当前项时，立即更新本地显示并调用项目更新接口持久化。
3. 更新进行中禁用两个按钮，防止快速重复提交。
4. 更新失败时恢复服务端确认过的值，并显示错误提示。
5. 当前项提供 `aria-pressed="true"`；控件组具有明确的“目标画幅”可访问名称。
6. 控件旁展示短提示：“仅影响后续生成；现有素材需重新生成或重新切分。”

不弹出阻断式确认框。画幅切换本身不修改或删除既有媒体，只有用户随后主动执行生成、重生成或拆分时才会产生新结果。

## 状态与数据流

项目的 `aspect_ratio` 是唯一事实来源：

1. `useProjectAspectRatio(project)` 将项目值归一化为 portrait 或 landscape。
2. 选择器将 `9:16` 映射为 portrait，将 `16:9` 映射为 landscape。
3. 切换时复用项目更新 mutation，将 orientation 映射回项目 `aspect_ratio` 并持久化。
4. 页面从同一个归一化 orientation 推导动作参数 `aspectRatio`。
5. generate、regenerate、split 和组合视频请求全部显式携带该值。

页面不维护第二份长期画幅配置。允许在保存期间做乐观显示，但失败时必须回滚到项目值。

## 组件边界

选择器作为叙事组工作台标题栏中的小型展示组件，职责仅包括：

- 展示当前选项。
- 发出 orientation 变更事件。
- 表达保存中和无障碍状态。

项目读取、更新 mutation、失败提示以及下游请求传参保留在叙事组工作台容器中。这样选择器可以保持纯展示，业务规则也不会散落到各阶段组件。

如现有 Beat 工作台已有可复用且语义一致的画幅控件，可提取共享的分段选择器外观；不强制复用其旧的 checkbox 交互。

## 下游一致性

所有叙事组动作必须以当前项目画幅为准：

- `generate`：组图生成请求携带 `aspect_ratio`。
- `regenerate`：重新生成时携带相同参数。
- `split`：即使不提交引用选择，也必须显式携带 `aspect_ratio`。
- 组合视频：使用当前画幅构造 H3 请求尺寸与工作流参数。

既有媒体保持不变。切换后页面可继续展示旧媒体，但提示文字负责说明它们不会被自动转换。

## 错误处理

- 项目保存失败：回滚选中项，并使用现有 toast/error 机制报告失败。
- 项目数据缺失或画幅无效：沿用项目画幅工具的默认值，并确保界面始终只有一个选中项。
- 动作提交失败：沿用各动作当前错误处理，不回滚已经成功保存的项目画幅。
- 保存进行中：禁止再次切换，避免乱序响应覆盖新选择。

## 测试策略

以前端组件测试为主，至少覆盖：

1. portrait 项目显示 `9:16` 为选中状态。
2. landscape 项目显示 `16:9` 为选中状态。
3. 点击另一选项会调用项目更新并传入正确的项目 `aspect_ratio`。
4. 保存期间控件不可重复操作；失败会回滚并提示。
5. 切换后 generate/regenerate 使用新画幅。
6. 横屏状态下 split 请求显式携带 `16:9`。
7. 组合视频调用继续使用当前项目画幅。
8. 当前按钮具有正确的 `aria-pressed`，控件组可以通过可访问名称定位。

同时运行相关 TypeScript 构建检查、聚焦 Vitest 与 `git diff --check`。若全量检查被仓库无关既有问题阻断，需要单独记录，不能把它误报为本次通过。

## 验收标准

- 叙事组页面标题栏可直接看到并切换 `9:16 / 16:9`。
- 刷新后仍保持最后一次成功保存的选择。
- 四条关键链路：生成、重生成、拆分、组合视频，均使用页面当前画幅。
- 横屏 split 不再发送空画幅或回落到 `9:16`。
- 切换不会自动修改既有媒体，页面对此有清晰提示。
- 相关回归测试通过，且未改动无关工作区文件。
