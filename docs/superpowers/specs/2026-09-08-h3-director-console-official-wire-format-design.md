# H3 导演台官方五模式与 Wire Format 设计

> 状态：待书面审阅
> 日期：2026-09-08
> 范围：MiniMax H3 导演台的模式选择、内部导演 IR、官方提示词编译与付费调用前质量门

## 1. 决策摘要

H3 只通过现有导演台使用。导演台接收剧本、首尾帧、全局参考资产、连续性契约和表演计划，先形成供应商无关的内部 Director IR，再按实际输入编译为 MiniMax 官方五种模式之一：`T2VA`、`I2VA`、`FL2VA`、`L2VA` 或 `Ref2VA`。

内部可以保留 Higgsfield 方法中的场景、引用、空间、光学、摄影机、动作、物理、灯光、表演、质量和正向约束字段，但这些字段不得以十五段大标题原样发送给 H3。最终 Prompt 必须严格遵循 MiniMax 官方 `h3-prompt-writing` Skill 的字段名、字段顺序、引用标签、时间格式和对白标记。

本设计替代 `2026-09-07-higgsfield-rigid-shot-prompt-design.md` 中“把十五段协议直接写入 `integrated_multimodal_description`”以及“强制 `No music. SFX only.`”的结论。该旧规格仍作为历史记录保留，不再作为实现依据。

## 2. 目标

- H3 导演台成为五种 H3 模式的唯一产品入口和唯一编译链路。
- 自动模式根据已冻结的输入资产确定实际模式，人工模式只能选择与输入兼容的模式。
- 所有模式使用同一个版本化 Director IR，避免五套业务规则漂移。
- 最终 Prompt 与 MiniMax 官方 Base/Ref2VA wire format 一致。
- 表演、空间、灯光和连续性在内部保持结构化，但编译成按播放顺序书写的可见、可听事实。
- 在任何付费视频请求之前完成确定性结构、时长、引用、对白和模式质量门。
- 旧 H3 编译入口收口到同一编译器；已有历史 Prompt 保持只读，不批量重写。

## 3. 非目标

- 本子项目不实现完整 Acting Bible、资产压力测试、迭代账本、状态资产、剪辑返单、锁片后期或成本面板。
- 不执行真实付费 H3 生成。
- 不依赖 MiniMax 托管 Context-IR 才能生成合法 Prompt。
- 不把五种模式拆成五套彼此独立的导演业务模型。
- 不保留与官方格式冲突的 `mode:` 前缀、裸 `dialogue:` 段或额外顶层字段。
- 不要求每个镜头都运镜，也不固定每个视频必须包含两个或三个动作。

## 4. 方案比较

### 方案 A：单一 Director IR 加五个模式发射器（采用）

导演台先生成统一结构化计划，再由模式发射器输出 Base 三字段或 Ref2VA 六字段。连续性、表演和资产规则只有一个权威来源；模式差异集中在小而可测试的编译边界。

优点是规则一致、可测试、能离线复现，也能继续复用现有 H3 typed plan、24 FPS 时间线、manifest 和质量门。代价是需要显式定义模式兼容矩阵并迁移旧入口。

### 方案 B：五套独立 Prompt 生成器（不采用）

每个模式独立生成最终文本，短期改动较少，但对白、引用、摄影机和连续性规则会快速分叉，难以证明五种输出长期一致。

### 方案 C：所有输入交给托管 H3 Context-IR（不采用）

实现量最少，但会把导演台的可解释性、可复现性和本地/第三方工作流兼容性绑定到一个托管服务，也无法保证历史任务可以在相同输入下重放。

## 5. 产品入口与模式语义

导演台仍是现有叙事组视频生成区域，不新建独立页面。项目默认、单次覆盖、参考资产编辑、Prompt 预览、质量错误和任务历史都在该入口完成。

### 5.1 自动选择

自动选择使用已经冻结且通过校验的输入，不根据尚未落盘的 UI 草稿猜测：

1. 存在全局图片、视频或音频参考，且不存在与工作流能力冲突的帧输入时，选择 `Ref2VA`。
2. 同时存在首帧与尾帧时，选择 `FL2VA`。
3. 只有首帧时，选择 `I2VA`。
4. 只有尾帧时，选择 `L2VA`。
5. 没有帧或参考资产时，选择 `T2VA`。

若当前 RunningHub 工作流不能承载所选模式或输入组合，导演台必须在上传或付费提交前返回能力错误，不得删除输入、换模式或静默回退。

### 5.2 人工选择

导演台展示 `自动` 和五个明确模式。不可兼容的模式保持可见但禁用，并显示缺失或冲突的输入条件。用户选择模式后，提交时仍重新校验冻结快照，防止 UI 状态与实际资产不同步。

### 5.3 模式规则

- `T2VA`：从三个核心字段开始，允许在不改变用户意图的前提下补足可见与可听细节。
- `I2VA`：首行使用官方 0.00 秒 Picture 1 对齐句；正文遵循首帧锚定、动作开始、连续发展、结果或反应。
- `FL2VA`：首行使用官方首尾帧对齐句；默认一个连续镜头，描述每项差异如何逐步收敛到尾帧。只有用户明确要求切镜且工作流支持时才允许多镜头。
- `L2VA`：首行使用官方尾帧对齐句；从合理前置状态逐步收敛到尾帧，不把尾帧描述成开场状态。
- `Ref2VA`：使用稳定的 `<Subject N>`、`<Picture N>`、`<Video N>` 和 `<Audio N>`，输出完整六段式引用说明与时间线。

## 6. 内部 Director IR

现有 `H3DirectorPlan` 保留为共享时间线核心，并扩展到五模式。其职责是保存：

- 模式、24 FPS 总帧数和连续镜头区间；
- 景别、角度、焦点、构图和摄影机意图；
- 动作与对白事件的帧区间；
- 首尾帧差异与收敛点；
- 全局引用定义及每个镜头的引用使用位置；
- 环境声、物理声音、非剧情音乐；
- 连续性锁和内部表演投影。

Higgsfield 十五段字段继续作为内部补充 IR，但必须满足两条边界：

1. `want`、`hidden`、剧情目的等抽象信息只用于推导表演，不直接输出；
2. 最终 H3 文本只保留可观察的表情、目光、呼吸、重心、动作、空间、光影和声音结果。

内部字段可以比最终 Prompt 更详细。Wire compiler 负责去重、排序和自然语言化，不能把内部字段名当作 H3 协议。

## 7. 官方 Wire Format

### 7.1 Base 与关键帧模式

最终顺序固定为：

```text
[I2VA / FL2VA / L2VA 所需的官方图片对齐句]

integrated_multimodal_description: ...

overall_soundscape: ...

non_diegetic_music: ...
```

`T2VA` 没有图片对齐句，直接从 `integrated_multimodal_description` 开始。不得添加 `mode:` 或十五段标题。

正文按播放顺序书写：

- `[Shot 1]` 不带时间戳；
- 后续镜头使用严格递增的 `[Shot N] At MM:SS.mmm, ...`；
- 切镜必须带来主体、空间、状态、视点或时间上的新信息；
- 轻微景别或角度变化优先用有动机的摄影机运动；
- static camera 是完整、合法的摄影机方案；
- 动态摄影机使用自然英语，运动类型必需，幅度和速度仅在具有区分意义时输出。

`overall_soundscape` 只汇总环境声、动作声和非语言人声。对白、歌唱和镜内音乐保留在时间线正文。`non_diegetic_music` 只描述角色听不到的配乐；无配乐时输出 `N/A`。

### 7.2 对白

- 说话源按全片实际发声顺序分配稳定 `(S1)`、`(S2)`。
- `<d>` 内只包含语言标签、一个空格和逐字原文，例如 `<d>[Chinese] 原文</d>`。
- 不翻译、不改标点、不规范化空白。
- 画外音使用官方措辞，并明确画面人物嘴唇保持闭合。
- 跨切对白在前后两段同时使用 `<scenetrans>` 并明确声音连续。
- 被视频终点截断的对白使用 `<cutoff>`，且只能出现在最后一个对白事件。

### 7.3 Ref2VA

最终顺序固定为：

```text
subject_definitions:
...

summary:
...

retention_analysis:
...

detailed_description:
...

overall_soundscape:
...

non_diegetic_music:
...
```

每个引用标签必须在 `subject_definitions` 定义，并在后续部分保持同一含义。`retention_analysis` 只允许官方关系值；可见内容使用 `fully_preserved`、`partially_preserved`、`attribute_transfer` 或 `weak_reference`，音频使用 `fully_copy`、`partially_copy`、`reference` 或 `weak_reference`。

Ref2VA 的 `detailed_description` 与 Base 正文共享镜头、时间、摄影机、说话人和声音规则，并在引用实际生效的位置写出稳定标签。

## 8. 动作、摄影机与信息密度

不再使用固定“2–3 个动作”或“一镜一个动作”规则。Director IR 根据有效时长、对白占用、主体数量、物理复杂度和模式计算动作预算。

- 简单表演可以由准备、执行、反应或稳定末态组成连续动作链。
- 动作之间必须物理可达，方向和状态变化不能互相抵消。
- 动作与摄影机不得竞争同一时段的主要注意力，除非导演明确锁定该设计。
- FL2VA 优先保证首尾帧路径，不为了增加变化而添加切镜。
- 动作过载时返回拆镜或删减建议，而不是继续扩写 Prompt。

## 9. 编译链与兼容迁移

建立一个权威入口，例如 `compile_h3_director_prompt(plan, references, capabilities)`，内部按模式调用五个小型发射器。所有供应商适配器只接收该入口的编译结果，不自行拼接 Prompt。

迁移顺序：

1. 为官方五模式建立黄金 fixture；
2. 让现有 I2VA/FL2VA typed optimizer 使用新入口；
3. 修正 Ref 工作流，使其提供完整六段式 Prompt 或明确记录供应商 payload 如何等价承载六段信息；
4. 将旧 `compile_h3(MotionSpec, mode)` 和 `render_h3_optimized_prompt` 改为兼容适配层；
5. 导演台开放五模式并使用同一预检接口；
6. 删除运行时的重复 Prompt 拼装，但保留历史 Prompt 展示。

已有历史任务按原 prompt profile 和 compiler version 解释。只有重新生成才进入新版本，不批量迁移或改写历史 manifest。

## 10. 质量门与错误处理

付费提交前至少验证：

- 模式与冻结输入兼容，工作流声明支持该模式；
- 时长为 4–15 秒，总帧数与 24 FPS 时间线一致；
- 镜头编号连续、区间覆盖完整、后续切点严格递增；
- I2VA、FL2VA、L2VA 图片对齐句与输入完全一致；
- FL2VA 默认单镜头且在终点收敛；
- 所有引用标签均已定义、无重号、无悬空引用；
- Ref2VA 六段齐全且顺序正确；
- 对白逐字一致，说话人 ID 稳定，跨切和截断标记合法；
- 环境声、镜内声音和非剧情音乐没有重复归类；
- 无音乐时为 `N/A`；
- 最终输出不存在 `mode:`、裸 `dialogue:`、十五段标题或内部抽象表演字段；
- 预览 Prompt、manifest Prompt 和实际供应商提交 Prompt 的哈希一致。

质量失败返回稳定错误码和字段路径，不创建供应商任务。模式不可用、输入缺失、引用超限或工作流能力不足时，不允许自动删输入或降级。

## 11. 测试

### 11.1 单元测试

- 五种模式的官方字段、顺序和对齐句黄金测试；
- T2VA 无对齐句，I2VA/FL2VA/L2VA 对齐句精确测试；
- Ref2VA 六段、标签稳定性和 retention marker 测试；
- 第一镜头无时间戳、后续镜头时间戳递增测试；
- static 与动态摄影机自然语言测试；
- 动态摄影机允许省略无意义的默认幅度和速度；
- 对白逐字、语言空格、speaker ID、`<scenetrans>`、`<cutoff>` 和画外音测试；
- 音频分类去重及 `N/A` 测试；
- 内部十五段字段不会泄漏到最终 Prompt；
- 旧入口与权威编译器输出等价测试。

### 11.2 集成测试

- 导演台自动模式五分支；
- 人工模式的可用、禁用与错误原因；
- 预览、冻结快照、manifest 和 provider request 使用同一 Prompt；
- Base 与 Ref 适配器不自行改变 Prompt；
- 不兼容输入在任何上传或计费之前失败；
- 历史 profile/version 仍可读取和展示。

### 11.3 非付费验证

本子项目只使用确定性单元、API、前端和 MockTransport 集成测试。真实 H3 生成需要单独授权和预算，不作为本地完成标准。

## 12. 成功标准

- 用户只通过 H3 导演台选择和运行五种官方模式。
- 自动与人工模式均按冻结输入和真实工作流能力决定，不静默回退。
- 所有新任务只产生 MiniMax 官方 Base 三字段或 Ref2VA 六字段 Prompt。
- Director IR 可以承载 Higgsfield 与 Acting 信息，但最终 Prompt 不出现内部协议标题或抽象心理描述。
- I2VA/FL2VA 现有连续性、帧哈希、manifest、恢复与质量门能力保持可用。
- 五模式 Prompt 都有离线黄金 fixture 和付费前阻断测试。
