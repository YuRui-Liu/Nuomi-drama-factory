# 导演拆解 Runtime 自动修复设计

## 背景

当前导演拆解生成后可能进入 `review_required` 状态，并附带场次级语义校验问题。用户可以手工修改戏剧节拍，但修改后的版本仍可能继承旧校验结果，形成“改完仍不能激活”的闭环缺口。对于问题较多的剧集，逐项手工修正成本也过高。

本设计新增独立的 Runtime 修复任务，让用户可将校验失败的场次委托给 Codex Runtime 或兼容文本模型修复，同时继续保留人工审查和“激活拆解”这一最终闸门。

## 目标

- 为导演拆解增加“委托 Runtime 修复”入口。
- 只修复当前版本中校验失败的场次，不扰动已经通过的内容。
- 最多自动修复两轮，第二轮只处理仍失败的场次。
- 修复结果保存为一个新的子版本，并执行完整重新校验。
- 无论校验是否通过，都不自动激活；由用户人工点击“激活拆解”。
- 让该任务拥有独立的 Runtime、模型、推理强度和回退策略配置。

## 非目标

- 不允许 Runtime 改写剧本原文、对白或故事事实。
- 不自动修改已激活版本。
- 不自动生成或激活导演镜头方案。
- 不在本功能中重构剧本导入、资产生成或视频生成链路。
- 不保证兼容历史测试数据生成的旧语义版本。

## 用户流程

1. 用户解析场次，系统生成语义拆解版本和校验报告。
2. 如果存在校验错误，“委托 Runtime 修复”按钮可用。
3. 用户点击后，系统创建 `screenplay_semantic_repair` 任务并冻结输入快照。
4. Runtime 并行修复失败场次，系统合并结果并完成第一轮全量校验。
5. 若仍有错误，只对剩余失败场次执行第二轮修复。
6. 系统保存一个新的子版本，并在界面中选中该版本。
7. 若新版本校验通过，“激活拆解”按钮解锁；用户人工确认后激活。
8. 激活语义拆解后，用户才能生成导演镜头方案。镜头方案仍走独立审查与激活流程。

## 任务与路由

新增任务类型和文本任务角色：

- 任务类型：`screenplay_semantic_repair`
- 文本任务角色：`screenplay_semantic_repair`

任务入队时冻结以下字段：

- `project_id`
- `episode`
- `source_revision`
- `semantic_revision_id`
- `agent_route_snapshot`
- `max_rounds = 2`
- `concurrency`，默认值为 `3`

`agent_route_snapshot` 至少包含 Runtime、模型、推理强度、回退策略、技能标识及来源。运行期间设置变化不得影响已入队任务。

设置页“运行时与媒体 → 文本任务路由”新增“导演拆解修复”配置项。它支持全局默认与项目覆盖，可选择 Codex Runtime 或模型 API、模型、推理强度和回退策略。未配置专用路由时继承全局文本任务路由；默认回退策略为 `stop`。最大修复轮数固定为两轮，不作为用户可调参数。

## 修复输入与输出契约

系统先按 `scene_id` 聚合校验错误。仅失败场次进入 Runtime；已经通过的场次和无关场次保持字节级语义不变。

每个场次的修复请求包含：

- 剧本原始文本块及行号。
- 当前场次和 Dramatic Beat 数据。
- 当前校验问题及精确位置。
- 允许修改的字段清单。
- 禁止修改的事实边界。
- 严格结构化输出 schema。

Runtime 只能返回结构化 Beat 修复提案，不获得文件系统写权限，也不能直接修改原始剧本或持久化数据。

允许修复：

- Beat 的原文范围。
- Beat 的拆分、合并和排序。
- 目标、阻碍、行动、反应、转折、结果、情绪变化。
- 与原文证据一致的角色引用、对白来源、`must_show` 和 `script_facts` 引用。
- 删除无原文支持的事实或导演性推断。

禁止修复：

- 剧本原文、对白和故事事实。
- 原始场次边界及场次顺序。
- 角色身份、人物关系和故事结局。
- 当前激活版本。
- 已经校验通过且与错误无关的场次。

服务端必须再次校验 Runtime 返回值。出现越权字段、无原文证据的新事实或场次边界变化时，拒绝该场次提案并记录 `repair_contract_violation`。

## 执行与合并

失败场次按默认并发度 `3` 并行处理。结果按稳定的场次顺序确定性合并，不能受任务完成先后影响。

第一轮结束后，系统在内存中合并修复结果并执行完整版本校验。若仍有错误，第二轮只提交仍失败的场次，并附带第一轮结果和最新错误。第二轮结束后再次执行完整校验。

两轮中间结果不分别创建版本。任务结束时最多保存一个以 `semantic_revision_id` 为父版本的新子版本，避免产生大量中间版本。

新子版本始终为 `review_required`：

- 校验通过：允许用户点击“激活拆解”。
- 仍有错误：保留错误报告，禁用激活并展示具体原因。

## 一致性与版本安全

任务开始和提交结果前都必须核对冻结的 `source_revision` 与 `semantic_revision_id`。如果剧本来源或用户当前选择的语义基础版本已经变化，任务以版本冲突失败，不写入新版本，也不覆盖任何现有内容。

任何情况下，原激活版本均保持不变。部分成功或仍有错误的子版本也绝不能自动激活。

## 错误处理

- 单场次 Runtime 失败：保留该场次原数据，继续修复其他场次，并在最终报告中列出失败原因。
- Runtime 整体不可用、传输失败或结构化输出无法解析：任务失败，不创建新子版本。
- 修复契约违规：拒绝该场次结果，记录 `repair_contract_violation`，其他场次可继续。
- 两轮耗尽仍有错误：保存一个 `review_required` 子版本，展示剩余错误，激活按钮保持禁用。
- 版本冲突：任务失败且不写新版本，提示用户基于最新版本重新发起。

## 前端交互

### 导演拆解工作台

顶部操作区按顺序提供：

1. “解析场次”
2. “委托 Runtime 修复”
3. “激活拆解”
4. “生成镜头方案”

状态规则：

- 当前版本存在校验错误，且没有冲突任务运行时，“委托 Runtime 修复”可用。
- 只有当前选中版本完整校验通过时，“激活拆解”可用。
- 只有存在已激活语义版本时，“生成镜头方案”可用。
- 禁用按钮必须显示具体原因，不能只显示灰态。

任务运行时，在工作台内显示进度面板，包括：

- Runtime、模型和任务角色。
- 当前轮次，例如“第 1/2 轮”。
- 场次数、问题数、已解决数和剩余数。
- 进度条。
- “不会修改剧本原文，完成后仍需人工激活”的安全提示。

任务完成后自动刷新并选中新子版本，展示修改摘要、未解决问题和激活状态。即使校验通过，也只解锁“激活拆解”，不代替用户点击。

### 任务中心

任务中心使用明确名称“导演拆解 Runtime 修复”，日志按轮次、场次和问题输出，结果元数据包含基础版本、生成版本、路由快照、修复统计、剩余问题和契约违规信息。

## 与导演镜头方案的关系

本功能只修复 Scene → Dramatic Beat 的语义层。导演镜头方案仍以“已激活的语义版本”为唯一输入，二者保持独立版本和独立人工闸门：

- 语义修复成功不自动生成镜头方案。
- 语义版本激活后，用户才能生成新的导演镜头方案。
- 新镜头方案仍需单独审查并人工点击“激活此版本”。
- 已存在的镜头方案不会因语义修复自动覆写；应通过版本依赖提示其来源已过期。

## 测试策略

### 单元测试

- Runtime 修复契约不能改写剧本事实或场次边界。
- 已通过的场次保持不变。
- 第二轮只包含第一轮后仍失败的场次。
- 最多执行两轮。
- 并行结果确定性合并。
- 越权结果产生 `repair_contract_violation`。

### 存储与服务测试

- 一次任务最多保存一个子版本。
- 新版本父子关系、状态和校验报告正确。
- 源版本变化触发乐观并发冲突，不写入结果。
- 部分场次失败时保留原场次内容。

### API 与任务测试

- 入队请求包含不可变路由和版本快照。
- 独立任务角色能正确选择全局或项目路由。
- 任务中心返回轮次、修复统计、剩余问题及错误详情。

### 前端测试

- 四个操作按钮在各状态下正确启用或禁用，并展示原因。
- 进度面板正确展示两轮状态。
- 成功、部分成功、整体失败和版本冲突均有明确反馈。
- 校验通过后仍必须人工点击激活。

默认测试套件使用确定性 Fake Runtime，覆盖结构化输入输出及错误分支。另提供一个显式启用的真实 Runtime 冒烟测试，不加入默认测试套件。

## 验收标准

- 用户能从存在校验错误的导演拆解版本发起 Runtime 修复。
- 系统只处理失败场次，最多两轮，并在任务中心持续输出可见进度。
- Runtime 无法改变剧本原文、故事事实、场次边界或激活版本。
- 任务结束时最多生成一个可审查子版本。
- 校验通过时由用户人工激活；未通过时显示剩余错误和禁用原因。
- 后续镜头方案仍基于已激活语义版本生成，并保留独立审查与激活机制。
