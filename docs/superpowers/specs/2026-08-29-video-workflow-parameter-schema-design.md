# 视频工作流参数 Schema 与 MiniMax H3 清晰度设计

## 1. 背景

当前叙事组视频生成已经通过统一工作流 ID `runninghub:minimax-h3` 调用 MiniMax H3 Director，但前端只暴露工作流和首帧/首尾帧模式，没有暴露工作流内置的 Size Settings。

后端请求模型已经存在 `resolution` 字段，当前实现却把 `720p` 当成长边 720 计算，得到约 `416×736 / 0.306MP`。这不符合 H3 Director 内置 Size Settings：该工作流以 `megapixels` 预设控制分辨率，并要求宽高为 32 的倍数。

本设计建立可扩展的视频工作流参数 Schema。首版只为 MiniMax H3 暴露清晰度，后续其他 RunningHub 工作流可以声明自己的产品参数和适配规则。

## 2. 已确认范围

- 采用“项目默认值 + 当前叙事组覆盖”。
- 建立通用工作流参数 Schema，但首版只暴露清晰度。
- MiniMax H3 提供 `720p 标准`、`1080p 高清`，项目默认 720p。
- 一个叙事组内所有逻辑视频单元统一使用同一清晰度。
- 用户在叙事组中切换清晰度时，默认只保存为本组覆盖。
- 提供“恢复项目默认”和“设为项目默认”。
- 1080p 只展示相对成本与耗时提示，不提供未经供应商确认的精确报价。
- 已有视频在设置变化后继续保留并可预览，界面标记“设置已变更，需重新生成”。
- 真机付费验收必须另行获得用户授权。

## 3. 非目标

- 不暴露 RunningHub 节点 ID、原始节点输入或任意 JSON 编辑器。
- 不修改用户提供的 RunningHub 工作流 JSON。
- 不将 H3 的 `megapixels` 规则复用为其他视频工作流的通用规则。
- 不在本功能中增加视频超分或后处理步骤。
- 不在首版暴露 FPS、seed、音频模式等高级参数。
- 不在切换清晰度时自动重新生成或删除旧视频。

## 4. 架构

### 4.1 工作流参数 Schema

`VideoWorkflowDefinition` 增加工作流参数定义。每个参数具有明确职责：

- `key`：稳定产品参数键，例如 `resolution`。
- `type`：首版支持 `enum`，为未来布尔值和数值参数保留扩展边界。
- `label`、`description`：前端展示文案。
- `default`：工作流默认产品值。
- `options`：候选产品值、标签、帮助文案和相对成本提示。
- `scope`：首版为 `narrative_group`。

公开目录 API 只返回产品参数，不返回 `megapixels`、节点 ID 或工作流内部绑定。H3 的传输映射封装在 H3 适配器中。

### 4.2 配置分层

项目媒体默认值按工作流 ID 保存：

```json
{
  "video_workflow_parameters": {
    "runninghub:minimax-h3": {
      "resolution": "720p"
    }
  }
}
```

叙事组 sidecar 保存：

```json
{
  "video_settings": {
    "workflow_id": "runninghub:minimax-h3",
    "revision": 1,
    "overrides": {
      "resolution": "1080p"
    }
  }
}
```

只保存真正不同于项目默认值的覆盖项。恢复默认会移除覆盖项；当“设为项目默认”后本组值与新默认一致，也清除冗余覆盖。

不同工作流使用独立命名空间。切换工作流时不读取其他工作流的参数值。

### 4.3 稳定生成快照

视频设置使用 revision 乐观锁。前端先保存本组设置，再在生成请求中提交：

- 工作流 ID；
- 视频方案 revision；
- 视频设置 revision；
- 当前视频 stage revision。

后端在预留新视频 revision 前重新读取项目默认、本组覆盖和工作流 Schema，完成合并与校验，再形成不可变任务快照。生成任务不信任前端提交的 RunningHub 内部参数。

现有顶层 `resolution` 字段保留兼容，但新前端不再以它作为配置事实来源。兼容请求必须经过同一个工作流 Schema 和适配器校验。

## 5. MiniMax H3 Director 内置 Size Settings

### 5.1 产品档位映射

H3 清晰度必须映射到 Director 内置 `megapixels` 预设，而不是把产品标签解析成长边。

| 产品档位 | Director `megapixels` | 16:9 输出 | 9:16 输出 |
|---|---:|---:|---:|
| 720p 标准 | `0.9` | `1280×736` | `736×1280` |
| 1080p 高清 | `2.0` | `1920×1088` | `1088×1920` |

### 5.2 序列化规则

适配器依据内置预设同步生成一致的 Director output：

- `mode=fixed`；
- `aspectRatio` 使用 Director 对应标签；
- `megapixels` 必须保持精确预设值 `0.9` 或 `2.0`；
- `multiple=32`；
- `width`、`height`、`longEdge` 使用上表确定值；
- `refMaxSize` 与 `longEdge` 一致。

禁止从最终宽高面积反算并传递 `0.942`、`2.089` 等近似值。`megapixels` 是导演台内置档位，宽高是该档位与画幅对应的确定性结果。

当前 `720p → 416×736 / 0.306MP` 行为属于待修复映射错误。

## 6. 前端交互

清晰度控件直接放在“视频生成”卡片内，与生成按钮和视频方案同屏：

- 两个紧凑选项：`720p 标准`、`1080p 高清`。
- 显示配置来源：`项目默认`或`本组覆盖`。
- 点击档位后立即保存本组覆盖，不弹窗、不自动生成。
- 本组覆盖状态下显示“恢复项目默认”和“设为项目默认”。
- 1080p 显示“画质更高，预计耗时和额度增加”。
- queued/running 状态禁用设置修改。

完成视频的实际设置与当前目标设置不一致时显示：

```text
现有视频：720p · 目标设置：1080p · 需重新生成
```

旧视频继续可预览和下载。用户点击“生成组合视频”后才创建新 revision；新任务成功前不删除或覆盖旧产物。

视频结果区和提示词抽屉展示：

- 产品档位；
- Director `megapixels`；
- 目标尺寸；
- ffprobe 实际尺寸；
- 项目默认或本组覆盖来源。

## 7. API 与错误处理

新增叙事组视频设置读取/更新契约，更新请求包含 expected revision 和产品参数覆盖值。后端只接受当前工作流 Schema 声明的键和值。

以下错误必须在调用 DeepSeek 或 RunningHub 前返回：

- 未知参数；
- 非法档位；
- 设置 revision 冲突；
- 当前工作流不支持该参数；
- 保存的旧档位已从新 Schema 移除。

不得对非法或过期档位静默回退，以免使用错误配置消耗额度。

RunningHub 成功返回但实际尺寸与目标尺寸不符时：

- 保留供应商产物、任务号和 manifest；
- 将视频结果标记为质量异常；
- 在任务详情中记录目标尺寸与实际尺寸；
- 不误报为完整成功。

## 8. 可观测性与复盘

任务快照和 manifest 同时记录：

```json
{
  "workflow_parameters": {
    "resolution": "1080p"
  },
  "provider_parameters": {
    "megapixels": 2.0,
    "multiple": 32,
    "width": 1088,
    "height": 1920,
    "longEdge": 1920
  },
  "actual_output": {
    "width": 1088,
    "height": 1920
  }
}
```

提示词审查接口返回同一任务快照中的参数，不能根据当前项目默认值重新推导历史结果。

## 9. 测试与验收

### 9.1 后端测试

- 精确验证 `720p → 0.9MP`、`1080p → 2.0MP`。
- 验证 9:16 和 16:9 的确定性尺寸以及 32 倍数约束。
- 验证 Director output、根级 width/height、refMaxSize 相互一致。
- 验证项目默认、本组覆盖、恢复默认和设为项目默认。
- 验证设置 revision 冲突、非法档位和不同工作流参数隔离。
- 验证任务快照、manifest、视频结果和提示词审查接口使用同一历史参数。
- 验证尺寸不匹配进入质量异常并保留产物。
- 保留旧 `resolution` 请求字段的兼容测试。

### 9.2 前端测试

- 验证 720p/1080p 控件、继承/覆盖状态和相对成本提示。
- 验证 queued/running 时禁止修改。
- 验证设置变更后显示“需重新生成”，旧视频仍可预览。
- 验证恢复默认和设为项目默认。
- 验证生成请求只提交稳定 revision，不提交 RunningHub 节点参数。

### 9.3 真机验收

实施完成后，在用户单独授权额度的前提下，使用同一组短素材分别生成一次 720p 和 1080p，并核对：

- RunningHub 真实任务号；
- Director manifest 中的 `megapixels`；
- 最终 ffprobe 尺寸、编码、时长和可播放性；
- 前端任务详情和提示词抽屉中的参数追溯信息。

自动测试不得调用付费供应商或使用真机任务代替单元测试。

## 10. 成功标准

- 用户可在叙事组视频卡片中选择 720p 或 1080p。
- 设置支持项目默认和本组覆盖，并可恢复或晋升为项目默认。
- 720p、1080p 分别以 Director 内置 `0.9MP`、`2.0MP` 执行。
- 设置变更不会删除旧视频，也不会未经确认自动消耗额度。
- 每次生成都能从任务、manifest 和 UI 追溯产品参数、供应商参数和实际尺寸。
- 新增 RunningHub 视频工作流时，可通过独立 Schema 和适配器声明自己的参数，无需在视频卡片中硬编码供应商节点。
