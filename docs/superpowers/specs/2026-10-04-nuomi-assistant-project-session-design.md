# 糯米助手路由与项目持久会话

日期：2026-10-04

状态：用户已批准设计方向；本书面规格待审查。

## 目标与范围

在文本任务路由中提供「糯米助手」配置。同一用户在同一项目持续使用一个助手逻辑会话，刷新页面、切换项目、重启服务、普通失败重试均不重置；只有用户手动清除会话才创建下一代会话。不同项目、不同用户互相隔离。

本次仅管理糯米助手。编剧、导演和 QC 保留各自的运行与会话边界，不共享助手会话。首页助手拥有独立的 home scope，不混入任何项目。清除助手会话不删除剧本、资产、创作记忆、生成任务或生产记录。

## 当前证据

- `chat/runtime_settings.py` 与文本任务路由分开保存；TEAM 可保存聊天配置，CE 从环境读取。
- `chat/service.py` 的 Codex/Claude 会话访问函数接收 project，却只在用户级 `agent_sessions.json` 保存一个 backend/thread_id。
- `chat/hermes_pool.py` 当前按用户维护工作进程与跨项目会话。
- `chat/cli_agent.py` 已按 scope/project 保存历史，但会话标识还包含 backend/model/reasoning_effort；换配置会隐式选择另一份历史。此适配器通过重放历史调用结构化运行时，不等于供应商原生持续会话。
- 前端 `use-superchat.ts` 的 sessionControl 尚未提供实际清除接口。

因此不能仅在设置中新增一行，也不能把所有供应商执行都宣称为同一个原生 session。

## 方案选择

采用统一配置入口与项目持久会话管理器。

只补设置行不能解决跨项目混用和隐式换会话；让助手及全部后台 Agent 共用会话会破坏独立审稿与任务上下文边界，均不采用。

## 路由配置

使用已有逻辑角色名 `chat_agent`，显示名称「糯米助手」。在文本任务路由设置页提供运行时、模型、推理强度，保存后实际聊天执行必须读取同一配置源；原聊天配置入口代理到该配置，不保留两份可独立生效的设置。

聊天与结构化后台任务共用配置入口和优先级规则，但分别校验运行时能力。保留当前聊天支持的 Hermes、Codex、WorkBuddy、DeepSeek Harness；Hermes 不扩散为后台结构化任务选项，本次不新增 model_api 聊天适配器。模型和推理强度只在相应运行时支持时展示和下发。

未显式保存新路由时，沿用已有有效聊天配置，CE 沿用环境值、TEAM 沿用已保存聊天值，避免升级后自动换供应商。保存 `chat_agent` 后新路由成为唯一权威值；旧入口与环境值不再覆盖它。沿用当前项目覆盖机制：项目显式覆盖优先于全局设置。

每轮开始固定一次有效路由并记录来源。模型或推理强度调整在适配器支持原会话继续执行时于下一轮生效，不改变逻辑会话 ID；不能继续原会话的配置变化显示“需清除会话后生效”，禁止暗建新会话或静默回退供应商。

## 会话身份与存储

会话由服务端按用户身份、授权后的 canonical project ID（或 home scope）定位，不能由客户端指定任意供应商 thread ID 或磁盘路径。

持久记录包括逻辑 session ID、scope、generation、运行时绑定、供应商 session ID（如支持）、会话模式 native/replay、当前轮租约及更新时间。模型名不属于会话身份。每个用户与 scope 同时最多存在一个活动逻辑会话。

原生持续会话适配器必须恢复保存的供应商 ID；重放适配器在同一逻辑会话内持久保存消息及工具结果。页面刷新和 worker 回收不能丢失逻辑记录，重放模式必须如实标示，不能伪称原生会话。

上下文压缩可以保留逻辑会话与供应商会话身份；不能通过新建会话或悄悄丢弃旧历史处理长度限制。暂不支持的长度限制明确返回可操作错误，由用户选择是否清除。

## 执行与并发

1. API 先鉴权并解析项目，再解析糯米助手路由与会话记录。
2. 按用户与 scope 获取持久租约；同 scope 多标签页消息顺序执行，不并发写同一会话。不同 scope 不共享取消句柄、worker 上下文或权限令牌。
3. 通过适配器创建或恢复执行会话；新建供应商会话后及时保存 ID，避免结果返回前服务中断导致重复创建。
4. 每轮固定 session ID 与 generation。消息、工具调度、流式事件、结果落盘均检查它们；新 generation 拒收旧轮次写入。
5. 断线重连只重订阅原轮次。租约过期后的恢复先核验原执行状态；状态不明时不能自动重发有副作用的工具调用。

会话管理独立于具体供应商 SDK。管理器负责身份、持久化、租约和清除；适配器负责 native resume 或 replay；聊天服务负责项目上下文、工具权限和事件输出。复用现有持久存储与锁机制，避免继续扩大 `chat/service.py`。

## 手动清除

助手菜单增加「清除会话」，显示当前项目名称与作用范围。确认提示说明：清空当前助手对话上下文，保留项目内容。

清除接口只允许具备当前 scope 写入权限的用户调用，携带期望 generation 与幂等请求 ID。执行时递增 generation、标记旧会话终止、取消旧轮次并清除待执行消息；已派发的独立生产任务不随之删除或重复派发。已经发生的工具副作用不宣称能够回滚。

旧聊天记录不再进入新上下文，也不再出现在当前会话时间线；如保留内部审计记录，必须与活动上下文分开。清除成功后显示空会话，下一条消息才建立新的执行会话。客户端同步清除当前 scope 的重连游标和活动轮次引用，其他项目不受影响。

重复清除请求返回同一结果；过期 generation 返回冲突，避免重复点击误清除刚建立的新会话。

## 迁移与故障

- 旧数据可证明项目归属时，迁入对应项目，保留历史和有效供应商 ID。
- 用户级跨项目会话不能自动归给当前项目。保留旧记录但不注入项目；该项目首次继续前显示迁移提示，要求用户手动清除旧上下文后开始项目会话，不后台静默换会话。
- 旧 CLI 历史可按原 scope 迁移；同一项目若存在多份由不同路由派生的历史，不能合并或猜选。提示用户手动清除后建立唯一活动会话。
- 存储损坏、恢复 ID 失效、供应商暂不可用分别返回清晰错误；允许重试恢复原会话或手动清除，不以新建 session 掩盖失败。
- worker/token 更新保留会话身份，令牌权限跟随当前授权 scope，禁止借助跨项目 worker 继承另一项目能力。

## 验收

1. CE 与 TEAM 设置中均能看到、保存、重新读取糯米助手路由；真实聊天调用收到一致的有效配置，旧配置迁移不改变运行时。
2. 同项目连续多轮、刷新、多标签页、切换离开后返回、服务重启后，逻辑 session ID 保持不变；native 模式供应商 ID 也保持不变。
3. 两项目及两用户分别测试，对话、会话 ID、工具权限与取消动作均隔离；首页单独隔离。
4. 明确测试 replay 模式持久历史，不以伪造原生 ID 通过验收。
5. 并发消息保持顺序；清除时正在运行、等待执行、断线重连和晚到回调均不能污染下一代会话。
6. 清除后下一条消息建立新 ID，当前时间线为空且不重放旧历史；项目文档、资产和任务保持原值。
7. 换模型的兼容路径保留身份；不兼容配置和失效 resume 显示明确阻塞，不自动切换会话。
8. 覆盖迁移的唯一归属、跨项目旧会话、多份历史冲突以及重复清除请求。
9. App 验证配置保存、项目切换与手动清除；使用可控适配器测试故障和竞态，避免为同一行为反复调用付费模型。

## 规格自检

本规格不包含后台编剧/QC 合并、供应商扩展或无关聊天重构。明确区分逻辑会话与原生会话、清除上下文与删除项目、worker 生命周期与会话生命周期；迁移歧义不猜测，恢复失败不隐式重建。无待定实现需求；具体数据库表与适配器调用步骤由实施计划展开。
