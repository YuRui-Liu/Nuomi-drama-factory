# NuomiDrama v2 创作工作流选择性同步设计

日期：2026-08-28  
参考源码：DramaClaw v2.0.1（用户提供的 `E:\Proj\dramaclaw-main`）

## 1. 目标

选择性同步 DramaClaw v2.0.0 及 v2.0.1 中会实质改善创作链路的能力，同时保留 NuomiDrama 已有的产品品牌、叙事组、画幅控制、Episode Graph 和 RunningHub MiniMax H3 视频链路。

同步范围分为三阶段：

1. 大项目性能：缩略图、聚合查询、按需读取、视口加载和慢上传。
2. 媒体协议与守卫：统一请求边界、完整诊断、视频模式回退和素材前置校验。
3. 结构化导入与资产管理：默认结构化导入、角色/场景完整性、虚拟文件夹和用途分类。

本次不整体合并 v2.0.1，也不引入组织、多租户、联合品牌、公告中心、下载页或 EE 计费界面。

## 2. 不可破坏的兼容边界

### 2.1 RunningHub MiniMax

RunningHub MiniMax 是 NuomiDrama 的核心视频能力，属于受保护边界：

- 保留 MiniMax H3 文生视频、图生视频、参考生视频和组合视频链路。
- 保留现有 RunningHub 工作流 JSON、节点映射、参数注入、轮询和结果回传。
- 官方媒体目录不得覆盖、隐藏、重命名或降低 RunningHub 模型优先级。
- 统一媒体协议只能包装 RunningHub 适配器，不能把 H3 改写为其他供应商的默认协议。
- 诊断必须记录工作流标识、模式、画幅、素材摘要和节点参数摘要，但必须脱敏。
- 每阶段都必须执行 H3、叙事组视频和旧任务兼容回归测试。

模型选择优先级固定为：

1. 项目显式 RunningHub 配置。
2. 本地自定义模型配置。
3. 官方媒体目录。
4. 系统默认模型。

### 2.2 项目与资产兼容

- 现有项目继续使用其创建时绑定的知识流水线，不自动迁移。
- 现有稳定资产 ID、物理路径和任务结果路径保持不变。
- 虚拟文件夹操作不得移动或删除物理文件。
- 叙事组参考图、角色参考图、场景参考图和 RunningHub 输入继续读取原路径。
- 任何新增数据库字段和表必须支持旧数据库增量迁移。

## 3. 阶段 A：大项目性能

### 3.1 缩略图服务

新增独立缩略图工具和缓存边界：

- 生成历史图片、角色图、场景图和画布图片的降采样副本。
- 缩略图缓存键至少包含项目、逻辑资产身份、源文件版本和目标尺寸。
- 只返回已生成的缩略图；读取接口不得同步解码大图并阻塞请求。
- 缩略图缺失时返回原图降级标志，由后台任务补齐缓存。
- 不允许跨项目共用未带项目作用域的缓存键。

### 3.2 聚合与按需查询

- 资产引用索引使用项目级聚合接口，避免按剧集扇出 Beat 请求。
- 资产列表只返回列表展示所需的轻量字段。
- Beat 引用、文件状态、完整元数据和历史结果在用户展开时读取。
- 查询缓存键必须包含项目 ID、筛选条件和分页游标。
- 页面切换必须取消已经失去消费者的请求。

### 3.3 视口加载

提供通用的视口图片组件：

- 使用 `IntersectionObserver` 判断真实可见性。
- 进入视口附近后才设置图片 `src`。
- 首屏关键图片可显式 eager，其余均按需加载。
- 离开视口后不反复清空已加载图片，避免滚动抖动和重复下载。
- 加载失败显示轻量占位和可重试状态。

### 3.4 上传超时

- 文件上传不使用通用 API 的固定 30 秒总超时。
- 上传仍支持用户主动取消、连接错误和服务器大小限制。
- 普通 JSON 查询继续保留有限超时与重试策略。

## 4. 阶段 B：媒体协议、诊断与守卫

### 4.1 统一媒体请求边界

定义供应商无关的媒体请求外壳，包含：

- 媒体类型与能力。
- 逻辑模型和供应商模型。
- 生成模式、画幅、时长与质量。
- 图片、视频、音频参考素材。
- 供应商扩展参数。

各供应商继续由独立适配器执行。RunningHub 适配器拥有自己的工作流选择、节点参数生成、提交和轮询逻辑。

### 4.2 诊断数据

每次媒体调用记录：

- provider、channel、logical model、resolved model。
- generation mode、aspect ratio、duration、quality。
- 工作流 ID、工作流版本和关键节点参数摘要。
- 各类参考素材数量、时长和尺寸摘要。
- 上游任务 ID、状态码、阶段、重试次数和脱敏错误摘要。
- 模式自动回退或自动切换的原因。

不得记录 API Key、Authorization、签名 URL、本地绝对路径、完整提示词中的敏感内容或原始上游响应。

### 4.3 入队前守卫

- 视频模式必须与模型能力和实际素材匹配。
- 视频素材全部移除时，节点退回文生视频。
- 参考图片在入队前校验数量、尺寸、宽高比和文件可读性。
- 音频在入队前校验单条时长、总时长、格式和声线。
- 不支持的素材组合在计费、任务创建和供应商调用前被拒绝。
- 用户获得具体、可执行的错误信息。

### 4.4 结果完整性

- 角色生成只有完整、校验通过的结果才能替换正式结果。
- 场景生成复用同一轮已经生成的资产，不重复构建。
- 部分失败保存在诊断和临时结果中，不伪装成成功终态。
- 已发布的旧任务 payload 和结果结构继续可读取。

## 5. 阶段 C：默认结构化导入

### 5.1 项目知识流水线

项目持久化 `knowledge_pipeline`：

- 新项目默认 `structured_v1`。
- 现有项目缺少该字段时解释为 `cognee_legacy`。
- 流水线是项目级属性，不随页面或任务临时变化。

状态机：

```text
new
  -> structured_pending
  -> structured_ready

structured_pending --失败--> structured_pending
  -> 重试 structured_v1
  -> 用户确认切换 cognee_legacy
```

只有结构化导入尚未成功、且没有正式分集/角色/场景资产时，才允许切换到 `cognee_legacy`。不进行自动降级。

### 5.2 结构化处理流程

```text
保存原文
-> 确定性分块
-> 生成分集骨架
-> 抽取角色与场景
-> 完整性和确定性校验
-> 单事务原子写入
-> 进入现有剧集、叙事组和视频链路
```

结构化结果必须保留源文本位置、章节映射和稳定逻辑身份，以便重试时复用且不产生重复资产。

### 5.3 失败交互

失败页面必须展示阶段和原因，并提供：

- 重试结构化导入。
- 切换知识图谱导入。

切换前明确说明会使用更慢的图谱与嵌入链路。用户确认后原子更新项目流水线，再开始旧流程。

## 6. 角色与场景完整性

结构化角色至少包含：

- 稳定身份 ID、姓名、别名。
- 性别、年龄段、人物角色。
- 面部、发型、体型和显著特征。
- 服装和身份提示。

结构化场景至少包含：

- 稳定场景 ID、名称、地点和时段。
- 环境描述、空间结构和视觉锚点。
- 章节与分集引用。

缺失字段允许为空，但不得用错误默认值污染身份提示。完整结果通过校验后一次性发布；失败轮次不得覆盖上次成功结果。

## 7. 虚拟资产文件夹与用途

### 7.1 数据模型

新增独立元数据表或等价存储：

- `asset_folders`：folder ID、project ID、parent ID、名称、排序和时间戳。
- `asset_placements`：asset ID、folder ID、purpose 和排序。

用途枚举：

- character
- scene
- prop
- storyboard
- video
- audio
- other

物理资产记录和路径不变。文件夹可嵌套，但首版不支持跨项目文件夹和同一资产多文件夹映射。

### 7.2 操作语义

- 新建、重命名、移动和排序只更新元数据。
- 删除文件夹只解除该文件夹及子文件夹归类，资产回到未归类区。
- 删除资产继续走现有资产删除流程，并清理对应 placement。
- 列表支持用途、文件夹、类型和关键词组合筛选。
- 迁移后旧资产默认进入基于现有类型推导的用途，文件夹为空。

## 8. 实施策略

不整体合并上游。按以下策略选择性复用：

1. 无产品耦合的工具和领域模块优先直接移植并保留许可证信息。
2. 路由、数据库、任务和 UI 仅抽取算法和契约，适配 NuomiDrama 现有边界。
3. 上游名称和用户可见文案全部转换为 NuomiDrama 术语。
4. 每阶段独立提交、独立回归和独立回退。
5. 当前工作树中的用户修改不得被覆盖或纳入无关提交。

## 9. 验收标准

### 阶段 A

- 大型资产列表不会在初次渲染时请求全部原图。
- 资产引用不再按剧集扇出请求。
- 慢上传不会在 30 秒被客户端主动取消。
- 画布和资产列表保留可见加载、失败和重试反馈。

### 阶段 B

- RunningHub MiniMax 全部现有模式和工作流回归通过。
- 错误模式、越界素材和无效音色在入队前失败。
- 任务详情能显示脱敏后的完整模型诊断。
- 旧任务和旧项目仍可执行或读取。

### 阶段 C

- 新项目默认使用 `structured_v1`，不调用 Cognee 或嵌入模型。
- 旧项目继续使用 `cognee_legacy`。
- 结构化失败不会自动降级，用户可明确选择切换。
- 角色或场景部分失败不会覆盖完整结果。
- 虚拟文件夹操作不改变任何物理资产路径。
- 现有叙事组和 RunningHub 任务继续解析原资产路径。

## 10. 测试策略

- 所有生产修改遵循测试先行。
- 为知识流水线状态机、项目迁移、结构化幂等和原子发布建立后端契约测试。
- 为缩略图缓存隔离、聚合接口和上传超时建立 API 测试。
- 为视口加载、虚拟文件夹和失败交互建立前端行为测试。
- 为 RunningHub 工作流选择、节点参数、画幅、参考素材和诊断脱敏建立专项回归。
- 每阶段运行相关聚焦测试、静态检查和生产构建；基线失败必须与本次变更明确区分。
