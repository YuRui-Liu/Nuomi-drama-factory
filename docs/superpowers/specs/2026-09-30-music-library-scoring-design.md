# 漫剧音乐库与剧情段落配乐设计

## 1. 已确认的产品规则

音乐库优先，生成必须由用户点击。个人音乐库跨项目复用，项目通过收藏和引用组织本剧常用配乐。配乐默认纯音乐，界面不要求歌词；RunningHub 默认工作流 ID 为字符串 `2059090557116440578`，允许在服务配置中显式更换。

核心交付是“为剧情段落选定合适音乐并进入成片”，不是仅提供音乐生成按钮。生成候选不会自动应用、收藏或触发成片重合成。允许整集或某段不配乐。

## 2. 当前代码与边界

- 工作流文件：`runninghub/Ace-Step1.5X工作流(打造你的专属音乐).json` 及同目录 `_api.json`。
- 复用 `media_capabilities/runtime/runninghub_client.py` 的提交、查询、下载、任务及已有费用记录边界，不另建直连绕过实现。
- 现有合成请求有 `add_bgm`，前端 compose 页面固定传 false；仅启用该布尔值不能表达音乐来源、时段和剪辑。
- 既有 `compose_episode` 与画布视频合成负责产出成片。配乐台接入一个已完成的成片版本，以独立后期混音任务输出新的配乐版视频；不重做分镜或重新拼接上游视频。

首版不做歌词歌曲制作、音乐训练、任意外部曲库抓取、自动付费补库或基于参考音频的改编。所给工作流没有音频输入，不能把 ACE-Step 原生的 Cover/Repaint 能力当成当前 RunningHub 工作流已具备的能力。

## 3. 统一的配乐段落

配乐段落可以跨多个叙事组，不等于逐镜头生成一首音乐。每个段落保存：关联叙事组、剧情用途、情绪变化、强度、对白密度、目标时长、进入/退出点、角色或主题标签。首版从既有组时间线提出可编辑的连续段落，手动拆分、合并、留白；自动建议只形成草稿。

同一份段落需求用于音乐库匹配及生成提示词。剧情意图先转换为音乐特征，如“发现线索但尚未确认危险”对应克制悬疑、稀疏配器、逐渐增加张力。不能把人物名和整段剧情直接堆入模型提示词。

配乐台以接入成片的真实时长为时间基准，可自由选择任意起止时间，不受叙事组边界限制。已有剧情信息作为选曲参考；无关联剧本的成片也能手工配乐。替换源成片时要求核对原安排，不静默迁移或延长音乐。

## 4. 音乐库与检索

### 资源

音乐资源包含稳定 ID、所有者、内容版本及哈希、可播放文件、名称、说明、时长、来源（上传/生成）、情绪、强度、剧情用途、乐器、风格、BPM、是否含人声、主题标签、授权备注、可用片段及循环点。

实测属性和人工标注分开：读取真实时长、格式、采样率等；BPM、人声、情绪等未分析时允许未知，不能把生成要求当作测量结果。首版人工标签和描述即可使用，不依赖另一个付费模型。未知项显示未知。

个人库列表仅对所有者开放；项目成员读取已授权项目引用及其固定快照，不因此获得整个个人库的访问权。项目收藏保存引用，项目采用时固定文件版本及所需元数据，后续改名或发布新版不改变旧成片。归档阻止新选用，保留已有引用，不在首版做破坏性删除。

### 匹配

首版使用描述关键词和结构化标签进行可解释排序，不宣称已具备音频语义理解。先过滤访问权限、文件有效性及用户要求的人声条件，再按剧情用途、情绪、能量、乐器、主题连续性和可用时长排序。未知属性不视为满足条件。

推荐展示理由与不足，例如“悬疑、低强度匹配；无循环点，长度不足”。返回可试听的片段起止点；无足够依据时只推荐整首供人工选择，不伪造最优切点。匹配不足显示空态和手动生成入口，绝不自动提交 RunningHub。

## 5. ACE-Step 提示词与 RunningHub 编译

整体音乐描述用于 `94.tags`：类型、情绪、乐器、音色、配器密度、对白空间及简洁发展方向。中文编辑意图可以转换为明确的英文音乐描述，但保留用户审阅和修改入口。避免互相冲突的情绪和配器要求，不默认引用特定作品或创作者名称。

`94.lyrics` 默认固定 `[Instrumental]`。首版不暴露歌词框；复杂结构标签作为后续可选能力，不把提示词中的时间点当作精确同步控制。

| 参数 | 写入位置 | 约束 |
| --- | --- | --- |
| 音乐描述 | `94.tags` | 非空，明确纯音乐及对白空间 |
| 纯音乐标记 | `94.lyrics` | `[Instrumental]` |
| BPM | `203.value` | 显式合法数值，与音乐描述不矛盾 |
| 目标时长 | `205.value` | 有限正值，节点边界由部署契约校验 |
| 拍号/调性 | `94.timesignature` / `94.keyscale` | 使用实际节点支持枚举 |
| 种子 | `109.value` | 编译为节点支持的非负整数，保存实际提交值 |
| 音频输出 | `107` | 当前为 320k MP3 |

`205` 同时连接 `94.duration` 和 `98.seconds`，必须保持同步。不得使用 UI 中未连接的残留 widget 值替代实际连线。当前模板负种子及浮点尾差在请求编译时规范化，用户原文件不静默覆盖。采样器和模型加载等固定参数沿用已核对工作流，不让普通音乐描述改写协议。

本地节点映射还需在接入时做远端工作流只读契约核对；不一致则明确失败，不能带猜测参数提交收费任务。纯音乐是生成要求而非质量保证，候选须试听确认。

## 6. 生成、采用与混音

点击生成前展示描述、时长、数量和可能费用。默认生成一个候选；额外候选明确增加任务。记录幂等请求标识、远端任务 ID、冻结参数和提示词、实际结果时长及已有费用信息。未知费用显示未提供。

网络中断后优先查询已提交任务，不能盲目重提。取消遵循 RunningHub 实际支持能力；远端已运行时不宣称一定免费取消。失败可手动重试，保留可恢复的成功结果。

候选分别支持“用于当前段落”和“收藏到音乐库”。采用后记录源音乐入点/出点、时间线起点、增益、淡入淡出及对白压低配置，允许一个主题片段跨段复用。

导出前冻结配乐计划与源成片版本，复用既有任务基础设施执行独立后期混音任务，保留原成片。音乐过短时要求换片段或选择已标注可循环区间，不自动拉伸节奏或重复不合适的尾音。转折对齐、交叉淡化由混音层执行。

对白压低优先使用已有对白时间区间，支持手动修正；缺少可靠对白区间时不伪造精确对白检测，采用用户指定区间或整体降低配乐增益，并标注状态。预览与导出使用同一混音参数。

源视频已有内嵌音乐时，界面提示用户试听，不能承诺可无损去除；首版不自动执行人声/音乐分离。未采用配乐计划时保持原成片行为。

## 7. 前端信息结构

个人音乐库入口提供上传、检索、标签编辑、试听和归档；项目视图提供收藏及本剧主题筛选。

画布增加独立“配乐台”节点，接在成片之后，属于可选后期步骤。可先创建空节点，接入一个有效成片后开始编排；节点展示封面、源版本、配乐片段数及导出状态，点击打开大尺寸工作台。输出新的配乐版成片引用，原成片继续可用。

工作台左侧为个人音乐、项目收藏和生成候选；中间为同步视频预览；右侧为选区及片段设置；底部为多轨时间线。固定视频轨和原声轨，支持全局配乐与任意选段配乐共存。“生成配乐”为显式次级动作，展示音乐描述和参数，候选由用户采用。

### 多轨、多配乐（2026-10-01 已确认）

- 可新增、删除、重命名配乐轨；每轨可放多个片段，不同轨允许重叠混音。
- 每轨独立音量、静音与独奏；有独奏时只播放未静音的独奏配乐轨。原声单独控制，不受配乐独奏隐式关闭。
- 每个片段独立源音频入点、时间线起点、时长、增益、淡入淡出；支持移动、裁剪、拆分、复制和删除。轨道增益与片段增益叠加计算。
- 全局范围为源成片完整时长；自由选段使用时间线拖选或输入起止时间。选曲和生成候选采用时，明确显示目标轨道和范围。
- 同轨碰撞时不静默覆盖：提供“替换选区”或“新增轨道叠加”。替换仅切除目标轨选区内的旧片段，保留两侧并正确调整右侧源音频入点；叠加新建轨道。取消不修改安排。
- 拆分后两段保持音乐源偏移连续；复制生成新片段 ID。片段不得超出源音频可用长度或成片边界，除非显式启用有效循环区间。
- 全局铺底可与局部情绪音乐分轨叠加；轨道和片段删除支持撤销。关闭再打开或刷新恢复已保存草稿；保存草稿不自动导出。
- 预览和导出使用相同的轨道启用规则、音量、淡变和对白压低参数。导出混合所有启用配乐轨与启用原声；最终输出控制峰值避免多轨叠加削波。
- 首版不提供 MIDI、虚拟乐器或音符编辑；ACE Studio 作为视频配乐工作台的交互参考，生成仍使用指定 RunningHub ACE-Step 工作流。

段落状态区分未选择、留白、已采用、来源失效、时间线待核对、生成中及失败。试听不等于采用，收藏不等于应用，保存计划不等于重新导出。

## 8. 数据一致性与验收

库编辑和计划保存使用版本检查，冲突保留用户编辑。导出和生成冻结输入，后续修改不改变在途任务。文件上传校验可解码音频与真实媒体属性，播放和下载走现有权限边界。

最低验收：

1. 无 RunningHub 配置仍可上传、检索、选用库内音乐；检索从不调用音乐生成。
2. 一首音乐跨项目复用，项目收藏隔离，旧引用不随库更新而改变。
3. 默认请求纯音乐，无歌词输入；节点映射、时长共享连线、幂等和远端结果恢复有测试。
4. 用户点击才生成，候选不自动写入正式时间线，失败不影响已选音乐。
5. 实测音频长度与剪辑区间有效，音乐与对白混音、淡入淡出及版本冻结有本地合成验证。
6. 旧项目无配乐计划时合成结果行为不变；缺少对白区间、音乐太短、源视频变化均有清晰处理。
7. 自动化验证使用假 RunningHub 与短测试音频，不默认进行付费生成。
8. 多轨重叠、独奏与静音组合、片段拆分偏移、选区替换保留两侧、复制独立 ID、删除撤销及草稿恢复有测试。
9. 通过真实短音频验证两条配乐轨叠加、音量及淡变、输出时长与峰值；导出不覆盖源成片。
