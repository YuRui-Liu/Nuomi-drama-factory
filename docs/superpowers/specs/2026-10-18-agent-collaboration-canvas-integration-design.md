# 真实 Agent 协作与构思／分集画布接通设计

日期：2026-10-18。状态：核心方向及群聊触发规则已获用户确认；本补充设计待书面审阅，尚未实施。

## 1. 已确认方向与范围

以 2026-10-13 Agent 画布 PRD、2026-10-16 专业 Agent 工作合同与画布交互规格、2026-10-17 剧本及导演生产节点规格为基线。此次补齐实际协作、成果落图与画布作用域，不重新设计产品主题，也不把固定流水线包装成 Agent。

主创调度专业 Agent；多个 Agent 可以常驻同一画布的群聊。常驻表示成员身份和会话参与记录持久化，不表示后台持续推理或每条消息调用全员。仅在主创明确调度、用户点名或任务相关的定向唤起时调用对应角色。用户可以选中节点或内容组进行局部委托。

构思画布可以直接创建资产出图节点；导演工作空间属于对应集画布。最终仍须完成新项目整集真实成片验收，当前已有 API 生成产物只作为可复用证据，不计为新交互路径验收。

## 2. 群聊与真实协作

群聊顶部显示当前画布、主创及常驻成员，成员可展开查看职责和已接入能力。主体显示用户消息、真实 Agent 回复与任务卡。任务卡关联负责人、目标、输入版本、执行范围、状态和可定位的成果。模型响应、工具执行、画布写入和任务交付分别呈现。

- 普通消息由主创承接；纯讨论不自动启动媒体任务。
- 用户 @ 某专家时由该专家承接；主创可读取其交付，是否继续协调由当前任务决定，不额外强制再调用一次主创。
- 主创分工时建立真实子任务，各专业 Agent 使用固定的角色配置、相关输入和工具能力执行。不能用一次通用模型回复伪造多个角色的独立执行记录。
- “任务相关”由主创或已授权任务的显式依赖／交接事件决定；记录触发理由、目标角色和事件身份。全员不轮询每条消息，也不因某个 Agent 发言而自动全体回复。
- 专家可提出邀请建议；主创在原任务范围内决定是否委托。重复事件不重复唤起，同一议题无新增依据时收敛并交付，不无限互邀。

无依赖的专业任务可并行；有依赖时等待真实上游成果。一个成果的同一字段由协调者合并差异后提交，不能按最后发言覆盖。超出已授权范围的故事改动、共享资产替换或付费操作列出影响；已有明确授权不重复询问。

任务没有对应工具能力时明确显示“可提供方案，暂不能执行”，不降级为隐藏调用旧流程并宣称专家已完成。

## 3. 画布身份与局部委托

项目保留唯一构思画布、每集唯一主画布以及自由画布。前端与服务端均使用完整画布身份（项目、画布 ID、类型、关联分集），禁止用缺省 E01 代替未知集数。

选中节点或内容组后，用户可交给主创或点名专家。发送时冻结选区内节点、业务对象及版本；后续改变选区不会改变已提交范围。视觉分组只组织工作，不决定剧情顺序或自动执行全部组内节点。完成后在原位置交付新增草案或替换候选，不移动其他内容。

每个画布恢复自己的群聊、输入草稿与任务；切换画布不停止原任务，也不能使回执写入当前新画布。跨画布引用显示来源与版本；跨画布修改必须在任务中明确目标范围。

## 4. 构思画布与资产出图

用户从想法、完整剧本或素材开始。主创按目标调用立意、故事、角色或场景等专家。文档写入后须生成对应可操作的画布成果，不能只藏在旧表单或文档列表里。

人物／场景设计任务交付一个内容组：设定内容、关联的资产出图节点及所需参考。出图节点显示对象身份、设计版本、有效风格、模型、输入引用、生成动作、候选与错误；直接操作和 Agent 调用走同一个命令合同。

新资产尚无基础版本时，以设计对象为来源生成候选；已有资产的变体节点固定基础资产及版本。不能要求先有成图才能建出图节点，也不能以同名文字猜测角色身份。

节点创建不自动产生付费请求。用户已授权出图时，Agent 可以在同一任务内生成并把真实结果写回该节点。失败保留设定和输入；结果未知先核对原请求。查看、比较和采用节点候选，与“保存为项目共享资产”是独立动作。发布后各集引用固定版本，后续变体不静默改变旧集。

复用现有图像生成节点与角色／场景正式生成能力，增加缺失的对象及版本绑定和结果投影，不另造一套资产真相来源。道具遵守当前导入能力边界，未接通的生成能力不展示为可执行。

## 5. 分集交接与导演工作空间

主创依据内容提出分集、顺序和归属。确认分集后，服务幂等建立或复用对应集画布；用户明确要求创作 E01 时不重复询问同一归属。交接携带来源构思内容、采用剧本版本和共享资产引用，返回可点击的目标集画布及落图回执。

E01 剧本与导演空间绑定 E01 的真实身份。导演空间在该集主画布创建和编辑；构思及自由画布可以保留指向它的只读引用卡，点击定位到对应集，不能嵌入一个默认读写 E01 的编辑器。其他集同理。

上述限制仅针对分集导演空间，不剥夺构思／自由画布的独立创作、生成、预览和导出能力。非分集作品以项目及画布身份作为任务范围，分集身份为空，继续使用自身内容和媒体节点；需要关联分集时显式交接，不能自动伪造 E01。

导演读取采用稿和有效创作约定，按内容委托分镜、站位、摄影、灯光、表演或美术专家。各专家提交有来源的专业成果；导演融合为共享场景调度及组分镜，真实任务记录关联到相应成果。无需每个镜头调用所有岗位。

剧本节点、导演空间、场景调度、组分镜、视频及声音剪辑是同一集的可编辑内容和投影视图，不另存互相漂移的副本。采用方案、开始媒体制作和正式导出保持独立；已授权的范围内正常推进，不逐岗位重复确认。

## 6. 实现边界与旧链路处理

复用现有角色目录、委托、任务回执、文档版本、资产、导演领域模型、媒体适配器及画布投影。补齐主创到专业子任务的实际调度、画布作用域合同、资产节点绑定、分集交接和统一交付记录。

旧脚本创作／导演服务可作为具体工具被专业 Agent 调用，但用户目标和创作分工不能被隐藏的固定批流程接管。新入口不得直接跳过专业委托、在画布外人工补资产后回填一个完成标记。历史数据保留可读和来源；旧入口迁移到新作用域后不得继续允许错集写入。

新 Agent／画布链禁止把 `director_production` → `production_batch.run_batch` 整批入口包装为单个工具或幕后执行器。允许复用的是可独立调度、固定输入、查询回执并记录输出的领域操作。真实验收须检查操作轨迹，确认专业子任务及组级制作命令实际发生；供应商为整组内部划分物理视频片段仍由正式组服务负责。

既有错误归属节点不按名称自动迁移：依据可靠的分集与对象身份建立迁移提案；同一业务对象在其他画布留下引用，目标集建立正确编辑视图。无法确定的历史节点标明待关联并阻止错集执行，不删除用户内容。

风格与音频也纳入有效输入版本：项目风格变更不悄悄改已采用导演快照，需展示差异并产生受审查的新版本；视频原生声音或外配策略在生成前明确，合成缺少声音依赖时不能提前宣称制作条件齐全。此次发现的古装快照和音频缺口必须在制作验收前处理。

## 7. 恢复与冲突

父任务、专业子任务、工具调用、成果版本和投影回执相互关联。停止禁止后续准入和成果应用，保留已提交调用与已完成成果。未知提交先查原回执，禁止自动重复扣费。模型完成但落图失败显示写入失败，可幂等恢复，不能再次调用模型补偿投影。

源版本改变时保留原任务输入和候选，标明过期与具体差异；不强制覆盖人工修改。一个失败子任务不阻止无依赖的任务；主创汇总实际完成、失败和未满足项，不能用聊天总结取代成果检查。

## 8. 交付顺序与验收证据

按同一闭环落实：作用域与群聊合同 → 真实专业委托和成果投影 → 构思资产出图 → 分集交接与导演协作 → 媒体及交付。各项不是独立演示页面，最终须在同一个项目中贯通。

1. 新建项目，验收目标明确包含人物与场景设计等至少两类专业工作，从构思画布发出目标，验证相应专业角色的真实调度及调用证据。普通单专家任务不得为满足验收数量而额外调度；无关角色不调用，重复交接不重复唤起。
2. 角色与场景成果形成可编辑的设定和出图节点；从节点真实调用已配置的 Grsai，结果回写、刷新可见，来源与版本正确。
3. 确认 E01 后建立或复用 E01 主画布；导演空间在该集编辑，构思画布提供引用。E02 及自由画布不会缺省操作 E01。
4. 选中节点或内容组点名专家，交付限定在该范围；可看到实际输入、专业贡献及成果，选区外内容不被修改。
5. 验证切换画布、刷新、重复回执、人工并发修改和停止后的迟到结果，不串画布、不重复生成、不覆盖已有成果。
6. 在对应集画布通过真实 Agent 调度生成分镜与 MiniMax 视频，声音策略与素材依赖齐备，正式导出整集；检查实际文件、时长、内容、对白音轨及播放。记录质量缺陷，不以测试通过或 HTTP 200 代替成片验收。

验收不能以外部脚本逐项手工串 API 代替用户路径。API 可用于诊断和核对，真实创作动作必须由产品入口及受控 Agent 工具完成。没有运行过的岗位、缺失素材及未完成环节均明确标注。

## 9. 自检与待审边界

已核对：常驻不等于全员调用；专家调用与角色展示区分；新增草案与替换采用区分；构思生成与资产发布区分；业务对象唯一性与画布投影区分；分集导演编辑与跨画布引用区分；任务完成与媒体交付区分。本文无占位需求，不改变已有模型配置和保存的并发策略。

用户审阅本补充设计后，进入 writing-plans，将各合同、迁移和验收拆成明确实施任务。本文不声明功能已实现。
