# 剧本专用知识图谱五集分组设计

## 背景

现有批量剧集导入把新增文本交给 Cognee 默认 `cognify()`。约 31 万字的 E2–E30 会先形成 29 个数据项，再被 Cognee 切成文本块；每块分别执行图谱抽取与摘要。DramaClaw 又将 LLM 并发限制为 2，导致一次批量导入产生大量碎片化请求，并让“剧本入库”同步等待完整图谱。

本设计用面向分集剧本的专用抽取管线替代批量导入中的默认 `cognify()`。目标是保留增量、安全切换和失败恢复，同时将 E2–E30 的主要 LLM 请求收敛为 6 次。

## 已确认决策

- 按连续集号分组，每组最多 5 集。
- E2–E30 形成 6 个组，并允许 6 组同时执行。
- 每组只执行一次 DeepSeek 结构化图谱抽取。
- 成功组保留检查点；重试时只执行失败组。
- 使用剧本专用抽取器，不使用 Cognee 默认逐块 `cognify()`。
- 全部组成功并完成本地合并后，才原子切换正式图谱。

## 数据流

1. Episode import repository 产生本次发生变化的剧集集合及目标 source revision。
2. 分组器按集号排序，切成最多 5 集的连续组。集号不连续时立即结束当前组，避免把缺失集隐藏在同一上下文中。
3. 每组构造一个请求，正文使用明确的 `EPISODE_START/EPISODE_END` 边界，保留集号、标题与原文，不做 Token 固定长度二次切分。
4. 六个组通过同一批次并发执行；每个组输出严格结构化的角色、身份、场景、道具、事件和关系，并为每项保留来源集号。
5. 本地合并器使用稳定键去重并合并来源：
   - 角色、场景和道具使用规范化名称与类型生成稳定键；
   - 事件使用来源集号与事件序号生成稳定键；
   - 关系使用起点、关系类型、终点与来源集号生成稳定键；
   - 同名但属性冲突时保留别名、冲突属性和来源，不发起额外 LLM 请求。
6. 合并结果批量写入候选 Cognee runtime；Embedding 独立批量执行，不通过文本 LLM。
7. 全部写入成功后，沿用现有 revision、pointer journal 与原子激活协议切换正式图谱。

## 分组与增量规则

- 分组输入只包含本次新增或覆盖的剧集，不重新抽取未变化剧集。
- 最大组大小固定为 5，不允许因上下文窗口更大而自动扩大。
- 例如 E2–E30 分为：E2–E6、E7–E11、E12–E16、E17–E21、E22–E26、E27–E30。
- 若输入为 E2、E3、E8、E9，则分为 E2–E3 与 E8–E9。
- 单集导入使用同一管线，仅形成一个组。
- 覆盖剧集在候选图谱中删除该集旧来源产生的节点/边贡献，再写入新结果；共享实体的其他来源贡献不得被删除。

## 并发、检查点与重试

- 一个导入批次最多同时运行 6 个分组请求。
- 分组检查点键由项目、目标 revision、首尾集号和内容哈希组成。
- 检查点只接受 schema 校验通过且内容哈希匹配的结果。
- 网络错误、429 和 5xx 仅重试对应失败组；成功组不重发。
- 结构化输出校验失败属于该组失败，可在修复提示或模型配置后单独重试。
- 用户取消时停止未开始及正在等待的组，保留已成功检查点供下次续跑。

## 进度与可观测性

任务中心显示以下阶段和粒度：

- 准备分组：`已识别 29 集，共 6 组`。
- 抽取：`已完成 3/6 组`，并列出运行中与失败组的集号范围。
- 合并：显示实体、关系和冲突计数。
- Embedding：显示已写入批次数与总批次数。
- 激活：显示目标 revision。

每组记录开始时间、结束时间、请求耗时、重试次数、输入字符数和输出项目数，但不得记录 API key 或完整敏感响应。单组超过 5 分钟时标记为慢请求并允许取消，不把整个任务伪装成固定百分比卡住。

## 错误与事务语义

- 任一分组失败时，不激活候选图谱，也不重复调用成功组。
- 合并、Embedding、候选写入或指针激活失败时，正式图谱保持原 revision。
- 剧集正文入库与图谱状态分别呈现：正文可先完成导入；图谱显示“索引中”或“索引失败，可重试”，不阻塞剧集页面使用。
- 重试必须校验 source revision；正文已再次变化时，旧检查点失效并重新分组。

## 兼容边界

- 现有图谱读取、搜索、角色构建和场景构建接口保持不变。
- 旧项目的既有 Cognee 图谱无需立即迁移；首次发生剧集变更时使用新管线生成候选 revision。
- 默认 `cognify()` 仍可供非剧本文档或维护工具使用，但 episode import 不再调用它。
- 当前 DeepSeek 普通文本运行时继续作为模型与凭据来源，不新增独立密钥配置。

## 测试与验收

- 单元测试：连续分组、非连续分组、最大 5 集、单集、稳定检查点键、本地实体/关系合并及来源保留。
- 并发测试：6 组可同时进入执行器，峰值不超过 6。
- 重试测试：部分失败后仅重发失败组；内容哈希或 revision 改变后不得复用旧检查点。
- 事务测试：任一后续阶段失败时正式 pointer 不变；全部成功后只切换一次。
- 集成测试：E2–E30 只产生 6 次主要结构化 LLM 调用，不调用 Cognee 默认 `cognify()`。
- 可观测性测试：任务进度包含组数、集号范围、失败组与慢请求状态。
- 性能验收：在上游服务正常且无 429 的条件下，E2–E30 图谱构建目标为 1–5 分钟；剧集正文入库不等待图谱完成。

## 非目标

- 本次不重做图谱查看器和搜索 API。
- 不用单次百万 Token 请求处理整本剧本。
- 不通过提高固定 Token 分块尺寸继续修补默认 `cognify()`。
- 不在本次引入新的模型供应商或计费协议。
