# MiniMax H3 两阶段导演提示词编译器设计

## 背景与目标

当前叙事组视频已使用 MiniMax H3 官方三字段外形，但导演提示词仍由一个宽松的通用生成步骤直接产出。它缺少精确时间线、镜头幅度与速度、首尾帧差异路径、对白表演节奏和付费生成前质量门禁，容易形成空泛运镜与内容动作不足。

目标是将提示词链路改为“两阶段导演编译器”：第一阶段生成可验证的结构化镜头计划，第二阶段由确定性代码编译成 MiniMax H3 官方 wire prompt。系统必须保存并展示真正提交给 RunningHub 的最终提示词，便于逐次复盘。

本设计以 MiniMax H3 官方 `h3-prompt-writing` Skill 和 `base-en.txt` 为格式与镜头语言依据。

## 现状问题

- 当前规则只要求 2–3 个连续动作，没有按时长建立可检查的动作节奏。
- 运镜缺少“类型、幅度、速度”以及景别、机位、焦点和构图终态。
- I2VA 过度避免复述首帧，缺少必要的风格、身份、空间和构图锚定。
- FL2VA 只要求抵达终帧，没有显式描述首尾差异、物体状态变化及逐步收敛路径。
- 对白在生成结构化描述后追加，导演模型无法安排开口、表演、停顿和口型时序。
- 相邻 Beat 合成首尾帧时只形成简短起点和终点描述，缺少动作桥与空间接力。
- 优化器仍依赖 NewAPI 文本路由。
- 当前 manifest 已保存 `entries[].segment.prompt`，但前端没有展示入口。

## 两阶段架构

### 阶段一：结构化导演计划

导演 LLM 接收：

- 当前视频单元包含的 Beat、时长和叙事意图；
- 首帧和可选尾帧的视觉事实与差异摘要；
- 人物身份、服装、道具、场景、屏幕方向和光线约束；
- DirectorWorld 的相机、演员站位和道具状态；
- 前后镜头连续性摘要；
- 对白、说话者、语气及对白源。

输出为严格类型化的 `H3DirectorPlan`，至少包含：

- 模式、总时长、视觉风格和连续性锁；
- 单镜头或多镜头决策；FL2VA 默认单镜头，除非叙事明确要求切换；
- 每个镜头的起止时间、景别、角度、焦点和构图；
- 运镜类型、方向、幅度和速度；
- 按时间排列的动作节拍：建立、准备、执行、反应/收势、终态锁定；
- 人物表演、口型和对白时间；
- 环境声、动作声和非画内音乐计划；
- FL2VA 的首尾差异清单和每项差异的收敛动作。

导演 LLM 通过项目统一文本模型抽象调用，不依赖 NewAPI。模型不可用时仅允许使用经过质量门禁的确定性模板；无法形成合格计划时停止，不提交付费视频任务。

### 阶段二：确定性官方格式编译

编译器将已验证计划转换为 MiniMax H3 官方提示词：

1. 按模式生成精确的 Picture 对齐首行；
2. 生成 `integrated_multimodal_description`；
3. 生成 `overall_soundscape`；
4. 生成 `non_diegetic_music`。

编译器负责字段名、顺序、空行、时间格式、Shot 编号、稳定 speaker ID、原文对白和语言标签。LLM 不直接控制 wire 格式。

I2VA 使用“首帧锚定 → 动作启动 → 连续发展 → 结果/反应”。FL2VA 使用“首帧状态 → 可观察中间变化 → 差异逐项收敛 → 尾帧终态锁定”。运镜自然写入镜头动作，表达类型、幅度与速度，不堆叠标签。

## 时间与镜头规则

- 视频单元时长以已保存视频方案为准，并转换为 H3 合法帧数后回算实际时长。
- 结构化导演计划必须使用实际时长，尾帧对齐时间必须与最终帧边界一致。
- 动作节拍必须覆盖全时长，不允许全部动作挤在开头或结尾。
- 默认每 5 秒最多一个主要动作和一个反应动作，避免高动作密度造成形变。
- FL2VA 默认单镜头连续运动；I2VA 只有在引入新信息且时长允许时才使用切镜。
- 相邻 Beat 配对时，左 Beat 是起始状态，右 Beat 是目标状态；导演计划必须解释姿态、道具、位置、视线和构图如何连续变化。
- 对白时间必须落在对应视频单元内；跨切镜对白使用官方连续标记，结尾截断使用官方截断标记。

## 质量门禁

付费提交前运行确定性检查：

- 官方字段、顺序和 Picture 对齐格式正确；
- 时间连续、递增且不超出实际时长；
- I2VA 包含首帧锚点和后续变化；
- FL2VA 每个首尾差异都有可观察的中间动作并在尾帧前收敛；
- 每个镜头包含有效构图和动作，动态镜头包含运镜类型，必要时包含幅度和速度；
- 人物、服装、道具、空间方向和场景约束无冲突；
- 对白原文未改写，speaker ID 稳定，口型与表演存在时间安排；
- 不凭空添加文字、UI、标志、人物、道具、粒子或场景；
- 动作密度未超过安全阈值；
- 禁止仅用“镜头缓慢推进、人物自然动作”等空泛描述通过。

失败时返回具体问题并停止 RunningHub 提交。导演计划可按有限次数自动修复；超过次数后要求人工调整。

## 提示词复盘与可见性

### 页面入口

在“镜头 → 叙事组 → 组合视频”结果卡中增加“生成提示词”按钮。点击后打开抽屉，按视频单元展示：

- Beat 范围、I2VA/FL2VA 模式、实际时长；
- 首帧和尾帧缩略图；
- 结构化导演计划；
- 最终提交给 RunningHub 的完整 wire prompt；
- 提示词 profile ID/version、文本模型、工作流 ID和 provider task ID；
- 质量门禁结果与警告；
- 一键复制和下载 manifest。

页面明确区分“原始 Beat 提示词”“导演计划”和“最终提交提示词”，避免复盘错对象。

### 持久化入口

最终视频旁继续保存：

`videos/epNNN/narrative_groups/<group_id>_r<revision>.manifest.json`

manifest 中每个 `entries[].segment` 保存最终 wire prompt，并新增导演计划、profile 版本、输入摘要、质量报告和生成参数快照。接口将这些安全字段转换为可读 URL/JSON 返回前端，不暴露密钥、Authorization 或完整服务端配置。

任务中心调试信息只保留 manifest 链接和安全摘要，避免复制大量提示词或泄漏凭据。叙事组结果卡是主要复盘入口。

## 缓存与版本

- 提示词缓存键包含导演 profile 版本、编译器版本、模型 ID、实际帧时长、首尾帧哈希、Beat 内容和 DirectorWorld 上下文。
- 官方规则、导演 schema 或编译器改变时提升版本，旧缓存自动失效。
- manifest 永久记录当次 profile 与编译器版本，后续升级不改写历史结果。

## 错误与回退

- 统一文本模型不可用：尝试确定性模板并重新通过质量门禁。
- 模板无法满足复杂 FL2VA 或对白时序：任务停止，提示需要人工调整，不提交 RunningHub。
- DirectorWorld 数据缺失：允许基于首尾帧和 Beat 生成，但在质量报告中标记约束来源不足。
- 官方格式编译失败：视为内部错误，不使用未编译草稿。
- 不回退到 NewAPI，不回退到无提示词或旧低质量提示词。

## 测试与验收

- 官方 I2VA、FL2VA 示例结构具有黄金测试。
- 运镜类型、幅度、速度，首尾差异收敛和时间边界具有契约测试。
- 对白原文、语言标签、speaker ID 和跨镜头规则具有契约测试。
- NewAPI 文本路由不再被 H3 导演优化器引用。
- 质量不合格时 RunningHub transport 不会被调用。
- manifest 保存最终 wire prompt、导演计划、版本和质量报告。
- 前端结果卡能查看、复制和下载实际提交提示词。
- 历史 manifest 缺少新增字段时仍可播放视频，并显示“旧版本无导演计划”。

## 非目标

- 不在本次工作中训练或微调视频模型。
- 不承诺用提示词修复参考帧本身的身份、构图或画质问题。
- 不自动修改用户对白文本。
- 不把 RunningHub 密钥、节点凭据或私有工作流 JSON暴露到前端。
