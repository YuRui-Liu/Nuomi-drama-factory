# Agent、节点与画布创作工作空间 PRD

日期：2026-10-13

最近更新：2026-10-16

状态：V1.1 已获用户整体批准，V4 交互原型已审阅。2026-10-16 专业 Agent 与全链路增量已逐节讨论确认，汇总为本文第 15 节；整合后的书面规格已获用户整体确认。接续工作见[增量实施计划](../plans/2026-10-16-professional-agent-node-integration.md)。本轮仅更新计划，不据历史开发授权自动恢复实现。本文优先于旧技术设计与实施计划中不一致的产品定义。

## 1. 产品目标（已确认）

将创作过程变为以 Agent、节点、画布为核心的持续协作。用户通过 Agent 表达意图，通过节点查看、编辑和运行创作内容，在画布中组织作品。支持不同题材和不同创作目的。

完全舍弃当前切页规则流水线，删除相应功能和专属逻辑。不能只隐藏导航，也不能把旧阶段横向排列到画布后继续施加阶段门禁。

沿用当前视觉风格、基础画布交互与节点专业能力；保留资产中心、基础资产与变体、手法库、风格库。删除旧流程与保留专业创作能力分别评估。

## 2. 三种创作入口（已确认）

| 入口 | 用户已有内容 | 创作方式 |
| --- | --- | --- |
| 想法起步 | 创意或创作目标 | 与 Agent 探索故事、资产和表现方法，逐步形成可编辑内容 |
| 剧本起步 | 已有剧本 | 导入后理解内容、组织创作与制作，允许用户随时介入 |
| 素材起步 | 图片、视频、音频或任意节点 | 自由添加、组合和局部委托，也可以扩展为完整作品 |

三种入口同等重要，进入共同工作空间，创作途中可以混用。自然语言与直接操作均为正式入口。

## 3. 工作空间与内容组织（已确认）

- 项目构思画布承载创意探索、完整剧本、总体结构和未分集素材；不要求先建集。
- 每集有独立主画布，集内自由创建、连接和编辑节点。
- 项目内允许创建多张不归属任何集的自由画布，承载探索、实验、素材组合或独立短片，也可直接生成、预览和导出。自由画布共享项目资产、创作约定和主创 Agent，使用与构思／分集画布相同的创作能力，不形成旧主线与自由区双轨。
- 项目资产中心管理跨集共享资产；临时素材不自动发布为资产。
- 从项目构思进入分集的内容记录来源及采用版本。源内容更新后提示差异，由用户或获授权的 Agent 主动采用，不静默同步。
- 默认按剧情片段或创作任务组织内容组，例如“雨夜追逐”“角色形象探索”“广告开场方案”。组内可混合文字、素材、镜头、声音及候选。
- Agent 可自动整理，用户可以拆分、合并、移动和折叠。分组不规定执行步骤，不要求组内全部节点执行，画布坐标不决定成片顺序。
- 默认展示可编辑的创作内容；生成参数、执行记录和来源按需展开。

分集由 Agent 根据内容提出方案，展示各集内容、顺序和已有素材归属，用户可调整边界和归属，确认后建立分集画布并关联内容与采用版本。也支持手动创建和组织。分集不构成继续创作或生成的前置条件，自由画布内容也可按需关联到分集。

跨集调整明确区分“移动到另一集”和“在另一集引用”。移动改变主要归属，保留来源、候选及历史产物，执行前展示对原集和相关任务的影响；引用保持原集不变，在目标集新增独立采用记录并固定版本，后续修改不自动影响另一集。存在运行中任务或引用冲突时提示，不静默改变正在执行的范围。

## 4. Agent 产品形态（已确认）

采用项目主创 Agent + 专业 Agent 局部委托。用户选择适合作品的主创 Agent，主创持续理解整体目标、结构及创作约定；某集或选中节点可委托其他 Agent，明确输入、修改范围和交付要求，结果回到对应画布。

内置与自定义 Agent 并存。用户可复制或新建 Agent，配置职责、创作方法、参考作品、可用手法、风格和技能。对话生成配置，用户通过可视化编辑查看、修改和试用。

Agent 长期配置与当前作品要求分开。一次作品的调整不自动污染可复用 Agent。不同 Agent 共享项目确认的事实，各自的方法和建议可以不同。

项目主创统一理解，各画布保留自己的对话和任务。切换画布时恢复该画布的讨论与任务上下文，各画布共享已确认的项目事实。引用其他画布时明确来源与范围，跨画布修改仍须符合授权。

管理方式采用“就近编辑 + 集中管理”：在 Agent 侧栏编辑当前 Agent，在项目中编辑创作约定；可复用 Agent 与创作模板有统一管理入口，并支持从当前创作中保存。资产、手法、风格保留各自的库入口。临时调整与保存为可复用配置明确区分，不能因编辑当前 Agent 而隐式修改其他项目使用的配置。

### 4.1 发布与复用（已确认）

首版“发布”表示保存到自己的可复用库，不扩展为公开市场。Agent 保存职责、创作方法、技能和默认偏好；创作模板保存对象定义、关系与规则，两者可以关联。

保存前展示包含内容及引用依赖，不默认带入项目剧本、媒体和运行历史。作为示例的素材由用户明确选择。发布形成版本，新项目可选用，已有项目主动选择升级，不静默更新使用中的配置。

## 5. Ontology 的产品应用（已确认）

用创作语言表达对象、关系及可执行操作，不要求用户学习本体术语。系统提供角色、场景、剧情、镜头、媒体等基础对象，Agent 配置明确其关注对象、关系和能力。

按需扩展：用户通过对话提出，或由 Agent 建议增加“线索”“商品卖点”等对象及关系。说明用途、属性和关系，经确认后用于项目。项目内验证成熟后，可以发布为创作模板供其他项目或 Agent 选用；更新不自动影响已有项目。

增加对象类型不必增加节点外观，优先使用现有节点承载。对象身份、版本、资产变体、画布节点和方案分支是不同概念。

资产沿用基础 + 可复用变体。采用记录明确基础资产、可选变体及版本；第二集更换或新增变体不改变第一集采用内容。

## 6. 项目创作约定（已确认）

约定记录内容、来源、适用范围和约束级别。用户可调整级别。

| 级别 | 行为 |
| --- | --- |
| 硬约束 | 用户明确锁定的事实或要求。发生冲突时说明冲突和影响，继续不受影响的工作；用户可批准例外或修改约定 |
| 创作偏好 | 风格、节奏、镜头倾向等。允许在某集、场景或节点范围内调整，不自动改变项目全局 |
| 草案设定 | 尚未确认的内容及 Agent 推测，不能自行升级为必须遵守的事实 |

Ontology 将约定与创作对象、关系及适用范围连接，支持各 Agent 共同理解作品和解释变更影响。

### 6.1 手法与风格引用（已确认）

手法库和风格库作为可引用的创作配置，可应用到项目、画布、内容组或选中节点。界面展示生效配置、来源和作用范围，局部可以覆盖或解除。Agent 将配置转化为具体创作要求，配置变化提示影响，不自动重生成已有结果。配置互相冲突时说明冲突，不静默叠加。

这些配置不等同于必须依序执行的节点模板，不因选择某个手法或风格自动启动付费生成。

## 7. Agent 行动与授权（已确认）

Agent 自动完成可修改的准备：理解内容、整理对象、搭建节点、提出剧情和分镜草案。付费生成、替换已采用内容、修改共享资产前集中展示操作及影响并确认。已明确授权的范围内不重复确认，方向不明确时询问关键问题，不恢复阶段审批。

新内容直接以草案节点进入画布，用户可立即编辑。对已有内容的修改保留原版，通过候选方案呈现，采用后更新。

局部修改采用“选中内容 + 必要依赖提案”。例如修改一个镜头的表情，Agent 检查相关提示词、参考和下游视频，提出最小修改范围；不默认重做整场戏，范围外内容保持原样，付费执行遵守授权。

### 7.1 任务交付边界

按用户指令确定目标、范围和交付内容，存在实质歧义时才询问。明确请求直接推进，并展示本次任务边界。例如“试两个角色形象”交付两个候选，不自行扩展为分镜或视频制作。

达到目标后交付，可以建议下一步，等待用户决定是否继续。交付物可以是设定、方案、素材、片段或完整成片，不强制每次任务推进到整集制作。

交付时展示实际结果及未满足项，“生成成功”不直接等于“任务完成”。例如“两套角色方案”生成且可查看后即可交付，不因用户尚未采用而持续运行；“20 秒含对白预览”缺少声音时标为部分完成，说明原因及可选处理方式。交付要求在委托时明确，有歧义才询问。

### 7.2 付费与预算授权

默认按批展示生成数量与预计费用，经确认后执行。用户可为具体任务授予预算，例如“在 50 元内完成这场戏的预览”。授权同时限定任务范围和费用上限，扩大任务或超出预算需再次确认；预算授权不自动包含替换已采用内容或修改共享资产的权限。

用户可随时停止后续提交，已发生费用保留记录。严格预算同时计入已发生费用和已提交未结算费用，新提交前计入其可确定的最大费用，重试同样占用预算，不能因尚未扣费而重复使用余额。无法保证费用上限时展示估算区间及不确定原因，暂停该项提交；用户可改用费用可控的方案，或单独授权这次不确定费用。不把估算上限描述为保证上限。

### 7.3 失败与重试

- 技术失败：仅在已授权的重试次数及预算内重试，未获得自动重试授权时询问用户。
- 提交状态不明：先查询或对账，不盲目重发造成重复付费。
- 创作效果不满意：针对审美、表演等问题先提出修改建议，再按已有或新增授权执行，不默认持续生成到 Agent 自认满意。

重试仍受原任务范围约束，不能借重试扩张创作目标。未明确授权自动付费重试时不自动重试；授权时明确次数和预算。授权界面的布局在原型中验证。

### 7.4 并发编辑与撤销

允许用户与 Agent 同时编辑。Agent 基于任务发起时的内容工作；用户修改同一内容时，Agent 结果保留为候选，展示差异供用户采用，不覆盖人工修改。移动节点和调整布局不阻塞内容结果返回。

Agent 一次委托产生的变更作为一个可撤销单元，默认整体撤销，也可展开选择局部变更。例如“调整这场戏的节奏”涉及多个节点，用户无需逐节点撤销。保留用户之后独立做出的修改；撤销与后续修改冲突时提示具体内容，不以整张画布回滚覆盖其他工作。

撤销保留已生成媒体、生成历史与费用记录，不表示退费或取消已提交的外部任务。

### 7.5 运行、停止与恢复（已确认）

- 切换画布或关闭页面，任务继续运行，重新打开后恢复进度与结果。
- 停止任务立即阻止后续提交；已经提交的任务尽可能取消。无法取消时明确展示状态，返回结果保留，但不自动继续下游。
- 部分失败定位到具体节点，保留成功产物，不阻塞无依赖的其他创作。
- 继续执行复用有效结果；原授权仍有效时继续，输入、任务范围或预算变化时展示差异，必要时重新确认。
- 节点展示局部状态，Agent 侧栏汇总本次委托，支持直接定位需要处理的内容。

停止、撤销和放弃候选分别表达执行控制、内容变更恢复和方案选择，不互相隐式替代。

## 8. 候选与方案分支（已确认）

单节点候选默认收纳在对应节点内，可展开对比，也可拖出成为独立创作分支。明确展示当前采用结果；采用新候选后保留旧结果历史。

对一整组尝试新方向时，建立整组方案分支。例如“雨夜追逐更悬疑版”关联对应剧情、镜头、画面与声音，保留当前方案。用户可整体比较和采用，也可挑选局部结果；混用出现事实、角色或素材不一致时，提示具体影响。

候选与分支不是必须逐项清空的审批队列，也不意味着生成更多付费内容的默认授权。

## 9. 预览与修改闭环（已确认）

预览直接关联创作节点。用户播放片段并暂停在某个时间位置，可以定位相关镜头、素材和声音，直接向 Agent 描述修改要求。一个时间位置可能关联多个对象，界面应明确本次修改目标。

修改仍遵循局部范围、候选方案和付费授权规则，结果回到对应节点或方案分支。此选择不包含重建完整通用剪辑产品的授权。

### 9.1 核心创作旅程（已确认）

用户将剧本和角色图拖入项目自由画布，提出“先试做雨夜追逐的 20 秒片段”。主创 Agent 明确任务目标，调用专业 Agent，将相关草案组织为内容组。用户直接调整镜头，在预算范围内授权生成。

预览时用户暂停并提出“这里的表情更克制”，系统定位相关节点，提出最小修改范围，生成候选供比较。用户也可要求“整场再试一版更悬疑的”，形成组级方案分支。满意后直接导出，或将内容关联到第一集；全程无需进入阶段页面。

这是用户确认的示例旅程，不是所有创作必须依次执行的步骤。想法起步、已有剧本和素材探索均可进入同一创作空间，按本次目标决定交付范围。

## 10. 功能去留边界（已确认）

以下产品边界已获用户确认，后续文件级删除须依据真实依赖关系落实。

| 处理方式 | 产品范围 |
| --- | --- |
| 保留 | 当前视觉与专业节点能力、资产中心基础／变体、手法库、风格库、必要项目／账户／模型管理 |
| 融入画布与 Agent | 剧本编辑、分镜组织、生成参数、图像／视频／声音制作、质量检查、局部批量操作、合成预览与导出、任务进度与费用记录 |
| 删除 | 剧本／分镜／视频／音频／合成等旧阶段工作台与导航、阶段解锁和完成度规则、固定顺序推进、旧阶段批量生产与按阶段重跑、旧主线与自由区双轨、向主线提交／回填／同步及专属投影、仅服务旧阶段的执行入口 |

批量操作保留：用户可以选中多个节点统一生成或修改，由本次目标和依赖决定执行范围。删除的是绑定旧阶段规则的批量流水线。不能只隐藏入口并在后台继续运行旧阶段引擎；共享专业能力需接入统一创作方式。

删除功能不等于删除历史用户数据。此前确定面向新项目、旧项目不自动迁移，继续保留该约束；新 PRD 不承诺旧流程兼容执行。

## 12. 产品验收（根据已确认需求整理，待整体审阅）

### 12.1 三入口场景

| 入口 | 场景 | 验收条件 |
| --- | --- | --- |
| 想法 | 探索两套悬疑开场，暂不制作视频 | 无需建集；方案可编辑、比较与保留；不启动未授权的媒体生成，不扩张为整集；推测不成为硬约束 |
| 剧本 | 导入完整剧本，只试做某段 20 秒含对白预览 | 原剧本和未选片段保持不变；付费前展示范围与费用；预览可定位相关节点；修改形成候选；缺少对白明确标为部分完成 |
| 素材 | 在自由画布拖入图片与音乐，制作氛围片段 | 无需剧本、分集或先发布资产；人工与 Agent 操作同一内容；不覆盖源素材；可保留音乐、只重做选中画面；支持直接预览与导出 |

共同验收：全程无阶段页面和前置门禁；实际交付可查看或播放；用户只完成当前目标；关闭页面后可恢复查看进度，停止后按授权继续，不承诺所有供应商任务支持断点续跑；局部修改不越界；共享引用不静默升级；专业节点与库入口沿用现有视觉和能力。产品验收需要真实交互与真实产物，不能只凭节点创建成功判定完成。

### 12.2 关键规则验收

| 场景 | 必须可观察到的结果 |
| --- | --- |
| 两集引用同一角色，第二集采用新变体 | 第一集引用与产物保持不变，第二集可查基础、变体与采用版本 |
| 自由画布与分集之间组织内容 | 移动和引用明确区分，展示影响，来源、候选及历史产物可追溯 |
| Agent 运行中用户编辑同一内容 | 不覆盖人工编辑，返回候选并展示差异；仅移动节点不阻塞结果返回 |
| 探索整组新方案，再撤销一次委托 | 旧方案仍可查看，支持整体采用和局部挑选；撤销不覆盖后续独立修改，不删除生成记录 |
| 多个生成任务同时占用预算 | 待结算费用占用额度；无法保证上限时暂停相关提交，单独授权前不执行 |
| 切换画布、关闭页面、停止任务、部分失败 | 恢复对应对话与进度；停止后无新提交，无法取消的任务状态明确；独立任务不被无关失败阻塞 |
| 复用自定义 Agent、模板及风格／手法 | 可看配置来源、版本与适用范围；项目临时修改不污染复用配置；版本升级不自动重生成 |
| 移除旧流程并检查现有能力 | 无旧阶段入口、门禁或隐藏阶段引擎；专业节点和保留库可实际使用；旧项目文件未被迁移或删除 |

以上为产品验收要求，不代表当前实现已满足。不得用模拟结果替代真实生成与播放验收。

## 13. 主工作空间交互结构（已确认）

沿用现有视觉、节点卡片和专业编辑器，本节确定信息组织与操作位置。

| 区域 | 内容与行为 |
| --- | --- |
| 顶部项目栏 | 项目名称、画布切换、资产中心、手法库、风格库；任务、费用和设置放在管理入口 |
| 画布导航 | 按项目构思、分集、自由画布组织，可收起，支持新建、搜索、返回最近位置；不显示阶段完成度 |
| 中央画布 | 创作主体，保留节点、连线和专业编辑器，按剧情片段或任务分组，候选默认收纳 |
| Agent 侧栏 | 当前画布的对话、委托进度与确认卡，明确显示选中内容及操作范围 |
| 按需展开区域 | 节点参数、候选比较、来源详情和预览，关闭后回到原画布位置，不跳入阶段页面 |

空白处可添加节点、上传素材或描述目标；选中节点／内容组后可直接编辑、运行或委托 Agent，默认带上选择范围。查看结果时可比较、采用候选和展开分支，并从预览定位回节点。切换画布后恢复各自视图位置、对话和任务状态。

### 13.1 局部委托交互（已确认）

1. 选中节点或内容组后，附近出现轻量操作入口。“交给 Agent”将选择带入侧栏输入框，展示如“已选 3 个镜头”的引用，支持逐个移除和定位。
2. 用户描述目标后，Agent 展示修改对象、保持不变的内容及必要关联影响。范围明确时直接准备草案。
3. 需要授权时，同一张任务卡集中说明生成内容、替换内容、预计费用及预算，支持调整范围后执行，不连续弹出多个确认框。
4. 节点展示各自状态，侧栏汇总该次委托；结果收纳为候选，可定位、比较和采用，交付时明确未满足项。新建内容按第 7 节以草案直接进入画布，对已有内容的修改保留原版。

发送后固定该次委托范围。用户随后选择其他节点，不改变正在执行的任务；改变运行中委托须显式调整，遵守已有授权与停止规则。

### 13.2 候选比较与采用（已确认）

- 节点默认显示当前采用结果并标注候选数量；新候选到达不抢焦点、不自动移动画布。
- 点击候选，在画布上就近展开对比区域，明确标记当前采用结果和各候选，支持查看差异、预览及继续修改。
- 采用只更新选定内容，下游受影响结果标记为可能过期，保留原产物，不自动付费重生成。用户主动点击采用即为明确操作，无冲突时不重复确认。
- 整组方案在组标题处切换，保持视图位置；浏览切换不等于采用。整体采用时说明更新范围，混用局部结果时提示不一致。
- 候选可拖出为独立分支；关闭比较后恢复原画布视图和选择。

### 13.3 资产中心与画布衔接（已确认）

沿用当前“基础 + 变体”的操作方式。

| 操作 | 交互与结果 |
| --- | --- |
| 引用资产 | 在资产中心选择基础形象或变体，拖入画布或应用到选中节点；应用前展示目标范围 |
| 查看引用 | 节点优先显示角色名／变体名，详情中查看采用版本、来源及更新提示 |
| 创建变体 | 从当前资产发起并描述差异，创建后明确选择是否应用到当前节点，不自动影响其他引用 |
| 保存为共享资产 | 将画布结果显式保存为新基础资产，或已有资产的变体／新版本，展示保存目标 |
| 采用更新 | 资产更新后，引用节点提示可用版本；比较后决定更新哪些引用，不自动重生成已有产物 |

变体表达可复用的差异，版本表达同一基础资产或变体的修改历史，保存目标应明确区分二者。用户直接确认的保存／应用操作不额外重复询问；Agent 未获授权时仍遵循第 7 节。

## 15. 专业 Agent 与全链路创作增量（2026-10-16 逐节确认）

本节来自本轮 brainstorming 的明确选择和分节确认。沿用第 1—14 节及现有恢复计划的产品基础，不另建创作体系。完整岗位契约见[专业 Agent 补充规格](2026-10-16-professional-agents-script-handoff-prd.md)及[生产交接契约](2026-10-16-manga-production-agent-contracts.md)。具体字段和节点适配仍需实现设计，角色配置存在不等于执行已接通。

### 15.1 Agent、节点与画布的关系

以 Agent／节点为中心，画布为创作内容与协作关系的承载形式。Agent 理解目标、读取上下文、调用节点能力、检查结果并交接任务；用户可选中节点直接委托，也可向主创下达完整制作目标。

专业 Agent 按需驻入，从团队入口选择或由主创调度。内容节点集中呈现剧本、分镜、站位、灯光、动作、表情及媒体；关联任务节点保留负责人、输入版本、进展、专业贡献和产物，过程默认收起，可展开、继续讨论或按授权重跑。不要求全部专家固定铺在画布上，也不为每个专业字段创建独立节点。任务节点是既有委派／运行记录的呈现，不另存一套执行状态。

新增成果按委托范围进入画布并继续已授权的下游任务；已有采用内容、人工编辑、共享资产及付费调用继续遵守第 7 节。没有采用替换授权时，修改保留为候选，不因“自动推进”静默覆盖。

### 15.2 完整专业团队与直接节点调用

提供创意师、主笔、剧本编辑、导演、分镜、站位、摄影、灯光、动作、表情、美术资产、连续性、图像执行、MiniMax 执行、声音、剪辑及交付检查等专业职责，由主创统筹。专业岗位完整可见、独立配置，实际参与由任务决定；不要求每场戏经过全部岗位或固定十八次调用。

主创负责目标、授权、预算、进展和最终交付；导演协调专业方案之间的创作冲突。各专家围绕同一对象与版本工作，专业贡献可追溯，实际生成使用协调后采用的方案。核心故事方向、用户硬约束发生冲突时提出关键问题。

| Agent | 对应节点能力要求 |
| --- | --- |
| 创意师、主笔、剧本编辑 | 读取与创建剧情／剧本，修改草案，对已采用内容提交候选 |
| 导演、分镜师 | 组织分镜，关联人物与场景，调用分镜拆分、生成及预览 |
| 站位、摄影、灯光师 | 读取空间关系，编辑专业设计，调用适用的场景、3D、图像和分镜能力 |
| 动作、表情师 | 编辑动作与表演，引用人物素材，生成局部预览或候选 |
| 图像、MiniMax 执行师 | 适配模型输入与参考素材，提交生成、查询状态、取回结果及按授权恢复 |
| 声音、剪辑师 | 调用音频、音乐、字幕和合成能力，组织时间关系、预览及导出 |

Agent 与用户手动操作使用同一套受支持的节点能力。每次调用固定目标节点、输入版本、修改范围和授权，执行后读取真实结果。缺少节点操作或接入时明确列为开发缺口，不能以提示词交付代替媒体完成。

专家可直接调用已经授权的能力，无须每次经过主创转发。MiniMax 执行师提供模型适配、参考组织和故障处理的专业服务；其他专家需要时委托，不把它设为所有视频调用的强制中转。

### 15.3 专业配置与目录体验

专业配置包含五项：工作方法、可调用节点能力、交付要求、参考与示例、协作规则。提供直接可用的预设，允许复制、修改、保存个人版本和项目固定采用；沿用已有版本系统。长期方法、本项目要求、本次临时要求分开。方法配置不能扩大运行授权。

从 Agent 侧栏或选中节点的“交给 Agent”进入目录，支持按职责和任务搜索，依据当前内容推荐专家。详情展示方法、真实能力、交付示例及输入要求；案例说明成片、提示词、素材与工作流的公开情况，不把案例效果作为本地能力证明。

状态区分可执行、缺少输入、模型或工具未配置、能力尚未接通。返回原画布时保留选择和视图，不要求用户先配置完整团队。

### 15.4 剧本按目标逐步展开

交接保留原始剧本节点、来源与版本，先建立内容结构和已有资产关联。按本次目标逐步展开相应分集、场景、分镜及专业任务，不在导入时强制生成全剧的全部节点。完整制作目标由主创持续推进全部授权范围；局部任务到指定成果为止。

原文事实、AI 补充、用户确认及采用结果明确区分。重交接比较差异，保护人工修改，复用不受影响的有效成果。

### 15.5 本体作为协作和检查的基础

复用第 5 节的稳定对象、版本与关系体系。专业语义包含：

| 层次 | 表达内容及作用 |
| --- | --- |
| 对象 | 人物、场景、剧情事件、分镜、声音、媒体，明确操作目标 |
| 状态 | 人物伤势、服装、持物、空间位置等随剧情时刻变化的状态 |
| 关系 | 参与、表现、引用、采用版本、由其生成，支持上下文与影响分析 |
| 操作 | 调整站位、设计灯光、生成视频、采用候选，声明输入、写入范围及交付 |
| 约束与证据 | 区分确认事实、创作偏好、推测和实际结果，支持冲突定位 |

画布节点是对象与操作的呈现；人物可以被多个镜头引用。各专家读取共同事实，只修改负责范围。结构检查不能替代实际媒体检查。

已定义类型和关系内可自动建立关联；不确定关联标为候选。新增类型、改变关系含义或将推测确立为项目硬事实须说明并确认。优先复用既有定义与节点外观，不强制为新概念新增卡片样式。

修改后主动解释影响，例如“涉及三个分镜，其中一个视频已生成，建议修改持物动作并重做相关片段”。明确直接依赖与推测影响，保留旧产物；在已有授权内处理，替换采用内容、修改共享资产或新增费用仍适用原授权规则。

### 15.6 分层检查与真实交付

专家检查自身专业成果及相关生成结果；导演协调空间、摄影、灯光、动作和表情冲突；主创检查整体目标及交付。问题定位到具体内容和任务，复用有效成果，在授权次数及预算内修正，不无限生成。检查深度随任务决定，不默认增加付费 ASR、反复 QC 或逐帧深审。

完整制作维护关联到节点的目标、依赖、授权、进度和未完成项。独立任务可以并行，用户可随时查看、编辑和停止。交付包含：

- 故事与资产：可编辑剧本、人物、场景及必要参考。
- 导演与专业设计：可编辑分镜及空间、摄影、灯光、动作、表情要求。
- 真实媒体：生成的图像、视频与声音，可追溯输入版本和执行记录。
- 成片：按明确顺序合成，满足任务要求的对白、音效、配乐、字幕，实际可播放和导出。

这些是成果依赖，不是强制切页或逐阶段批准。方案完成、任务提交、媒体生成、作品交付分别表达。缺少任何必要成果标为部分完成；状态不明先查询，失败仅阻塞相关依赖，保留成功结果。

### 15.7 统一工作空间与原型修订

中央画布承载内容及关联任务；现有 Agent 侧栏保留唯一主输入、当前范围和委托进展。选中节点可直接编辑、运行、委托专家或查看影响。参数、候选、来源和播放预览按需展开，可从播放位置定位相关创作节点。

保留现有视觉、专业编辑器、资产中心、风格库、手法库，以及构思／分集／自由画布。目录、制作进度、成片交付融入这一工作空间，不新增必须依次进入的页面。
