# 角色工作台与 Agent 出图闭环设计

日期：2026-10-04

状态：生成与修复机制、沿用现有软件视觉的角色交付台原型已获用户确认。进入实现计划阶段；功能尚未实现。

## 1. 目标与范围

将资产中心的角色操作收敛为一个工作台，减少重复表单与入口。用户先比较三套文字造型方案，选定、微调并确认后，一次生成完整角色设定图，再从原图定位裁切头像。首次生成不再依赖独立肖像。

采用已选方向 A：角色工作台加后台 Agent。方向 B 为固定流程的精简资产中心，异常主要依赖用户判断；方向 C 为覆盖编剧、美术、导演、后期的漫剧公司任务台，改造范围过大。本阶段以角色交付为边界，为后续部门协作提供明确的资产契约。

本阶段不新建公司级 Agent 调度平台，不要求将内部调用改为 MCP，也不改造视频生产、场景或道具流程。Agent 负责创作和检查，现有任务与服务负责执行、状态和保存。MCP 是否作为未来外部工具接口另行决定。

用户反馈包括操作繁琐和出图效率低；尚未测得渲染、排队、模型调用等耗时，不能将 Agent 化等同于性能提升。

## 2. 当前依据与兼容优先级

- `frontend/src/routes/_app/projects.$project/characters.lazy.tsx` 中并存基础资料、基础肖像、剧情选角、身份阶段等界面职责。
- `src/novelvideo/task_backend/runners/character_image.py` 的现有身份生成链路依赖角色 Portrait 或 Identity Portrait，没有独立肖像就报错。
- 既有剧情选角规格已经定义事实依据、三套提案、版本快照、候选检查与用户定角，应复用而非再建一份角色事实来源。
- 既有 identity_sheet_v3 为无头正面、完整背面、脸部特写三联图。本次新流程使用四区设定图；旧图片仍按原版本读取。

本规格对新角色工作台流程覆盖以下旧约定：首次先生成独立头像、三联版式、所有质量修复必须手动发起，以及首次质检通过即可自动采用。新流程允许最多一次有上下文的自动质量修复，但最终采用始终需要用户确认。既有入口和历史数据不做隐式批量迁移；旧入口应最终汇入工作台，兼容接口可保留。

## 3. 页面与用户流程

### 页面结构（以最终确认原型为准）

- 保留资产中心页头、角色/场景/道具/声线分类、统计条、左侧搜索筛选与角色列表，以及右侧角色标题栏。沿用现有组件和主题令牌：背景 #0D0E10、卡片 #14161A、边框 #2A2F37、强调色 #E5FF5C，不建立独立页面主题。
- 仅重组右侧角色内容区。取消身份、肖像、服装、剧情选角等分散操作标签，不使用固定三步向导，也不设置常驻右侧修改栏。
- 默认展示当前已采用形象与变体，变体条支持切换及新增。新增时填写名称和变化要求，区分换装/剧情状态与年龄/身份阶段；身份阶段不能仅作为服装变化处理。
- 完整设定图为主要内容，旁边显示小尺寸派生头像、来源说明与调整裁切入口。基础形象头像用于角色列表；采用变体只更新该变体的图与头像，不自动替换角色主头像。
- 三套方案在当前内容区展开，选中后直接微调。制作期间显示紧凑进度，允许切换角色并恢复现场；制作状态与已有资产可用状态分别表达。
- 处理方案或新交付时，旧已采用形象折叠保留，不在主区堆叠两个大图。新交付只突出“采用”和“提出修改”。修改意见直接针对当前交付，不强制重新三选一；原图、原方案与反馈继续作为上下文。
- 裁切面板支持拖动矩形、调整范围和实时头像预览；保存仅更新派生头像。待采用候选的裁切不会提前更新当前角色头像。
- 声音采用简洁条，显示当前声线、试听和更换；台词与声线设置按需展开，复用已有真实试听能力。人物资料、历史和修复记录通过次级入口展开。
- 最终确认原型：`.superpowers/brainstorm/44250-1791122291/content/asset-character-content-v2.html`。该文件是本地交互参考，不是实现代码；图像生成、审核与音频均未接入，单任务演示限制不是产品约束。

### 操作顺序

角色资料 → 生成三套文字造型方案 → 选择一套 → 手动微调或提出修改意见 → 确认方案并生成设定图 → 独立审核与受限修复 → 定位裁切头像 → 展示候选 → 用户确认采用。

主操作随状态变化，明确区分“确认方案并出图”和“采用角色资产”。方案确认不提前替换当前角色设计与头像。刷新页面可恢复当前步骤，避免重复提交。

## 4. 三套文字造型方案

三案共享原文明确事实、适用身份阶段与项目画风。差异集中在原文未限定的服装剪裁、配色、材质、发型和配饰等设计选择；头像外貌遵守明确设定，不通过改写年龄、物种或身份事实凑差异。

每套展示方案名称、设计摘要、具体造型、设计理由及事实依据。创作补充明确标记为创作选择。已有差异校验需覆盖实质视觉差异，不能仅通过文案换词。

若事实冲突或约束过强，无法生成三个有效方案，展示原因及已形成的有效内容；不得伪造三案成功。用户可调整创作空间后重新生成方案。

用户可直接编辑选中方案，也可提交自然语言修改意见。修改产生新版本，确认后冻结生成快照。已确认角色的换装和状态变化引用当前已采用头像作为身份依据；明确的年龄或面部变化按身份阶段事实解释，不静默替换其他阶段。

## 5. 四区设定图与派生头像

新契约命名为 `character_sheet_v4`，按从左到右固定语义排列：

1. 头像大图：完整可识别面容与发型，唯一清晰五官来源，留足裁切空间。
2. 正面身体图：无头部，完整展示服装、体型、手部和鞋履。
3. 侧面身体图：无头部，完整展示侧面体型、服装轮廓、配饰和鞋履。
4. 背面全身图：保留后脑与发型，不回头、不露面部。

提示词要求干净背景、足够区域间距与统一角色造型。无头区域采用干净的服装展示形式，不生成断颈、伤口、血肉、假人头或用遮挡物代替头部。受伤与污损只来自已确认的剧情状态。

不在规格中固定单一像素尺寸；沿用所选提供方支持的横向画布，并保存实际尺寸与布局契约版本。头像定位依据图像内容返回归一化矩形，不能盲目按固定百分比截取。

生成工具一次返回完整设定图。定位工具接收该图与区域语义，返回矩形、定位状态及依据；确定性裁切工具校验矩形边界并保存头像。派生记录关联原图版本、内容摘要、像素尺寸及裁切框。调整裁切框只产生新的派生版本，不调用图像生成。

定位失败、多个候选区域或裁切缺损时，展示原图与可调整的框，不自动重画整图。用户修正裁切后完成裁切有效性检查；没有有效头像的资产不能成套采用。

## 6. 后台模块与接口边界

| 单元 | 输入 | 输出与责任 |
| --- | --- | --- |
| 资料与快照服务 | 角色事实、阶段、风格、参考图、方案版本 | 持久化不可变上下文，复用已有事实存储 |
| 造型 Agent | 上下文、已有方案、用户修改意见 | 三案或更新后的选中方案，不自行采用资产 |
| 生成工具 | 已确认快照、版式契约、参考图 | 候选原图、实际提示词、提供方任务信息 |
| 审核 Agent | 候选图、原始依据、确认方案、版式契约 | 逐项检查、问题区域、证据、修复建议 |
| 修复 Agent | 完整修复上下文包 | 修订提示词、变更说明、保留项与问题对应关系 |
| 定位与裁切工具 | 候选原图、区域语义或人工矩形 | 可追溯的头像派生资产 |
| 采用服务 | 候选资产组、预期版本、用户确认 | 原子更新当前设定图、头像与设计引用 |

造型与修复可复用同一创作角色及其会话能力；审核保持独立判断上下文，不能直接采信修复 Agent 的自评。完整上下文必须显式重建，不以会话记忆作为唯一依赖。

接口复用现有项目权限、持久化任务、模型路由、取消及成本采集。Agent 不直接修改当前资产引用。任务输入保存路由与快照版本，重启和刷新不改变原任务依据。

## 7. 完整上下文修复与复查

每次修复提交必须包含：

- 原始依据：相关原文材料与出处、角色事实、适用阶段、项目画风、参考图片。
- 已确认要求：选中方案、用户微调意见、四区契约和应保留的正确部分。
- 失败结果：实际失败图片及其摘要、实际生成提示词、生成配置和版本。
- 审核反馈：稳定的问题 ID、具体表现、图像区域、违反的要求、依据及修复建议。
- 修复历史：之前的失败图、问题、修改动作、复查结果，以及重复出现的问题。

图片须作为可访问的图像输入提供，不能只交付路径字符串；材料缺失或引用失效时暂停修复并显示具体原因，不降级为空上下文重试。

修复 Agent 逐项形成“问题 → 修改 → 必须保留内容”的修复计划与新提示词。问题不能只靠追加通用负面词处理；如计划未对阻断问题形成有效修改，停止并交由用户处理。

复查接收修复前后图、同一份原始依据、修复计划及历史报告。每个旧问题记录已解决、仍存在或无法判断，同时检查新问题；语义相同的问题不能通过换 ID 避开重复判定。无法判断不等于通过。

首次生成后最多自动重新出图一次，即单轮最多两次图像生成。相同问题再次出现、修复仍不合格或检查无法完成时，停止自动质量修复并展示报告。额度是后端任务链约束，前端刷新、恢复或调用重试不能重置额度。用户后续显式重试创建新一轮任务，并继承原有修复历史。

技术重试沿用现有受限机制；提供方结果未知时先恢复或查询原任务，不盲目重复付费提交。单纯审核失败可重跑审核，单纯定位或裁切失败只处理派生步骤。

## 8. 状态、版本与异常

流程状态区分：资料准备、方案生成中、待选方案、待确认方案、出图中、审核中、修复中、待裁切处理、待采用、已采用、需处理、失败和已取消。原图、审核与裁切保留各自子状态，不能用“图片已生成”冒充整体完成。

每个候选资产组关联项目、角色、身份阶段、事实与风格版本、方案版本、提示词快照、原图、裁切框、头像、审核、修复链及任务 ID。

生成期间编辑资料或方案时，原任务继续按提交快照执行，但结果标记为基于旧方案，不能直接作为当前方案采用。重复提交幂等，并发采用校验预期版本。采用必须同时更新设定图、头像和对应设计；写入失败保留原资产组，避免头像和设定图属于不同版本。

质量审核不通过或不可用时不自动采用。沿用已有显式人工确认能力时，应清晰显示问题并记录原因；缺失图片、无有效裁切、权限与版本冲突不能绕过。取消后的晚到结果不自动恢复任务或更新当前引用。

已有角色和历史资产继续可读，主动重新设计才进入新链路。下游通过现有资产解析边界读取当前引用，旧引用不自动重建。与音色及角色阶段相关能力保持兼容。

## 9. 效率与验收标准

### 交互与耗时

比较改造前后的完成步骤、重复录入次数、首次候选就绪时间、模型调用次数和修复次数。分别记录排队、三案生成、图片生成、审核、定位裁切的耗时。现有资产详情切换和保存也测量请求与渲染耗时，再决定针对性优化；本规格不承诺未经测量的加速比例。

前端展示当前步骤、等待原因和可恢复错误，不要求用户手动依次触发多个后台工具。首次生成链路不包含额外的独立头像生成调用。

### 自动验证

- 无独立肖像的新角色可由确认方案直接生成四区设定图。
- 三案遵守共享事实，差异不是仅改措辞；人工修改进入冻结快照。
- 提供方收到头像、无头正面、无头侧面和完整背面的同一契约。
- 修复输入包含原文、参考图、失败图、实际提示词、审核问题与建议、历史记录；缺失必需材料不会继续生成。
- 修复复查逐项对照旧问题和新增问题；重复问题停止自动重试，恢复任务不重置一次修复额度。
- 头像派生可由原图和矩形复现；调整矩形不产生图片生成调用。
- 单独审核或裁切失败不会自动重绘原图。
- 刷新、取消、重启、重复提交、并发修改和采用失败不会造成资产版本混合或误采用。
- 历史三联图及原有角色、声线和阶段数据保持可读；服务端权限继续生效。

### 视觉与流程验证

使用有可追溯资料的角色验证三案选择、微调、四区生成、头像裁切及采用全过程；检查正侧身体无头、背面发型完整、唯一面容位于头像区、服装一致且没有异常断颈。以换装样例检查已采用头像的身份参考是否传入。

故障用例验证定位失败可人工调整、审核服务失败可独立重试，以及重复缺陷会停止。自动测试可使用固定样本与替身；真实提供方样例记录模型、调用次数、耗时及费用，文本规格通过不等于真实视觉质量通过。

## 10. 实现衔接

书面规格审查通过后使用 writing-plans 制定计划，围绕现有 character_visual、角色 API、character_image runner、资产解析和角色页面拆分工作。不覆盖工作区其他未提交修改。

实现顺序以完整交付链为中心：快照和四区契约 → 三案与确认 → 生成与独立审核 → 上下文修复 → 裁切与成套采用 → 工作台整合与回归验证。当前文档提交仅为设计成果，不代表功能已实现。
