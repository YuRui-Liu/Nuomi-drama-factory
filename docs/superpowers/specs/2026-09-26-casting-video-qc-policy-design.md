# 选角与视频生成：解除主观 QC 阻塞

日期：2026-09-26

状态：方案与书面规格均已获用户批准，已实施并完成针对性验证。

用户后续约束：前端布局、样式和文案变更必须另行确认。本次仅授权选角按钮禁用逻辑与对应测试，不改变导航、统计栏或页面视觉呈现；保留工作区内其他任务的界面改动。

## 目标

选角和视频生成仅因可验证的不可用条件停止。模型审美评价、语言描述充分性、无法判断以及复核服务故障，不触发自动重写、重新生成或下游阻断。已有可用产物持续可用，避免重复消耗 token 和生成费用。

## 已确认的证据

- `character_visual/casting_proposals.py` 将方案结构相似、少于三个候选（即使提供原因）加入拒绝列表；`casting_service.py` 最多生成两轮后将整个选角任务判为失败。
- `media_capabilities/video/h3_prompt_quality.py` 的 issue severity 目前只有 error，语言启发式检查与结构契约检查共用失败结果。
- `task_backend/runners/narrative_group_video.py` 在 guard/enforce 策略下，可因视觉复核失败或不可用阻断生成或交付。
- 本地 `shanhai_shiyi` 第一集 `group-07_r5.manifest.json` 的两份 quality_report 均为 passed，但 reference/generated 视觉复核均为 unavailable，technical_error 为 KnowledgeRuntimeError，manifest 状态为 quality_mismatch。此证据证明复核故障被计作产物质量问题，不证明该视频画面本身合格。
- 当前工作区已有大量未提交修改，实施必须在现状上做最小改动，保留其他修改。

## 方案选择

采用“硬错误阻断、主观 QC 仅提示”。全面关闭校验会放过不可消费输入；仅减少现有重试次数仍保留错误门禁，均不采用。

## 决策契约

| 分类 | 例子 | 行为 |
| --- | --- | --- |
| 可验证硬错误 | 文件不可读、媒体损坏、引用不存在、重复或错误对象 ID、provider 必需字段缺失、明确的帧数/时长协议不合法 | 阻断受影响对象，给出具体字段、证据和修复动作 |
| 完整性冲突 | 输入版本变化、引用哈希不符、并发修改、已确认身份与所用资产不对应 | 保留现有保护，不自动覆盖或采用失效资产 |
| 主观或启发式建议 | 方案差异度、构图/表演建议、自然语言是否充分、仅凭措辞推测的人设或剧情问题 | 保存 warning，不影响可用性，不触发自动修复 |
| 复核不可用 | QC 超时、服务异常、无法判断、缺少比较材料 | 保存 unavailable 或 unjudgeable，不视为媒体失败 |

判断以证据类型为准：确定性代码中的正则或关键词推断也可能只是建议；模型声称“严重”不能自行升级为硬错误。对既有检查逐项分类，不用统一吞异常或一律置 passed 的方式放行。provider 失败、取消、任务超时和租约丢失继续按真实任务结果处理。

## 选角流程

1. 保留生成、选择、编译、采用入口的输入与版本保护，统一其问题分类，防止生成成功后在选择入口再次被同类建议拒绝。
2. 一至三个结构可消费的候选可进入选择；候选差异不足、候选数量不足三个及推荐标记等非必需设计约定不导致整批重写。必要的唯一 ID 和编译必需字段仍校验。
3. 主观建议随候选保留并展示。用户正常选择和采用即表达选择意图，不再为每项主观 finding 强制逐项确认和填写 override reason；不得自动替用户采用候选。
4. 视觉 QC 默认不自动付费运行；用户主动发起的复核可生成建议。复核不可用或正在运行不应单独剥夺可用候选的采用能力；采用记录绑定实际候选快照，后续复核不得撤销采用。

## 视频流程

1. 将报告的“存在问题”与“存在阻断错误”分开；passed 表示硬契约满足，warnings 可同时存在。
2. 提示词的措辞、表演丰富度等建议不触发优化器重写。协议字段和必需引用仍在提交 provider 前验证。
3. 默认不自动运行付费视觉 QC；主动请求复核时，结果只形成建议。guard/enforce 仍保护硬契约，但不赋予语言或视觉模型否决权。
4. QC 不可用应被局部处理并记录，不吞掉取消、租约丢失或真实生成异常。
5. 可读取、可消费且硬契约满足的视频进入正常完成状态，保留其 warning/unavailable 报告供查看。前端、批处理和合成不得再将这些报告等同于失败。

## 重试与产物复用

- 主观建议：零次自动修复。结构问题：同一输入最多一次模型修复，即初次生成加一次修复；优先使用不调用模型的确定性规范化。
- 沿用现有缓存/manifest/任务记录，按输入版本、检查策略版本及结构错误签名记录修复预算；任务重试和服务重启不重置同输入预算。修复仍失败时保存结果并明确停止，不启动下一轮 QC—生成循环。
- 输入或策略改变可产生新检查键；用户明确要求重新生成可创建新的生成操作，不能由 warning 自动触发。
- provider 的网络重试与 QC 修复预算分开，不在本次改动中全面重构传输重试。
- 保留已生成的候选和视频。显式恢复旧 QC 阻塞任务时，重算问题分类并执行必要硬检查，优先复用已有产物；不批量把历史失败改成成功，也不因复核故障重新购买媒体生成。

## 实施边界

在现有选角校验与采用模块、H3 报告与优化器、叙事组视频 runner 及直接消费者内修改。复用已有存储，不新建通用审批平台。按需要更新报告模型、前端提示及生产说明，避免后端放行而前端仍阻断。历史报告缺少 severity 的条目依据明确的检查代码映射分类，不盲目当作 warning；无法识别的历史条目通过当前检查重新判断。

## 验证与验收

先用固定输出和本地 fixture 复现，不依赖付费模型或视频调用；每个行为修改先有失败回归用例，再验证修复：

- 选角仅有差异度或候选数量建议时，一次生成后可选择；通过选择、编译和采用入口不会再被同类建议拒绝。
- 主观 finding、复核未启动和复核服务失败不强制填写覆盖理由；实际缺失资产、错误身份和版本冲突仍拒绝。
- H3 仅有语言建议时不追加模型调用；非法协议或缺失必需引用仍在提交前拒绝。
- reference/generated 复核 unavailable 或主观不通过时，硬检查通过的已有视频可交付；取消和租约丢失不会被误判为 QC 故障放行。
- 同输入结构修复最多一次，重试任务及恢复运行不重置预算。
- 恢复历史 QC 阻塞时复用已有有效媒体，provider 调用次数为零；真实失败媒体不能误用。
- 前端、批处理和合成按可用状态消费带警告产物；运行相应后端测试和受影响前端测试。

验收结果同时报告状态变化和模型/provider 调用计数。付费端到端制作不是本次验证的必要步骤；若尚未执行真实生成，不宣称已完成真实画面质量验证。

## 规格自检

已检查范围、术语与状态语义：警告不等于失败，复核失败不等于生成失败；硬检查、输入版本保护和用户采用权保留。修复上限覆盖任务恢复，历史恢复为显式操作。不存在未决占位符；下一步是用户审查本规格，随后编写实施计划。
