# 创作工作室首版设计

日期：2026-09-26。状态：交互方案与原型已获用户确认，本文供书面规格审阅；尚未完成生产功能实现。

## 1. 目标与确认依据

在当前 NuomiDrama 项目中加入角色造型室、导演自定义、3D 预演、片头制作。四项均属于首版范围，按独立模块依次实现，共用版本、任务、素材引用和来源上下文。不能以原型或无后端的按钮替代正式功能。

用户已确认独立工作室与上下文快捷入口、角色候选与选择性更新、三种导演来源、默认不改剧情、模板加可选 AI 片头。后续明确增加角色动作片段时间轴，并提供片头布局参考图；v2 布局已确认。

原型：`.superpowers/brainstorm/3384-1790431797/content/creative-studios-v2.html`。它只用于交互讨论：背景、人物、动效与候选均为示意，生成和导出未接真实服务。原型中的 10 秒轨道、素材数量、角色及模板图不是产品限制或真实数据。

## 2. 原软件兼容约束

- 复用现有 Header、ProjectHeaderNavigation、ProjectSwitcher、应用布局、主题、弹窗和基础表单组件。保留项目切换、通知、费用、设置、账号、助手等现有功能。禁止把原型的 HTML 顶栏、全局 CSS 或导航结构覆盖进产品。
- 在现有项目导航机制中增量增加“创作工作室”，其页面内部切换四个工作室；窄屏沿用原导航的响应式处理。
- 角色卡进入造型室；镜头或叙事组进入导演、预演；成片进入片头；画布节点进入对应工作室。入口携带项目、来源类型、对象 ID 和引用版本，完成后可返回来源。
- 直接进入工作室时先选择操作对象；对象不存在或被删除时显示原因，不能默认修改其他对象。切换项目不带入前项目的未提交状态。

## 3. 角色造型室

采用可视化选项与自然语言描述驱动 AI 出图。可编辑面部轮廓、发型、体态、服装及特殊标记；首版不做实时三维捏脸。

流程：选角色与基础/服装模式 → 编辑要求 → 主动生成候选 → 比较并选择 → 查看关联影响 → 采纳所选范围。生成失败保留编辑内容和已成功候选，重试不重做已成功候选。

基础身份与服装造型分别版本化。剧本明确的人物事实保留，冲突需展示并由用户修正。角色卡可保存到个人角色库供其他项目选用；跨项目使用创建项目引用或副本，不联动覆盖来源项目。

采纳时列出实际受影响的分镜图、组视频与画布引用，区分“更新后续引用”和“重新生成已有素材”。默认不勾选付费重生成。选择重生成时展示范围及可用估算，按现有叙事组生产流程提交任务。已经运行的任务使用提交时快照；旧角色版本与旧素材保留。上游分镜更新成功后才提交依赖它的视频任务。

## 4. 导演自定义

首版同时提供：内置导演预设、自建可编辑配置、导入个人方法。导入支持粘贴文字和 TXT/Markdown/PDF/DOCX 文档文本提取；扫描件或无可提取文本的文档给出明确说明，不默认加入 OCR。

配置包括叙事节奏、运镜、构图、人物表演偏好和补充方法。导入后的结构化配置展示来源片段，允许修改，确认保存后才启用。文档内容是创作素材，不能改变应用权限、工具规则或发送数据范围。

应用到选中镜头或整集，生成可比较、逐项或批量采纳的导演建议。默认保持剧情、人物动机和对白；只有用户开启“允许改编”后才提出故事与对白修改，并单独审阅。采纳创建新方案版本，展示下游影响，不自动覆盖已生成视频。

与既有画布导演生成约定兼容：工作室中的配置选择和建议审阅发生在创作阶段，不给每次画布生成额外增加强制审阅关卡。继续沿用既有单次规划、任务恢复与失败暂停机制，不回退到未经验证的原始提示词。

## 5. 3D 预演与动作编排

首版采用简化真实三维场景、人物和物件，支持自然语言搭景、参考图、拖动和对话调整站位、机位、灯光，以及绘制摄影机移动路径。复用现有 director world 与三维 viewer 能力，不以 v2 的二维 SVG 示意替代三维实现。

每个角色有动作轨道，摄影机有独立轨道，共用时间尺、播放头和播放/暂停。首批动作：走、跑、转身、坐下。可添加、选中、删除、拖动片段和调整长度，也可输入开始时间与时长。时间轴随内容延展；同一角色的主动作不能重叠，越界或冲突在编辑时提示，不静默覆盖。

走跑动作配置地面路径及终点，时长决定预演速度；转身配置目标朝向；坐下配置座椅或坐姿目标及朝向。片段结束保持结束姿态，后续动作从该状态继续；插值过渡避免跳变。提供基础人形动画与适配检查，非人形角色不能静默套用人形坐姿。复杂交互、打斗、精细手势、口型与完整动捕编辑器不属于首批动作库。

自然语言可生成结构化动作片段，先显示可编辑结果再采纳；仅调整预演不改写剧本。角色动作与摄影机路径同步预览、拖动播放头可检查任意时刻。输出摄影机参考帧和含角色动作的白模预演视频，可带回来源镜头或画布。

输出记录场景、动作、角色引用及相机版本。依据目标模型真实能力选择参考帧或预演视频，明确不能保证模型逐帧复现动作。缺少模型支持不伪装为已使用动作控制。

## 6. 片头制作

采用用户参考图的工作区布局：左侧素材与“片名设计/文字特效”切换，右侧大幅播放预览，底部候选版本。仅借鉴片头编辑区域，不照搬对方全局界面、价格或品牌资源。

素材支持从已有成片选帧、上传底图；无成片时仍可上传。片名设计支持片名、副标题、字体、颜色、对齐与位置、时长、输出比例。字体选择展示实际可用字体及回退状态。文字独立渲染，修改文字与排版不重新生成背景。

首批本地模板包括静态定版、柔和显现、逐字浮现、缩放入场、光影掠过；粒子聚合及自由描述效果作为可选 AI 效果入口，根据已配置服务能力开放。界面区分可直接预览模板与需生成的效果。v2 中各效果播放只是示意，正式版必须分别实现并可辨认。

用户可主动生成背景或动态效果，结果形成候选版本，支持播放、比较、采纳、下载。生成前展示所用平台和可用计价，不照搬参考图的“150/个”。人民币与 RH 币分别展示，RH 币不强制折算人民币；未知价格明确显示未知。

默认输出独立片头；打开“插入当前集片头”后输出新的完整成片，保留原片与原音轨。无可用成片时禁用插入并说明原因。生成和渲染显示进度、失败原因与可恢复入口，不能只弹出成功提示却没有文件。

## 7. 模块边界与数据流

工作室外壳只管理路由、对象选择、来源与未保存状态。四个编辑器独立管理各自草稿和预览，不写入其他模块内部状态。

角色模块复用 character_visual 的身份、服装、候选与采纳服务；导演模块复用 director_plans 与导演评审的数据接口；预演模块复用 director_world、viewer-kit 与画布场景保存/引用接口；片头模块单独管理排版、效果与合成任务，复用资产、任务中心和成片输出机制。

持久化对象包括：角色版本引用、导演配置与建议版本、预演场景与动作片段、片头草稿与候选。共同记录 ID、项目或个人库归属、版本、来源、创建时间与关联任务。保存采用预期版本校验，过期写入返回冲突及重新加载入口；不覆盖其他会话的新版本。

统一流程：读取对象 → 编辑草稿 → 保存版本/提交生成任务 → 任务中心回传状态 → 登记可访问素材 → 用户采纳 → 更新指定引用。普通表单编辑、时间轴拖动、播放预览不调用模型。提交使用幂等标识；结果未知时先查询已有任务，禁止盲目重复付费提交。

## 8. 失败处理与验证

- 刷新页面恢复已保存草稿和运行中任务；离开未保存页面提供保存或放弃选择。
- 任务失败保留输入、任务 ID、已成功结果及可读原因；重试范围明确。无效导入、缺少引用、版本冲突、模型不支持、输出不可访问分别显示，不混成空白页。
- 后端验证项目归属、版本、时间范围、动作适配、输入文件与模型能力；前端提示不能替代服务端校验。
- 使用本地渲染和模拟 provider 验证流程。付费验收单独明确模型、范围与次数，不因 UI 验证批量生成。

验收重点：原顶栏/项目切换/费用/通知等回归；上下文进入与返回；角色基础和服装隔离、选择性更新；导演三种来源及改编权限；动作编辑、冲突检查、连续播放及导出；片名修改不触发模型；候选与旧版保留；真实输出可播放；重复提交不会产生重复任务。

## 9. 实施顺序

先完成工作室外壳与上下文契约，再依次实现角色、导演、预演、片头四个模块。每个模块有独立实施任务与验收，未完成的能力不能显示为可用。最后完成跨模块引用、失败恢复与导航回归。

本文审阅通过后进入 writing-plans，制定具体文件、接口、迁移与验证步骤。现有工作区有大量并行修改，实现必须按文件核对并保留，不做无关重构或整仓覆盖。
