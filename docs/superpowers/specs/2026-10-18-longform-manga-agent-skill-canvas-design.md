# 长篇漫剧 Agent／Skill 与自由画布创作设计

日期：2026-10-18

状态：设计方向已由用户确认；规格文档待用户审阅。

最新交互修订：用户明确要求少量节点、自动传递资产与分镜、减少确认和前台版本管理，并确认拆分镜头默认收在宫格节点内部。普通制作交互以[轻量制作画布规格](2026-10-18-lightweight-production-canvas-design.md)为准；下文逐次采用、计划审批、独立制作任务入口等与之冲突的交互要求已被取代。长篇内容模型、后台来源追溯与跨集连续性仍保留。

## 1. 背景与目标

Nuomi 的创作流程需要支持 60–100 集长篇漫剧。创作者要能从立意、全剧规划和分集剧本，一路协作完成角色／场景资产、导演设计、表情与站位、视频生成、镜头合成和配音。Agent 负责理解目标、组合岗位与 Skill；创作画布持续呈现并承载可编辑、可追溯的结果。

本设计延续已批准的 Agent／画布、专业岗位、剧本和导演生产设计，补充长篇全剧状态、跨阶段 Skill 编排、候选结果生命周期和 60–100 集连续性要求。画布是开放的创作空间；内容关系与任务依赖不能演变成必须逐页解锁的固定流水线。

### 首轮验证范围

- 建立一部 60–100 集作品的全剧故事圣经与分层分集大纲。
- 连续完成 3 集剧本，验证人物弧线、事实状态、伏笔和集间承接。
- 选择其中 1 集完整走通资产准备、导演与分镜、表情／站位、媒体生成、镜头合成及配音，检查可播放交付与来源追溯。

三集剧本和一集成片是首轮验证样本，不是产品的集数上限。

## 2. 已确认的产品决定

| 议题 | 决定 |
| --- | --- |
| 长篇规模 | 长期按 60–100 集设计；首轮连续创作 3 集并完整制作其中 1 集 |
| 画布边界 | 项目构思画布、每集一张主画布、自由画布；跨集资产使用项目级资产中心 |
| 分集大纲 | 全剧主线弧 → 故事弧 → 分集纲；大纲覆盖全剧且可自由修改、重排、扩写 |
| 故事圣经 | 创作者以一份统一、可读、可编辑的故事圣经为主要入口；内部用本体化结构支撑身份、关系、状态和来源检索，不要求创作者编辑图谱 |
| Agent 与 Skill | 自然语言为主，Skill 可发现；Agent 展示任务计划，创作者确认后执行 |

| 并行 | Agent 提议可编辑的任务依赖关系；独立工作可并行，内容依赖仍须满足 |
| 运行结果 | 画布显示可折叠的运行组；展开后候选产物成为可自由布局的节点 |
| 候选与正式版本 | 候选可逐项或批量采用；仅采用后更新正式内容，旧版本和未采用产物保持可追溯 |
| 连续性检查点 | 采用剧本时提议更新计划状态；成片完成后提议更新已发生状态。两次都由创作者审阅并采用故事圣经补丁 |
| 媒体授权 | 文本工作按已确认计划执行；图像、视频和配音按批次展示规模与可用配置，须再次明确确认后启动 |

## 3. 用户心智与对象关系

### 3.1 项目与画布

- 项目承载创作简报、统一故事圣经、故事弧／分集大纲、共享资产、岗位与 Skill 配置，以及可追溯的任务记录。
- 项目构思画布用于自由探索、形成方向、组织项目级内容并交接到分集。
- 每集有且仅有一张主画布。剧本以每集一个主节点呈现；导演、分镜、表演、媒体和音频产物按需要创建关联节点。
- 自由画布可以承载非分集创作。用户没有指定集数时，任务作用域保持为空，不默认写入 E01。
- 资产中心继续管理跨集基础资产与变体。集内节点引用资产 ID 和所用变体／版本；普通生成不会自动覆盖共享资产。

节点空间位置不代表叙事顺序或强制执行阶段。结构化关系表示“来源于”“引用”“候选更新”“属于故事弧／集／场景”等语义；任务依赖只约束具体运行，不锁定创作画布。

### 3.2 故事圣经与本体数据

故事圣经是创作者的统一阅读、编辑入口，按全剧主线、故事弧、人物与关系、世界规则、时间线、伏笔和分集纲组织。分集大纲可在圣经中统一浏览，也可由画布节点承载局部工作；避免重复录入同一事实。

系统内部维护稳定对象身份及可追溯关系。至少支持角色、场景、道具、事件、关系、故事弧、集、伏笔和创作约束等对象类型。关键事实保存：

- 稳定对象 ID、事实类型和关联对象；
- 状态：候选、已确认、计划、已发生、已撤销或未知；
- 来源内容、版本、场景／段落等可定位证据；
- 生效集数／故事弧和被哪些后续内容引用；
- 修改前后差异及可能受影响的候选与正式内容。

本体用于检索、来源和影响分析，不在首版要求通用本体编辑器、图数据库界面或“Ontology”用户术语。信息不足时保持未知并向创作者展示，不把 Agent 推断自动提升为已确认事实。

### 3.3 长篇故事结构

全剧采用可编辑的分层大纲：

1. **全剧主线弧**：核心命题、主角总体变化、核心冲突、终局方向与关键约束。
2. **故事弧**：按叙事需要分组，记录范围、弧心冲突、关系转折、关键揭示、伏笔埋设／回收及弧间承接。
3. **分集纲**：每集目标、主要冲突、关键行动／转折、人物状态变化、与前后集的承接、相关伏笔及结尾效果。

故事弧不是固定季数、页签流程或集数模板。用户和 Agent 都可以重排集、调整弧的边界、拆合故事弧和改变细化程度。结构变化须展示来源和下游影响；不能静默重写已采用剧本或已完成媒体。

## 4. Agent 与 Skill 交互

### 4.1 角色分工

主 Agent 作为创作者的统一协作入口，负责理解目标、读取范围内上下文、提出计划、委派专业任务、整合结果和解释阻断。专业岗位 Agent 保持有边界的责任，例如：

- 故事架构／立意与全剧规划；
- 分集主笔、剧本编辑、连续性审阅、对白与台词；
- 角色／场景／道具资产设计；
- 导演、分镜、表情与动作、站位与调度；
- 视频提示与生成、镜头合成、声音设计和配音。

Agent 角色定义责任、可读写内容和允许操作；Skill 提供可复用的创作方法、知识和阶段操作。角色配置的存在不意味着对应操作已开放或获准调用。

### 4.2 发起、计划与执行

创作者可以选择画布节点／范围并描述目标，也可以从 Skill 目录浏览方法后发起任务。自然语言是默认入口，Skill 目录用于发现和定向调用能力，不要求每一步填写专用表单。

执行计划至少展示：

- 目标项目、画布、集、节点／范围和输出位置；
- 读取的设定、内容及确切版本；
- 准备调用的岗位 Agent、Skill 及职责；
- 任务依赖、可并行任务和检查点；
- 预期输出类型、候选状态与建议关系；
- 涉及媒体生成时的批次范围、模型／规格和系统可提供的用量估计。

创作者可调整计划，再明确确认文本执行。Agent 按依赖图并行可并行任务，保留每个任务独立状态、输入快照、结果和错误。对来源变化、授权不足、不可恢复错误等阻断状态要停止受影响任务并解释原因，不让失败状态继续显示为运行中。用户修订输入后，Agent 应基于新版本生成新运行，而不是覆盖旧结果。

文字运行的确认不授权媒体供应商调用。媒体批次单独展示可用配置、镜头／资产／音轨数量和可估算用量，创作者可调整、跳过或确认。没有可靠估算时明确显示“未提供估算”，不能编造费用或将提交成功说成成品完成。

### 4.3 单集剧本到成片的默认主线

自由画布和局部委托仍可从任意有效节点发起；但创作者已经生成并采用单集剧本后，产品必须提供一条无需理解内部节点关系的默认下一步。剧本节点的主要操作为 **“制作本集”**，而不是把“交给导演”“审阅方案”“创建制作节点”“配置分镜引用”等内部动作并列给普通用户。

点击后建立一个绑定已采用剧本修订的“本集制作任务”。主 Agent 负责调度适用岗位和 Skill，自动完成不需要用户判断的准备工作：拆解场景与叙事组、读取并匹配角色／场景／道具资产、识别缺失或歧义、整理导演意图，并按镜头需要综合站位、动作、表情、灯光和摄影意图，形成可追溯的分镜输入。上述内容作为内部结构和专业 Agent 的工作结果保存；默认界面只展示简明摘要、真实资产匹配结果和需要用户决定的问题，不要求用户逐镜填写表格或维护提示词。

默认路径如下：

1. **准备本集**：固定采用剧本和创作约定版本；自动生成场景／叙事组计划，匹配已发布共享资产或已有变体，并检查声音依赖。只有身份冲突、关键资产缺失或会改变剧情事实的实质歧义才暂停询问。明确不存在歧义时继续，不要求用户逐岗位审批。
2. **制作分镜图**：根据已匹配资产和导演准备结果，构造包含构图、空间关系、视线／表情、动作时刻、光线气氛及镜头意图的分镜生成输入。用户看到按场景／组折叠的分镜成果并集中审阅；可用自然语言提出局部修改。坐标或摄影词若只是模型提示意图，必须如实标记，不声称模型精确执行。
3. **生成视频与声音**：用户确认分镜方向后，按采用分镜和固定剧本／资产版本生成组视频，并准备对白／配音及声音轨。若本次任务已对完整 E01 授予了明确总预算和媒体范围，所有批次都在该授权内继续，不为每个 Agent 或每个组重复弹窗；每批仍记录目标、实际配置、费用／未知估算和授权依据。任务超出范围或预算、出现新的不可估费用或需要替换已采用内容时才暂停。
4. **合成并交付**：自动将成功组视频与可用对白／声音按剧本顺序整理为整集时间线，检查缺组、缺声和可播放性。画布呈现可预览成片与明确未完成项；“生成任务成功”不得代替最终产物检查。

需要用户做决定时，暂停在一个清晰的待处理项上，说明原因与影响；已完成且无依赖的工作继续。剧本／资产版本变化、媒体失败及提交状态未知均按具体节点回报并提供继续、修订、对账或重试入口，不能让整条任务无限转圈。

### 4.4 普通视图与高级源文件

普通创作者看到制作任务、整体进度、可播放／可比较的结果、真正待决定的问题，以及“继续制作／重试失败项”。运行组默认折叠；一次制作产生的导演方案、场景调度、分镜、视频和声音通过来源关系组织为一个集制作成果，不把内部依赖节点当成五套互相竞争的工作流程。

灯光属性、站位坐标、镜头结构字段、模型参数、提示词、revision ID、任务回执及完整 Agent／Skill 调用细节收在“查看制作依据／高级编辑”中。用户仍能在此检查或修改，也能打开对应源文件；默认只展示决定创作方向或阻塞执行所必需的信息。隐藏高级项不删除底层数据、正式操作合同、自由节点能力或追溯证据。

制作准备与产物仍按稳定业务对象、修订和来源保存。高级设置更改后，影响范围与过期产物必须显式标记；不得因为 UI 收起字段而丢失版本、授权或失败状态。

## 5. 结果、采用与故事事实更新

### 5.1 运行组与候选节点

- 每次 Agent 执行形成可追溯的运行记录，保存输入版本、计划、岗位与 Skill、实际操作、输出、错误及创建时间。
- 运行完成后在画布放置可折叠运行组卡，显示任务目标、候选数量和待审状态。展开后候选产物作为节点，参与自由画布布局。
- 创作者可以查看、比较、逐项采用或批量采用。报告等非正式产物可以只读；业务内容采用前继续保持候选。
- 采用更新该业务对象当前正式引用并新增修订，保留历史。未采用候选保留在运行记录，不自动充当后续创作的权威输入。
- 重新运行不自动创建重复正式对象，也不自动删除已完成媒体。画布可折叠和整理运行组；清理历史不改变来源链。

### 5.2 计划状态与已发生状态

采用分集剧本后，连续性 Agent 根据新剧本对照当前故事圣经和前文，生成“计划状态”补丁候选，例如角色将获知某事实、关系将变化或某伏笔预计在哪集回收。创作者查看事实差异、证据和影响后采用补丁；未采用的内容不进入后续事实快照。

整集媒体制作和创作者验收完成后，再生成“已发生状态”补丁。该补丁以实际采用剧本与最终成片／已确认制作结果为来源，指出剧本计划与成片差异。经创作者采用后，后续创作可区分计划和已发生事实。成片完成不等同于自动通过故事连续性或画面质量审查。

任何故事圣经修改均生成带来源的候选修订，并在采用前保留正式版本。冲突、推测、没有证据的连续性推断不得静默更新权威设定。

## 6. 阶段能力地图与资料复用

用户提出的阶段作为可组合能力目录，不作为固定顺序：

| 创作能力 | 典型结果 | 可复用线索／依赖 |
| --- | --- | --- |
| 立意与题材探索 | 方向候选、题材与受众约束 | 现有立意节点、创作简报和题材参考 |
| 全剧主线与故事弧规划 | 全剧主线、故事弧、关键转折 | `script-master` 的 framework、pattern library；需接入 60–100 集来源与事实追踪 |
| 分集大纲与连续剧本 | 分集纲、每集剧本候选、连续性报告 | `script-master` 的 writing、doctor、dialogue 与剧本节点设计 |
| 角色／场景／道具资产 | 基础资产、可复用变体、资产引用 | 现有资产中心、基础／变体模型和画布引用；共享资产需显式发布 |
| 导演与分镜 | 场次／叙事组、分镜、镜头意图与参数 | 现有导演工作区、组级制作能力与导演研究；遵守固定来源版本 |
| 表情、动作与站位 | 可定位到角色／场景／镜头的表演候选 | 复用专业 Agent 与调度字段；操作注册与画布版本写入须逐项核验 |
| 图像、视频及提示词适配 | 媒体任务、带模型输入合同的候选素材 | 现有节点、模型适配器和正式生产 CLI；严格按用户确认的媒体批次执行 |
| 镜头合成与剪辑 | 组视频、时间线及成片候选 | `nuomi-canvas-production`、`nuomi-production` 及既有合成路径 |
| 声音设计与配音 | 角色声音、对白／表演、采用的配音音轨 | 现有声音与配音节点、固定版本与试听／采用合同 |

仓库中的 Skill、角色目录、API 和测试是可复用线索，不互相等同。`script-master` 当前 README 描述了九阶段总控流程；本产品只抽取可独立调用的创作方法与题材资料，不复制其固定阶段门槛。`nuomi-canvas-production` 和 `nuomi-production` 支持组级制作、任务恢复和版本检查；实际授权、供应商能力和端到端验收按现有正式接口执行。

实现开始前须以当前分支重新核对每项能力的：用户入口、Skill 发现、角色合同、可读输入、专业写入操作、版本／来源回执、媒体权限和真实验收证据。现有代码核对详见[实现覆盖审计](../../design/integrated-production-2026-10-17/PRD-COVERAGE-AUDIT.md)；审计日期与当前分支存在差异时不得沿用过期状态宣称已接通。

## 7. 关键体验要求

- 画布为主要工作区，Agent 侧栏协作；Agent 侧栏不遮挡主创作区域，项目／画布导航可以折叠。
- 节点呈现清楚显示业务对象、候选／采用状态、来源／关联、当前版本、运行状态和可执行动作；内部模型推理不冒充业务文档。
- 运行组初始折叠，展开与收起不改变画布自由布局；候选节点和正式节点易于区分。
- 每个执行计划能看到 Agent 的输入范围与权限，媒体生成有独立批次确认。
- 任务失败后显示失败原因、重试或恢复入口，并立即停止运行指示；不得以无限 spinner 阻断重试。
- 已采用单集剧本时，“制作本集”是清晰默认下一步；不要求普通用户在导演交接、方案采纳、制作图创建和各组引用配置之间自行拼接链路。
- 站位、灯光、表情、动作、摄影和提示词默认由适用专业 Agent 根据剧本与匹配资产综合准备；只在真实歧义、用户主动编辑或能力边界需要时进入高级视图。
- 一次已授权的单集任务按约定预算自动完成其中各媒体批次；同一范围内不重复索取相同授权，扩大范围或预算才再次确认。
- 60–100 集作品中，创作者可以按集、弧、人物、资产或伏笔检索；每项事实可回到来源，Agent 按当前任务取相关片段而非无选择地塞入所有历史文本。
- 桌面画布上的全局搜索与定位支持快速跳转；折叠运行组与节点，不隐藏待处理候选和失败任务。

## 8. 非目标

- 不恢复按“立意→剧本→导演→剪辑”等顺序切页并逐步解锁的旧流水线。
- 不把所有节点生成绑定到前置页面或唯一主线；保留自由画布和局部创作。
- 不因引入 Agent／Skill 删除资产中心、基础资产与变体、手法库、风格库或既有可复用媒体能力。
- 不自动采用 Agent 的剧本、故事事实或共享资产，不把计划误报成已发生事实。
- 不在没有批次确认的情况下调用付费图像、视频、声音或配音服务。
- 不把 Skills 目录直接暴露成缺少上下文的技术工具清单；也不要求创作者操作通用 Ontology 编辑器。
- 不在本设计内声称所有岗位、Skill、媒体服务均已完成接通或真实供应商验收。

## 9. 验收标准

### 9.1 长篇规划和连续性

1. 新项目可保存创作简报、统一故事圣经、主线弧、故事弧和 60–100 集分集纲；创作者可只查看完整大纲，也可定位到单弧或单集。
2. 用户修改一项角色关系、规则或伏笔时，系统能展示来源、修订以及已引用内容；不能无提示地替换已采用集纲／剧本。
3. Agent 为指定集创建任务时，只读取当前计划所需设定、已采用前文和相关状态，并在执行计划中列出确切来源版本。
4. 能连续创作 3 集剧本，检查人物已知／未知、人物状态、时间线、道具／关系状态和伏笔承接；审阅结果可定位到正文与圣经来源。
5. 采用剧本后，计划状态更新仍为候选补丁；成片完成后已发生状态另提候选，二者均有创作者采用记录。

### 9.2 Agent、Skill 与画布

1. 用户自然语言任务可得到可编辑计划，计划明确岗位、Skill、作用范围、输入版本、依赖关系与候选产物；计划确认后才启动文本执行。
2. 无依赖的文本任务可并行；存在输入依赖的任务不会读取未采用或过期候选作为正式事实。
3. 完成的运行以可折叠组出现在正确画布；展开可查看和自由摆放候选节点；采用前后状态明确。
4. 重新执行、部分失败、取消和未知回执均保留任务身份与原结果；明确失败后可恢复或重试，不会继续显示运行中。
5. 岗位 Agent 使用项目简报时能加载匹配阶段和题材 Skill；局部风格偏移在计划中明确展示且须确认。

### 9.3 完整制作与媒体授权

1. 文本生产依赖正式剧本修订；导演、资产、表情／站位、分镜、媒体和音频结果有稳定业务身份与来源关系。
2. 共享资产引用不复制成失去身份的提示词；基础资产、变体及被镜头实际使用的版本可以核对。
3. 一集漫剧可通过真实正式接口完成从已采用剧本、导演／分镜和资产，到分批确认的图像／视频／配音、剪辑合成与可播放导出。
4. 每个媒体批次启动前展示输入、数量、供应商配置和可用的成本／用量估算；跳过与取消不损害其他已完成批次。
5. 最终成片核对剧情、对白音轨、镜头顺序、时长和可播放文件。HTTP 成功、自动测试通过、单个媒体完成或任务提交成功不能单独作为整集通过证据。

## 10. 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| 故事圣经过长，Agent 遗漏或错误拼接设定 | 保持统一人类入口，按稳定对象、事实状态、来源和任务范围检索；在计划里列出引用版本 |
| 长篇改纲使大量后续内容过期 | 用故事弧和分集引用表示影响；展示候选修订，逐项选择是否重新检查或重写 |
| 题材 Skill 把具体模板机械套在创作上 | 区分参考方法与项目约束；用户简报优先；明确标注局部偏移，不强制套路配额 |
| 多 Agent 并行引入风格冲突或重复写入 | 计划共享同一简报快照，任务写入范围受限；结果以候选提交，主 Agent 整合后由用户采用 |
| 运行组和候选节点使画布变乱 | 默认折叠运行组、按业务类型和状态筛选；采用后保留历史但不复制正式对象 |
| 长链媒体任务等待、失败或重复付费 | 批次前确认，任务恢复前对账；只重试明确失败且输入未变的目标范围；失败状态及时停止 spinner |
