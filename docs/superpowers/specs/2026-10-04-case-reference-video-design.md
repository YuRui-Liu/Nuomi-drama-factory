# 案例参考创作：视频分段设计

日期：2026-10-04

状态：交互范围已确认，书面规格待用户审查。

## 目标与范围

让用户从当前视频分段进入案例库，选择借鉴维度，结合自己的剧情得到可审阅的视频方案，确认后应用到该分段。沿用现有视频生成入口，不自动提交视频生成。

首期仅接入创作画布的视频导演分段。全局手法库保留案例浏览；没有目标分段时说明需从视频分段进入。暂不接入分镜图、剧集批量生产、自动推荐或案例模板市场。

## 现状与依据

- `CaseBrowser.tsx` 当前仅展示标题、摘要、出处和关联手法，无媒体预览、参考方案或应用入口。
- 后端案例模型已有 `media_url`、模式、时长和来源字段，前端 `TechniqueCase` 尚未完整声明这些字段。
- 本地目录共 2,664 个案例，330 个具有媒体链接；存在只有概括性摘要的案例。链接存在不代表可播放或已完成分析。
- GitHub 来源可能公开原提示词，但现有导入器明确只读元数据、排除提示词正文；Case 模型也未保存提示词。这是参考内容缺失的独立原因，不能用媒体链接数量推断案例是否有可借鉴内容。
- `TechniqueContext` 已携带分段、模型能力、参考图存在状态和手法选择回调；尚缺少生成参考方案所需的项目、画布、节点、草稿版本与完整参考图信息。
- `DirectorSegment` 保存提示词、时长、首尾帧及可选手法。现有导演服务已支持文本运行时、任务状态与生成快照。

## 用户流程

1. 从视频分段打开“手法库 → 案例”，持续显示目标分段及其时长。
2. 查看案例详情。优先展示来源中公开的完整提示词，可展开和一键复制，并标明原作者公开、第三方反推或来源不明。有效媒体可播放或展示；无媒体或加载失败时提供原始出处及明确状态，不展示虚构封面或分析结果。
3. 查看有证据支撑的可借鉴点，勾选运镜、动作节奏、人物表演、结尾构图，至少一项。
4. 点击“生成参考方案”。显示文本任务进度，可取消或重试，不调用视频提供商。
5. 审阅当前方案与建议方案：展示修改后的完整视频提示词、所选维度对应的建议及依据、保留的剧情约束与兼容性说明。
6. 用户可编辑建议提示词，点击“应用到当前分段”。成功后返回目标分段，显示案例参考标记；视频生成仍需单独点击。

## 参考内容的证据边界

目录条目、媒体链接与内容分析分开记录。不得将通用摘要标记为已观看的视频分析。

可用于生成方案的依据至少具备一种：来源公开的有效提示词正文；有明确内容的已审核拆解；成功完成的媒体分析；用户补充的具体参考片段描述。优先以原提示词分析镜头、节奏、表演与结尾结构，再替换成当前分段的角色和剧情，而非直接拼接原提示词。没有视频也可基于公开提示词生成方案，但应标为“基于提示词”，不能声称效果已被视频验证。只有标题、通用摘要或打不开的链接时，禁用生成按钮并提示补充参考描述。此时仍可查看和应用关联手法。

导入阶段从已固定版本的 GitHub 快照读取实际提示词字段及 Markdown 正文段落，保留原文、语言、来源仓库、提交版本、文件路径、原条目 ID、正文哈希及提示词来源类别。各来源独立适配，不凭标题猜测提示词字段；外链、摘要、未公开标记和示例占位文本不作为完整原提示词。多个来源的不同提示词分别保存，不因媒体去重而覆盖。重导入保留既有案例 ID 和关联手法。公开原文与反推内容分开显示，翻译不覆盖原文。

首期支持已有图片/视频链接的预览，以及用户文字补充的参考描述。媒体分析仅复用项目已有且可验证的多模态能力；没有对应能力时不另建视频抓取或转码系统，也不假装已经理解媒体。未分析的可播放视频允许用户观看后补充描述。

借鉴说明标注依据来源：公开提示词、目录拆解、媒体分析或用户描述。推断需单独标明。保留来源与现有未实测状态；借鉴表现手法不自动把案例媒体加入生成参考图，不自动下载原视频或复制原角色、服装、场景和对白。来源正文作为分析资料，不作为系统指令执行。

## 组件与服务职责

- 案例浏览：沿用 `CaseBrowser` 的查询、筛选和详情，拆出媒体展示和参考维度选择组件，避免把异步创作逻辑堆进列表组件。
- 来源导入：扩展现有适配器及案例模型保存提示词记录；列表只返回提示词可用状态，完整原文由详情接口返回，避免大目录列表携带所有正文。旧目录无提示词字段时仍可读取，重导入补全公开内容。
- 方案审阅：独立组件处理前后对比、建议编辑、应用与过期提示；不自行修改画布。
- 目标适配器：从视频导演节点建立完整上下文，并通过画布现有更新动作应用结果。全局浏览入口不创建虚假的分段上下文。
- 参考方案服务：读取可信案例资料与目标快照，组装结构化输入，调用现有文本任务运行时，校验输出并保存可追溯提案。与实际视频提交服务分离。
- 兼容性校验：复用现有模型模式、时长、首尾帧和手法适用性检查，客户端辅助提示，服务端作最终校验。

## 数据与接口契约

新增项目范围的案例参考提案资源，设计接口为：

- `POST /projects/{project}/case-reference-proposals`：提交案例 ID、借鉴维度、依据描述、画布/节点/分段 ID、草稿版本和目标快照，返回任务及提案 ID。
- `GET /projects/{project}/case-reference-proposals/{id}`：返回状态、结构化建议、来源快照、错误信息和基准版本。
- `POST /projects/{project}/case-reference-proposals/{id}/cancel`：取消未完成提案；即使底层调用无法即时停止，迟到结果也不得应用。

所有接口沿用项目访问校验；创建和取消要求编辑权限。提案绑定拥有者与项目，不接受客户端伪造的案例来源或分析状态。

输入包含当前提示词、模型、模式、时长、首尾帧、参考图、选中手法及其版本。角色和场景仅使用当前分段已有信息，不默默引入项目中无关资产。媒体是否真的被模型读取需在结果中明确记录。

输出包括 `suggested_prompt`、按维度组织的建议与依据、保留约束、兼容性结果、案例来源快照、输入指纹和运行时/模型标识。不得返回可执行工具命令或视频生成指令供自动执行。

分段新增可选 `caseReference` 元数据：提案 ID、案例 ID、所选维度、来源/依据快照、应用时间和已应用提示词指纹。旧画布无需迁移，缺少字段时按未引用处理。字段需贯穿前后端模型、序列化、画布保存和导演 attempt 快照。

## 应用语义与冲突处理

应用仅替换当前分段提示词并保存引用信息，不改变分段数量、时长、首尾帧、参考图、角色绑定、模型或已有手法。

如已有手法与借鉴要求冲突，展示冲突，阻止应用；用户可调整借鉴维度或另行修改手法后重新生成。不能暗中叠加相互冲突的指令。

应用前比对目标分段 ID、基准草稿版本和输入指纹。期间修改了剧情、图片、模型、时长或手法，则提案标为过期，要求重新生成；删除或切换分段不能把结果写到其他分段。首期采用保守的草稿版本冲突检查，即使其他分段发生变化也重新生成，避免覆盖并发修改。

应用通过现有画布撤销与版本保存流程完成；增加草稿 revision，使旧优化结果失效。保存失败必须提示，不将仅内存变化标记为已保存。用户后续修改提示词时保留引用来源，但标记方案已经编辑；生成快照使用实际最终提示词。

## 任务与失败状态

状态为等待、生成中、成功、失败、已取消；过期由目标快照比较确定。任务使用现有文本任务路由与配置，不写死模型、不绕过已有凭据和费用记录。

无有效依据、缺少当前剧情、模型能力不可用、图片失效或不兼容时，在请求前给出具体说明；服务端重复校验。超时、格式错误、取消和重试均保留当前原方案。相同客户端请求 ID 应返回同一任务，防止重复点击产生多个提案。成功后不自动应用，也不自动生成视频。

## 验证与验收

1. 案例媒体可加载时正常显示；缺失、不可播放时提示并保留出处。
2. 有公开提示词但没有媒体的案例可展示、复制原文并生成参考方案，标明提示词依据；原作者内容与反推内容不混淆。仅有通用摘要的案例无法被伪装成已分析；补充具体描述后可生成，并标明用户描述来源。
3. 四类维度可选，至少一项；只对选择项生成参考建议，保留已有角色、场景、剧情结果与时长约束。
4. 有效任务展示前后方案和证据，编辑建议后可准确应用到目标分段。
5. 过期、切换/删除目标、手法冲突、模型不支持、取消及服务失败均不覆盖原方案。
6. 应用可撤销，刷新后引用信息仍在，旧画布正常打开；新的导演生成快照保留引用依据。
7. 创建、审阅及应用提案全过程均不向 RunningHub 或其他视频服务提交生成任务。
8. 自动化覆盖服务结构化输出、权限/幂等/状态、前端媒体降级和应用冲突；实测一次真实文本方案生成、编辑、应用、保存刷新。只有用户另行触发时才验证付费视频生成。

## 实施顺序

先核对三个 GitHub 来源的实际提示词结构，扩展导入和详情展示并补全目录；其次实现目标上下文和持久化契约；再接入提案任务服务；最后完成审阅应用、冲突保护及真实链路验收。导入测试需覆盖 JSON/Markdown 正文、未公开与反推标记、多来源提示词保留、旧目录兼容及案例 ID 稳定。实现计划在用户审查本规格后编写。

已检查范围、前后端边界、媒体依据、失败路径、并发冲突和验收标准；无待定占位项。首期不以所有案例都可分析为前提，不依赖新增视频生产链路。
