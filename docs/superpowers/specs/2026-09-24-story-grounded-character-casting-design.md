# 剧情驱动的人物选角设计

日期：2026-09-24

状态：分节设计已获用户确认；本书面规格等待审查，尚未进入实现。

## 1. 目标与范围

解决人物头像趋于网红式精修、角色之间缺少差异、外貌与剧情割裂的问题。面向所有项目提供通用的“剧情选角档案”，以当前项目的典型角色验证。采用电影选角方向：人物可以好看，但年龄、妆发、生活质感和个体特征必须符合剧本与项目审美。

不以丑化、加皱纹、伤疤或脏污替代角色设计；不把职业、善恶或性格机械映射为五官。不改造视频生成流程，不引入批量付费试镜或自动循环重绘，不自动更新已有角色资产。

## 2. 创作经验与现状

奥斯卡学院的 [Costumes & Makeup 教材](https://www.oscars.org/sites/oscars/files/costumes_and_makeup_activites_guide.pdf?VersionId=mvtYcF0qA2XNb08bzFzxcpCasWRvLvXO) 强调研究时代资料，并通过造型让人物显得在故事开始前就已有生活。[How To Create a Great Costume Design](https://www.oscars.org/news/how-create-great-costume-design) 将造型联系到人物内在经历和自我形象。这里吸收其创作方法，不把服装经验直接当作人脸生成效果的证明。

现有代码已有 narrative profile、带出处的事实、三套 design proposals、confirmed visual bible、prompt snapshot 和人物图像任务。`nanobanana_character.py` 已包含禁止美颜、时尚杂志精修等指令。因此单独追加负面提示词不是完整方案；仍需通过实际角色档案、提示词和图片对照验证具体失败原因。

扩展现有 `character_visual` 模型、提案校验、编译器和存储，复用人物 API、任务系统和角色详情页面。工作区已有未提交的人物设计、音色与身份相关修改，实现计划必须以当时工作区为基线协调，不能覆盖这些工作。

## 3. 剧情选角档案

档案分为三层：

1. **原文事实**：年龄、物种、明确外貌、特殊标记，以及时代、身份与经历。事实保留稳定 ID、原文摘录、来源文档版本和定位。复用已有 fact/source span；只有明确且可信的事实成为硬约束。不同身份阶段的事实按阶段适用，不能把晚年的外貌强加给少年阶段。
2. **造型解释**：每条记录目标视觉属性、具体设计、选角理由和所引用的事实 ID。没有原文支持的内容标为“创作选择”，不伪造引用、不补造人物经历。生活环境对妆发或养护状态的影响属于解释，不自动升级为原文事实。
3. **项目审美**：写实程度、时代妆感和修饰程度形成可版本化快照。人物共享项目风格，但不共享同一套脸。原文明示的俊美或精致必须保留。

用户可以修正解释和创作选择；事实纠错进入可追溯的事实修订，不能仅修改一条提示词就绕过明确约束。事实相互矛盾时展示冲突并要求澄清后再生成受影响的方案。

三套提案共享硬约束，各自展示选角理由、外貌设计、剧情依据和自由创作部分。差异应是合理的选角解释，不能只换发型或服装。原文约束过强、无法形成三套有效差异时返回说明，不为凑数改写事实。非人角色沿用物种约束，不强套人类五官、年龄皮肤或服饰模板。

## 4. 模块职责与数据流

| 单元 | 输入与输出 | 边界 |
| --- | --- | --- |
| 档案构建 | 已合并的角色事实、身份阶段、项目风格 → 带版本的选角档案 | 不重新抽取全篇，不生成图片 |
| 提案设计与校验 | 档案、其他已确认角色设计 → 三套选角提案及问题 | 区分事实和推断；复用现有提案机制 |
| 提示词编译 | 已选定提案、硬约束、项目审美快照 → 不可变生成快照 | 确定性编译，不新增人物经历 |
| 候选生成 | 生成快照 → 候选资产、任务状态 | 不直接替换当前头像 |
| 选角检查 | 候选图、生成快照、项目角色参考 → 分项证据与结论 | 与身份一致性检查分开；不负责激活资产 |
| 定角服务 | 用户确认、候选 ID、预期版本 → 当前头像引用更新 | 校验权限、版本和资产完整性，记录操作 |

档案与提案扩展现有 visual workspace 存储，避免建立第二份事实来源。候选记录关联角色/身份阶段、档案版本、提案版本、风格版本、提示词快照、任务、图片与检查结果。记录与图片在服务重启后仍可恢复。

“选定提案”仅确定候选生成依据；“确认定角”才激活该提案对应的 visual bible 和头像。现有当前头像与当前 visual bible 在定角前保持一致，不能先更改当前 bible 再等待图片。下游资产继续引用既有版本，按现有版本/失效机制提示需更新，不自动批量重建。

## 5. 生成要求

将可见年龄、面部结构、发型妆容、肤质、修饰程度和个体特征写成具体要求。优先级为：适用阶段的明确原文事实 > 用户选定的角色设计 > 项目通用审美 > 模型默认倾向。

保持近正面、完整头部、干净背景、中性光线等身份锚点构图。剧情适配体现在人物本身，不以戏剧灯光、背景或复杂服装掩盖选角偏差。缺乏依据时不默认年轻化、磨皮或添加沧桑感。所有本功能支持的图像提供方使用同一份编译快照；提供方适配只负责格式转换。

## 6. 检查与定角规则

分别展示三个维度，不合并为颜值分：

- **事实符合度**：对照明确年龄、外貌、物种和特殊标记；仅判断图中可观察属性，隐藏或无法观察的属性标为无法判断。
- **选角落实度**：对照已选方案关键特征，指出被弱化、年轻化、过度修饰或遗漏的地方，并关联对应依据。
- **角色区分度**：与同项目其他已确认人物头像比较，指出明显近似；剧情要求的亲缘相似作为上下文，不要求所有亲属彻底不同。没有参考头像时标为无法比较。

检查状态区分未开始、运行中、已完成和失败；已完成的分项结论区分符合、有偏差和无法判断。模型判断是辅助证据，用户承担最终定角决策。存在偏差、无法判断或检查失败时，界面必须显式展示，用户经明确确认仍可采用并记录原因，不能伪装为检查通过。确定性的版本冲突、资产缺失或提案违反硬事实校验不能绕过。

针对偏差重生成必须由用户发起，保留原候选和原检查。没有无限自动重试；沿用基础设施已有的受限技术重试，但不能因审美评分自动触发新的付费生成。

## 7. 用户流程与兼容

角色详情增加“剧情选角”入口，展示当前形象与新候选的区别：查看依据 → 修正创作选择 → 选择三套提案之一 → 生成候选 → 查看三类检查 → 确认定角或针对偏差再生成。

已有角色保持现状，仅主动执行“重新选角”才产生新档案/候选。缺少可信事实的旧角色显示依据不足；用户补充或确认可追溯材料后再建立约束，不能将旧提示词冒充原文事实。新角色沿用设计后生成的入口，纳入本流程，最终采用仍需明确确认。

编辑档案、提案或项目审美会产生新版本。历史候选保留并显示“基于旧方案生成”，不得当作当前方案候选直接确认；首版不提供隐式回滚旧方案定角。生成中的任务继续使用提交时快照，完成后按当前版本判断是否过期。

读取与编辑沿用现有项目角色权限。生成、修改和定角在服务端检查写权限与项目归属；不能仅靠隐藏按钮。定角带预期版本，重复提交幂等；并发修改导致版本不符时返回冲突并刷新状态，不覆盖其他人的选择。

## 8. 异常与费用

- 原文不足：明确展示缺失依据，允许有标记的创作选择，不补造事实。
- 提案不满足事实或差异要求：保留可解释的问题，不继续图像生成。
- 图像任务失败：显示失败原因，可由用户重试；保留当前资产。
- 检查失败：显示“未完成检查”，可独立重试检查，无需重绘头像。
- 网络中断或进程重启：通过持久化任务和候选恢复，不凭前端超时再次提交生成。
- 文件保存或定角写入失败：旧当前引用仍可用；不得出现已激活但无图片的状态。

复用现有成本采集，角色与项目归属随生成/检查任务传递。提供方未给出实际费用时保留估计或未定价语义，不把缺失费用记为免费。

## 9. 验收

### 自动验证

- 原文明示美貌、年龄、特殊标记、非人结构在提案与编译阶段不丢失；时代信息不被默认现代妆容覆盖。
- 创作解释能追溯到事实或明确标记为自由选择，禁止引用不存在的事实 ID；冲突事实不静默择一。
- 改方案、改风格、生成期间修改、并发定角和重复确认遵守版本与幂等规则。
- 生成失败、检查失败、检查无法判断均不会自动替换当前图；刷新后候选仍可恢复。
- 不同提供方接收到等价的选角约束；旧角色无主动操作时保持原资产。
- API 权限、跨项目候选访问、缺失文件以及激活失败覆盖有意义的集成测试。

### 视觉验收

实施阶段从当前真实项目选择至少四个有充分原文依据、年龄与身份气质不同的角色；其中应包括原文明示俊美/精致的人物，如当前项目不具备该类别则另用明确标注的测试剧本补充。角色名单在生成前记录，不能为凑类别改写原文。

同一角色并排展示现有头像、新候选、原文依据和已选设计；同时展示项目人物合照式对照以检查撞脸。图像模型、风格、版本与费用记录在案。验收要求：没有未解决的明确原文冲突，关键设计可见，人物差异可解释，俊美设定没有被“去网红化”误伤。主观剧情适配由用户最终判断，不以模型自评分宣称成功。

视觉伴侣已获授权，后续用于上述实际角色对照；本规格阶段尚未生成对照图，不将文字设计批准视为视觉效果验收通过。
