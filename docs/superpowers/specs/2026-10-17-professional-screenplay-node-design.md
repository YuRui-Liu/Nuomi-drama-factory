# 专业漫剧剧本节点 PRD

日期：2026-10-17

状态：用户已逐项确认核心设计；本文为书面规格，待整体审阅。功能实现与真机 E01 验收尚未完成。

## 1. 目标和适用范围

在统一画布内，让主笔与用户从已采用立意形成专业剧本，经明确采用后交给导演，最终支撑漫剧 E01 真实生产。每集一个剧本主节点，正文可连贯阅读，场景可定位、编辑、委托和追溯。大纲、人物、故事圣经、审稿报告与导演画面版为关联内容，按需展开。

本规格覆盖规划确认、正文创作、自动审改、采用、导演准备交接及已有节点兼容。后续图片、视频与整集合成复用正式生产链路；本次交接动作不包含媒体生成。漫剧指动画／动态漫影视作品，不含漫画书印刷分页。

上位依据：[统一 Agent／画布 PRD](2026-10-13-agent-canvas-prd.md)、[专业 Agent 与交接 PRD](2026-10-16-professional-agents-script-handoff-prd.md)。上游入口：[立意节点 PRD](2026-10-17-ideation-node-design.md)。方法及外部来源详见 [研究记录](../../research/2026-10-17-professional-screenplay-node-research.md)。

## 2. 已确认决策与优先级

| 议题 | 用户确认结果 |
| --- | --- |
| 节点粒度 | 每集一个剧本主节点，按场导航；选段委托，按需展开关联节点 |
| 开始创作 | 点击立意节点“创作 E01”先生成大纲与人物方案；用户确认规划后才写正文 |
| 正文格式 | 标准中文影视拍摄稿，不以镜头表替代主剧本 |
| 审改 | 初稿后自动独立审稿、有依据的有限返修，交付待采用稿 |
| 采用 | 只固定剧本版本，保留其他候选和历史，不自动交接或生成媒体 |
| 导演交接 | 显式点击“交给导演”，生成导演画面版、资产拆解和叙事组方案 |

规划确认这一决策细化并取代立意 PRD 早期“创作 E01 后一次完成全部产物”的概括。既有后端 bootstrap 的连续执行行为不能越过该确认点。确认规划和采用正文是不同决定；规划检查通过、正文审查通过都不等于用户已确认／采用。

## 3. 主流程和操作边界

1. **接收立意**：读取已采用立意及其简报快照，建立 E01 剧本主节点和关联内容。复用同集主节点，避免重复点击建立多个正式 E01。
2. **生成规划**：主笔产出故事大纲、人物方案、必要世界规则和目标集计划。连续剧包含分集梗概；单篇使用本篇计划。角色、场景、道具设计均属于文字设定，不购买素材。
3. **待确认规划**：展示主线、人物动机与关系，以及 E01 的目标、冲突、关键行动、结果或结尾。用户可编辑、局部委托或要求重写。采用立意仍可被查看和对照。
4. **确认规划并写正文**：动作明确命名“确认方案并创作 E01”。固定当前规划版本集合，开始正文创作及自动审改。确认时如有未保存编辑或来源冲突，先处理冲突。
5. **待采用稿**：正文与审改报告分开展示，支持阅读、比较、局部调整和再次定向创作。用户决定采用哪个具体修订。
6. **已采用**：固定剧本及其依赖，标明后续编辑形成的新修订。采用不发起导演任务。
7. **交给导演**：按当前采用版本执行导演准备，输出与剧本场景关联的画面版、资产拆解及叙事组方案。可查看已有交接、任务状态与失败原因。

用户可停止运行、返回编辑或切换画布，已保存内容与任务继续保持可定位。不存在固定页面阶段解锁；以上为内容依赖与用户明确选择的动作边界。

## 4. 画布与阅读编辑体验

### 4.1 节点外观与详情

收起的节点显示集号／标题、简短梗概、场数、正文状态、当前任务与主要操作；目标时长来自项目或已确认简报。估算片长单独标为估算，不将页数或字数等同实际片长。

展开后以正文为主要区域，配有场景导航。相关规划、角色、连续性和审稿信息按需打开，不默认挤占阅读区域。运行阶段可展开查看，内部模型调用和提示词不进入剧本正文。

画布坐标不决定场序。场序以剧本文档为准；移动关联场景节点不会重排剧情。场景重排是独立内容编辑，展示连续性与下游影响。

### 4.2 局部委托与人工修改

用户选中场景或文本范围后，可委托主笔、剧本编辑或台词专家，明确修改目的和范围。必要时将该场展开为关联节点，仍引用同一内容标识，不复制成另一份独立正式正文。

修订先作为候选。系统对比任务基线、最新正文和返回结果；自动应用仅限明确授权且无冲突的范围，其他部分保留。并发人工改动与 Agent 修改相遇时展示差异，不按最后写入者覆盖。

正文局部修改导致原审稿结论失效时，标明待复核及范围。用户编辑不会自动触发新的付费模型任务；主动提交定向修订时才运行相应检查。

## 5. 标准中文拍摄稿合同

正文遵循可读、可表演、可拆解的中文影视拍摄稿惯例。以下为产品约定的格式示例，不声称存在唯一强制行业排版标准：

```text
第 1 集《门后的来客》

1-1 老旧公寓客厅 内／夜
人物：林夏、周川

△ 林夏将湿外套搭上椅背。门外传来两声敲击，她的手停在椅背上。

周川（压低声音）：你还约了别人？
林夏：没有。

△ 门把手缓缓转动。
```

示例仅用于格式测试，不是本次 E01 已选题材或创作内容。

| 元素 | 要求 |
| --- | --- |
| 集标题 | 集号、标题；与目标集身份一致 |
| 场次头 | 可读场号、场景名称、内／外景和时间；特殊时空如回忆明确标注 |
| 人物 | 本场出场人物可识别；画外发声区别于画内出现 |
| 动作 | 可见、可表演、具有因果的动作与环境变化，使用 `△` 等既有解析支持的标记 |
| 对白 | 角色名和台词，必要时有简短表演提示；旁白、画外音清晰标注 |
| 声音 | 写明叙事必需的音效与环境声，避免无信息的音效堆砌 |

完整稿不得以“此处略”“自行发挥”代替必要剧情；不能把心理分析或场景意图当成可拍动作。允许题材需要的旁白、留白、喜剧重复与无对白场景，不机械要求每场相同节拍。

正文不混入镜头焦段、模型提示词、资产 ID、打分、检查清单或运行状态。稳定场景 ID、来源行／文本块锚点和修订存于结构元数据；场号是展示编号，调整编号不能破坏既有场景身份。拆场／合场保存继承关系并提示引用变化。

## 6. 专业规划与连续性

故事圣经是相关文档的统一视图，首版复用已有文档类型，不要求用户另填重复表格。

| 内容 | 专业关注点 |
| --- | --- |
| 故事主线 | 立意、核心冲突、行动因果、人物关键抉择、目标观众体验 |
| 人物 | Want／Need、恐惧与弱点、关系矛盾、行为边界、语言指纹 |
| 世界规则 | 与剧情相关的能力、代价、限制和例外；现实题材不强制构造奇幻规则表 |
| 分集计划 | 本集目标、阻力、行动与结果、观众回报、跨集承接；终集允许完整收束 |
| 连续性 | 人物已知／未知与获知来源、所在位置、关键道具归属、伤势／状态、伏笔埋设与回收 |

续写读取已确认设定、已采用前文、目标集计划和相关连续性记录。计划、推测、候选与已发生事实严格区分。记录需带来源，不能让模型推断自动升级为硬事实。用户可修正并查看影响。

上下文超限、缺失必要前文或来源不可读取时保留任务并报告具体缺口，不能无声裁掉关键材料。并非每个普通场景都必须填满所有属性，记录以故事实际需要为准。

## 7. 自动审稿与有限返修

复用现有 `run_craft`，正文流程为：初稿 → 独立结构审查 → 必要结构返修及复查 → 台词诊断 → 必要台词整合 → 改动后的最终复查。

- 正文结构返修最多两轮；规划文档沿用最多一轮。达到上限仍有阻断问题时进入需处理状态，保留草稿与证据，不能伪报合格或自动开启新一轮。
- 独立审稿不依赖作者自评分；每个问题保存原句／位置、维度、影响和修复目标，同时记录值得保留的有效设计。
- 检查人物动机、因果、信息边界、连续性、场景必要性、对白和格式。用户风格为权威；审美偏好作为建议，不因未达到固定金句／爽点配额而阻断。
- 台词整合只改变有依据的措辞与必要相邻动作；新增事件、人物调度或情节结果属于剧情级修改。
- 超出确认大纲或授权范围的修复，提交建议并等待决定，不能借自动审改改变核心故事。
- 报告绑定确切正文、输入和方法版本；文字更新后旧报告显示过期。模型“已修复”的自述必须由复查证据支持。

正文、创作笔记、审稿报告与对外交付分别保存。提示“审查完成”不等于“已采用”，也不等于媒体已制作或整集验收通过。

## 8. 内容、运行与版本模型

产品状态分为三类，不能混成一个成功标记：

| 维度 | 语义 |
| --- | --- |
| 内容决策 | 规划候选／已确认规划；正文草稿／待采用／已采用；新修订不替换旧采用 |
| 执行状态 | 未运行、运行中、失败、停止、需处理、来源变化、完成；映射已有任务实际状态 |
| 下游状态 | 未交接、导演准备中、准备完成、交接失败、来源已有新版本 |

规划确认记录包含相关文档的准确修订与来源立意版本。正文任务冻结该集合，采用候选时验证依赖仍对应确认内容。修改规划后须重新确认变更内容，不能复用失效确认继续写。

一个文档拥有多次修订和采用历史，一个画布节点引用文档而非拥有独立正文副本。跨画布引用保持内容来源明确；独立创作分支须显式创建候选／副本，不能由拖动节点暗中产生。

保存任务身份、授权范围、节点／文档引用、输入修订、实际方法配置、模型路由、阶段结果和错误。提交响应未知时查原任务；输入未变才可恢复原运行，输入变更则提示基于新版本重新执行。保存设置不追改历史任务记录。

## 9. 采用与导演交接

导演交接后的节点、专业协作、制作与剪辑导出细化见 [导演与成片节点 PRD](2026-10-17-director-production-nodes-design.md)。后续用户明确选择采用方案、开始制作、局部重生成和正式导出分别启动，该约定细化本节的下游行为。

采用检查目标修订、确认规划依赖和审稿结论是否仍有效。阻断问题未解决时保留待处理状态；普通建议不强制返修。采用事务固定该版本，旧采用版本及产物仍可追溯。

“交给导演”以明确采用版本为输入，复用正式交接服务及幂等任务记录。首次交接展示范围；已有制作来源时展示版本差异与影响，并明确是否替换。该动作不得静默采用新草稿。

导演准备交付三个相互关联的结果：

1. **导演画面版**：保留主稿剧情、人物关系及对白含义，补足出入场、站位、动作过程、表情与受击反馈、环境和声画承接。改变故事事实的建议回到剧本修订，不直接改写主稿。
2. **资产拆解**：按场景原文定位人物、场景和必要道具，关联已有实体／变体，显示缺失引用。仅生成清单和文字设计，不自动生成角色图、场景图或扩充道具库。
3. **叙事组方案**：包含组与来源场景、内容范围及顺序的映射，供正式生产链路消费。画面版完成不代表叙事组方案有效，必须分别记录真实结果。

提取失败、场景遗漏或对白丢失时不能把整次交接标为成功；保留已完成结果和原交接身份，按支持入口恢复。更换采用剧本后，旧画面版和方案仍绑定原版本，并显示需要评估的差异，不自动重生成功媒体。

导演准备完成后，由用户另行启动制作。生产继续使用项目保存的模型、画幅和并发，按叙事组分镜图 → 组视频 → 整集合成执行；不得由本节点绕过 CLI／API 变成逐镜头供应商循环。

## 10. Agent 能力与现有节点兼容

| 角色 | 节点操作职责 | 边界 |
| --- | --- | --- |
| 主创 | 目标、范围、上下文和岗位协调 | 不代替用户的规划确认和正式采用 |
| 主笔 | 规划、起草、续写、指定范围改写 | 遵守确认规划、风格和人工修改保护 |
| 剧本编辑 | 独立审稿、定位问题、提出修复目标 | 审美建议与硬问题区分，不自行扩大修改范围 |
| 台词专家 | 台词诊断与局部润色 | 剧情级改动须显式说明 |
| 导演 | 派生画面版、资产拆解与组方案 | 读取采用主稿，不偷偷重写剧情，不自动购买媒体 |

用户和 Agent 使用同一受支持操作，授权限定具体节点／文档、范围与动作。岗位配置可见不代表运行能力已接通；任务回执须带实际结果和来源。

专业剧本使用独立内容类型与操作合同接入画布。既有 `scriptNode` 的剧情转分镜表能力、数据及 API 保留兼容；菜单和详情区分“剧本创作”与“分镜脚本”，不得将旧镜头表内容按新正文格式解释。无需迁移用户已有媒体。

## 11. 现有能力与实现缺口

| 模块 | 可复用能力 | 仍需实现／验证 |
| --- | --- | --- |
| `script_creation/models.py`、store | 文档、修订、采用、候选 | 节点文档关联、规划确认集合及场景稳定身份 |
| `generation.py` | 版本冻结、bootstrap／续写、候选依赖 | 规划与正文分开启动，服务端阻止越过确认点 |
| `craft_pipeline.py`、craft store／report | 独立审稿、有限修订、台词处理、恢复与报告 | 节点内展示、局部授权、人工编辑冲突路径的端到端验证 |
| screenplay semantics | 场景、动作、对白与原文定位 | 标准中文稿往返保存、重排／拆合与来源映射验证 |
| `handoff.py` | 固定来源、差异、任务记录与恢复 | 现有 confirm 同时采用、写生产来源并可能派发语义提取；新增仅采用操作与独立导演准备操作，后者须校验采用修订；三类导演准备产物需完整联通 |
| 画布注册／机组运行 | 既有节点、授权、任务回填 | 新剧本操作路由、同文档引用、旧节点兼容 |

这张表是设计接入清单，不将既有后端模块等同于新增节点已上线。具体 API 字段和代码任务在实现计划中展开。

特别说明：现有 handoff 的 `update_scope` 控制生产来源更新范围，不代表三类导演准备能力。不能将“采用”按钮直接绑定 handoff confirm，也不能把语义提取完成当作导演准备全部完成。旧接口保持兼容，新节点的规划确认、采用与导演操作必须有服务端约束；相应验收测试需分别覆盖新边界，不能直接复用旧 bootstrap 自动完成正文的成功结论。

## 12. 验收与真机 E01

| 场景 | 可检查结果 |
| --- | --- |
| 立意进入规划 | 使用准确采用版本；只产出规划，确认前零正文生成任务 |
| 确认并写作 | 确认版本集合可查；生成完整中文拍摄稿和独立报告 |
| 规划被修改 | 旧确认不能启动新正文；差异、旧内容和任务可查看 |
| 局部改写 | 未授权正文保留；并发人工编辑不被覆盖 |
| 有限审改 | 有原文证据、实际轮次与停止原因；超限不循环、不假报通过 |
| 采用 | 固定修订，零导演／媒体自动提交；旧采用仍可追溯 |
| 交给导演 | 绑定采用稿，三类结果分别可查；未生成图片／视频 |
| 引用与恢复 | 重复提交／响应丢失不产生重复任务，冲突不暗换输入 |
| 兼容 | 旧分镜表节点打开、运行和媒体关联不退化 |
| 全链路 | 从立意经上述决策、正式叙事组生成到可播放 E01，任务与产物逐段可追溯 |
