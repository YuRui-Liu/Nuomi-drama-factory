# 立意节点：题材创意工作区设计

日期：2026-10-17。状态：A 方案可点击原型已获用户确认；本文供实现前审查。

## 目标与依据

立意节点首次打开即进入完整题材创意工作区，消除当前空白外层面板、嵌套设定弹窗和三列同时编辑造成的操作负担。参考 `origin/fix/codex-identity-qc` 的 ScriptSetter 题材融合、创作预设及六项设定组织；保留当前工作流的候选编辑、单方向重做、采用及版本化规划能力。

用户已选择 A：题材创意与立意方向两个阶段；已确认 `.superpowers/ideation-workspace-a-20261017.html` 原型。原型为示例数据，不是生产实现，尚未通过浏览器自动点击验收。产品实现沿用 NuomiDrama 品牌和现有设计令牌，不复制原型中的 SUPER TALE 标记、示例文案或模拟生成结果。

## 页面与操作

### 题材创意

- 打开立意节点直接呈现工作区。保留画布节点入口，替换其展开内容；不增加第二层“设置简报”弹窗。
- 左侧创作预设；主体包含主题材 × 融合题材、始终可见的故事想法，以及受众、角色、时代、看点、风格、结构六项设定摘要。
- 点击设定摘要打开侧边编辑抽屉；支持现有多选、自定义项与结构配置。应用后更新工作区草稿，取消则不改变草稿。
- 预设沿用现有设置器的字段及撤销逻辑，保留用户手写故事想法；不新增与 ScriptSettings 冲突的存储字段。
- 底部固定主操作“生成三个立意方向”，次操作“保存草稿”。保存草稿使用现有简报 API，反馈未保存、保存中、已保存或保存失败。
- 生成前先校验并保存当前简报；保存成功后使用返回的简报版本生成方向。保存失败不得生成，输入保持可恢复。
- 保留“自己写一个方向”次入口，填写现有四个候选字段后保存；不要求先进行 AI 生成。

### 立意方向

- 生成提交成功后切换到方向页，生成中显示明确进度状态；完成后左侧展示候选摘要，右侧展示选中方向的完整可读详情。
- 使用现有四字段：一句话立意、主角与核心冲突、故事看点、人物最终抉择。原型额外展示标题仅作为摘要呈现，不新增后端契约。
- 默认只读；点击“编辑方向”进入编辑，提供保存与取消。保存失败保留草稿，取消恢复服务端已保存内容。
- 切换查看候选与采用完全分离，切换不清除已采用状态。未保存编辑期间禁止采用、重做和规划；离开当前编辑提供保存、放弃或继续编辑的明确选择。
- “仅重做此方向”只影响目标候选；请求中禁用重复操作，其他方向仍可阅读，失败保留原内容并提供重试。
- “采用此方向”以候选 ID 和版本显式提交，成功后标记已采用。未采用时不显示可执行的规划主操作。
- 查看已采用的准确版本时显示“进入故事规划”；查看其他方向时仍提供“采用此方向”。采用与启动规划必须是两次明确操作。
- 返回题材创意保留草稿与已有候选；修改简报不自动重生成，不自动覆盖已采用方向。

## 数据与版本规则

复用 ScriptSettings、decodeBriefSettings、encodeBriefSettings 和现有简报文档 API；保留简报中的其他 Markdown，不另建原型 localStorage 存储作为正式数据源。编辑草稿按项目、节点、候选版本隔离，沿用画布草稿持久化方式。

沿用 creativeWorkflowApi 的 createIdeation、editCandidate、addCandidate、regenerateCandidate、adoptIdea、plan。请求继续携带 client_mutation_id 和 base_revision_id；API 负责最终版本有效性，UI 不自行伪造采用状态。

已采用记录固定引用 candidate_id、revision_id 与 brief_revision_id。后续编辑产生新版本，不把旧采用标记错误地显示在新版本上；保留服务端旧采用记录，提示新版本尚未采用。新简报不悄悄替换已采用的简报引用。规划必须使用采用记录绑定的简报版本及该版本的结构设置，不能混用最新简报的 mode/episodeCount。

规划保持现有 E01 剧本节点创建或复用及连线行为，只在用户点击规划后执行；不在采用时自动生成剧本、媒体或开启生产任务。

## 组件边界

- IdeationNode：画布适配、节点引用和工作区挂载。
- 题材创意内容组件：可嵌入的设定编辑内容，复用 ScriptSetter 数据与字段逻辑；保留其他页面原有 ScriptSetter 弹窗入口。
- 方向列表与详情组件：只读、编辑、采用、重做的展示与事件。
- 工作区状态协调层：阶段、选中候选、草稿、请求状态与 API 刷新。复用 useProductionAction，不把重复请求和错误处理散落在展示组件中。

## 视觉与可访问性

沿用现有暗色和黄绿色强调色，单一主操作层级；正文及主要控件约 14px，辅助文字不小于 12px。避免用缩小字体把内容强行塞进一屏。

在 1280×800 与 1024×768 验证内容不横向溢出、底部操作可达。主体滚动，抽屉独立滚动；窄屏将预设压缩为可展开区域，候选列表与详情改为纵向布局。使用可见焦点、字段标签、语义按钮、状态播报；抽屉支持 Escape 关闭并恢复触发按钮焦点。

## 异常与验收

无项目显示明确提示；加载、生成、保存、重做、采用、规划分别展示中文状态。失败保留用户输入与已有结果，错误靠近对应操作，不仅显示原始状态码。重复点击不创建重复任务；切换节点或项目时异步结果不得写入新上下文。

必须验证：首次打开完整创意区；设定抽屉应用与取消；保存失败不触发生成；生成成功切换方向页；编辑保存/取消/失败保留；切换候选不改变采用；单方向重做不改变其他方向；采用成功后才允许规划；规划使用冻结版本及对应设置；返回创意页保留输入；自写方向入口可用。

运行针对相关组件和 API 契约的测试、TypeScript 检查，并在两个目标视口实际点击主流程及检查截图。验证使用 mock 或固定测试数据，不调用付费生成。不要求为纯样式修改增加镜像实现的测试。
