# RunningHub 统一视频工作流注册表设计

## 背景与目标

项目的视频生产链路不再提供 NewAPI。当前唯一可用的视频能力是 RunningHub MiniMax H3，但系统不能把 H3 写死在页面、请求模型或任务执行器中。目标是建立注册表驱动的统一视频抽象，使当前界面只展示 H3，同时允许以后通过注册新的 RunningHub 工作流扩充和切换模型。

本设计覆盖叙事组视频生产链路，包括模型目录、项目默认值、请求校验、任务载荷和执行路由。它不开放任意工作流 JSON 上传，也不保留 NewAPI 兼容执行路径。

## 方案

采用服务端视频工作流注册表作为唯一事实来源。每个可生产工作流拥有稳定的模型 ID，格式为 `runninghub:<workflow-key>`。当前只注册 `runninghub:minimax-h3`。

注册项至少包含：

- 稳定模型 ID、展示名称、供应商和启用状态；
- RunningHub 工作流标识及执行适配器键；
- 支持的生成模式，例如自动、首帧和首尾帧；
- 支持的画幅、分辨率和时长约束；
- 叙事组视频等适用场景；
- 从统一请求到工作流节点参数的映射器。

工作流 JSON 和密钥属于服务端配置，不通过模型目录接口暴露。

## 后端边界

`VideoWorkflowRegistry` 提供以下稳定接口：

- 列出指定场景下已启用的工作流能力；
- 按模型 ID 解析注册项；
- 校验模式、画幅、分辨率及帧输入是否受支持；
- 返回对应的执行适配器和参数映射器；
- 返回当前场景的默认模型。

视频能力目录 API 直接由注册表生成。叙事组视频接口继续接受字符串模型 ID，但必须在注册表中解析为“已启用且支持叙事组视频”的工作流，否则返回 422。接口层不使用 H3 单值 `Literal`，也不使用 `runninghub:*` 前缀作为充分条件。

任务载荷保存稳定模型 ID。任务 runner 在执行时再次解析注册表，防止排队后配置被删除或停用；解析失败时返回明确、可诊断的工作流不可用错误。执行器根据注册项选择参数映射器并调用统一 RunningHub transport。H3 特有的导演提示词和节点映射留在 H3 适配器内，不泄漏到通用路由。

## 前端行为

前端只消费视频能力目录，不再与旧视频 backend 列表合并。

- 目录只有一个可用模型时，显示不可编辑的模型标签，例如“RunningHub MiniMax H3”。
- 目录存在多个可用模型时，显示模型切换控件，并允许保存项目默认模型。
- 项目保存的模型不存在、已停用或属于 NewAPI 时，内存中自动回退到目录默认模型；下一次显式保存时持久化新值。
- 生成请求始终提交目录中解析后的稳定模型 ID，不提交过期配置。
- 模式控件根据选中注册项的能力动态展示，不能假设所有 RunningHub 工作流都支持首尾帧。

因此，新增第二个 RunningHub 工作流后，叙事组页面无需修改即可出现切换能力。

## 数据流

1. 服务启动时加载并验证内置及配置化的 RunningHub 工作流注册项。
2. 前端读取视频能力目录和项目媒体默认值。
3. 前端以目录校验项目默认值，选择有效模型或注册表默认模型。
4. 用户保存方案并发起生成，前端提交稳定模型 ID、模式、画幅、分辨率和视频计划版本。
5. API 通过注册表校验请求后排队。
6. runner 再次解析注册项，通过其参数映射器生成 RunningHub 节点参数，并使用统一 transport 提交任务。
7. 结果、错误和调试元数据继续沿现有任务中心返回。

## 错误处理

- 未知、停用或不适用于叙事组的模型：422，不创建任务。
- 模式、画幅、分辨率或帧输入不满足能力约束：422，并返回具体字段错误。
- 排队后注册项失效：任务失败，错误标识为工作流不可用，不静默切换模型。
- RunningHub transport 失败：保留现有重试、并发限制和错误诊断；不得回退到 NewAPI。
- 项目旧 NewAPI 默认值：前端安全回退，不阻断页面使用。

## 扩充流程

新增 RunningHub 工作流需要：

1. 添加注册项和稳定模型 ID；
2. 添加或复用参数映射器；
3. 配置工作流 ID 与凭据引用；
4. 添加能力和 runner 契约测试。

不需要修改叙事组 API 模型、页面模型判断或通用任务 transport。

## 测试与验收

- 目录当前只返回 `runninghub:minimax-h3`，且不包含 NewAPI。
- 叙事组接口接受已注册 H3，拒绝 NewAPI、未知和停用模型。
- 旧项目保存 NewAPI 时自动选中 H3，生成请求提交 H3。
- 单模型时页面显示固定标签且无模型选择器。
- 模拟注册第二个工作流时页面自动显示选择器并能保存、提交该模型。
- 不同注册项使用各自参数映射器，H3 特有参数不会进入其他工作流。
- 相关前端组件、API 契约和任务 runner 测试全部通过。

## 非目标

- 不支持用户从界面上传任意 RunningHub 工作流 JSON。
- 不在本次改造中重写 RunningHub transport、并发调度或任务中心。
- 不保留 NewAPI 视频生成或自动回退路径。
