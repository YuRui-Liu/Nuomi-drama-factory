# 漫剧画布组织与返修管理设计

日期：2026-10-29。对话设计已确认，书面规格待审阅。

## 目标和范围

解决 Skill 制作过程和多轮返修中，同一镜头的结果分散、当前状态难辨的问题。更新 Toonflow 漫剧制作 Skill 的画布操作规则，并在实现阶段按同一规则整理《飞升骗局》的现有画布。仅改变画布展示和 Skill 操作方式，不改变作品内容、成果采用状态、真实依赖或媒体文件，也不发起生成。

现状：2026-10-29 只读检查《飞升骗局》画布时有 88 个节点和 30 条连线，实际数量可能继续变化；第 03 镜的原生成、修正版、风格返修及待修视频分布在不同位置。实际整理须重新读取，不依赖此快照作为当前事实。

## 画布组织

阶段顺序固定为：剧本与规划、角色与场景资产、分镜与首帧、视频与声音、成片。每一阶段在画布上有独立的可辨认区域；同一区内按集数和镜号排列。资产按角色、场景、道具等已有身份组织。采用阶段区域表达业务含义，不因展示关系虚构媒体连线。

单个镜头在其所属阶段聚合：当前采用成果与正在处理的返修候选紧邻。E1 镜 03 分镜返修放在分镜区对应镜头旁，视频返修放在视频区对应镜头旁；各自仍指向真实成果或任务。节点名称应包含集数、镜号、成果类型和简明状态；已有作品级资产按真实身份命名，不虚构集数或镜号。

画布默认展示当前采用版及正在处理的候选；旧版本节点移动到独立历史区域，保留节点、内容及所有连线。历史区域放在主要工作区外并可定位，名称和节点位置应能追溯原镜头。没有充分证据判断归属或状态的节点进入独立待确认区域，保留原名称和内容，不根据位置或生成成功推断采用。

在现有画布能力内优先使用坐标区域、已有节点标题与公开操作实现。画布 UI 有分组能力，但当前公开 Agent 操作清单未证明可创建或调整分组；不得假设自动分组接口存在，若未来公开相应能力再按实际 schema 使用。此设计不要求增加新节点类型、侧栏或额外 UI。

## Skill 日常操作规则

1. 先确认工作区与当前画布，分页读取已有节点、连线、绑定成果和任务状态；沿真实版本、采用及任务引用判断集、镜头、阶段和状态。
2. 为新操作先查找对应阶段、镜头和节点，优先复用现有节点；现有节点无法同时保留当前成果与候选时，在同一镜头旁建立必要的候选节点。不为每次检查或执行日志新建节点。
3. 有冲突、未知状态或记录不完整时，不把最新生成等同已采用，不覆盖已采用节点，不将它当历史；保留并标记待确认。
4. 返修候选采用后，先确认新旧节点及成果绑定，再将不再作为当前展示的旧节点移至历史区域。采用、版本和依赖关系继续由既有 production 操作维护；仅位置变化不修改连线或引用。
5. 新增或移动节点前读取尺寸和占用位置，按阶段和镜号选择不重叠的位置，给同镜返修预留空间；实际节点较大时允许区域扩展。执行后回读节点与连线，检查是否遮挡，必要时定位相关节点查看。
6. 候选仍在进行中时放在对应镜头旁；失败或拒绝的候选不冒充当前成果，保留记录并归入历史或待确认。详细过程、错误、提示词和任务记录留在既有成果与任务中，不将日志堆在画布。

画布上的普通媒体节点未必有 production 引用或采用状态；只有实际可核对的引用、任务结果、用户明确指定或已有采用记录才能确定状态。单凭名称中的“候选”“最终”不视为采用证据。

## 整理《飞升骗局》画布

1. 用现有公开画布读取接口分页获取全量节点、坐标、必要绑定字段和连线；读取相关成果采用与任务状态，生成整理映射：节点 ID、现位置、归属、状态、目标位置及判断依据。把无法确认的项列入待确认，不删除或自动归档。
2. 以当前画布数据确定区域尺寸和坐标，按照真实阶段、集数和镜头建立位置安排。存在绑定、内容或连接关系不明时按待确认处理；历史节点移走前确认其不是当前采用或正在处理的候选。整理清单应能让操作者在执行前核对原位置和目标位置。
3. 使用已公开 `moveNodes` 分批移动（每批不超过 64 项），必要时使用 `renameNodes` 仅调整已能确定的节点标题。既有分组子节点必须先确定父子坐标与移动行为，不直接假设顶层坐标；不能安全移动时留在原处并报告。不得用全图 `arrangeCanvas` 代替按阶段／镜头的业务布局，不直接改写画布 JSON。
4. 每批前后核对画布身份和被操作节点；若作品、节点或连线被其他操作改变，停止并重新读取受影响部分，不覆盖并发改动。移动或重命名失败时，记录已完成批次和未完成项，不重复盲写；依据整理前的位置映射通过公开接口恢复需要回退的节点。
5. 移动后等待实际保存，分页回读全量节点和连线，对比节点 ID、绑定、连线端点及数量，确认没有删除、重建或意外改动；用可视检查确认分区、镜号与返修相邻且不重叠，至少检查第 03 镜和一处跨阶段节点。若保存失败、尺寸未就绪或无法读取，明确报告未完成范围，不声称整理成功。

保留现有画布、历史素材和生产记录；不新增概念连线、清理节点或发起供应商任务。用户以后明确要求清理时再单独处理。

## 验证与边界

Skill 内容自检：制作与返修都先查重、按阶段和镜头定位；区分已采用、候选、历史和待确认；不能发明未发现的操作；不自动删除、替换成果或触发付费。按仓库规范不新增测试文件、测试专用导出或检查脚本。

实操验证仅使用当前作品的公开操作和实际画布：执行前后核对节点、绑定和连线；检查不同阶段及同一镜头返修的位置；确认历史节点仍可定位。不能访问画布或遇到并发修改时保留现状，报告具体限制。若后续发现现有公开接口无法可靠实施分区或回退，先报告缺口，不宣称已整理；不扩展成另一个画布产品功能。

本轮先提交规格供用户审阅。获批准后编写实现计划，再执行 Skill 修改与画布整理；保留工作树中已有改动。
