# 专业 Agent、剧本交接与漫剧成片：交互设计稿

日期：2026-10-16。状态：文字交互按本轮确认同步；原九页 Pencil／PDF 为讨论前草稿，尚未重画，不能视为本轮已批准的视觉稿。本文件配合 [PRD](2026-10-16-professional-agents-script-handoff-prd.md)，不替代已批准的 [统一画布 PRD](2026-10-13-agent-canvas-prd.md)。

## 1. 设计载体与边界

设计载体为 Pencil MCP 打开的 `E:/Proj/nuomi.pen`。原有空白画板保留，新画面以 P01—P09 命名。P01—P06 展示局部选择、交接和修订；P07—P09 补齐专业团队、完整制作任务与成片交付。Pencil 用于表达界面、状态和转移；只有实际建立并验证的跳转才可称为可点击原型。屏幕间的文字指引和节点 metadata 不等于可运行交互。

视觉沿用 `frontend/src/index.css` 的 NuomiDrama Editorial Black：背景 `#0D0E10`、面板 `#14161A`、浮层 `#1A1D22`、边框 `#2A2F37`、正文 `#F2F4F7`、次要文字 `#9299A5`、主操作 `#E5FF5C`。字体采用可读的中文无衬线体；状态同时使用文案，不只靠颜色表达。

本轮新增交互设计不创建旧阶段工作台。目录是选人入口，交接是内容进入当前工作空间的动作，主创继续在画布侧栏协作。

## 2. 九个核心状态

以下编号用于覆盖状态，不表示独立页面或强制导航顺序。已确认统一布局：中央内容节点＋默认收起的关联任务；现有 Agent 侧栏唯一主输入与委托进展；节点就近编辑、运行、委托、影响分析；参数、候选、来源与播放按需展开。目录、进度和交付回到原工作空间，保留选择与视图。

P01／P07 应作为团队目录的按需入口，P02 为详情及委托，P03／P05 为交接和差异；P06／P08 为当前任务的进展与恢复，P09 为画布内交付与预览。制作新视觉稿时核对既有节点、侧栏和编辑器，不能直接沿用旧草图的独立页面布局。

P01—P09 是评审用状态编号，不是产品阶段，也不要求用户按顺序访问。完整制作目标与“仅交接整理”明确区分：后者在草案完成后交付，前者在有效授权内继续推进到成片，不能每一项交接后都停下来等待再次指挥。

## 3. P01：用任务选择 Agent

默认展示内置与我的 Agent，并可按故事剧本、视觉分镜、连续性等任务筛选。搜索同时匹配角色名称、职责、输入和交付；筛选后保留搜索词及当前画布上下文。

每个条目包含名称、一句话职责、输入摘要、交付物、能力状态和来源。P01 为当前任务推荐摘要，完整 18 岗位在 P07 展示，包含创意、主笔、站位、灯光、动作、表情和 MiniMax 执行等。职责与交接见 [专业 Agent 契约](2026-10-16-manga-production-agent-contracts.md)。推荐必须有简短理由，例如“当前已有剧本，适合整理冲突与人物动机”。推荐不自动更换项目主创。

能力状态区分文本草案可用、媒体能力依当前接入、缺少配置、暂不可执行。方法模板可浏览，不把模板名称显示为已经接通的生产能力。加载失败保留旧列表并给重试；搜索无结果显示清除筛选和新建 Agent；没有个人配置时给复制内置配置入口。

## 4. P02：详情、示例与范围

详情默认先展示交付示例，再展示方法与能力。示例标注来源、模型或工具条件及证据：仅成片、公开提示词、公开输入、公开工作流、独立复现分别表达。没有素材时展示结构化文字示例，不伪造实测作品或复现记录。

“设为项目主创”和“委托当前任务”是不同动作。切换主创展示项目采用的固定版本；不自动升级其他项目，不重新归属既有运行任务。局部委托显示选中内容和必要依赖；默认范围外只读，额外修改必须说明影响。

点击委托先保存任务边界并给回执，再进入对应画布的任务状态。缺少必要输入时原位指出，保留用户编辑；能力未接通时提供保存配置或仅生成文字方案的明确选择。重复点击复用正在提交的动作，不新建多个任务。

P02 与 P03 共用集中授权卡子状态：涉及付费调用时，展示本次内容、数量、预计费用、预算上限与不确定项。已有有效且覆盖本次范围的授权则直接继续；没有覆盖授权时，用户确认后才提交付费调用。取消授权保留输入和准备结果。首次点击“委托”或“交接并整理”不等于授权任意付费文本处理。

## 5. P03：交接原稿与可编辑草案

P03 与 P04 的现有画面示例对应“仅交接整理”目标，不是完整制作任务的终点。用户已明确要求制作成片时，交接是全链路中的内容准备，完成后主创按 P08 在有效授权内继续；不得因交接动作完成而要求用户重新发出每个后续任务。

原文区提供文件名或剧本名称、修订、更新时间、可读正文，以及字符或场次概要。交接清单分别列出原文、已有确认设定、参考素材和待提取候选。候选不得用“已确认”样式呈现。

目标画布默认采用用户当前上下文；从项目入口进入时推荐项目构思画布，也允许当前集或自由画布。创建画布不要求创建分集。默认继承项目主创，可在同一位置选择其他适用配置。

主操作为“交接并整理草案”。说明其结果：保存来源与采用版本，建立可编辑内容，主创整理并给出后续建议。文本处理若涉及模型调用，应按实际配置展示，不承诺免费；媒体生成不因交接而自动发生。

点击后立即给出提交状态；用户可离开，任务继续。取消预览不提交。解析失败保留原始输入，指出可重试或手动补充的内容；参考素材不可用时明确缺项，不声称完整接收。

## 6. P04：内容占主要空间，主创就近解释

画布示例使用“雨夜来信／雨夜追逐”这一虚构项目：原文、剧情片段、角色设定与镜头草案保持可见关联。组名表达创作内容，不使用阶段编号。连线区分参考与派生，不能把画面位置当作成片顺序。

主创侧栏展示“本次目标—输入范围—正在做什么—已交付—未满足项”。完成整理后明确列出原文和草案的数量、待确认设定和可选下一步。接受了交接与整理完成分别回执；整理失败时不能把整项交接伪报成功或丢弃已保存的原文。

新内容以草案进入画布；对现有内容的修改以候选呈现。用户可直接编辑、采用、撤销或局部委托；候选未采用不意味着任务必须继续运行。来源、配置版本与运行记录按需展开，避免用技术字段占据默认画面。

## 7. P05：重交接不覆盖人工编辑

同一请求身份因网络重试再次到达时，返回既有回执。新的用户动作即使来源修订相同，也必须检查目标画布与范围，并展示已有交接的重复提示；用户明确继续后按新任务处理，允许同一修订交到另一画布或采用不同范围。重交接比较选定目标的上次采用版本，计算新增、修改、删除与本地编辑冲突，不能仅按源修订去重。

展示三种信息：上次采用的来源、当前人工编辑、新来源内容。默认保留人工编辑，将冲突改动作为候选；用户可以逐项采用新来源、保留当前内容或手动合并。对来源删除不默认删除已有媒体或下游成果。

应用前展示所选内容及受影响引用。未选择的内容保持当前版本；存在运行中的关联任务时，旧任务仍基于原始快照，返回结果不能静默覆盖新内容。用户改变选择不会自动触发付费重生成。

## 8. P06：可理解的失败与恢复

状态至少区分提交中、已接收、执行中、部分完成、完成、失败、已停止、状态待核实。交付目标与实际结果逐项对应，成功产物直接可打开；失败行能定位画布内容并说明阻塞原因。

恢复前显示复用哪些结果、还会执行什么、输入是否变化及授权是否仍有效。原范围、输入和预算均有效时不重复确认；需要扩大范围、超预算或新增替换权限时集中展示差异。提交状态未知先查询或对账，按钮显示“查询任务状态”，不提供盲目重复提交。

停止阻止后续提交；已提交且不能取消的外部任务展示真实状态，产物返回后保留但不自动继续下游。停止、撤销内容修改与放弃候选分别提供入口。

## 9. 键盘、窗口与可访问性

- 输入和筛选有可见标签；搜索清空、返回详情和关闭浮层后保留上下文。
- 弹层打开后焦点进入标题或首个可操作控件，关闭后回到触发位置；Escape 不取消已经提交的后台任务。
- 主操作、危险操作和能力不可用状态既有文字也有视觉差异；禁用按钮旁解释原因。
- 桌面采用画布＋侧栏；窄窗口将详情与任务侧栏改为可关闭面板，保留画布位置与选中内容。原型首先验证桌面，不声称移动端已验收。
- 长剧本、角色名和任务名允许折叠或换行，不能遮挡主操作。任务状态更新通过可访问通知表达，但不反复抢焦点。

## 10. 设计验证清单

1. 从目录能判断输入与交付，从详情能判断真实能力与采用版本。
2. 交接前能看清原稿、目标画布和默认整理范围；没有隐式媒体执行。
3. 画布区分来源、确认设定与草案；主创输出与可编辑对象对应。
4. 重交接保护人工编辑，重复提交不重复建内容或执行任务。
5. 部分失败保留成功产物，未知状态先查询，恢复不重复确认有效授权。
6. 九个状态中的按钮、文案与 PRD 行为一致；布局无裁切，文字和控件可读。
7. 首次付费文本交接展示集中授权卡，确认前不提交付费调用；有效授权范围内恢复不重复询问。
8. 同修订跨画布或不同范围交接可创建明确的新任务；仅相同请求身份的重送复用旧回执。
9. 完整制作目标能看到实际组产物、专业方案如何进入执行、授权消耗和阻塞；主创不能在分镜草案处宣称目标已完成。
10. 成片以实际可播放文件和本次要求验收；缺关键组、必要声音或字幕时明确部分完成。播放占位和示例状态不能作为功能验收证据。

## 12. P07—P09：完整制作的新增交互

P07 的岗位按创作职责组织，不设置解锁顺序。每个岗位都应有独立方法、结构化交付和当前接入状态；用户可挑选角色局部委托，主创也可按整片目标调度。没有调用的岗位不显示虚假执行记录，未接通能力明确标出。

P08 展示已授权的整集目标、画幅/时长来源、预算与费用占用、每个叙事组的实际图像和视频产物，以及等待或阻塞原因。站位、灯光、动作、表情等专业输出在组详情中可展开，能追踪到导演采用版本和实际生成请求。缺少引用时先复用或按授权补齐，独立组继续；恢复以原任务和有效结果为基础。并发读取保存配置，执行依赖为整组分镜图到整组视频再到合成，不要求用户逐阶段切页。

P09 必须加载实际合成文件。播放暂停后可定位相关叙事组、台词、参考和音轨，发起最小范围的修改提案。交付清单显示必要组、关键剧情、声音字幕和可播放性；输出实际时长、画幅、可取回文件与未满足项。缺关键组不得显示完整交付。原型的播放占位只验证布局，不代表真实视频已生成。


## 13. 本轮确认后的原型核对清单

- 选中内容委托专家，关联任务默认收起，可展开查看输入、调用、结果和后续修改。
- 剧本按目标逐步展开，完整目标持续推进，局部目标不扩大。
- 专家可直接调用授权节点，生成状态与文字方案明确区分。
- 本体关系用于影响解释；显示确定依赖与不确定推断，候选不冒充事实。
- 修改与分层检查定位到具体节点，保留有效产物，预算与重试沿用原规则。
- 五项配置、版本、真实能力状态和案例证据可查看；缺少接入不伪装可执行。
- 从预览定位内容并局部修改，真实播放及导出须由实际业务验收。
