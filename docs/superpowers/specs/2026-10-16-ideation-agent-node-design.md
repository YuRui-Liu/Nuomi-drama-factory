## 1. 目标与范围

补齐专业 Agent 与画布入口，先完成立意 Agent 的添加、配置、运行、候选比较和采纳闭环。用户选择布局 A：节点内保留常用输入，完整创作设定展开编辑。交互和样式均参考 `fix/codex-identity-qc`，核对时提交为 `d4f9e68`。

本规格是现有 Agent 画布设计的增量，不恢复固定阶段流水线。已有通用主创、文本编剧继续可用，新增立意专业角色；新增入口能够承载已有角色，立意使用专用设定面板。更多专业角色沿同一入口扩展，但分镜等角色的专用编辑器不纳入本次立意闭环。

- A（采用）：节点内选择题材、编辑故事种子、查看设定摘要；展开完整设定器。保持画布紧凑，沿用原交互。

- C（未采用）：右侧面板编辑全部参数，节点轻量但切换上下文频繁，与现有侧栏需要协调。

## 3. 入口与节点

画布添加入口增加可发现的 Agent 入口，选择角色后创建对应节点。立意角色开箱可用，不要求先填写职责、工具权限等管理配置。角色名称和用途对用户可见，节点绑定明确的 Agent 配置版本。

立意节点包含：名称、运行状态、主题材、融合题材、故事种子、完整设置摘要、展开设置入口、生成按钮，以及候选结果入口。节点内题材可直接选择，允许不融合。节点与展开设定器读写同一份已保存设置。

展开设置时创建编辑草稿；保存成功后更新节点，取消不应用草稿。节点内直接编辑走现有画布保存路径。运行使用已保存的输入快照；保存失败时不以未持久化设置启动生成。

## 4. 复用原分支的交互与视觉

参考实现是 `frontend/src/features/script-creation/script-setter.tsx`、`script-setter-data.ts`、`script-setter.css`。核对时三个文件与当前分支均无差异。优先复用这些组件、选项和样式；必要的共享抽取限定于本次消费者，不复制第二套设定规则。

完整面板保留：

1. 左侧创作预设、选中态、显示预设开关和撤销预设。
2. 主题材与融合题材两列，中央重叠圆形融合展示；支持不融合和自定义题材。
3. 六项设置：目标受众、角色设定、时代背景、核心看点、画风、剧本结构。
4. 设置抽屉中的分组、搜索、多选、自定义输入、已选项移除及完成设置。
5. 故事种子文本、单集／连续短剧、计划集数、目标时长。

切换预设保留故事种子、篇幅和原组件未管理的字段；撤销不得覆盖用户在应用预设后手动修改的字段。中文输入法、数值归一化、保存错误与防重复保存沿用原行为。

视觉沿用深色底板（`#111317`、`#14161A`）、灰色边框（`#2A2F37`）、黄绿色主操作（`#E5FF5C`）、绿色／暖棕融合圆、选项标签、卡片层次及圆角。完整面板保留原有桌面布局与窄屏重排；节点外框、连接端口和选中态服从现有画布规范，内容区延续设定器视觉，不重做全局主题。

保留键盘焦点、可访问名称、对话框关闭与焦点返回行为。输入、选项点击和滚动不得误触画布拖拽或缩放。

## 5. 运行与候选

运行路径：节点已保存设定及显式引用 → 输入快照 → 现有 Agent 运行服务 → 结构化立意候选 → 节点显示结果 → 用户采纳 → 后续 Agent 可显式引用。

立意角色依据题材和设定提出 3 个可比较方向。每项包含标题、一句话立意、主角目标、核心冲突、主要看点和可展开方向；允许用户修改候选后采纳。三个方向是产品输出要求，结果不完整时显示问题并允许重试，不伪造补齐。

运行记录保存项目、画布、节点、Agent 版本、设定快照、引用版本和候选标识。沿用现有服务的权限、幂等、版本冲突和作用域校验，不在前端新增直接模型调用。

生成完成仅表示候选可供审阅。采纳是显式操作，关联选定候选版本；后续 Agent 引用采纳结果，不将全部候选当作确定事实，也不因连线自动运行下游。用户可独立使用立意节点，不要求执行后续阶段。

修改已保存设定后，保留历史候选并标记其输入已变化。重新生成建立新一轮结果，不覆盖历史；已被下游引用的采纳版本不静默替换。

## 6. 模块边界

| 单元 | 职责 | 依赖 |
| --- | --- | --- |
| 专业 Agent 目录 | 名称、职责、内置版本与可用能力 | 现有 `creation/builtin_agents.py` 和 Agent 配置服务 |
| 画布 Agent 节点与入口 | 添加、设定摘要、运行和结果入口 | 节点目录、画布状态和保存机制 |
| 立意设定编辑器 | 题材、预设、六项设置及草稿 | 共享 `ScriptSettings`、原设定器和样式 |
| 立意运行适配 | 将保存的设定与引用转换成运行输入 | 现有 Agent 运行契约 |
| 候选与采纳适配 | 结果校验、比较、编辑、采纳与版本引用 | 现有提案和创作对象机制 |

候选内容沿用创作对象／提案的权威存储，节点保存引用和展示状态，避免新增互不一致的副本。节点类型、接口字段与兼容适配在实现计划中逐项映射到现有代码。

## 7. 错误、恢复与冲突

- 设定保存失败保留编辑内容并允许重试，不关闭编辑器或启动生成。
- 运行中禁止重复提交；状态不明时先查询已有运行，不盲目重新发起。
- 失败展示可理解的原因并允许重试；停止和刷新恢复沿用已有运行服务。
- 运行期间修改输入，返回结果归属原快照，显示已过期而不覆盖新设定。
- 节点删除、切换画布或作用域变化时，不将迟到结果应用到其他节点或画布。
- 采纳遇到版本冲突保留候选并提示刷新后重试，不静默覆盖已采纳内容。

## 8. 验收

1. 从画布入口添加立意 Agent；默认可运行，无需先创建个人 Agent。
2. 节点内题材与完整设定器保存后相互同步；取消草稿不改变节点。
3. 原预设、融合展示、自定义、搜索、多选、撤销及中文输入行为保持一致。
4. 生成获得三个真实候选，可比较、编辑和采纳；后续 Agent 可引用明确采纳版本。
5. 输入修改标记旧候选；重复提交、失败重试、停止、刷新和迟到结果不造成重复或跨画布应用。
6. 用原分支设定器作视觉基准，检查深色配色、融合圆、题材选中态、六项卡片、抽屉及窄屏表现；检查节点输入不误触画布操作。

测试覆盖设置同步和取消、运行快照与输出契约、幂等及作用域、采纳版本与冲突。复用原设定器测试，新增针对节点集成的回归；完成实际界面检查与一条立意生成到采纳引用的运行验证，不用静态原型替代运行验收。
