# 规划期资产绑定与生成前引用选择设计

## 背景

当前“生成前引用确认”同时承担引用匹配、资产追加、上传归类和本次选择。正式资产与临时素材混在同一区域，资产按钮只有单向添加动作，没有可靠的选中状态与取消入口。场景变体还可能在生成预览阶段通过拼接名称创建，导致实体关系建立过晚、命名不稳定，也无法明确判断某张图究竟属于角色身份、场景变体还是道具。

本设计把正式关系建立提前到身份、场景和道具规划阶段。生成阶段只消费已规划关系、选择本次使用的子集，并允许添加不持久化的临时上传。

## 目标

- 规划身份、场景和道具时建立规范资产实体、变体与叙事范围之间的稳定链接。
- 唯一匹配自动绑定；歧义、缺失资产或缺失图片进入明确的待处理状态，不通过相似名称猜测。
- 生成阶段不创建正式资产、不创建变体、不修改绑定、不拼接资产名称。
- 已规划引用默认全选，整张卡片可点击选择或取消，并提供明显的高亮、勾选、状态文字和计数。
- 保留仅供本次生成使用的临时图片上传；临时图片可移除，但不写入项目资产或绑定关系。
- 后端使用稳定绑定 ID 校验选择并冻结引用快照，使任务可复现。

## 非目标

- 不在生成弹窗中提供“从资产库自由追加正式资产”。
- 不在生成弹窗中提供上传并保存为角色、场景、变体或道具的表单。
- 不自动修复历史项目中语义含糊的名称，也不静默猜测旧名称对应的实体。
- 不改变图像模型、生成模型或分辨率配置逻辑。

## 核心模型

新增持久化的规划引用清单。实现可复用现有 `ReferenceRequirement`、`ReferenceBinding` 和生产资产槽位语义，但清单必须在规划成功时写入 SQLite，而不是到生成预览时临时推导。

每条 `PlannedReferenceBinding` 至少包含：

- `binding_id`：稳定且项目内唯一的绑定 ID；客户端提交它，不提交显示名称或文件路径。
- `project_id`、`episode_number`：所属项目和集数。
- `asset_kind`：`character_identity`、`scene_base`、`scene_variant` 或 `prop`。
- `entity_id`：规范实体 ID。
- `base_entity_id`、`variant_id`：存在变体时分别记录基础实体和变体；不得通过连接显示名称表达关系。
- `asset_slot_id`：对应的逻辑生产资产槽位。图片版本更新后绑定仍然有效。
- `group_ids`、`beat_ids`：适用的叙事组和 Beat 范围。
- `required`：是否为生成必需引用。
- `status`：`ready`、`pending_confirmation`、`missing_asset` 或 `missing_image`。
- `resolution`：`auto_matched`、`manually_confirmed` 或 `explicit_fallback`。
- `display_label`：只用于界面展示，不参与匹配和身份判断。

规划产物、规范资产/变体和绑定清单必须在同一规划事务中提交。规划失败时不得留下半成品关系。

## 规划期行为

身份、场景和道具规划器在建立实体与变体后立即生成绑定：

1. 使用规范实体 ID 和结构化变体 ID 匹配资产槽位。
2. 唯一且类型一致的结果写为 `ready`，并自动绑定。
3. 多个候选、类型不一致或旧数据只有模糊名称时写为 `pending_confirmation`。
4. 实体不存在时写为 `missing_asset`；实体存在但没有可用图片时写为 `missing_image`。
5. 明确的回退关系必须在规划期写为 `explicit_fallback`，生成阶段不得自行回退。

场景变体由规划器创建并保存独立 `variant_id`。禁止在引用预览或生成提交期间调用类似 `基础场景_变体描述` 的名称拼接逻辑。角色身份/状态和道具外观状态遵循相同的“基础实体 + 结构化变体/状态 ID”关系。

## 生成期数据流

1. 引用预览接口按项目、集数、叙事组读取规划引用清单。
2. 服务端根据 `asset_slot_id` 解析当前采用的图片版本和缩略图；不重新按名称匹配。
3. `ready` 且适用于当前组的引用默认选中；响应同时返回由绑定更新时间和当前图片版本计算的 `reference_revision`。
4. 用户提交选中的 `binding_id[]`、临时 `upload_id[]` 和该 `reference_revision`。
5. 服务端重新校验绑定的项目归属、集数、叙事范围、状态、当前图片版本和数量上限。
6. 校验成功后冻结包含最终文件路径和版本 ID 的引用快照，任务后续只读取该快照。

生成路径是只读消费者。任何创建资产、创建变体、修改绑定或拼接名称的调用都属于契约违规，应由测试阻止。

## 生成弹窗交互

弹窗分为两个视觉层级。

### 已规划引用

- 按“角色身份”“场景与变体”“道具”分组。
- 顶部显示“已选 N 张 / 上限 M 张”，并提供“全选”和“清空”。
- 相关且可用的引用默认全选。
- 整张卡片是可聚焦按钮，点击或按 Enter/Space 切换；内部复选框与卡片状态同步。
- 选中卡片使用高对比边框、背景、勾选图标和“已选择”文字；未选中卡片明确显示“未选择”，不能只依赖颜色。
- 卡片显示规范实体标签、资产类型、变体/状态标签、适用 Beat，以及当前采用版本。
- 不可用卡片禁用选择，并显示 `待确认`、`缺少资产` 或 `缺少图片` 的具体原因。

项目风格继续使用现有的独立开关。它是生成提示词配置，不是图片引用，不进入绑定清单，也不占用图片数量上限。

### 临时参考

- 只保留“上传图片”入口，不展示项目资产自由追加按钮。
- 上传成功后显示缩略图、原文件名、“仅本次使用”标签和“移除”按钮。
- 临时图片默认选中并计入数量上限。
- 关闭弹窗或提交完成后清空，不创建资产实体、变体或绑定。

后续 Mock 使用浅色底、深色文字、明确边框的高对比方案，避免低对比深色示意图影响判断。

## 数量与选择规则

- 达到上限后，未选卡片和上传入口进入不可继续添加状态；取消任一选择后立即恢复。
- 界面持续显示当前计数，不等提交时才提示超限。
- 分类“全选”只选择该分类中可用且未超过上限的项目；全局“全选”按角色、场景、道具的稳定顺序填充。
- 选择状态以 `binding_id` 和 `upload_id` 为唯一键，禁止以显示名称作为 React key 或请求标识。
- 弹窗重新打开时恢复规划默认值，不保留上一次未提交的临时选择。

## 错误处理

- 任一必需绑定处于 `pending_confirmation`、`missing_asset` 或 `missing_image` 时阻止生成，并提供“返回规划处理”入口。
- 可选绑定不可用时允许跳过，但仍显示原因。
- 资产版本在预览后被删除或更换时，提交端重新解析并返回结构化的 `STALE_REFERENCE_BINDING`，前端刷新预览，不静默使用旧路径。
- 客户端提交其他项目、其他集数或不适用于当前叙事组的绑定时，返回 4xx 并拒绝创建任务。
- 临时上传不存在、过期或路径越界时拒绝提交。
- 错误文案使用规范实体和变体的展示标签，不暴露内部文件路径。

## 兼容与迁移

- 新规划任务直接写入持久化清单。
- 没有清单的旧项目显示“需要重新规划引用”，通过规划/修复动作一次性建立关系；生成接口不得为了兼容而恢复名称猜测。
- 已存在且结构化字段完整的旧实体可以在迁移中确定性转换；存在歧义的记录进入 `pending_confirmation`。
- 历史生成任务继续使用已经冻结的引用快照，不因当前绑定或采用版本变化而改变。

## 测试策略

后端覆盖：

- 身份、场景、场景变体和道具规划成功后原子写入绑定。
- 唯一匹配自动绑定，歧义项不猜测并进入待确认。
- 生成预览只读取清单，生成提交不创建实体、变体或绑定。
- 当前采用版本解析、显式回退、过期绑定、跨项目/集数/叙事组越权、临时上传路径和数量上限。
- 冻结快照在后续资产版本变化后保持不变。

前端覆盖：

- 默认全选、整卡点击、键盘切换、复选框同步、再次点击取消。
- 分类及全局全选/清空、高对比状态文字、实时计数和达到上限后的禁用恢复。
- 待确认/缺图卡片不可选，必需问题阻止提交并显示规划入口。
- 临时上传显示、选中、移除和关闭后清空。
- 请求只发送 `binding_id[]`、`upload_id[]`、`reference_revision` 及生成配置，不发送资产名称或持久化归类字段。

## 验收标准

- 用户无需猜测任何卡片是否已选择，且能通过整卡、复选框或键盘完成选择和取消。
- 生成弹窗不再出现自由追加项目资产、资产类型、目标实体、基础场景或变体 ID 输入。
- 规划完成后可以从规范实体追踪到变体、适用叙事范围和当前采用图片。
- 生成期间不会新增或重命名身份、场景、变体、道具。
- 所有正式引用均来源于规划期绑定；所有临时引用均清楚标记且不会持久化。
