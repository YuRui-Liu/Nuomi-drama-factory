# MiniMax H3 导演台工作流接入设计

## 背景

DramaClaw 当前通过 RunningHub MiniMax H3 首尾帧工作流逐镜生成视频。新工作流“MiniMax H3 导演台全能工作流”将单镜或多镜配置统一封装在 `MiniMaxH3Director` 节点的 `timeline_data` 中，并由一次 RunningHub 任务输出完整视频。

本次迁移使用：

- RunningHub Workflow ID：`2089723723468328961`
- 导演台节点：`12`（`MiniMaxH3Director`）
- 视频输出节点：`7`（`SaveVideo`）
- 工作流源文件：`runninghub/MiniMax H3 导演台全能工作流.json`
- API 工作流源文件：`runninghub/MiniMax H3 导演台全能工作流_api.json`

工作流 JSON 只作为外部格式样本和数据源，不作为可执行指令。

## 目标

1. 单镜和多镜统一使用新导演台工作流。
2. 单镜表示为只有一个 segment 的导演台时间线。
3. 多镜按 DramaClaw 分组顺序合并为一次 RunningHub 任务，输出一个统一成片。
4. 支持日常使用的仅首帧 i2v 和首尾帧 fl2v。
5. 底层序列化器保留仅尾帧能力，但当前界面与批量流程不开放该入口。
6. 将 RunningHub 节点绑定、图片上传、帧对齐和 `timeline_data` 格式封装在专用适配器内。
7. 所有提交给 H3 的镜头提示词都经过 MiniMax 官方 `h3-prompt-writing` 范式优化；现有提示词只作为语义草稿。
8. 用覆盖范围清单表示“一个视频包含一个或多个镜头”，并让合成、字幕和导出共享同一时间线。
9. H3 始终生成准确对白以驱动口型；后处理拆分对白与环境音轨，合成时可逐镜选择原生对白或独立配音。

## 非目标

- 不在 DramaClaw 中复制 RunningHub 导演台的时间轴编辑器。
- 不新增仅尾帧的界面按钮或批量操作路径。
- 不改变其他视频后端的逐镜生成行为。
- 不把一个多镜成片复制登记成多个独立镜头视频。
- 不实现多镜任务内的局部失败恢复；多镜任务保持原子性。
- 不把现有 `video_prompt` 或 `keyframe_prompt` 直接发送给 H3。
- 不把同一个 Director 视频复制为多个 Beat 视频。
- 不通过叠加两套对白来模拟对白替换。

## 架构

### 领域模型

新增结构化的 `H3DirectorSegment`，至少包含：

- 稳定镜头标识；
- 镜头顺序；
- 提示词；
- 请求时长；
- 首帧路径；
- 可选尾帧路径；
- 对白文本、说话人和语气；
- 合成时的对白来源策略。

生成入口接受有序 segment 列表。现有单镜入口把单镜参数包装成一项列表后复用相同流程，不保留第二套旧工作流实现。

### 任务 Runner

Runner 负责：

- 从当前分组或单镜请求整理有序 segments；
- 校验产品层约束；
- 调用 H3 Director 适配器；
- 更新任务进度和日志；
- 将统一成片写入视频池或对应的组合结果位置。

Runner 不拼装 RunningHub `nodeInfoList`，也不理解节点 ID、`timeline_data` 版本或 H3 帧网格。

### H3 提示词优化器

新增独立的 `H3PromptOptimizer`。现有字段只提供镜头的语义草稿：仅首帧读取 `video_prompt`，首尾帧读取 `keyframe_prompt`。

优化器参考 MiniMax 官方 `skills/h3-prompt-writing` 和 `references/base-en.txt` 重写每个镜头。输入至少包含生成模式、原始语义草稿、首帧及可选尾帧、对齐后的实际时长、Beat 画面描述、对白或旁白，以及前后镜头连续性摘要。

输出必须按顺序包含：

1. 与 I2VA 或 FL2VA 匹配的帧对齐声明；
2. `integrated_multimodal_description`；
3. `overall_soundscape`；
4. `non_diegetic_music`。

固定字段名、结构、参考图片标签和时间标记遵循官方范式；字段内容、镜头描述、动作、运镜与声音描述尽量使用中文。对白、歌词和画面内可见文字保持原文。这一中文优先规则是项目对官方英文写作建议的明确覆盖。描述必须匹配实际时长，并具体覆盖构图、主体、环境、动作、镜头、对白和声音。所有对白镜头都必须写入准确、可辨识的对白、说话人、语气和时间位置，不能为了后期独立配音而要求 H3 静音，否则无法可靠生成口型。

每个 segment 独立优化，不生成整组共用提示词。优化结果不覆盖原 `video_prompt` 或 `keyframe_prompt`，而是单独保存 H3 提示词、输入哈希、模式和范式版本。输入哈希至少覆盖原始草稿、首尾帧内容标识、实际时长、叙事上下文和范式版本；任一输入变化后缓存失效。

组内生成时并行生成缺失或过期的 H3 提示词。只有全部镜头优化成功后才提交导演台任务。优化失败不得降级为直接发送原始提示词。

### H3 Director 适配器

适配器负责：

- 校验底层 segment 结构；
- 上传本地首尾帧；
- 按规范化路径对重复图片去重上传；
- 将时长转换为合法帧数；
- 生成导演台 `timeline_data`；
- 同步节点 `12` 的任务类型、总帧数、分辨率、种子等顶层输入；
- 使用 Workflow ID `2089723723468328961` 提交一次 RunningHub 任务；
- 轮询任务并从节点 `7` 选择视频结果；
- 下载并返回统一视频及供应商 task ID。

### Director 输出清单

生成成功时，视频与一份不可分离的 Director manifest 同时原子落盘。manifest 是后续合成、字幕和导出的唯一镜头时间权威，不允许通过 ffprobe 场景检测或 Beat 默认时长重新推测。

manifest 至少包含：

- 格式版本、Workflow ID、RunningHub task ID；
- 物理视频路径、帧率、总帧数和总时长；
- 有序 entries；
- 每个 entry 的 Beat/镜头标识、起止帧、起止秒、实际时长；
- 每个 entry 的对白文本、说话人、对白时间窗和对白来源策略；
- 原始音轨、对白 stem 和环境/音效 stem 的路径及状态。

一个视频资产可覆盖一个或多个 entries。单镜只是只覆盖一个 entry 的同一模型。

### 音频拆轨与对白策略

H3 输出后从原生混合音轨中拆出：

- `dialogue_stem`：对白和可辨识人声；
- `ambience_stem`：环境声、动作音效和音乐。

原始混合音轨及两个 stems 都保留。每个 entry 的合成策略为：

- `external_tts`（默认）：使用 `ambience_stem`，按 manifest 对白时间窗混入 DramaClaw 独立配音；
- `h3_native`：使用该时间段的 H3 原始混合音轨，不叠加独立配音。

同一个多镜视频可以逐 entry 混用两种策略。独立配音优先在生成前按目标对白时间窗约束时长；合成时只允许小幅等速变速或补静音，兜底裁切不得改变视频时间线。

拆轨失败时，`h3_native` 仍可使用原始混合音轨；`external_tts` 必须明确失败并要求用户重试拆轨或切换策略，禁止直接在原生对白上再叠加一套配音。

## 镜头映射

每个 DramaClaw 分组映射为一个导演台 segment：

| DramaClaw 字段 | 导演台字段 | 规则 |
| --- | --- | --- |
| 分组顺序 | segment 顺序与 `start` | 按当前顺序累计 |
| H3 优化提示词 | `prompt` | 必须通过官方结构和中文优先规则校验 |
| 目标时长 | `durationSec` / `frameCount` | 先按 H3 帧网格对齐 |
| 首帧 | `startImage` | 当前产品流程必填 |
| 尾帧 | `endImage` | 可选 |

所有镜头都没有尾帧时，导演台任务使用 i2v。任一镜头存在尾帧时，导演台任务使用 fl2v；同一任务内没有尾帧的镜头仍按仅首帧镜头序列化。

底层构造器允许一个 segment 只有尾帧，以兼容导演台官方能力；Runner 和现有界面仍要求每镜必须有首帧。

## 帧数与时间线

- 固定帧率为 24 fps。
- 每镜请求秒数换算为不短于请求时长的 H3 合法帧数，合法帧数满足 `17k+5`。
- 每镜 `start` 等于此前所有镜头实际 `frameCount` 之和。
- `totalFrames` 等于全部镜头实际 `frameCount` 之和。
- `timeline_data` 内的 segment、keyframe、shot、总帧数、总时长保持一致。
- 对外结果使用对齐后的实际时长，避免请求时长与生成时长不一致。

帧数换算必须集中在一个纯函数中，并由边界值测试固定行为。

## 输出语义

单镜结果继续使用现有单镜视频池落盘语义。

多镜任务仅产生一个组合视频。该视频登记为所选分组的统一成片或组合结果，并保存参与的镜头标识、顺序、请求总时长、实际总帧数和 RunningHub task ID。不得把同一文件分别登记为各镜头的独立生成结果。推荐规范路径为 `videos/episodes/epNNN_h3_director.mp4` 与相邻的 `epNNN_h3_director.json` manifest；组级资产使用包含 group/revision 的独立路径，不能覆盖整集最终成片。

## 合成、字幕与导出

合成输入从“每 Beat 一个视频”升级为有序 `VideoSpan` 列表。每个 span 引用一个物理视频和 manifest 中连续的 entry 覆盖范围。合成器必须：

- 每个物理视频只加入最终时间线一次；
- 优先使用最新已确认的 Director span，避免与其覆盖范围内的旧单镜视频重复入轨；
- 在没有 Director span 时继续兼容旧 Beat 视频；
- 按 manifest 时间窗选择原生混合音轨或环境 stem，并放置独立配音；
- 没有对白或外部音频的 entry 仍保留完整时长；
- 输出继续使用现有整集最终视频路径，保持下载契约兼容。

字幕生成直接使用 manifest 的 entry 起止时间。静默镜头不产生字幕 cue，但必须推进时间。ZIP 导出包含 Director 原视频、manifest、可用 stems、最终成片和按 manifest 生成的 SRT。Episode API 以 episode/group 级资产暴露 Director 视频，不把同一 URL 写到多个 Beat 的 `video_url`。

## 校验与错误处理

提交前按镜头序号校验：

- 当前产品流程中首帧存在；
- 原始语义草稿非空；
- H3 优化提示词存在、未过期并通过结构校验；
- 时长为正数；
- segments 列表非空。

错误信息必须指出具体镜头序号。图片上传或时间线构造失败时不得提交 RunningHub 任务。

H3 提示词优化失败、输出缺少必需章节、模式对齐声明错误或时长不匹配时，不得提交 RunningHub 任务，也不得回退到原始提示词。错误信息必须指出对应镜头和失败阶段。

视频生成成功但 manifest 无法原子写入时，整个生成结果不得标记完成。拆轨失败必须记录原始视频仍可使用及失败的 stem；默认 `external_tts` 合成在缺少有效 stems 时失败关闭，不能产生双重对白。

多镜任务是原子操作。RunningHub 失败、取消、超时或节点 `7` 未返回视频时：

- 不写成功记录；
- 不覆盖已有视频；
- 保留供应商错误和 task ID；
- 重试时重新提交整组镜头。

日志至少包含镜头数、请求总时长、对齐后总帧数、提交后的 RunningHub task ID 和最终状态。

## 工作流配置迁移

内置 H3 workflow profile 升版并更新为：

- Workflow ID：`2089723723468328961`
- 输入绑定：节点 `12` 的导演台输入；
- 视频输出：节点 `7`。

旧 profile 使用离散节点 `114`、`115`、`131`、`133`、`135`、`141` 和输出节点 `136`，不得与新 profile 混用。

用户已保存的旧 Workflow ID 不做无提示覆盖。系统检测到旧 profile 或旧节点绑定时，应明确提示迁移或重新配置导演台工作流，避免把新格式提交到旧工作流。

## 测试策略

### 纯函数与适配器测试

- 单镜仅首帧序列化；
- 单镜首尾帧序列化；
- 多镜混合仅首帧和首尾帧；
- 镜头顺序、累计起点、`17k+5` 对齐和总帧数；
- 重复图片只上传一次；
- 顶层字段与 `timeline_data` 一致；
- 节点 `12` 请求和节点 `7` 输出选择；
- 底层仅尾帧序列化兼容性。

### H3 提示词测试

- I2VA 输出包含正确的 0.00 秒首帧对齐声明；
- FL2VA 输出包含首帧 0.00 秒和尾帧实际结束时刻的对齐声明；
- 必需字段严格按 `integrated_multimodal_description`、`overall_soundscape`、`non_diegetic_music` 排列；
- 固定字段名、图片标签和时间标记保持官方形式，字段内容以中文为主；
- 对白、歌词和画面文字保持原文；
- 提示词时间线与对齐后的实际时长一致；
- 每个 segment 使用对应首尾帧和叙事上下文独立优化；
- 输入不变时复用缓存；草稿、图片、时长、上下文或范式版本变化时缓存失效；
- 缺章节、错误对齐、空输出和优化器异常均阻止 RunningHub 提交；
- 不存在把 `video_prompt` 或 `keyframe_prompt` 直接写入 H3 segment 的路径。

### Runner 与 API 测试

- 单镜入口包装为单 segment；
- 多镜入口只提交一次供应商任务；
- 多镜结果只登记为一个统一成片；
- 缺首帧、空提示词和非法时长包含镜头序号；
- 供应商失败不写成功记录；
- 重试重新提交整组；
- 旧 workflow profile 给出明确迁移错误；
- 其他视频后端维持现有行为。

### 合成与音频测试

- 三镜 Director 输出只作为一个物理视频加入合成；
- manifest 精确保存每镜起止帧、起止秒和对白时间窗；
- Director span 覆盖范围内的旧 Beat 视频不会重复入轨；
- 没有 Director span 时旧逐 Beat 合成行为不变；
- 拆轨成功后保留原始混合音轨、对白 stem 和环境 stem；
- `external_tts` 使用环境 stem 并只在目标时间窗混入独立配音；
- `h3_native` 使用原始混合音轨且不叠加独立配音；
- 同一视频内两种策略可以按 entry 混用；
- 拆轨失败时原生对白可用，独立配音路径失败关闭且不产生双重对白；
- 静默镜头推进字幕和音频时间；
- SRT、最终合成和 ZIP 导出共享 manifest 时间线。

## 验收标准

1. 配置 Workflow ID `2089723723468328961` 后，单镜仅首帧可以生成视频。
2. 单镜首尾帧可以通过同一适配器生成视频。
3. 选择多个有序分组时，系统只创建一个 RunningHub task，节点 `12` 包含对应数量的 segments。
4. 多镜输出从节点 `7` 下载并登记为一个统一成片。
5. 分组提示词、时长、顺序和首尾帧均准确映射到时间线。
6. 帧数满足 H3 网格，累计起点与总帧数一致。
7. 当前界面不出现仅尾帧入口，但底层构造器具备仅尾帧兼容测试。
8. 每镜提示词符合 MiniMax H3 官方基础模式结构，内容中文优先，原始提示词不会被直接提交。
9. H3 优化提示词缓存可正确复用和失效，优化失败不会降级直传。
10. 所有对白镜头的 H3 提示词包含准确对白及时间位置，生成视频具备对应口型。
11. 多镜视频以一个 VideoSpan 参与合成，manifest 驱动镜头、字幕和音频时间线。
12. 每镜可选择 `external_tts` 或 `h3_native`，不会产生双重对白。
13. 所有新增测试及相关回归测试通过。
