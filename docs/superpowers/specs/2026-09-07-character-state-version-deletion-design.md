# 人物身份图历史版本删除设计

## 目标

允许用户在人物身份图历史版本卡片右上角删除不再需要的版本，删除版本记录和对应图片，避免废弃资产持续占用项目存储。

## 用户体验

- 每张人物身份图版本卡片右上角显示垃圾桶按钮，包括当前采用版本。
- 点击按钮后弹出确认框，显示待删除版本 ID。
- 删除当前采用版本时，确认框说明系统会自动采用剩余版本中创建时间最新的一张。
- 删除期间禁用重复操作；成功后刷新版本列表和当前主身份图；失败时保留原状态并显示错误提示。
- 删除最后一个版本后，版本区域消失，主身份图和当前版本指针被清空。

## 后端接口

新增：

`DELETE /api/v1/projects/{project}/production-assets/slots/{slot_id}/versions/{version_id}`

接口要求项目 `editor` 权限。返回更新后的 slot、剩余 versions、current_version，以及是否删除了 canonical 主图。

## 删除事务

删除在 `production_workflow_project_lock` 内执行：

1. 读取 slot 和目标版本，不存在时返回 404。
2. 校验版本图片路径位于项目目录内。
3. 从 slot 的 `version_ids` 和 workflow 的版本表移除目标版本。
4. 如果目标不是当前版本，保留当前版本不变。
5. 如果目标是当前版本，按 `created_at` 降序选择剩余最新版本；时间缺失时使用稳定的 `version_ids` 顺序，以最后注册者优先。
6. 有回退版本时，将其设为 `adopted`（其余版本保持或变为非采用状态），并把图片复制到该 slot 的 canonical 路径。自动回退是删除恢复动作，不再执行 QC 准入检查；没有回退版本时，清空 `current_version_id` 并删除 canonical 主图。
7. 原子保存 workflow 状态后删除目标版本图片。

删除操作必须支持回滚：workflow、canonical 文件或版本文件任一步失败时恢复删除前快照，不返回部分成功。

采用事件历史保留，作为审计记录；事件引用已删除版本是允许的。

## 文件安全

- 版本文件和 canonical 路径都必须解析在项目根目录内。
- 不允许删除目录、项目外文件或不属于目标版本的文件。
- 当版本文件路径与 canonical 路径相同时，先完成回退复制或 canonical 清理，再处理目标文件。
- 多个版本意外共享同一文件路径时，只有不再被任何剩余版本引用才删除物理文件。

## 前端

- 在 `CharacterStateVersions` 卡片内增加右上角绝对定位的图标按钮。
- 新增删除 mutation；成功后失效对应 production asset slot 查询。
- 确认框根据目标是否为当前版本展示不同说明。
- 删除 mutation 进行中时锁定目标按钮，避免重复请求。
- 增加中英文文案和无障碍按钮名称。

## 测试

- Store：删除非当前版本、删除当前版本并采用最新剩余版本、删除最后版本、缺失时间的稳定回退、共享文件引用。
- API：权限、版本不存在、路径越界、版本文件删除、canonical 回退、失败回滚。
- 前端：垃圾桶按钮出现、确认取消、删除非当前版本、删除当前版本提示、mutation 参数与成功刷新。

## 非目标

- 不提供批量删除。
- 不提供回收站或撤销。
- 不改变道具、场景等其他资产版本界面；后端接口保持通用，以便后续复用。
