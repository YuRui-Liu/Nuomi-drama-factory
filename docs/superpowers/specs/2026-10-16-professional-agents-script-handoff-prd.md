## 1. 产品目标

用户可从创意或已有剧本开始，在同一项目画布中完成故事与剧本、人物和场景造型、导演分组与分镜、站位/摄影/灯光/动作/表情设计、整组分镜图、MiniMax 整组视频、声音、剪辑、字幕和可播放导出。

当用户明确要求完成一集或完整制作目标，并已提供或授予所需预算授权时，主创制片与专业 Agent 应在授权范围内自动协作推进到目标交付。系统不得在每个角色交接后只给建议并停下，也不得把图像、视频、声音、字幕或导出排除在产品范围之外。只有遇到会改变核心故事方向、违反硬约束、缺少必需输入或超出范围/授权的实质问题时，才暂停并提出关键问题。

用户只要求剧本整理、一个人物方案、一场戏、一组分镜或其他局部目标时，系统只完成该范围，不自动扩展成整集或媒体制作。完整成片和局部委托共用同一画布、资产、任务记录和角色能力；交付边界由这次请求决定。

目录与配置必须诚实展示能力：角色名、方法说明或可见配置不等于真实工具、模型、授权或执行链已经接通。功能只有通过真实端到端验收后才可标为可交付。

## 2. 用户与主要任务

| 用户目标 | 需要完成的工作 | 可见结果 |
| --- | --- | --- |
| 从想法制作一集 | 将创意整理为故事和剧本，完成角色/场景设定、导演与分镜、制作、声音、剪辑、字幕和导出 | 一份按项目配置制作、实际可播放并可追溯的成片 |
| 从已有剧本制作一集 | 保留原文和版本来源，补齐制作所需资产与分镜，运行获授权的整组生产链 | 可播放成片、字幕、声音及完整来源/运行回执 |
| 只修改局部 | 指定一场戏、人物、镜头组或素材，委托对应角色 | 范围内的草案、候选或媒体结果，不扩成整集 |
| 管理专业角色 | 查看角色输入、方法、结构化交付、接收方、验收和当前能力缺口 | 可判断角色是否适合本任务、能否真实执行 |
| 中断后继续 | 检查已完成与失败组，复用有效结果并只恢复失败范围 | 任务状态明确，不重复购买已完成组，不交付残缺成片 |

## 3. 范围与边界

### 3.1 本文纳入范围

- 从想法或已有剧本到可播放漫剧的全链路目标；用户要求完整成片时，媒体生产、声音、剪辑、字幕和导出均在范围内。
- 专业 Agent 目录与十八个可独立配置的岗位契约；每个岗位显示输入、方法、结构产物、接收人、验收条件和实际能力缺口。
- 从项目构思或分集剧本到统一画布的交接、来源与版本记录、创作对象、任务回执和候选保护。
- 从创意/剧本到分集、场景、叙事组及其分镜和媒体产物的关联。
- 把完整制作与局部委托接入统一节点操作，复用受支持的共享媒体能力、版本、任务及恢复机制；按既有计划移除旧阶段引擎，完成真实端到端连接。
- 角色造型与场景资产、叙事组分镜图、叙事组视频、声音、时间线剪辑、字幕、导出、任务状态和中断恢复。
- 读取并使用项目当前保存的画幅、片长、模型和并发设置；不以文档中的示例替代运行时设置。
- 局部委托、候选、人工编辑保护、费用与预算授权、停止及失败恢复，沿用上位 PRD 和生产技能的边界。

### 3.2 明确边界

- 不建立面向公众的 Agent 市场，不把配置数量、角色卡片或样例展示当成能力证明。
- 不恢复剧本、分镜、视频、音频、合成等旧阶段工作台、阶段解锁、强制确认门禁或双轨流程。画布可显示生产进展，但不可要求用户逐阶段点击批准才能继续已授权任务。
- 当前批量生产不拆成单镜头或单段付费循环，不绕过受支持入口。目标产品保留已有节点的局部能力，运行单位由具体能力合同和依赖明确，不能从画布位置或视觉分组推断。
- 不硬编码 MiniMax 的模型能力、时长、画幅、营销参数或供应商宣传内容；能力以当前已保存设置、执行合同和实际接入状态为准。
- 不承诺任何供应商都支持取消、断点续跑或相同费用结果；界面按真实任务状态说明。
- 不默认无限重试、不默认追加付费 QC，不为软警告或审美偏好重做已合格内容。

## 4. 产品原则

1. **先识别本次交付目标。** 完整成片请求与局部委托有不同终点；不得把完整目标缩成建议清单，也不得把局部目标扩成整集。
2. **完整请求自动推进。** 用户授权的范围内，专业角色交接是系统内部协作过程。完成一个岗位后，符合条件的后续工作继续运行，不逐次停下来询问是否继续。
3. **角色分别配置，任务可以合并调用。** 十八个岗位各有独立配置与可读契约，但不要求十八次模型调用；编排器可以合并不冲突的工作，仍须保留每个岗位的输入、产物和版本 provenance。
4. **导演负责创作冲突协调。** 导演在既定剧本、用户约定和项目范围内协调创意、分镜、表演、摄影等方案冲突。与用户硬约束冲突、改写已确认事实或无法确定的重大故事决定，交由用户裁决。
5. **共用事实、版本与来源。** 所有角色读取同一份已确认项目事实、当前剧本/导演方案版本和任务范围；推断、候选、用户确认和采用结果明确区分。
6. **Agent／节点为中心，画布承载创作。** Agent 与用户使用同一套受支持节点操作，按明确输入、版本、授权和依赖执行。现有叙事组能力保留其输入合同，但不将其固定顺序施加给所有画布任务。
7. **授权一次覆盖已说明的范围。** 付费任务在开始前按上位 PRD 汇总范围、数量和费用/不确定性；明确授权后不对每个角色、阶段或组重复索要同一授权。超出范围/预算、修改共享资产或替换已采用内容仍按上位 PRD 处理。
8. **重试有边界。** 只按已授权次数、预算和生产入口允许的恢复机制重试；成功组复用，只处理失败组。不因“做到满意”为由持续生成。
9. **配置和模型能力动态读取。** 生产调用从当前项目/账户设置与执行合同读取模型、参数、画幅、并发和工作流版本；历史任务记录其当时的有效参数，不拿当前设置补造旧记录。
10. **功能准备就绪靠真实交付证明。** 目录显示“可配置”不代表“可执行”；有任务提交不代表完成；可播放导出和必要交付条件全部满足后，才表示全链路功能 ready。

## 5. 专业 Agent 目录与岗位契约

### 5.1 目录入口与能力状态

目录按任务展示十八个岗位，包含当前主创制片、导演和可委托角色。每个角色卡必须呈现职责、适用任务、所需输入、结构化交付、接收角色、配置版本、样例证据与当前能力状态。状态至少区分：

- **可执行**：本任务所需输入、工具/模型、授权和下游接收路径均已确认可用。
- **配置可用、执行未接通**：可查看或编辑方法配置，但不能提交假任务。
- **能力受限**：指出缺少的具体输入、模型、工具、权限或适配。
- **运行受阻**：显示真实任务/组的阻塞原因及支持的修复动作。

示例须标为本地真实运行、界面示意、外部公开案例或研究推论，并带来源和日期。“角色存在”“配置已保存”或“其他产品演示过”不能标记为 Nuomi 可执行。

### 5.2 必需岗位及交接契约

以下十八个岗位均须可独立配置。表中“能力缺口”是当前已知待核实项；实现时须根据真实配置、工具、供应商、任务记录和端到端证据更新，不能把“未核实”直接说成“已接通”或“完全不存在”。

| MiniMax执行师 | 已完成的组级分镜图、导演/摄影/动作/表演方案、引用快照和当前 MiniMax 执行设置；通过受支持生产入口提交整组视频 | group_id、任务 ID、执行合同、有效模型/参数/画幅/设置版本、输入引用、视频产物及状态 → 声音师/剪辑师 | 组视频完成并可播放；报告有效参数和失败原因；不改剧情或擅自换模型 | 当前已知路径为 RunningHub 托管 H3 工作流而非直连 MiniMax API；统一画布适配及当前账户支持范围须核实；不硬编码 H3 等历史规格 |
| 声音师 | 原始对白与说话人、动作和镜头节拍、音色约定、音乐/声音要求；规划或生成对白/TTS、环境/动作音效及配乐 | 声音 cue 表：原文台词、说话人、时间点、音效、配乐层、素材/任务 ID → 剪辑师 | 台词与剧本一致、声音符合方案且可播放；未知声纹不臆造 | 原声/TTS/环境音路径可见；BGM 参数虽有 API 输入，当前合成链未消费 add_bgm，须补齐真实闭环并核实混音 |
| 剪辑师 | 按序组视频、声音素材、剧本节拍、项目片长/画幅及字幕要求；装配时间线并处理节奏、转场和同步 | 有序时间线、组裁切/转场、音轨/字幕轨、可播放导出及项目文件 → 交付检查 | 顺序符合导演方案；对白/声音/字幕可辨且时序相符；整集无残缺组 | episode compose 路径存在；当前字幕 SRT/ZIP 有自动时间估算，但不等于逐字对齐；BGM 合成、可编辑时间线和统一画布衔接需验证 |
| 交付检查 | 完整任务书、导演关键节拍清单、组状态、导出视频、声音/字幕与 provenance；做最小交付核验 | 交付清单：成片可播、关键剧情覆盖、人物动作/台词/声音/字幕/顺序、文件/来源/未解决项 → 主创制片/用户 | 所有必需项通过才标“完成”；缺任一关键项即阻止整集成功并定位原因 | 现有生产汇总能报告任务/视频状态；完整内容与导出端到端验收未完成；不得增加默认付费 QC |

### 5.3 角色详情与运行契约

每个角色详情必须同时展示职责、必需/可选输入、工作方法、结构化输出字段、接收人、局部验收、样例来源、配置版本、实际工具/模型/权限和能力缺口。用户能查看任务将引用哪些画布节点、设定和资产；源内容与 AI 补充分开标示。

角色配置独立维护，某次编排可以合并兼容岗位的模型调用，但必须在任务回执中记录各岗位实际承担的部分、输入版本和输出去向。只有真实可执行所需能力完整时才允许提交；不能创建空委托或在目录里显示模拟成功。

### 5.4 主创制片与局部委托

- 项目设置主创制片配置，并保留导演这一独立岗位；导演负责创作冲突协调，主创制片负责用户目标、范围、预算和交付统筹。
- 用户从空白/想法入口、剧本或画布节点发起任务。输入包括全篇、分集、场景、叙事组或所选节点范围。
- 完整成片请求启动全链路编排；局部目标只启动必要岗位和依赖，不默认进入下游媒体步骤。
- 任务卡展示目标、输入、交付、授权覆盖范围、项目当前设置和需要用户决定的真实歧义。目标明确时直接继续，不用每个角色完成后询问。
- 角色缺少能力时显示缺口、影响范围和受阻任务；不得伪造空结果、绕过生产接口或用其他未授权供应商替代。

## 6. 从想法/剧本到统一画布与生产

### 6.1 发起与目标判定

用户可从项目构思、剧本导入/编辑、分集画布或自由画布发起任务。开始时识别并展示一次：

- 输入来源、修订和范围；已有剧本的原文快照及需保留的事实。
- 目标是创意/剧本/人物资产/某场或某组局部交付，还是完整可播放分集。
- 完整分集所用项目片长、画幅、字幕要求和当前有效模型/并发设置；从项目设置读取，不以 PRD 示例固定值覆盖。
- 计划涉及的岗位、媒体类型、数量范围、预算/估算、不确定性和已有授权。

想法起步时，系统将创意交给创意师与主笔等角色形成故事和剧本；已有剧本起步时保留源文和版本，除非用户要求改写，否则不把完整剧本重写作为隐含行为。两种入口都可按用户目标继续到完整制作。

用户明确要求完整成片时，若媒体任务需要付费，先按上位 PRD §7.2 展示整个已知范围和费用估算/不确定性，并获取适用的授权；有覆盖该范围的既有授权则直接继续，不逐阶段、逐角色重复确认。授权外扩展、无法控制的额外费用、修改已采用内容或共享资产时按原规则处理。

“把剧本交接到画布”“看看人物方案”“只做这场戏的分镜”等局部请求，不自动生成整集媒体。只有当本次请求目标包含完整分集/成片时，媒体生产才属于本次默认交付。

### 6.2 共享事实、来源与版本

画布及回执能区分：

| 内容类别 | 展示方式 | 行为 |
| --- | --- | --- |
| 用户原始想法/剧本 | 来源、修订、范围和原文快照 | 保持可查；不得被 Agent 草案覆盖 |
| 已确认事实/约定 | 确认人、来源、范围和约束级别 | 所有岗位共用；冲突依硬约束处理 |
| AI 推断/创意提案 | 标签、依据和不确定性 | 不自动成为硬约束、共享资产或采用版本 |
| 用户/Agent 修订 | 操作者、配置版本、差异和时间 | 保留旧版；冲突时作为候选 |
| 生产输入与媒体结果 | group_id、镜头/资产引用、设置/执行合同、任务和输出版本 | 可追溯到使用的剧本、导演方案、引用和角色交接 |

不凭名称静默合并角色、场景、道具或镜头。稳定对象 ID、剧本修订、导演方案版本、画布节点、采用状态和媒体任务分别记录。

### 6.3 重交接与人工编辑保护

剧本或设定再次交接时，比较源修订和上次采用版本，列出新增、更新、双方冲突、源删除和范围外内容。用户编辑、已采用角色/场景设定和已生成媒体均保留；可无冲突应用的内容形成候选，冲突项提供差异和选择。

上游改动不得静默重跑下游生成。需要重做的角色、场景或组及其费用影响须明确列出，并按已有授权范围决定是否执行。源内容删除不自动删除画布对象或媒体历史。

### 6.4 任务回执与全链路来源记录

每次任务形成可从画布、Agent 目录和任务记录重新打开的回执，包含：

- 任务 ID、目标/范围、源修订、画布/导演方案版本和授权。
- 实际参与岗位及各自配置版本、输入版本、结构化输出、接收人和未接通能力。
- 按叙事组显示图像、视频、声音/剪辑/字幕、合成各状态；包含有效模型设置、执行合同、引用版本和生产任务 ID。
- 成功、失败、阻塞、跳过与待处理对象；每个失败项有原因和受支持恢复操作。
- 输出视频、字幕/声音文件或轨道、导出设置、可播放状态、费用及未解决问题。
- “完整成片完成”仅在所有必需组、声音、字幕、顺序导出和交付检查全部通过时成立。部分完成必须清楚标记，不能显示整集成功。

### 6.5 成果依赖与统一画布

以下为采用现有叙事组能力时的完整制作示例。未来具体任务按节点能力合同组织依赖，不将此示例规定为所有创作的固定执行图，不创建阶段审批页面：

1. 剧本/故事和角色、场景、道具等资产形成可用版本。
2. 导演将内容组织为叙事组并激活机器校验通过的导演方案；关键剧情节拍映射到组。
3. 每个组按支持入口先完成整组分镜图，再生成该组视频。
4. 组视频、对白/声音、时间线剪辑及字幕按导演顺序组合为完整分集并导出。
5. 交付检查验证本次要求并回传结果。

UI 将这些内容显示为画布中的关联节点、组任务卡和整体进度，不复制旧阶段工作台，也不要求用户在“剧本完成”“分镜完成”等节点逐项批准已经授权的任务。运行顺序由 production runtime 保证，用户可以停止任务并查看其实际状态。

## 7. 运行任务、失败与恢复

### 7.1 状态与身份

用户可见状态至少包括待开始、处理中、待用户处理、已完成、部分完成、失败、已停止和状态待核实。生产任务还要显示分集、叙事组、当前受支持的组阶段、task_id、有效设置版本、错误和产物。

“组任务已提交”“一个组视频已完成”不等同于整集完成。失败、排队、提交状态不明或未写回结果不得显示成功；任何必需组未完成、缺声音/字幕或未导出均不能标记完整成片成功。

### 7.2 当前叙事组路径的调度与恢复

以下规则适用于当前受支持的批量生产路径；统一节点架构迁移按主 PRD 第 15.8 节处理。节点的局部任务仍按相应能力合同执行。

- 调用 nuomi/production_cli 支持入口或其受支持服务端能力，遵守 group → storyboard image → group video → compose 顺序。
- 读取当前已保存的 default/video 并发值和运行时模型设置；不自行降低并发、不猜测设置、不静默改写配置。
- 组间按保存并发执行；一个组失败不阻塞无依赖组，但有失败组的集不得合成残缺成片。
- 中断后先核对任务和组状态、接续已有 task_id；有效已完成产物复用，仅恢复失败组。不得绕过 API/CLI 做单镜头、片段循环或供应商直连。
- 先前失败的付费操作只有在查明原因、修复后按支持的失败组恢复机制处理；不自动无限重发。提交状态未知先查状态，不能盲目再次付费。
- 停止后不再提交后续组；不能取消的外部任务如实显示，结果返回后不自动启动下游。
- 不对已通过必要生产检查的组增加重复付费 QC、语音识别或按帧深审。只检查任务完成、产物存在、关键剧情无明显缺失及最终播放。

### 7.3 失败显示和能力降级

分清输入缺失、资产引用失效、方案校验失败、组图/组视频失败、音频/字幕/剪辑失败、导出失败和供应商状态不明。错误卡保留原 group_id/阶段，列出失败证据、可修复项和受支持恢复入口。缺少必要角色或模型能力时阻止相关提交并说明影响，不得自行降级成逐镜头付款或宣称成片成功。

## 8. 空状态、授权与协作

### 8.1 空状态

- 项目只有创意时，说明可先提供的关键信息；用户目标已明确且不缺硬事实时允许创意师/主笔自动给出草案继续。
- 空白或无效剧本时保留原输入和回执，说明需要导入/补充的内容。
- 无目标画布时可按来源建议项目构思、分集或自由画布；创建遵循上位 PRD。
- 无可运行岗位或生产设置时，显示具体缺口与可完成的准备工作，不显示虚假的成功/生产按钮。
- 素材库缺少必需人物、场景或道具时使用已有的受支持资产准备路径；不能创建虚假引用或绕过生产校验。

### 8.2 费用、授权和重试

沿用上位 PRD §7.2—§7.3：已明确预算/范围内的调用不重复确认，重试计入预算；无法保证费用上限时按原规则处理。不得把生产批次 API 提交次数上限当成货币预算。用户停止后停止新提交。默认无无限重试和额外付费质量检查；软警告不自动购买重生成。

### 8.3 并发编辑

Agent 依据任务开始时固定的剧本、资产和画布修订工作。用户同时编辑同一内容时，将 Agent 结果作为候选并展示差异，不覆盖人工内容。用户拖动或整理画布布局不丢失内容结果。上游采用版本变化时提醒真实受影响组，只有用户授权覆盖范围内才自动继续重新生成。

## 10. 验收场景与 Ready 标准

以下场景必须以真实服务、实际配置和真实媒体运行验收。目录文案、静态节点、模拟任务、原型播放占位、CLI 提交成功或配置页截图均不能替代成片。

| 场景 | 验收结果 |
| --- | --- |
| 十八岗位目录与配置 | 十八个岗位可独立配置；每个详情都有输入、方法、结构化产物、接收人、验收条件和能力缺口；不支持的角色不会假称可运行 |
| 想法起步全链路 | 从用户创意经故事/剧本、资产与导演方案，自动推进到项目设定片长和画幅的可播放完整分集；每个角色交接后不因等待用户重复点击而停摆 |
| 已有剧本全链路 | 原文、修订和确认设定可追溯；生成的角色/场景/组与来源相连；完成同一完整分集交付且不静默改写源剧本 |
| 局部请求 | 只修改选定场景/组/节点及必要依赖，不自动生成整集；未授权的下游媒体不运行 |
| 导演冲突协调 | 对同一目标下的创作/视觉角色冲突由导演按已确认事实和用户约定协调；涉及硬约束或重大故事取舍时只向用户提出必要问题 |
| 当前组级能力接入 | 真实生产记录证明每个叙事组先整组分镜图、再整组视频，最后整集合成；无逐镜头付费生产、无供应商直连旁路 |
| 设置与并发 | 运行时读取并记录用户保存的实际并发、画幅、片长和模型执行设置；不硬编码 MiniMax 宣传参数，不私自降低配置；合成回执能证明配置的 BGM 已被消费 |
| 真实成片内容 | 至少一集按项目配置实际时长和画幅完成；成片可播放，人物与场景连贯，包含必要人物动作、原剧本对白、符合声音方案的对白/音效/配乐、按序剪辑、时序可读的字幕及真实导出文件；配置 BGM 时确认该轨实际进入合成结果 |
| 剧情完整性 | 对照导演关键节拍清单，关键因果/揭示/结局没有缺项；不得用其他镜头或字幕伪称缺失剧情已完成 |
| 来源与运行追溯 | 可从导出追溯到剧本/导演方案版本、叙事组、引用资产、各岗位配置版本、执行合同、模型/设置、任务 ID、声音/字幕/剪辑顺序和费用 |
| 付费授权 | 在提交前一次性展示本完整任务的已知范围及费用/不确定性；授权内不逐岗位/逐组重复确认；任务超出既有授权时按上位 PRD 处理 |
| 中断与恢复 | 在实际任务中断后读取既有 task/group 状态，复用成功组，只恢复失败组，不重复购买已完成产物；组失败时不导出半集成功 |
| 失败、停止与状态未知 | 停止后无新组提交；不可取消的任务如实展示；提交未知先查询；阻塞组保留原因和原 ID |
| 统一画布适配 | 可从统一画布发起完整任务、查看真实进度和产物、预览/编辑/导出；Agent 与人工共用受支持节点操作，复用共享生产能力；未接通部分明确标受阻，不能隐藏旧阶段引擎继续执行 |
| 原型覆盖说明 | P01—P09 仅表示交互状态覆盖；P09 是视频占位；真实全链路未接通前，产品和 PRD 不得宣称功能已全面覆盖 |

**功能 Ready 标准：** 十八个岗位契约已定义且状态诚实；统一节点操作与共享执行能力适配完成；在当前保存设置下至少真实完成一集端到端验收，含人物动作、台词、声音、字幕、顺序剪辑、可播放导出、来源与运行追溯和中断恢复；零关键剧情缺失；无半集成功；失败恢复不重复生成已成功组。配置展示或原型完成不满足 Ready。

### 10.1 验收范围说明

验收集的实际片长和画幅来自项目/当前用户设置；本 PRD 不固定具体数字。声音、字幕及其导出属于全链路必需产物。质量核验按生产技能保持适度，不增加默认付费 ASR、重复 QC 或逐帧深审。

## 11. 产品信号

观察用户能否从想法/剧本完整到达可播放分集、完整任务中途停顿的频率、关键剧情遗漏、导出播放失败、字幕/声音缺项、重复提交和费用偏差。按角色记录委托是否有可检查结构化产物、能力受阻原因和下游接收结果。

Agent 浏览、目录角色数、草案节点数和批次已提交数量不是交付成功指标；验收关注真实可播放、来源完整且用户授权范围内的目标结果。

## 13. Nuomi 现有能力与必须完成的缺口

下表结合 2026-10-16 静态研究及生产技能整理。它不是当前分支的完整实现审计；所有状态在实现前需按实际分支与运行证据核对。

| 需求区域 | 已知基础 | 仍须交付/核实 |
| --- | --- | --- |
| Agent 配置与主创 | agent_profiles.py、builtin_agents.py 有职责、方法、技能、版本和通用主创/文本编剧基础 | 十八岗位分别配置、完整输入/结构产物/接收人、真实能力状态与全链路调度 |
| 配置界面和目录 | AgentConfigurationPanel.tsx 有新建、复制、个人发布、项目采用等基础；AgentRuntimePanel.tsx 有主创、节点范围和运行状态 | 目录体验、十八岗位详情、结构化交接与运行能力缺口；不得另建第二套版本系统或只做配置页 |
| Agent 运行和候选 | agent_tools.py、delegations.py、agent_runs.py 可读取授权上下文、保存文本候选和对象草案 | 导演/角色专业交付与媒体任务之间的真实下游接收、版本、恢复及来源追溯 |
| 剧本交接 | handoff.py 和 handoff-dialog.tsx 有冻结正文、来源修订、差异、确认、outbox 和 screenplay_semantics 派发 | 接到统一画布、项目/分集/自由目标、角色资产、导演分组和完整任务回执 |
| 叙事组生产 | production_cli / nuomi 支持按 group 调度整组分镜图、整组视频、合成，读取已保存 default/video 并发，并按失败组恢复；narrative group execution contract 冻结有效参数并由 runner 核对 | 统一画布到受支持入口的适配、任务状态/输出回写、停止/恢复、完整分集声音/剪辑/字幕/导出链路真实验收；freezone 导演规划 DAG 尚未统一到组级生产合同 |
| 视频模型和参数 | 生产运行记录有效模型/模式/画幅/参数/引用快照；当前 MiniMax 路径是 RunningHub 托管 H3 工作流，不是直连 MiniMax API | MiniMax 执行岗位须动态读取当前账户和项目实际支持能力，并经受支持入口提交；不得硬编码历史规格或暗示直连官方 API |
| 资产与连续性 | 生产端有引用预览、版本检查、刷新引用和人物/场景资产路径 | 统一画布中的稳定对象/版本链接、跨组状态账本、声音参考及角色设定全链路核验 |
| 声音、剪辑和字幕 | 有原声/TTS/环境音及 SRT/ZIP 字幕路径；episode compose 路径存在 | 补齐 add_bgm 从 API 到 compose 的消费闭环；字幕估时需与实际台词/声音时序验收，不能把估算等同逐字对齐；时间线、混音、统一画布到导出的全链路仍须实测 |
| 当前原型 | 九页目录/交接/全链路状态原型可供讨论 | 原型仅表达状态，P09 播放区为占位；必须与真实业务执行链连接 |

项目中的能力缺口必须修复受支持入口或明确标记阻塞；不能因为 CLI 存在就宣称统一画布已接通。production runtime 继续遵守生产技能，不把画布自由组织误作逐镜头执行，也不以“先做出来”为由绕过已有校验。

## 14. 实施前待核实项

以下是实现设计需据当前分支和用户项目设置落实的细节，不改变全链路产品目标：

1. 统一画布的想法/剧本/媒体输入，如何映射到项目构思、分集和自由画布的稳定对象 ID。
2. 十八个岗位的配置版本、共享事实上下文与结构化输出 schema 如何复用现有 Agent 模型。
3. 导演方案和叙事组状态如何回写画布，同时保证 Agent 与人工使用同一套节点操作，并明确旧引擎替换范围。
4. MiniMax 执行能力、项目模型选择和费用估算如何从当前设置/执行合同读取。
5. 声音、可编辑时间线、字幕和最终导出当前由哪些真实执行能力承担，以及缺少的适配。
6. 真实短集端到端验收选择项目已配置的片长/画幅与预算，并记录中断恢复证据。

这些核实项不能被简化为“只做目录和剧本交接”，也不能以九页原型或角色配置完成替代完整产品验收。



## 15. 本轮确认决定与实施承接

以主 PRD 第 15 节为统一产品依据：按需驻入的专家、内容节点及默认收起的关联任务、专家直接调用授权节点、五项专业配置、按目标逐步展开剧本、本体关系与主动影响解释、分层检查及真实成片完成标准。专家可直接执行，不要求所有视频调用经过 MiniMax 执行师；该岗位负责模型适配与故障处理专长。

专业成果写入共同内容对象，实际生成读取采用版本；修改人工内容、共享资产或已采用内容不因自动推进而跳过既有授权。结构化字段及本体检查不能替代真实媒体检查。

复用[恢复计划](../plans/2026-10-14-agent-canvas-resume.md)的已交付基础及任务 9—13，不另起平行版本、任务或存储系统。本轮未实施代码或重画原型；完成书面审阅后再更新计划与设计。
