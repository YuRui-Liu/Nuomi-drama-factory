# NuomiDrama 首次多集剧本导入设计

> 日期：2026-09-01  
> 状态：待审查  
> 范围：首次空项目的多集导入入口、多个分集文件导入、单个合集文件自动拆集及预检反馈。

## 1. 背景与目标

NuomiDrama 已有 `EpisodeImportDialog` 和分集剧本导入 API，支持一次选择多个文件、预检集号、处理已有集冲突并异步提交。但是首次空项目仅展示原有单文件上传与粘贴入口；“追加导入 / 批量导入”按钮被 `hasImportedContent` 条件隐藏，导致用户必须先完成一集导入，才能使用既有的多集能力。

本设计要求：

- 首次空项目即可主动选择“多集导入”。
- 同时支持多个分集文件和单个合集文件。
- 保持现有单文件上传、粘贴和已有剧集追加导入行为不变。
- 所有拆分结果先预检、后提交，不静默改号、不静默丢弃原文。

## 2. 方案选择

评估三种方案：

1. 首次页面始终展示独立的“多集导入”入口，复用现有弹窗和后端导入链路。
2. 把现有上传区改成统一上传器，自动判断普通文本、多个分集文件和合集文件。
3. 首次进入时增加导入向导，让用户先选择单集、多文件或合集。

本设计选择方案 1。它明确区分普通文本导入与已有分集剧本导入，改动范围最小，也不会破坏现有单集流程。

## 3. 前端交互

### 3.1 首次空项目

- 页面头部始终提供“多集导入”按钮。
- 现有单文件上传和粘贴入口保持原位。
- 点击“多集导入”打开 `EpisodeImportDialog`。
- 空项目不显示“追加导入”，避免把首次导入描述成追加操作。

### 3.2 已有剧集

- 继续显示“追加导入 / 批量导入”。
- 两个入口继续复用同一个 `EpisodeImportDialog`。
- 已有集号传入弹窗，沿用覆盖、跳过和批量冲突处理。

### 3.3 文件选择与预检列表

- 文件选择继续支持 `.md`、`.txt` 和 `.docx`，并允许多选。
- 每个上传文件可产生一个或多个预检候选。
- 合集拆分后的显示名称采用“原文件名 · 第 N 集”，但持久化来源仍保留原始文件名。
- 每个拆分候选必须拥有独立 `file_id`，前端提交始终使用 `file_id`，不以显示名称作为主键。

## 4. 合集拆分契约

新增纯领域函数，把一个已解析为文本的上传文档转换为一个或多个 `EpisodeCandidate`。

### 4.1 分集边界

只识别独占标题行：

- `第 N 集`，其中 N 支持现有阿拉伯数字和中文数字规则。
- `Episode N`，大小写不敏感，并兼容现有分隔符写法。

标题行可以包含该集标题，例如 `第十二集 失踪` 或 `Episode 7: Return`。正文段落中普通提及“第 N 集”或 `Episode N` 不形成边界。

### 4.2 拆分行为

- 检测到两个及以上边界时，按边界拆成多个候选。
- 没有边界或只有一个边界时，保持现有单集候选行为。
- 第一条边界前的剧名、简介或制作说明保留并合入第一集，同时附加“首集包含合集前言”警告。
- 每个候选保留其边界标题行和正文，禁止重写或重新编号。
- 多文件批次中，每个文件独立拆分，最终候选统一进入现有批次预检。

### 4.3 异常与冲突

- 集号重复：标记“批次内部集号重复”，必须手动改号或跳过。
- 集号乱序：允许预检，前端按集号排序展示，不自动重编号。
- 相邻边界造成某集无实际正文：该候选标记为解析失败，其他有效候选仍可提交。
- 无分集标题的单文件：保持单集候选，并允许手动填写集号。
- 已有集冲突、预检过期和项目版本变化：继续使用现有错误码与覆盖/跳过规则。

## 5. 后端数据流

```text
读取上传文件
→ 解析为纯文本
→ 按安全标题行检测分集边界
→ 生成一个或多个 EpisodeCandidate
→ 扁平化整个上传批次
→ 检查缺失、重复和已有集冲突
→ 保存版本化预检
→ 用户明确确认
→ 进入现有 episode_import 异步任务
```

`preview_episode_imports` 从“每个上传文件生成一个候选”调整为“每个上传文件生成候选序列并扁平化”。提交、事务、revision、canonical novel 合成和下游失效机制不重写。

## 6. 错误与数据安全

- 不根据模型推断分集，拆分必须是确定性的文本规则。
- 不自动提交拆分结果。
- 不静默丢弃合集前言、非法段落或冲突候选。
- 无效候选在预检中单独显示；同批有效候选仍可处理。
- 继续使用现有文件名清洗、扩展名检查、单文件大小限制和文档解析隔离。
- 持久化来源文件名保持原值，显示名称仅用于 UI。

## 7. 测试策略

### 7.1 领域测试

- 中文、英文和带标题的分集边界。
- 正文提及集号但不拆分。
- 合集前言合入第一集并产生警告。
- 无边界和单边界保持单集。
- 重复集号、乱序集号和空正文候选。
- 一个文件拆出的候选拥有唯一 `file_id`。

### 7.2 API 测试

- 单个合集文件预检返回多条候选。
- 多个文件中既有单集文件也有合集文件时正确扁平化。
- 拆分候选保留原始来源文件名和独立提交标识。
- 既有冲突、invalid 候选和 preview revision 契约不回归。

### 7.3 前端测试

- 首次空项目显示“多集导入”。
- 首次入口打开 `EpisodeImportDialog`，已有集号为空。
- 已有剧集时继续显示追加与批量入口。
- 合集拆分结果按集号排序，显示可追溯来源名称。
- 现有单文件上传、粘贴和冲突处理测试继续通过。

### 7.4 真机验证

- 重启 NuomiDrama 前后端。
- 使用隔离测试项目上传一个包含中文和英文分集标题的真实合集文件。
- 验证首次空项目能打开多集入口，预检生成多集候选且不自动提交。
- 验证前端代理、后端 API 和任务入口均保持可用。

## 8. 非目标

- 本轮不使用 LLM 推断缺失的分集边界。
- 本轮不把普通文本/小说导入与已有分集剧本导入合并为同一个自动判断入口。
- 本轮不重写 episode import 的事务、版本或下游失效系统。
- 本轮不自动修复重复集号、乱序集号或空正文。

## 9. 验收标准

- 空项目首次进入剧本导入页即可选择多集导入。
- 多个分集文件与单个合集文件都能产生正确预检候选。
- 合集前言、来源文件名和每集正文均可追溯且无静默丢失。
- 所有冲突必须在预检阶段显式处理。
- 现有单集导入、追加导入和批量冲突处理不回归。
- 自动化测试、类型检查和真机预检验证通过。
