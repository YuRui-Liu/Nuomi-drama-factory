# H3 提示词规划失败修复与消耗控制

日期：2026-09-26。用户选择方案 A；本文供实现前审查。

## 目标与证据边界

修复人物字段的正确修复被合并逻辑丢弃、observe 模式重复规划、规划失败后进入不可用回退的问题。保留硬性人物、参考图及协议校验，不以放宽校验换取提交成功。

用户提供的 group-03 / r14 日志显示：DeepSeek 规划报 character_count_mismatch，随后 Ref 执行因 shot-03-01、shot-03-02 缺少 typed director plan 终止。日志不能确定具体错误人物，也不足以计算 token 总数。

离线复现确认 merge_repaired_rigid_prompt 将原名单 (lin)、人数 1 与修正名单 (lin, mei)、人数 2 合并后，仍返回原名单和人数。当前 observe 分支会先调用普通规划，再调用连续性规划；普通规划失败后仍可能运行第二遍，并最终因缺少结构化计划失败。

工作区已有其他人物规范化、失败缓存及质检修改。实现前以最新差异为基线整合，保留他人修改，不重复引入现有机制。

## 1. 有边界的字段修复

保留现有合并函数入口，用明确的错误码和字段路径决定哪些字段可替换。character_count_mismatch 允许修复 scene_context 的 active_characters 与 exact_character_count；其他字段继续沿用原有保护规则。人物站位或表演若也报错，分别依据对应错误码开放其最小修复范围。

替换后对完整计划重新执行现有检查。修复候选仍必须匹配输入人物集合、真实参考图及镜头约束；不自动添加不存在的角色或伪造站位。修复前后数据与检查结果保存在本地诊断记录中。

## 2. 每组只走一条规划路径

先确定连续性策略与可用输入，再执行一次权威提示词规划，不执行第二遍付费影子规划。observe 中连续性准备不可用可记录警告，并以已验证的基础上下文进入这唯一一次规划；guard/enforce 保留各自前置阻断规则。

规划得到的结构化计划、编译提示词和参考图绑定来自同一结果。Ref 模式没有合格结构化计划时立即结束该阶段，禁止回退后继续走到 provider。取消、超时和租约丢失必须直接传播，不能当作观察性失败吞掉。

一次规划可能因现有图片批次限制包含多个请求；“单路径”不等于无条件承诺每组只有一个 HTTP 请求。自动语义修复每个失败片段最多一次，且在调用前持久化预算；输入不变时任务重启不能重置预算。

## 3. 结果复用与消耗边界

沿用现有缓存与锁机制。缓存身份覆盖实际影响请求的剧本、参考图内容、人物事实、相邻上下文、运行时/模型以及提示词、编译器、校验版本。任务 ID 或仅用于重试计数的版本不得单独使相同输入失效。

成功结果直接复用。语义失败保存初始结果、修复结果、具体错误和已用修复次数；重复点击返回保存的失败原因，不自动重新付费。修改有效输入或明确升级相关规则后产生新缓存身份，可重新规划。此次修复使用有针对性的规则版本变更使旧错误结果失效，不清空全部缓存。

网络失败与语义失败分开处理：只重试现有分类中可安全重试的暂时性错误；响应不确定的超时、取消及中断不自动重新提交付费请求。记录尝试状态并提示用户核查。并发相同输入共享缓存锁；锁内再次检查结果与预算。

保留每个已完成片段的缓存；后续片段失败不能要求已完成片段重算。已有 provider 任务号与已生成视频继续使用现有恢复路径，不因本次改动重复提交视频。

## 4. 错误与诊断

对外显示“提示词规划失败，视频尚未提交”，附组/片段、错误码、人物预期与实际差异，以及是否复用了失败记录。保留原始异常因果，不改写成泛化的“缺少计划”。运行时异常与人物检查错误分别显示。

记录规划请求次数、语义修复次数、缓存命中及 provider 是否提交。仅在运行时确实返回用量时记录 token；缺失显示未知，不推算为零。诊断不保存密钥，不在普通错误消息中展示完整模型输入或输出。

## 5. 验收

先离线验证，不调用模型或 RunningHub：

1. 人物修复候选正确时合并后保留；候选不合格仍被完整校验拒绝；未报错事实不被改写。
2. observe 不执行重复规划；语义失败后不执行影子调用、原始提示词回退或视频提交。
3. 取消、超时和租约丢失不会启动后续模型调用。
4. 相同输入重复点击、并发入队和重启均不能重置语义修复预算；成功缓存可复用；已完成片段不重算。
5. 有效输入或相关规则版本变化允许新规划；仅重试任务 ID 改变不会绕过缓存。
6. 错误记录保留原始人物差异及 transport_called=false；没有用量的记录不显示虚构 token。
7. 现有 legacy、guard、enforce、Ref 参考图及视频恢复相关回归测试通过。

离线验收后，通过项目支持的 production_cli 路径验证单个叙事组：检查规划记录、实际 provider 任务号、生成视频及基本播放。遇到失败即收集证据停止，不自动扩展到整集或反复付费质检。真实验证前检查用户当前任务与额度安排，避免与进行中的生成重复。

## 范围限制

本方案不重构整个任务系统，不更换用户模型，不变更 RH 币计费，不绕过人物或参考图协议，不覆盖其他工作区修改。历史失败的精确 token 消耗只在存在可信记录时报告。
