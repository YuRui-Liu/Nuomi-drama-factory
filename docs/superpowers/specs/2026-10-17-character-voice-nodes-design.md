# 角色声音资产与专业配音节点 PRD

日期：2026-10-17。

状态：用户已批准；声音版本及组配音已有接入，专业岗位、部分模式与试听交互仍未完整实现。实施任务见 [实现计划](../plans/2026-10-17-character-voice-nodes.md)，当前覆盖见 [2026-10-17 代码核对](../../design/integrated-production-2026-10-17/PRD-COVERAGE-AUDIT.md)。E01 声音真机验收尚未完成。

## 1. 目标、范围与依据

以角色声音资产节点保存跨集复用的声线，以现有音频节点的角色配音模式承载叙事组对白生产，接入每集统一的“剪辑与声音”主节点。角色、剧本台词、声音版本和生成结果具有稳定身份；画布承载这些内容及其关系。

模型分工固定为 Qwen3-TTS VoiceDesign 设计音色、IndexTTS2 克隆配音。复用已有声音候选、采用与生产服务，补齐画布和 Agent 可执行操作。

依据：[声音调研](../../research/2026-10-17-character-voice-nodes-research.md)、[既有角色声音设计](2026-09-23-character-voice-design.md)、[专业剧本节点](2026-10-17-professional-screenplay-node-design.md)、[导演至成片节点](2026-10-17-director-production-nodes-design.md)。本规格细化声音部分；不改变剧本采用、开始制作、局部重生成及显式导出的已确认边界。

## 2. 已确认决策

| 项目 | 决定 |
| --- | --- |
| 节点边界 | 角色声音资产节点＋现有音频节点的配音模式 |
| 声音来源 | 设计音色、导入参考、复用声音 |
| 配音模式 | 剧本配音、表演调整、自由试音 |
| 专业机组 | 音色设计师、配音导演、配音执行师，均通过注册操作调用能力 |
| 提示词 | 稳定声线、台词表演、朗读文本分层；结构化表单、可编辑描述及实际提交预览 |
| 生产范围 | 按叙事组组织任务，内部台词可选中局部委托；不强制一台词一画布节点 |
| 变更处理 | 标记影响范围，明确发起局部重配；不因上游修改自动生成 |
| 试听采用 | 同稿比较音色；单句、前后句、叙事组试听；生成与采用分开 |
| 剪辑交付 | 记录实测长度，明确处理时长差异，保留版本并显式导出 |
| 首次验收 | 一名 E01 角色＋一组真实对白，跑通后再扩展整集 |

## 3. 内容身份与连线

| 实体 | 内容与关系 |
| --- | --- |
| 角色／身份变体 | 引用现有角色及身份、年龄变体；角色名只用于显示，不作为唯一匹配键 |
| 声音候选 | 声线描述、试听稿、角色资料摘要、来源、音频及检查结果；生成不代表生效 |
| 声音资产版本 | 采用的参考音频及哈希、源候选、角色变体、采用记录；既有版本不可原地覆盖 |
| 台词 | 稳定 dialogue_id、剧本修订、说话人、原文、场景及叙事组关联 |
| 表演单 | 绑定台词和版本的意图、潜台词、情绪、重音、停顿及气息要求 |
| 配音 take | 台词与声音版本、表演单、实际参数、任务、音频、实测时长及采用记录 |
| 时间线音频片段 | 引用采用 take、裁切范围和轨道位置；与时间线修订关联 |

角色声音节点输出声音资产引用；配音节点接收剧本台词和声音资产，按角色／身份 ID 匹配。多角色叙事组可引用多个声音资产。缺少声音时显示具体角色及补齐入口，不任意替代。跨画布视图引用同一资产，移动节点或视觉分组不改变生产顺序或触发生成。

配音节点输出音频结果引用，进入“剪辑与声音”。未采用候选可预览，但不能被当作正式采用版本导出。原视频对白已满足要求时允许继续复用，不强制进行 TTS。

## 4. 角色声音资产节点

收起时显示角色／变体、来源模式、采用声音版本、试听入口和当前任务状态。展开后展示来源设置、声线描述、试听稿、候选比较及采用记录。

| 模式 | 输入与操作 | 产物 |
| --- | --- | --- |
| 设计音色 | 读取角色资料，由用户或音色设计师编辑声线描述和试听稿；明确生成数量后调用 Qwen3-TTS | 可试听的声音候选 |
| 导入参考 | 导入音频、选择有效片段并检查实际适配器要求；保留原音频与截取范围 | 可采用的参考候选 |
| 复用声音 | 选择已有声音版本，明确绑定目标角色／变体 | 声音资产引用，不重新生成 |

候选比较使用同一试听稿；改变试听稿须保留稿件版本并提示比较条件不同。候选数量在生成前明确展示，不自动抽样到“满意”为止。试听不隐式生成额外台词。

采用复用现有校验：角色资料摘要仍有效、技术检查通过、目标引用没有并发变化、存在真实的用户采用记录。采用固定声音版本，不启动批量配音。非语言发声角色不自动编造人类试听台词，动物声或音效不自动作为人类对白克隆参考。

## 5. 音频节点的角色配音模式

沿用现有音频节点及音乐能力，增加角色配音的上下文、表演和版本交互。收起时显示叙事组、台词数、缺失声音、任务进度和采用情况。

| 模式 | 行为 |
| --- | --- |
| 剧本配音 | 读取采用剧本与叙事组台词，绑定声音版本，准备表演单后提交明确范围 |
| 表演调整 | 选择一句或多句，修改表演要求，产生新 take；旧 take 继续可用 |
| 自由试音 | 使用临时文本和所选声音测试，不写回正式剧本或自动进入时间线 |

内部台词列表显示说话人、原文、表演、声音版本、候选、采用及更新状态。支持选中局部委托、单句试听、前后句连播和叙事组顺序试听。连续试听按剧本／组顺序，不按画布坐标。未生成、缺失和失败项明确显示，不用跳过失败项的播放冒充完整结果。

选择性生成以叙事组任务中的台词范围表达；底层分段由支持的执行器管理。任务读取已保存并发设置，不另起绕过生产入口的逐句 provider 脚本。

## 6. 专业提示词与模型能力

### 6.1 三层编辑与编译

| 层 | 可编辑字段 | 提交方式 |
| --- | --- | --- |
| 稳定声线 | 年龄感、音区、共鸣、质感、咬字、语言／口音、稳定节奏、基础表达及限制 | 编译为 Qwen VoiceDesign 的声音描述；保留结构与编译版本 |
| 台词表演 | 对谁说、意图、潜台词、情绪及强度、重音、停顿、气息 | 编译为实际支持的 IndexTTS2 情绪控制，其他字段保留为试听标准 |
| 朗读文本 | 已采用剧本的原文、台词 ID、必要读音映射 | 提交实际朗读文本；原文与发音替换映射均可审查 |

提供结构化表单、可编辑描述及实际提交预览。自由描述修改先解析成字段差异，用户接受后更新结构并重新编译，避免两个编辑入口保存互相矛盾的内容。预览区区分已提交参数、仅供表演参考的要求和不支持的控制。

用户说“更年轻一点，压住怒气”时，Agent 分别形成声线年龄感修改建议和台词情绪修改建议。前者影响角色声音候选，后者影响选中台词，不能混为一次全局重配。

原创示例：声线描述为“普通话，青年男性，中低音，声线清晰略带颗粒感，咬字利落，节奏自然”；表演单为“对同伴说，阻止其冒险，克制紧张，重读‘别进去’，之后短停顿”；实际台词为“别进去。我听见里面有人。”表演说明不混入朗读文本。

### 6.2 可用控制

IndexTTS2 情绪模式为沿用参考表现、情绪文本、情绪参考音频、专家向量，一次选择一种。仅开放当前 provider/workflow 支持的模式；沿用参考不保证中性。复杂表演单不能直接冒充情绪分析器可完整执行的指令。

Qwen 使用 VoiceDesign，Index 使用用户指定的 v2；模型、provider、workflow 与编译版本必须记录。不能静默换成 Qwen Base 克隆或 IndexTTS2.5。Qwen 样本作为 Index 的音频参考传递，跨模型声线保持程度由实际试听验证。

原版 IndexTTS2 的精确时长控制未开放；目标时长属于剪辑要求，实际结果需测量。音区、情绪、重音和停顿的描述不代表精确声学保证。原版参考音频的截断规则及托管工作流限制由适配器显式呈现，不让用户在未知情况下被截取。

当前 Qwen RunningHub 工作流将语言 Auto 保留在工作流内。界面可保存语言意图，但不能把未映射到工作流的参数显示为已提交。混响、电话效果和空间感由后期混音处理，保持长期声线参考可复用。

## 7. 机组与 Agent 可执行契约

| 岗位 | 职责与调用范围 |
| --- | --- |
| 音色设计师 | 读取角色依据，形成声线规格和试听稿，调用 Qwen 生成候选，解释差异并提出采用建议 |
| 配音导演 | 阅读上下文，设计台词表演、区分情绪与潜台词，组织试听和局部修改建议 |
| 配音执行师 | 校验声音引用与供应商能力，调用 IndexTTS2，追踪任务、错误、take 和版本 |

以下名称定义操作语义，实现时映射到现有节点协议；本文件不表示它们已经安装：

| 操作 | 输入重点 | 返回与写入边界 |
| --- | --- | --- |
| voice.prepare_design | 角色／变体及资料版本 | 声线规格、试听稿、依据；不生成音频 |
| voice.generate_candidate | 设计版本、试听稿、候选数量 | 任务、候选、实际参数；不采用 |
| voice.adopt | 明确候选和真实用户采用记录 | 校验后固定声音版本，保留旧版本 |
| dubbing.prepare | 剧本、叙事组、台词范围、声音版本 | 表演单、缺失依赖、提交范围；不生成 |
| dubbing.generate | 固定输入快照、表演与授权范围 | 可恢复任务及 take；不替换时间线 |
| dubbing.adopt | 指定 take 和采用授权 | 更新采用引用，返回时间线影响；已有片段替换另需明确授权 |

每次执行包含项目、节点、内容版本、范围、幂等键、provider/model/workflow 版本；返回任务状态、有效参数、不支持项、产物及错误。参数不支持时在提交前阻止该配置，并展示可选调整，不静默忽略。

复用 node.run 的精确节点、操作、次数和版本授权，补齐能力目录、请求 schema、适配器及结果投影。设计 Agent 的角色名称不等于工具已可执行。生成、采用、时间线替换和导出分别检查授权；已有授权范围内正常推进，不重复询问。角色音色采用继续通过既有人工采用契约，Agent 不伪造人工 actor。

## 8. 版本、影响与恢复

| 变化／异常 | 规定行为 |
| --- | --- |
| 某句原文变化 | 标记该句及其引用结果需要更新，保留历史 take |
| 某句表演变化 | 为选择范围产生新 take，保留旧版比较 |
| 新声音被采用 | 列出引用旧版本的台词，由用户或授权 Agent 明确选择重配范围 |
| 剧本增加／删除台词 | 展示差异和时间线影响；不静默删掉已采用媒体 |
| 节点移动或视觉分组改变 | 不触发生成或内容版本更新 |
| 执行期间上游变化 | 按启动快照完成候选，标记来源已更新；不覆盖当前采用版本 |
| 部分台词失败 | 组状态显示部分完成，重试仅提交失败项；成功产物复用 |
| 请求超时／状态未知 | 先按任务和幂等标识查询，不盲目重新付费提交 |
| 重试时输入已变 | 作为新版本任务；不能冒充旧任务恢复 |

候选生成状态与是否采用、是否过期分别记录，避免一个状态字段丢失信息。采用和时间线更新做版本冲突检查，发现冲突展示差异，不覆盖其他修改。

## 9. 试听、采用和剪辑交付

音色使用同稿比较；配音提供单句、上下文及整组试听。检查文件可解码、非空和已有技术检查结果，失败阻止采用。声音身份、情绪及衔接由实际试听确认，不默认增加 ASR 或重复付费质量检测。

采用配音保存原文、表演单、声音版本及实际参数。采用结果可以进入待放置素材；放入轨道及替换已有片段均绑定时间线版本，替换必须在明确授权范围内。

展示目标时间区间、实测长度和差值。超长时提供调整剪辑、重新表演、返回剧本修改三个处理入口，不擅自删台词或强制变速。修改剧本继续经过剧本采用及依赖影响流程。

候选生成、声音采用、批量配音、配音采用、时间线替换和正式导出为独立动作。采用声音不启动整集配音；完成配音不自动导出成片。

## 10. 复用面与实施缺口

复用 `media_capabilities/tts/models.py`、`voice_prompt.py`、`character_voice.py` 的结构和编译流程，`task_backend/runners/voice_design.py` 的 Qwen 任务，`voice_candidates.py` 和 `candidate_store.py` 的候选采用，以及 `freezone/audio_node.py` 的 Index 配音基础。已有角色资产面板继续与画布共享同一数据源。

已有 audioNode:speech/music 可经通用节点适配器执行；仍需补齐角色声音画布操作、角色／台词范围绑定、版本影响、表演编辑、候选投影、时间线采用及对应 Agent 契约。目录中的能力声明和普通 HTTP API 不能替代可执行适配器。

具体代码任务在书面规格批准后形成实现计划。本次不新增模型部署、供应商迁移或新的音乐生产系统。

## 11. 验收标准

1. 同一角色可设计、导入及复用声音；生成候选不改变生效声音，采用有可追溯版本。
2. Qwen 候选采用后，IndexTTS2 使用该参考生成真实 E01 台词；声线保持程度经实际试听确认。
3. 叙事组内多角色分别绑定正确声音，缺少引用可定位，台词原文与表演说明不会混读。
4. Agent 能通过注册操作完成准备、生成和任务查询；越范围操作被拒绝，已有授权无需逐项重问。
5. 改动一句只标记相关结果；旧 take 可回看，上游并发修改不覆盖当前版本。
6. 失败项可恢复，成功项不重复生成；未知状态先查询，输入变化形成新任务。
7. 单句、前后句、组试听及时间线播放可用；显示实测时长和差异，不承诺未支持的控制。
8. 首次使用一名 E01 角色及一组真实对白完成“设计→试听采用→克隆配音→试听采用→时间线播放”，记录输入版本、任务和实际结果；此后扩展整集并完成正式导出及播放验收。

后续真机生产遵循 `skills/nuomi-production/SKILL.md` 和 `novelvideo.production_cli`，叙事组仍为生产单位，使用保存的并发设置；阻塞时修复支持入口。实现验证覆盖能力映射、版本冲突、幂等恢复和采用边界；实际生成验证按上述有限范围执行，不把文档完成作为 E01 完成。
