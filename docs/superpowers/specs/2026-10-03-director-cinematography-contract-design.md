# 通用导演分镜与八项创作决策规格

日期：2026-10-03。

状态：用户已确认方案 1 及对话中的具体设计；本书面规格等待审阅。本文描述目标行为，尚不代表实现或实际分镜质量已验收。

## 1. 目标与范围

把焦段、景别、机位、构图、运镜、人物动作与表演、光影、镜头衔接的创作决策统一到现有通用导演计划。静态出图和视频生成消费同一采用版本。MiniMax H3 适配负责供应商输入表达，不承担补写或覆盖上游导演决策的职责。

保留「剧本语义 → 叙事组 → 导演镜头 → 组图 → 组视频 → 整集组合」生产入口和原文引用。扩展既有导演工作台的决策展示、修订和审查结果；不另建创作平台，不修改编剧系统，不自动覆盖生产剧本或重生成媒体。

本设计不能代替真实分镜审查。当前代码证据支持发现契约与传递缺口，尚不足以判定某一集的实际摄影、表演和剪辑质量。

## 2. 依据与现状

主要外部依据为 [Hell Grind 官方制作简报及训练室案例](https://higgsfield.ai/@higgsfield.studio/projects/hell-grind)，于 2026-10-03 通过动态页面读取。参考其空间地图、光学与机位联合表达、动作中的摄影机行为、行为式表演、跨镜状态延续和剪辑反馈。

本地参考材料：`assets/higgsfield/CINEDANCE HIGGSFIELD SKILL.md`、`assets/higgsfield/ACTING SKILL.md`、`assets/higgsfield/LIRA SKILL.md`。它们作为方法资料，不覆盖用户创作意图或供应商协议。单光源、首秒宽景、固定微动作频率、无配乐等项目经验不能成为所有题材的硬规则；不复制规避内容过滤的技巧。

当前已核对的实现：

| 模块 | 已有能力与缺口 |
| --- | --- |
| `director_plan/models.py` | 有意图、起止状态、景别、角度、构图和运镜；缺独立光学计划，构图允许为空，存在 4 镜/组及 15 秒/镜限制 |
| `director_plan/cinematography.py` | 已分离世界位置与屏幕位置，并记录轴线、调度和动机光源；主要验证引用与角色集合 |
| `director_plan/prompts.py` | 已有单镜职责、持物接触、状态连续性等要求；完整摄影和表演决策尚未统一表达 |
| `director_plan/validation.py` | 侧重来源覆盖、字段与引用，起止文本相同被拒绝；不能据此宣布创作合格 |
| `narrative_groups/service.py` | 传递基础镜头字段、cinematography 和 director_intent |
| `narrative_groups/image_prompt.py` | 投影起始帧，但朝向、视线和曝光重点没有作为专门字段完整传入 |
| `media_capabilities/video/h3_rigid_prompt.py` | 已有 H3OpticsPlan、H3LightingPlan、H3CharacterActingPlan，可提取创作语义复用 |
| `media_capabilities/video/h3_prompt_compiler.py` | 已能编译光学、表演等信息；应消费采用的通用决策 |

本文补充 2026-09-30 的剧本创作与导演转译规格，不改其原文保真要求。2026-09-08 的 H3 官方 wire format 规则继续有效；更早「十五段标题直接发送给 H3」的设计不恢复。

## 3. 职责与权威来源

```text
已采用剧本、语义节拍、资产与风格
                ↓
通用导演计划：场次 → 叙事组 → 单镜头 → 相邻镜头衔接
                ↓
         采用版本与依赖快照
          ↙             ↘
关键帧投影与组图装配      供应商执行计划与 H3 编译
          ↓             ↓
      图片观察证据 → 一致性冲突检查 → 视频执行
```

剧本拥有故事事实和对白；导演拥有摄影、表演、节奏和衔接决策；观察记录描述实际媒体；供应商适配拥有执行参数。冲突必须显式记录，后写入的数据不能静默覆盖另一种权威来源。

场次拥有稳定地理与光源；叙事组拥有戏剧目标、信息释放、节拍及覆盖关系；单镜头拥有具体拍摄决策。相邻镜头连接记录跨镜交接，不在两镜自由文本中各保存一份互相竞争的决定。

## 4. 通用创作契约

在 `director_plan` 下扩展版本化契约，依赖方向保持通用层不导入 H3 类型。复用现有 ShotPlan、DirectorShotIntent、ShotCinematography 和来源 ID，不建立平行的镜头事实库。

### 4.1 场次与叙事组

场次记录稳定 ID、空间地标、相对距离、动作轴、可用摄影机区域、光源和初始关系。世界关系固定，屏幕关系依据当前机位计算或明确描述，不把 frame-left 永久当作世界左侧。无需引入三维仿真引擎。

叙事组记录目标、观众获得的信息、表演策略转折、必需覆盖的源节拍、镜头顺序和切镜理由。原文和节拍覆盖保持可追溯；允许多个镜头共同承载一个节拍。静态反应、空镜和保持镜头不因缺少大动作而被拒绝。

### 4.2 八项镜头决策

每项决策携带具体选择、目的和来源。来源区分剧本事实、资产事实、导演创作选择、媒体观察，摄影创作不冒充原文明确事实。新契约必需项不得用空字符串或默认中景/平视/静止伪装已设计。

| 维度 | 必须表达 | 审查重点 |
| --- | --- | --- |
| 光学 | 焦段及画幅基准，或注明方向的视场角；主体距离、景深、焦点对象、焦点变化及目的 | 与景别、距离、透视和注意中心是否一致；无法确定画幅时不伪造毫米与角度换算 |
| 景别 | 开始与结束的取景范围、必须可读的人物/物件、选择理由 | 信息与表情是否看得清，变化是否服务叙事 |
| 机位 | 地标参照、位置/高度/距离、朝向、轴线侧 | 反打与屏幕左右关系、可达路径、人物视线关系 |
| 构图 | 注意中心、主体画面位置与占比、深度层、遮挡、视线空间、起止构图 | 关键动作与反应可见，避免参考图构图误继承 |
| 运镜 | 固定或运动、触发节拍、路径、速度变化、结束条件、约束与动机 | 运镜与动作同步，终点构图可达；固定也可为有效选择 |
| 动作与表演 | 起止状态、主动作与节拍、人物目标/阻力/策略、可见反应、视线、接触、持物、重量与惯性 | 行为可执行、情绪有延续；不能以情绪标签替代行为 |
| 光影 | 场次光源引用、当前机位的受光、阴影、光质、颜色、主体/背景曝光关系、必要眼神光 | 保持世界光源，改变视角时正确表达其效果，允许合理多光源 |
| 衔接 | 前后镜 ID、切点触发、空间/视线/动作相位/持物/情绪交接、声音桥接意图 | 区分有意跳切/越轴与无意错误，跨组边界同样检查 |

适用性显式表达：无人物镜头的表演项为不适用并说明原因；无焦点变化表示保持；固定镜头表示固定。风格化二维作品保留取景与深度意图，可标物理焦段不适用，不强加写实摄影或皮肤规则。

动作使用镜内相对时间与明确事件锚点。导演层保存创作时长，不绑定 24fps；适配层负责帧化及舍入并报告误差。保留静止张力、观察、等待、声音事件驱动的镜头；删除「起止文本必须不同」作为通用创作硬门槛。

## 5. 生成、审查与采用

沿用现有导演任务入口：先建立场次共享事实，再确定叙事组意图与覆盖，随后细化镜头，最后审查组内及跨组衔接。各阶段可在同一任务中完成，不要求固定数量代理或新增多代理团队。

确定性结构检查与语义创作审查分开保存。创作审查读取计划和源资料，不把生成者自填「通过」视为审查结果。审查可由现有文本运行时执行独立审查阶段，复用当前模型设置；不自动循环付费调用。

报告记录计划版本、规则版本、审查状态、问题严重度、维度、镜号或镜头对、证据字段、影响和修订建议。状态明确区分未审查、需修改、通过和待人工判断；结构通过不能推导创作通过。无法判断时保留不确定性。

新契约自动放行须结构通过且无未解决的创作阻断问题。人工可对审美争议记录采用理由；不可豁免无效来源或缺失引用等硬错误。报告和人工结论随版本保存。旧契约继续按原行为读取，不追溯宣称新标准合格。

修复生成候选修订，并显示差异；采用沿用项目既有交互。修改镜头数、动作、机位、对白或切点不能由适配层暗中执行。

## 6. 关键帧与出图投影

每个关键帧绑定镜头 ID、导演版本和时间/事件锚点。默认起始帧；结束帧或中间帧必须由导演明确指定。组图保持镜号与关键帧映射，不因版面限制改变叙事分组或镜头数。

投影时消费该瞬间的光学、景别、机位、构图、朝向、视线、持物、表情和受光关系。动作轨迹、未来结果、切镜指令不混入静态画面；起始状态不得使用动作完成后的道具状态。镜内拉焦或运镜仅投影选定时刻的状态。

参考图分别声明身份、造型、地理、风格或构图用途及限制。镜头构图由导演计划决定；场景参考不能未经声明覆盖导演机位。投影带上实际消费的字段依赖和版本/hash，确保修改相关导演信息后缓存失效。

## 7. H3 适配边界与生产拆包

从现有 H3 光学、灯光、表演类型中提取通用创作语义；H3 类型保留兼容读取或映射，不长期维护两份可独立修改的创作真相。不得批量把历史 H3 推测倒灌成已确认导演决定。

适配负责模型模式、参考槽位与标签、音视频格式、原生时长、分辨率和时间编码，维持现有官方 wire format。H3 专用诊断可以提出可执行性风险，不授予其改写创作事实的权限。

新导演契约解除供应商来源的 4 镜/组、15 秒/镜上限；导演时长仍必须有限且为正，镜头集合非空。组图布局与视频执行按能力拆成生产包，每包保留组/镜头和时间区间映射，不把生产包冒充叙事组。

若拆包仅改变调用边界且能保持采用的动作、切点、时间及交接要求，可自动派生；若需要新增切点、压缩表演、改变运镜或当前后端不能保持连续，则返回 capability_conflict 和备选方案，停止受影响包。未受影响包可继续。长镜头不能因底层时长限制被静默改成多个剪辑镜头。

媒体观察与导演计划冲突时，保存预期、观察、资产 hash 和受影响决策。修图、接受观察并形成导演修订、或补充核对都沿用显式修订流程。既有图像只是实际输入证据，不能在适配时偷换导演的空间或人数。

## 8. 修订与依赖失效

沿用不可变导演修订和稳定镜头 ID；拆镜/并镜记录替代映射。下游资产绑定采用版本、消费字段及依赖 hash。历史结果保留查看，不删除文件、不触发自动重生成。

| 改动 | 需重新计算或复审 |
| --- | --- |
| 单镜光学、构图、起始调度或受光 | 该镜关键帧与相关组图包、视频包、相邻衔接 |
| 仅后半段动作、运镜或表演 | 受影响时间的关键帧、视频包和相邻衔接；未消费这些字段的首帧不失效 |
| 场次地理或固定光源 | 所有依赖该场次事实的镜头及其衔接 |
| 单镜时长或切点 | 时间映射、视频执行包、整集组合及相邻衔接；静态画面仅在所选时刻状态变化时失效 |
| 仅供应商格式或引用编码 | 对应编译结果和执行计划，通用导演计划与静态图不失效 |

组图是一张共享资产时，其中一格变化使该组图包陈旧；不能声称共享资产的其他格仍可直接代表最新完整组图。

## 9. 历史兼容、接口和展示

新增独立创作契约版本，不依赖 prompt_version 字符串判断完整性。旧计划缺失字段保持缺失，标为 legacy_unreviewed；读取时不得补默认值后显示已设计。升级生成新的补全候选版本，保留原采用版本直到人工采用。

API 返回决策、来源、审查与依赖状态。现有导演工作台展示八项决策、逐镜/跨镜问题、候选差异和采用状态，不要求用户理解 H3 内部协议。编剧模块的未提交改动与本次导演设计分开实施。

历史消费路径保留兼容分支，新版通用契约覆盖的字段只能从该契约投影。镜头复制、手工编辑、组拆并、修复和 agent-team 入口均遵守同一读写契约，不能通过某个入口绕开审查或回填旧默认值。

## 10. 验证与验收

自动化验证覆盖数据与传递；创作审查覆盖文本决策；媒体验收覆盖真实执行。报告分别给出证据和未验收项，不汇总为一个含义不明的「生产级通过」。

| 样例 | 必须证明的行为 |
| --- | --- |
| 对白正反打 | 共享地理、机位投影、视线衔接、听者反应及情绪余波；不把画外说话者强制画入画面 |
| 持物交接 | 所有者、持物手、接触过程和落点一致；首帧不提前画成已交接 |
| 复杂动作 | 摄影机与动作节拍关联，重量/惯性/支撑可说明；不支持的执行请求显式冲突 |
| 静止反应 | 起止状态相同可合法，叙事职责与持续状态可审查；不强造动作 |
| 跨空间转场 | 地标、出入口、光源关系和交接有依据；允许有意风格变化并记录理由 |
| 长镜头与多镜组 | 超过 15 秒或 4 镜的新导演计划可保存；后端能力冲突不改写原计划 |
| 跨层保真 | 关键帧与 H3 对相同决策保真；修改视线、焦点或光源后只使实际依赖项失效 |
| 历史版本 | 旧数据仍能读取，缺项不冒充已审查；补全候选不覆盖原采用版 |

创作审查样例同时包含有意跳切/越轴和无意连续性错误，避免规则只会拒绝。未知画幅、二维风格、无人物镜头和多光源场景均需覆盖。

真实验收选取用户指定项目的已采用剧本与分镜，记录项目、集数、修订 ID 和源 hash 后逐镜检查八项，再检查全部相邻镜头，包括组间边界。当前尚未选定冻结样本，不影响实现契约测试，但不得宣称该集质量已通过。现有可用媒体可作观察依据；新增付费生成不属于本次规格编写任务。

## 11. 实施影响面与顺序

1. 通用创作模型、版本与历史兼容：`director_plan/models.py`、`cinematography.py`、store/editing 及新增职责单一模块。
2. 导演生成、修复、结构与创作审查：prompts/planner/validation/service 和既有运行时入口。
3. 数据投影与关键帧：`narrative_groups/service.py`、`image_prompt.py` 和组图布局消费方。
4. 通用决策到 H3 的兼容映射、编译与能力诊断；调整生产拆包，保留供应商协议。
5. 工作台展示/编辑、版本依赖失效和跨层验收。

先以离线 fixture 和 mock 验证数据流，随后对实际采用分镜执行只读审查。测试通过后才能说明契约实现完成；实际画面是否合格继续由对应媒体证据支持。

## 12. 本轮交付边界

本轮仅新增本规格并单独提交，未修改实现、未启动模型生成、未更换项目采用版本。书面规格经用户审阅后再使用 writing-plans 生成实现计划。

## 13. Hell Grind 经验吸收复核（2026-10-03）

复核结论：上一版已吸收八项决策和上下游权威边界，但对创作过程、提示词装配和失败修订的约束还不充分。以下补充属于目标规格，并不表示代码已经实现。证据范围是官方制作简报、训练室文字案例及上述三个本地技能材料；未逐镜观看全片，也未遍历全部生成记录。公开制作资料不等于所有材料均采用无限制的软件开源许可，复用时需保留其各自授权边界。

### 13.1 从经验到执行要求

| 经验与来源定位 | 上一版缺口 | 本规格补充的可验收要求 |

### 13.2 参考材料的冲突与适用边界

同一权限范围内，明确采用的场次例外优先于全局风格默认值，并记录覆盖理由。风格参考不能覆盖剧本事实、身份或导演调度；场景参考中的光线若与采用的场次光源冲突，应报冲突而非静默选一份。母本与场次表演矛盾时同样进入修订流程。

训练室文字示例中，托盘在两名人物之间的持有描述及后续数量存在歧义，应作为道具守恒审查的反例；不能因为来源是官方示例就复制为有效调度。案例中的群体同时微笑也不能覆盖 ACTING 的错峰反应建议，须按具体戏剧意图判断。

“从动作中段开始”是可选导演决定。选中中段关键帧时状态应与该时间一致；如果剧本必须交代拿取、蓄力或交接，则不能用模型更擅长静态状态为理由省掉因果链。首秒宽景、单一光源、固定眼动频率、固定静音间隔、特定修图模型顺序均不成为通用规则。参考中的模型能力断言须由当前能力配置验证。

### 13.3 补充验收案例

下列离线案例需同时给出正例和故意破坏的反例，验证审查能定位证据；不能只验证字段存在。

1. 三人训练室：关键背景与人物均需可读，光学和焦点方案应支持该意图；摄影机随指定头转事件轻微重构图，承重手臂影响肩姿，托盘数量与持有人全程守恒。
2. 坐姿对话：同一角色的焦躁行为适应坐姿，声线身份保持一致；听者在对白结束前已有可见反应，反打不重置情绪与视线。
3. 历史音频隔离：上一镜提到画外人物，本镜仅继承情绪背景；最终提示词不新增该人物、资产引用或重复对白。
4. 场景反打与阈限：反打保持地标和世界光源；穿过门口进入另一光区有空间依据。未提供反向资产时明确证据不足，不冒充验证通过。
5. 定点修订：仅修复眼神方向时保留其他采用决定；若修复导致身份或构图改变，媒体审查应报告新冲突而非自动采用。
6. 剪辑覆盖不足：观众需要看到的道具信息没有可读镜头时提出插入镜候选，保留来源节拍；未采用前不得由 H3 编译器自行插镜。

上述案例通过只证明方法和数据流具备对应约束。判断用户实际项目是否达到生产创作要求，仍需执行第 10 节冻结样本的逐镜与跨镜审查，并以实际媒体核对可实现性。

### 14.1 逐项返修与复查

每条 QC 问题具有稳定 issue_id，记录发现轮次、所审查修订 ID、具体问题、镜号/字段证据、影响及验收条件。每轮返修输入必须包含当前未解决问题及每条问题历次的作者修法、实际变更、下一轮 QC 复查结果，不能只传最新一段错误摘要。问题按 ID 关联，不能靠描述文本相同判定为同一问题。

作者对每个待处理 issue_id 提交一条响应：采取的修改、理由、受影响镜头/字段及可核查证据；未改则说明异议或阻塞原因。缺项、未知问题 ID、只说“已优化”而无具体修改均不能构成完整返修。作者响应只能标记 proposed_change / disputed / blocked，不能写 resolved 或替 QC 宣布通过。

下一轮独立 QC 针对新修订逐项判定 resolved / persists / regressed / needs_human；发现新问题时分配新 ID。检查此前解决项是否回归，未复查的旧问题保持原状态，不能因本轮报告未提及而自动关闭。只有该轮 QC 可更新问题结论，且结论必须绑定当前受审修订；过期 QC 不得覆盖新修订状态。返修记录和报告采用追加历史，任务重试不得重复追加同一轮结果。

QC 服务超时、输出无效或达到配置的返修预算时保留需审查状态，不将失败视为通过，不自动无限重试。作者拒绝或无力修改不抹除问题，由人工决定后续行动。运行时的 JSON 格式重试与创作返修分别计数，不能冒充已经进行了独立 QC。

### 14.2 作者 Codex 会话

同一修订链的作者持续使用真实 Codex session，持久保存 project_id、task_kind、revision_chain_id、author_session_id 和运行配置引用。首次创建后以明确 session ID 续接；禁止用 `resume --last` 选择不确定会话，禁止以重复拼接摘要替代真实 session 续接。

任务中断或进程重启后仍从持久映射恢复。并发修改同一链需串行锁或版本冲突拒绝，不允许两个返修同时推进同一个作者会话。CLI 能力以实际安装版本验证；不支持续接、会话丢失或凭据不可用时显式报告 session_resume_unavailable，不能静默新建后声称已续接。经显式重建时保存新旧会话关系与恢复上下文。

QC 使用独立执行上下文，不复用作者 session，也不继承作者未通过的结论。QC 获得剧本、当前候选、评价规则、历史问题及修复证据，不依赖作者会话中的隐含对话。作者与 QC 使用同一模型也必须保持独立会话；模型名称相同不等于可以共用上下文。

### 14.3 跨任务有效记忆

新任务在新的作者 session 中检索同 project_id、同 task_kind 的有效记忆，修订链内继续原 session。记忆包含来源修订/问题、规则版本、适用条件、QC 验证结果和有效状态；未通过的修法可作为明确标注的失败尝试提供，不能晋升为成功经验。跨项目、跨任务类型和已失效记忆不进入默认检索结果。

记忆是辅助证据，不能覆盖当前剧本、采用的创作决定或用户新要求。用户纠正、QC 回归或规则版本改变时标记受影响记忆失效或需复核，保留历史；不能用“记忆已存在”跳过当前 QC。检索与写入由服务控制，作者文本不能自行提升记忆可信状态。

### 14.4 必须通过的验收

1. 连续两轮返修实际调用同一 author_session_id，任务重启后仍使用它；另一修订链不串入。
2. 第二轮作者输入包含第一轮具体问题、第一轮修法、第一轮修改后的 QC 结果，并逐项提交响应。

4. QC 调用始终独立于作者 session；上一轮已解决问题回归时重新阻断采用。
5. 同项目同类任务有效记忆可继承；不同项目/类别、过期记忆和未经验证的“成功修法”不会作为有效经验注入。
6. 并发返修、任务重试、会话丢失及 QC 异常均保留可追溯状态，不重复推进轮次，不静默降级成无会话或自审模式。
