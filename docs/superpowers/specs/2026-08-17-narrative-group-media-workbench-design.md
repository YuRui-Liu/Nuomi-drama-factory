# 叙事组媒体生产工作台设计

日期：2026-08-17
状态：已确认设计，待实施计划

## 1. 背景与目标

当前虾镜页面以单 Beat 为中心，虽然系统已有多宫格生成、切分以及 RunningHub Minimax H3 能力，但主页面没有把这些能力连成可操作的生产流程，视频模型列表也仍来自旧后端枚举。

本设计将“叙事组”设为默认生产单位，建立以下主链路：

`叙事组 → 草图多宫格 → 自动切分与检查 → 渲染多宫格 → 自动切分 → Minimax H3 视频`

单 Beat 操作保留为局部修复方式，不再承担批量生产主流程。

## 2. 已确认的产品决策

- 采用统一的“叙事组生产工作台”，不另建割裂的批处理页面。
- 多宫格是默认生成方式；单 Beat 生图只用于补图、替换和重试。
- 先生成草图多宫格并切分，再生成渲染多宫格并切分。
- 每组自动选择 `2×2`、`2×3` 或 `3×3`；每组最多 9 个 Beat，超出部分自动续到下一组。
- 多宫格成功后自动切分，同时提供“整组重新生成”。
- 项目级默认视频模型为 RunningHub Minimax H3；Beat 默认继承，允许临时覆盖。
- 视频输入模式默认自动选择：首尾帧齐全使用 FL2V，只有首帧使用 I2V；高级设置允许手动覆盖。

## 3. 页面信息架构

### 3.1 左栏：叙事组导航

每个叙事组显示：

- 组号、标题与 Beat 范围；
- 当前阶段和完成比例；
- 草图、渲染图、视频的异常数量；
- “继续生产”与“整组重生”入口。

状态按项目与集持久化。刷新页面后恢复到最近操作的叙事组与阶段。

### 3.2 主区：生产阶段

主区按顺序呈现五个阶段：

1. 草图多宫格；
2. 草图自动切分；
3. 渲染多宫格；
4. 渲染图自动切分；
5. 视频生成。

每阶段显示 `未开始 / 排队中 / 生成中 / 待检查 / 已完成 / 部分失败 / 失败`，并提供对应日志、产物和恢复动作。

### 3.3 Beat 检查区

切分后的每个格子确定性映射到 Beat，不依赖文件名猜测。用户可以：

- 查看草图和渲染图；
- 标记通过或需修复；
- 单 Beat 重生、上传替换；
- 必要时重新裁切；
- 查看该 Beat 的视频状态和临时模型覆盖。

## 4. 分组与多宫格规则

后端根据叙事连续性形成稳定的 `narrative_group_id`。同一地点、时间段和连续动作优先同组；分组结果可人工调整，但调整后必须重新计算格位映射。

布局规则：

- 1–4 个 Beat：`2×2`；
- 5–6 个 Beat：`2×3`；
- 7–9 个 Beat：`3×3`；
- 超过 9 个 Beat：按叙事顺序拆成多个子组。

不足格位作为空白安全格，切分时不创建 Beat 资产。生成请求必须携带稳定的 `group_id`、`grid_revision` 和逐格 `cell_to_beat` 映射。

## 5. 图像生产链路

所有图片任务统一通过媒体能力路由选择 GRSAI，不再借用文本模型网关凭据。

### 5.1 草图阶段

- 输入：组内 Beat、角色/场景/道具引用、构图与连续性约束；
- 输出：一张草图多宫格与格位清单；
- 成功后自动切分并生成 Beat 草图资产；
- 任一格质量不合格可单格修复，也可整组重新生成。

### 5.2 渲染阶段

- 仅在草图格位映射稳定后进入；
- 使用草图多宫格及已确认资产作为参考；
- 输出渲染多宫格，成功后自动切分为 Beat 最终图；
- 整组重生创建新 revision，旧 revision 保留并可回退。

### 5.3 幂等与恢复

请求使用 `project_id + episode_id + group_id + stage + revision` 作为幂等边界。自动切分失败时不重复计费生成原图，只重试切分；整组重生才创建新的生成任务。

## 6. Minimax H3 视频链路

视频模型来源改为统一媒体能力目录，而非旧 `VideoBackend` 枚举。目录至少返回：模型 ID、展示名、提供方、支持的输入模式、分辨率/时长限制和可用状态。

项目设置持久化默认模型 `runninghub:minimax-h3`。生成时：

- Beat 有首帧和尾帧：自动选择 FL2V；
- Beat 只有首帧：自动选择 I2V；
- 输入不满足模型要求：在入队前给出可行动的校验错误；
- 单 Beat 模型覆盖只影响该 Beat，不回写项目默认值。

前端必须明确显示实际提交的模型与模式，避免选择器显示值和后端实际调用不一致。

## 7. API 与数据契约

建议引入叙事组聚合资源：

- `GET /projects/{project}/episodes/{episode}/narrative-groups`
- `POST /.../narrative-groups/rebuild`
- `POST /.../narrative-groups/{group}/sketch-grid/generate`
- `POST /.../narrative-groups/{group}/render-grid/generate`
- `POST /.../narrative-groups/{group}/{stage}/split`
- `POST /.../narrative-groups/{group}/{stage}/regenerate`
- `GET /media-capabilities/video/models`
- `PUT /projects/{project}/media-defaults`

可复用现有 `/grids`、`/sketches/generate`、`/grids/{grid_index}/regenerate` 与 `/cut` 实现，但前端只依赖新的叙事组聚合合同，避免自行拼装多个旧接口状态。

任务结果必须返回 `group_id`、`stage`、`revision`、`grid_asset`、`cell_assets`、`cell_to_beat`、`model/provider` 和逐格错误。部分格失败不能把整组伪装为成功。

## 8. 并发与性能

- 同一叙事组的阶段串行，组与组之间可并行；
- 草图和渲染各自设置项目级并发上限；
- 视频按 RunningHub 配额控制并发，界面展示排队数量；
- 前端提交后立即返回任务，不让 HTTP 请求等待完整生成；
- 通过任务事件刷新受影响的组与 Beat，避免全页面轮询和全量重取。

## 9. 错误与恢复体验

错误信息按“阶段 + 组/格位 + 实际 provider/model + 可执行动作”展示。

- 网关未配置：阻止入队并跳转对应设置项；
- 生成失败：可重试本阶段或整组重生；
- 切分失败：仅重试切分；
- 个别格失败：保留成功格，允许单格修复；
- H3 参数不支持：入队前校验并解释缺少首帧或尾帧；
- 任务超时：前端继续追踪后台任务，不把客户端超时误报为生成失败。

## 10. 兼容与迁移

- 现有 Beat 草图、渲染图和视频资产继续可见；
- 旧项目首次进入时按 Beat 顺序生成叙事组索引，不移动原文件；
- 现有单 Beat 接口保留一个版本周期，工作台通过兼容层调用；
- 功能开关先对单项目启用，稳定后替换当前虾镜默认页面。

## 11. 验收标准

1. 用户能从虾镜首页选择叙事组并一次生成多宫格草图。
2. 多宫格成功后自动切分，格位与 Beat 映射稳定且刷新后不丢失。
3. 用户能基于草图组生成渲染多宫格并自动切分。
4. 用户能整组重生，也能只修复一个 Beat；成功产物不会因局部失败丢失。
5. 项目可选择并持久化 Minimax H3，所有 Beat 默认继承。
6. 首尾帧齐全自动走 FL2V，仅首帧自动走 I2V，实际调用信息可见。
7. 所有图像任务实际走 GRSAI，视频 H3 实际走 RunningHub，不读取 DramaClawAPI 图像凭据。
8. 所有长任务异步返回；页面刷新后能恢复状态并继续操作。
9. 合同测试覆盖分组、布局、revision、自动切分、部分失败、模型选择与旧项目迁移。

## 12. 非目标

- 本期不重做图片提示词编辑器；
- 本期不移除单 Beat 生图；
- 本期不新增除 Minimax H3 之外的视频供应商；
- 本期不改变文本模型、TTS 或剪辑工作流。
