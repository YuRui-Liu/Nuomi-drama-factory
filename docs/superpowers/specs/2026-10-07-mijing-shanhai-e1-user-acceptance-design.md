# 密境山海 E1：真实用户制作实测

## 已确认目标

新建独立项目「密境山海」，通过软件的剧集/剧本创作入口产出 E1，最终交付可播放的完整配乐版成片。采用完整制作、沿途修复方案。已有项目只作为可复用资产来源，不改名、不覆盖旧剧本或旧成片。

创作方向：山海志怪悬疑冒险、东方奇幻动画；E1 约 60–90 秒，两名核心角色、少量场景，一次异兽事件开场并留下悬念。具体故事由软件创作功能产生，经界面审阅与修订定稿，不在后台直接写入成稿替代功能测试。

## 操作与费用边界

- 主要通过真实用户界面完成操作。API、CLI、代码和日志用于只读诊断及修复验证，不用后台写数据绕过卡点；此规则优先于仓库默认批量生产方式。
- 尽量复用适合人物身份、时代、画风和场景的已有图片；记录来源及采用关系。复用入口缺失或失效计为产品问题，不能静默复制数据库来算通过。
- 至少完成一次真实图片生成，覆盖描述编辑、提交、等待、预览和采用；优先选制作实际缺少的资产或分镜图，不为凑测试额外生成无用图片。
- 后续媒体只生成 E1 必需缺口，复用合格结果。失败先定位原因；不盲目重复付费任务，不为外围功能覆盖购买额外素材。预算上限尚未由用户给出，不视为无限额授权；首次付费前核对模型、计费信息和预计工作量，无法判断消耗时集中确认。
- 已保存并发设置保持不变；生产按叙事组推进。提交结果未知先找回原任务，不重复提交。

## 测试链路与覆盖记录

1. 新建项目，填写创作简报、风格与剧集设置；生成并审阅设定、人物、梗概和 E1 剧本，测试保存、重开、定向修订及交接。
2. 在资产入口检查角色、场景、必要道具和声音；复用适配图片，完成一次真实图片生成与采用，验证关联及引用预览。
3. 导演规划、查看审核问题、修订、复查并激活版本；检查剧情覆盖、可执行动作、角色连续性、提示词与输入的一致性。不伪造审核通过状态。
4. 整组分镜与视频生成；测试模型设置、进度、任务中心、结果预览、版本采用，遇到自然失败时覆盖恢复流程。
5. 整集合成、播放、保存与导出；配乐台优先采用库内音乐，验证全局与局部多轨、原声保留及独立配乐版输出。
6. 对本次经过的导航、素材选择、错误提示、保存恢复、费用记录逐项登记。软件外围功能和未自然触发的异常分支列为未覆盖，不声称一集制作等同于所有功能验收。

## 问题处理

每条问题记录：编号、阶段、页面入口、前置条件、操作步骤、预期、实际、截图/任务或版本 ID、影响范围、诊断、修复和复测证据。截图与日志不包含凭据。

阻止继续制作的 bug 先修；提示词导致明显剧情遗漏、身份冲突或不可执行画面时追踪到生成模板、上下文或参数映射，修复后通过原界面复测。非阻塞体验问题记录并在不扩大范围的前提下修复；重大流程重设计单独提出。不可将服务故障解释为素材质量失败。

代码在用户授权的当前分支修改，保留其他任务改动；按实际改动运行针对性回归。检查失败要区分本次引入与已有失败。重启服务前核对在途任务。

## 验收与交付

- E1 从创作入口生成并经过审阅交接；项目与来源资产关系可追溯。
- 至少一次真实图片生成成功并被采用；其余适配素材优先复用。
- 必需叙事组均有有效视频，成片无明显剧情漏段，音画可播放；配乐版独立保存，保留原片。
- 交付项目入口、剧本与成片位置、覆盖矩阵、已修复问题及证据、未解决问题和费用可得记录。无法完成的环节明确标为阻塞或未验证。
