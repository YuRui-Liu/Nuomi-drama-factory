# 项目制作成本监控设计

日期：2026-09-23。状态：页面原型与计费原则已获用户确认；本文等待书面规格审查。本文定义设计，不表示功能已经实现。

## 1. 目标与范围

在现有项目导航增加“成本”页面，用户可以看到项目全周期制作成本，比较渠道和媒体类型的花费，查看每日及累计开销，并追溯到具体调用。

首期覆盖 Codex、RunningHub、Grsai 经本系统发起的调用。图片、音频、视频分别汇总；若记录到文本调用，独立列为文本，不能遗漏于总额或混入图片。渠道是实际执行渠道，不能用模型名称替代；媒体类型按产出用途判断，不能由渠道推断。

采用“实际扣费优先、估算补齐”口径，统一展示人民币。共享订阅费单列，不分摊到项目。首期不包含跨项目排行榜、预算预警、完工成本预测、支付充值、自动抓取第三方账户账单或订阅自动分摊。

## 2. 已确认的页面

入口为项目导航中的“成本”，路由 `/projects/$project/costs`。复用当前项目切换器、深色主题和现有组件，切换项目后仍进入成本页，所有项目数据相互隔离。

页面顺序：

1. 标题和统计范围：项目全周期、人民币；计价规则入口。
2. 数据完整性提示：未计价调用数量、统计覆盖起点、历史记录是否完整。
3. 四张概览卡：累计制作成本、已确认扣费、估算费用、未计价调用数。
4. 项目开销趋势：每日开销 / 累计开销切换。
5. 渠道 × 媒体类型交叉表，旁列媒体成本金额及占比。
6. 共享订阅区：账户订阅金额、周期、本项目订阅覆盖调用量，明确不计入制作成本。
7. 调用明细：支持渠道、媒体类型、计价状态筛选和分页；详情侧栏展示用量、计算公式、价格版本、费用来源、任务及请求关联、变更记录。

交叉表点击金额会筛选下方明细。明细筛选不改变上方项目全周期总额和曲线，页面明确显示此范围区别。无调用显示“—”；确认零扣费才显示零元；订阅覆盖显示“订阅覆盖”；未知费用显示“待核算”。

原型使用示例金额，不作为真实渠道报价或能力声明。已确认视觉参考见本文相邻的 `2026-09-23-project-cost-monitoring-prototype.html`；该文件为独立设计附件，不进入应用构建。

## 3. 趋势图

范围从项目创建日期到当前日期，按北京时间自然日聚合；存储时间使用 UTC。每日图展示总开销、已确认费用、估算费用三条线；累计图展示同三项截至每日的累计值。估算使用虚线并配文字图例，不只依赖颜色。支持悬停、点击和键盘聚焦数据点查看日期及三项金额。

每日金额之和等于项目总额；累计图末点等于总额卡。只有完整采集且确实无调用的日期可补零；采集覆盖起点之前及已知数据缺口显示缺失区间，不连成零元线。存在未计价调用的日期附未计价数量提示，金额曲线仅代表已计价部分。累计值跨缺失区间时仍可展示已知累计金额，但持续标注不完整。

实际扣费补齐后更新原调用发生日，不归到补账日。订阅费不进入曲线。长周期仍使用每日数据，图形减少横轴标签并允许横向查看，不静默改变统计粒度。

## 4. 费用语义与优先级

制作成本 = 已确认费用 + 估算费用。每条调用只能贡献一次当前有效费用。计价状态与任务执行状态独立。

| 计价状态 | 判定 | 对总额的贡献 |
| --- | --- | --- |
| confirmed | 有可追溯渠道扣费依据，且人民币换算依据已配置 | 已确认费用 |
| estimated | 有可用计量信息及匹配的价格规则，无实际扣费 | 估算费用 |
| unpriced | 已发生调用，但缺少计量、规则或换算依据 | 不贡献金额，贡献未计价数量 |
| subscription_covered | 账户配置明确此次调用由订阅覆盖，且无额外扣费 | 不贡献金额，展示用量 |

不能默认 Codex 的所有调用都由订阅覆盖。按账户配置和单次调用依据判断；出现额外扣费时按实际费用记账。账户余额变化不能代替单次扣费证据，因为可能包含其他项目调用或充值。

渠道确认原币种费用但缺人民币换算依据时保留原金额，状态为未计价。已确认表示扣费来源已确认，换算来源仍须显式展示；不声称人民币换算值一定等于银行卡结算金额。

规则估算只使用有明确语义的计量字段。例如请求的视频时长可以作为预计计费量，但须标注其来源；不能将任意失败请求都套用成功调用单价。失败后无扣费和用量依据的调用保持未计价，不能按零收费处理。

## 5. 计价规则与订阅

规则按渠道、账户适用范围、模型或工作流、媒体类型、规格和生效时间匹配。具体规则优先于通用规则；同优先级重叠规则在保存时拒绝，避免随机匹配。

计价项支持每张、每秒、每次、每字符、输入及输出 Token、渠道积分。规则包含单价、计量基数、计费步长、最低计费量和原币种，支持多个计价项求和。计量字段必须与渠道的明确语义对应，不统一假设所有视频按秒或所有图片按张计费。首期仅实现明确的这些规则，不提供任意公式执行器。

计价规则面板支持新增版本、查看版本和停用未来匹配。保存记录生效时间与审计信息；价格、积分兑换率和汇率均由用户配置，不内置未经核实的外部价格。每条调用保存匹配规则及换算快照，规则修改不重算已经计价的历史调用。

对未计价调用提供显式“补算”操作：先展示匹配规则、影响记录数与预览金额，再由用户应用。仅更新指定未计价记录，保存修订历史。实际扣费到达则自动替换估算，同一请求不会新增第二笔费用。迟到估算事件不能覆盖已经确认的扣费。

订阅记录保存账户别名、渠道、起止周期、原金额、人民币换算和来源；支持手动维护。项目页只展示与项目调用有关的共享订阅，不将共享账户费用称为项目成本。订阅金额缺失显示未登记。不得保存或展示 API 密钥。

## 6. 数据与服务边界

新增独立的成本域，通过现有 SQLite 持久化机制管理表结构；不将渠道采购成本直接复用为产品积分消费。现有 `generation-credit-cost` 是单次积分报价接口，本地 `LocalCreditQuote` 返回零，不能作为项目成本账本。现有 `UsageMeter` 和调用上下文可作为接入位置参考，但不改变余额、预占和退款语义。

职责拆分：

- 采集适配层：从渠道请求、响应和已有轮询结果提取事实，传入稳定项目 ID、任务、媒体归属和单次尝试标识。
- 计价服务：根据事实、规则版本和账户配置生成当前费用，不负责页面聚合。
- 账本存储：持久化调用、当前费用、价格快照、历史修订及去重约束。
- 查询服务：从同一账本生成总额、趋势、分类和明细，统一舍入、范围及完整性口径。
- 前端页面：展示服务端结果及计价依据，不自行重新计算另一套总额。

核心记录：

| 对象 | 必需内容 |
| --- | --- |
| 调用 | 内部 attempt ID、稳定 project ID、渠道、账户别名、模型/工作流、媒体类型、任务/资源关联、发生时间、执行状态、外部 request/task ID、计量来源与用量 |
| 当前费用 | 计价状态、原币种/积分与数量、人民币金额、规则版本、换算快照、证据来源、更新时间、缺失原因 |
| 费用修订 | 调用 ID、前后状态与金额、修改原因、来源事件标识、时间 |
| 价格版本 | 匹配条件、生效区间、计量项、单价、单位、舍入规则与换算设置 |
| 订阅 | 渠道账户、周期、原金额、换算依据、来源 |
| 采集覆盖 | 项目/渠道覆盖起点、已知缺口、恢复状态 |

使用 Decimal 计算并以整数微元存储人民币值，禁止二进制浮点累加。展示账目按分舍入，所有汇总使用同一逐条展示金额口径，使明细、分类、每日及累计可对账；保留原始高精度值供详情审计。

## 7. 数据流与可靠性

1. 发起外部请求前分配稳定 attempt ID，持久化调用意图和归属。
2. 实际提交后记录已提交状态和外部请求标识；未提交意图不算发生调用。
3. 响应或现有任务轮询返回用量、结果、费用时，按 attempt ID 更新事实并计价。渠道外部 ID 以渠道及账户作为命名空间。
4. 数据库事务原子更新当前费用及修订，唯一事件标识使重复回调幂等。
5. 页面通过查询接口读取；可见页面每 15 秒刷新，离开页面停止轮询；相关手动配置操作后立即使查询失效。

重试是新的 attempt，可有新的费用；同一异步请求的多次状态查询不是多次生成，不计新调用。渠道内部子请求如独立计费，保留父子关系，父记录不得再次累加已计入子记录的同一费用。

发送前持久化失败时中止发送，避免产生无法归属的费用；发送后记录失败时保留已持久化意图，记录可恢复异常，使用现有任务状态恢复流程补写，不为记账重发生成请求。超时且无法判断是否提交成功时标记提交状态未知、显示数据完整性问题，不擅自认定零费用。

缺少项目归属的请求不得猜测分配到当前项目。归属校验在提交前进行；历史无法归属的数据不纳入任何项目，报告采集缺口。重新打开页面不触发渠道生成或付费查询。

## 8. API 与前端边界

项目成本 API 在现有项目授权路径下提供 summary、trend、breakdown、分页 entries 和 entry detail。响应包含统计范围、时区、快照时间、覆盖起点、完整性、未计价数量及货币单位。聚合与曲线读取同一一致性快照，避免后台补账时短暂不一致。

规则和订阅管理沿用已有本地设置的访问控制。项目明细查询必须验证记录所属项目；不能仅凭费用 ID 跨项目读取。渠道响应只持久化计费所需白名单字段，不保存密钥、提示词全文、签名资源 URL 或完整响应体。

前端将总览卡、趋势图、拆分表、订阅区、明细及详情分别组织为专注的组件，复用项目导航、React Query 和现有基础 UI。窄屏卡片换行，交叉表和明细允许横向滚动。

## 9. 空态与异常

- 新项目没有已发生调用：明确“尚无制作调用”，可计价总额为零。
- 有调用但全部未计价：总额显示“待核算”，而不是零；保留未计价数量。
- 只有订阅覆盖调用：显示“暂无按量费用”，订阅费用仍独立显示。
- API 加载失败：错误状态和重试入口；有缓存时注明数据时间和刷新失败，不用零覆盖缓存。
- 缺少规则或换算：说明具体原因，提供计价规则入口。
- 历史数据：仅从已有可追溯请求和用量回填，不能按最终产物数量推算生成次数；缺失历史明示不完整。
- 渠道真实退款：在原调用下记录费用修订，以确认净费用更新原发生日；产品积分预占释放不等同于渠道退款。

## 10. 验收标准

1. 三个渠道的现有实际调用入口均完成接入核对；每个可用的媒体类型至少验证一次。渠道未提供实际扣费时可按规则估算，并明确标记。
2. 按张、秒、次、字符、输入/输出 Token、积分、最低计费量和步长有边界用例；未知单位或缺字段不能静默计零。
3. 同一次请求重复回调不增费；独立重试单独计费；失败但扣费计入实际费用。
4. 估算转实际不重复累计，迟到估算不能覆盖实际；规则改价不改历史，未计价补算可审计。
5. 多项目、账户和不同渠道同名 request ID 不串账。
6. 每日金额之和、累计末点、分类合计与总额一致；时区跨日、无调用日期、缺失区间和补账回写有回归用例。
7. 订阅不分摊、不误标免费，账户额外扣费仍入账。
8. 页面验证项目切换、交叉表筛选、每日/累计切换、键盘查看数据点、详情、空态、错误态与窄屏布局。
9. 提交未知、采集失败和恢复不会触发重复生成；授权与敏感字段白名单有契约验证。

## 11. 交付边界与后续

本次设计交付为本文及已确认原型。书面规格审查通过后进入实现计划，盘点所有渠道调用入口与现有可用扣费字段，列明实际扣费可用范围和估算回退；不承诺供应商没有提供的数据。现有工作区还有角色语音相关未提交改动，实现计划须避开覆盖这些改动。
