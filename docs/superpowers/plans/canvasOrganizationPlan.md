# 漫剧画布组织与返修管理实现计划

> 面向执行者：按已审阅规格执行；保留工作树已有修改，不新增测试文件，不发起媒体生成。

**目标：** 让 Skill 按阶段及镜头组织当前成果、返修候选和历史版本，并安全整理《飞升骗局》现有画布。

**架构：** 画布作为成果展示，production 记录是版本与采用依据；通过实际发现的画布读取、移动与重命名接口操作，不修改画布 JSON，不假定自动分组接口。

**技术栈：** Toonflow Skill、公开画布和 production 操作。

## 任务 1：明确 Skill 组织规则

**修改：** `packages/skills/nuomiSkills/references/toonflowOperations.md`。

- [ ] 写明五个固定业务阶段、镜头相邻规则、当前／候选／历史／待确认的证据要求，以及缺失证据时不可猜测采用状态。
- [ ] 写明先读取实际尺寸、坐标、绑定与连线再放置；节点无需每次返修新建；保持真实输入关系、不创建概念连线。
- [ ] 写明旧版本进入历史区域但不删除；操作记录保留至已有成果或任务，失败时停止并记录。

## 任务 2：建立实际画布清单

**读取：** 当前作品的画布公开接口、production 成果与任务。整理目标是《飞升骗局》工作区中的当前画布；确认 connectionId、工作目录和 canvasId 后固定快照。

- [ ] 分页读取节点与边，补齐截断和必要的绑定字段，记录节点 ID、位置、尺寸、父子关系、标签、原有连接；按实际成果／任务查询采用与运行状态。
- [ ] 制定每个节点的阶段、集号、镜号、状态和位置映射；证据不足的节点放入待确认区；不能安全归类的分组子节点保留原位。
- [ ] 通过可用工作区文件接口保存原始坐标、标题与节点／边清单作为回退依据，不覆盖已有文件；记录节点版本和画布身份。

## 任务 3：执行与验证

**操作：** 仅使用发现的 `moveNodes`、必要的 `renameNodes`、`getCanvas*` 和 `fitCanvas`；不使用 `deleteNodes`、`deleteEdges` 或全图自动排列。

- [ ] 以真实节点尺寸安排阶段区、历史区和待确认区；同阶段同镜头的当前成果与活动候选相邻，活动节点和区域不重叠，真实连线保留。
- [ ] 每批最多 64 个节点；移动前重新核对画布、节点、父子关系、位置与连接。发现并发变化、缺失节点或失败即停下，回读并记录已完成批次。
- [ ] 用公开接口重新读取并等待保存；对照清单核对节点 ID、绑定、边 ID／端点和数量；实际查看第 03 镜及其他跨阶段节点，检查不重叠和历史可定位。
- [ ] 若需要回退，按保存的原位置／标题恢复已处理节点；若无法确认来源、持久化或回退则说明未完成，避免对用户画布做破坏性改动。

## 任务 4：结果报告

- [ ] 报告 Skill 规则改动、已整理／待确认节点数量、保存与连线核对结果。无法查看或验证的项目明确列出；不把构建或清单当成画布实操通过。
