# 漫剧统一风格传递实现计划

> **面向 AI 代理的工作者：** 按本计划逐项执行；不得覆盖工作树中已有的其他修改，也不得启动媒体生成任务。

**目标：** 让每部作品已采用的单一默认风格，以可追溯的版本快照进入角色／场景／道具资产、正式分镜和 H3 视频提示词，并让局部覆盖只影响明确指定的镜头。

**架构：** 沿用 production 版本记录与采用机制新增风格成果。作品工作目录中的已采用风格是默认值；生成方案显式保存风格引用及快照，作为依赖参与过期判断。图片与视频执行只使用生成方案中冻结的提示词和引用，不能在提交时静默读取最新风格或混合多套风格。

**技术栈：** Bun、TypeScript、Zod、Vue、现有 production API、节点插件和 Agent Skill；不增加依赖或测试模块。

**当前进度：** 已实现风格成果、作品默认风格、版本快照及正式图片／H3 的服务端校验，画布已加入 E1 风格候选节点。镜头图像必须经过实际画面核对；风格候选尚未采用，已有 E1 媒体尚未完成统一返修和成片验收。风格连线工作台和真实媒体效果仍需现场验证。

---

## 改动文件与职责

- `packages/nodeShared/src/production/schemas.ts`、`types.ts`、`operations.ts`：定义风格成果、作品默认采用及分镜／H3 的版本化风格引用。
- `apps/server/src/utils/production/operations.ts`：校验风格引用与镜头目标、解析默认风格、维护依赖及下游失效关系。
- `packages/nodes/productionNode/src/index.vue`：支持审阅和编辑风格成果，并显示成果采用状态与有效版本。
- `packages/nodes/styleNode/`：新增独立风格节点，提供风格浏览、来源／版本查看、编辑、采用和快照输出。
- `packages/skills/nuomiSkills/`：更新漫剧制作 Skill 的资产、分镜与 H3 提示词组织规则，使它先解析默认风格、再处理明确的镜头覆盖。
- `packages/nodes/imageGenerationNode/src/index.vue`、`packages/nodes/videoGenerationNode/src/index.vue`：在正式制作任务中显示并使用已冻结的风格提示词来源；不改变普通画布节点的既有自由生成行为。
- `apps/server/src/utils/production/taskSchema.ts`、`tasks.ts`：为图片任务显式绑定资产或分镜镜头目标，并在准备和提交时验证提示词携带的风格版本与已采用方案一致。

## 任务 1：增加可版本化的风格成果

- [ ] 在 `schemas.ts` 的 production 联合类型中添加 `style` 成果，字段为稳定 ID、名称、正向视觉描述、避免项、来源说明和来源版本；所有文本使用现有长度约束，避免任意额外字段。
- [ ] 为正式分镜增加可选风格引用与快照；为 H3 分段增加有效风格引用与快照。快照至少保存正向描述、避免项、来源和采用的修订号。
- [ ] 保持兼容：没有风格采用的旧工作目录允许沿用旧格式；一旦工作目录有已采用默认风格，新的正式资产、分镜图和 H3 方案必须保存解析后的风格快照。
- [ ] 在 `operations.ts` 中校验分镜覆盖必须指向 `style` 成果；未指定覆盖时，解析工作目录中唯一已采用的默认风格并固化为依赖和快照。
- [ ] 默认风格变更只令继承该默认值的下游成果过期；显式覆盖的镜头只依赖覆盖项。
- [ ] 使用现有 `packages/nodeShared` 类型导出，不在脚手架中增加漫剧业务类型。
- [ ] 在 `packages/nodeShared` 与 `apps/server` 执行既有 typecheck；确认旧记录不带风格字段时仍可解析，且不会自动补风格。

- [ ] 新建 `packages/nodes/styleNode/`，按现有节点插件结构创建 `package.json`、`vite.config.ts` 和小驼峰 `src/index.vue`。
- [ ] 节点绑定 production 风格引用，复用 `/api/production/get`、`/api/production/execute` 的读写与采用接口；不复制持久化实现。
- [ ] 展示风格名称、正向描述、避免项、来源、修订版本和默认／候选／过期状态；允许编辑并保存新修订，采用操作仍遵循现有审批证据字段。
- [ ] 只在用户显式采用时改变作品默认风格；库更新或新建节点不能自动替换默认风格。
- [ ] 执行该节点包的既有 typecheck 与 build，并在画布中确认其能读取、编辑、保存和采用一条风格成果。

## 任务 3：将风格快照注入分镜和 H3 方案

- [ ] 更新 `packages/skills/nuomiSkills/` 中负责图像资产、分镜和 H3 方案的已有 Skill，要求从正式成果读取有效默认风格；镜头明确覆盖时仅采用覆盖快照。
- [ ] 风格快照写入正式方案记录的依赖和结构化字段；同时将正向描述及避免项纳入图片提示词和 H3 `integrated_multimodal_description`，不可只显示在节点摘要中。
- [ ] 正式图片任务绑定独立 `imagePlan`，其 target 明确指定资产身份，或分镜固定修订加 `shotId`；不从画布位置、请求顺序或 prompt 文本猜测目标。
- [ ] 在正式任务准备阶段从绑定成果解析风格快照；prompt 必须包含格式固定的风格前缀（正向描述、避免项、来源修订），否则拒绝 prepare。任务记录保存目标、风格引用和最终提示词；submit 时重新读取并比较同一快照。
- [ ] 镜头覆盖不合并冲突默认描述；多个有效风格来源、缺失引用、过期风格或目标镜头不明确时停止生成规划并给出可定位错误。
- [ ] `packages/nodes/productionNode/src/index.vue` 显示风格版本和来源，并支持审阅分镜／H3 所绑定的快照；保存新版本后沿用现有采用流程。
- [ ] 在未发起供应商任务的情况下手动验证：默认风格进入资产、分镜与 H3 方案；显式覆盖仅改变指定镜头；修改风格后旧快照仍可查且相关下游显示过期。

## 任务 4：保护媒体执行边界

- [ ] 更新正式图片任务节点，使其显示目标镜头／资产和来源风格修订；H3 视频沿用现有 segment 目标及采用校验。普通非 production 图片／视频节点保持现状。
- [ ] 在 `apps/server/src/utils/production/tasks.ts` 提交前重新读取已采用方案，校验风格快照、方案依赖和实际请求提示词相同；若方案过期或被改写则拒绝提交。
- [ ] 已创建的媒体任务和历史媒体不因默认风格更新而自动重试、覆盖或扣费；重新规划生成由用户按既有额度授权。
- [ ] 在 `apps/server` 运行既有 typecheck 与 build；用本机画布检查任务准备阶段的只读提示词和依赖状态，不调用 Grsai 或 RunningHub。

## 验收标准

1. 一部作品只有一个有效默认风格；节点新建和库更新不隐式改变它。
2. 正式图像资产、分镜和 H3 方案都保存其实际采用的风格版本及来源。
3. 同一默认风格在各生成阶段被纳入实际提示词；镜头覆盖明确、局部生效且不与默认风格混合。
4. 默认风格变更只标记继承它的方案过期，保留旧方案和媒体，不触发生成。
5. 旧项目无风格引用时维持原行为；正式任务提交无法使用过期或不匹配的风格快照。
6. 仅类型检查、构建和本机无付费手动验证通过，不宣称模型视觉效果已通过；最终视觉一致性仍需在后续获授权的样片中审阅。
