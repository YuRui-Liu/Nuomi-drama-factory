# 创作画布：从剧本分段到分镜导演

日期：2026-10-11。状态：代码核对与产品研究后的设计提案，尚未实现、未通过 E2 成片验收。延续既有产品调研，不把公开产品说明当成生成质量实测。

## 1. 已定位的问题

画布存在三条不同的规划链路：

| 入口 | 当前代码 | 已有能力 | 问题 |
| --- | --- | --- | --- |
| 脚本生成器 | `src/novelvideo/freezone/text_node.py` 的 `FREEZONE_STORY_SCRIPT_SYSTEM_PROMPT` | 逐镜景别、画面、情绪、场景、光线、声音、时长，分别输出静态与运动提示词 | 没有充分表达切镜理由、导演锁定与资产版本；默认短镜和强制丰富细节也可能误导 |
| 主线导演 | `src/novelvideo/director_plan/prompts.py` 的 `CREATIVE_AUTHORITY` 和 `_CINEMATOGRAPHY_AUTHORITY` | 戏剧目的、可见变化、轴线、站位、光源、首尾状态、用户导演偏好、连续性 | 需要核对这些字段从编辑到画布执行是否完整保留 |
| 画布 CLI 整集规划 | `src/novelvideo/freezone/orchestration/planning.py` | 原文覆盖、总时长、资产连线、节点编排 | `Shot` 只有描述和时长；提示词和编译器都硬性要求四镜，固定 2×2；没有显式戏剧转折和导演意图 |

截图中的节点并非完全没有逐镜描述：`frames` 保存了描述。但顶层显示原文摘录、四格约束和薄弱的镜头结构共同导致导演意图不可审查。仅重写节点标题或加入“专业导演”几个字不能解决。

应复用主线导演已有合同，并吸收脚本生成器的逐镜呈现；不能继续维护第三套简化导演规则。原文行号保留用于追溯，不能决定镜头边界。

## 3. 先定义导演对象，再编排节点

建议链路：剧本事实 → 戏剧节拍 → 叙事组 → 镜头覆盖 → 分镜画格 → 时间预演 → 模型执行批次。

- **戏剧节拍**：角色行动、阻力或观众认知的一次变化。记录人物目标、障碍、观众原先知道什么、现在知道什么。
- **叙事组**：围绕一个戏剧任务组织的连续表达，可以包含多个节拍。记录组起点、转折、落点及成立理由。不能靠字数、固定秒数或四格凑组。
- **镜头 Shot**：一次连续观察，记录视点、可见动作、景别、构图、机位、运动、声音及切镜动机。
- **画格 Panel**：镜头中一个瞬间。同一移动镜头可能需要起止两格；两格不自动代表两镜。
- **执行批次**：受模型时长、参考图数量和输入模式约束的请求单位。拆请求不能偷偷增加剪切、改对白或改变导演方案。

叙事组仍是生产和恢复单位，内部镜头不变成绕过官方 CLI 的独立供应商循环。四格只是一种排版；镜头数量必须由表达决定。长镜头执行不了时，应提出可审查的改镜方案，不能靠均分秒数解决。

原文事件归属与镜头引用分开：一个事件归属一个节拍，但可以由多个镜头共同表达；对白拥有独立 ID 和音频时间区间，跨反应镜头继续播放时不能重复发声。原文覆盖率只能验证遗漏，不能证明导演质量。

## 4. 统一合同应包含什么

优先扩展现有主线模型，以下是概念字段而非另建一套平行 schema：

| 对象 | 必需信息 | 检查方式 |
| --- | --- | --- |
| 方案 | 原文 revision/hash、导演简报版本、风格、画幅、模型能力快照 | 执行前检查版本，不用过期方案覆盖新编辑 |
| 叙事组 | 目标、阻力、转折、情绪落点、源事件 ID、镜头顺序 | 导演审查是否形成明确表达 |
| 镜头 | 稳定 ID、目的、观众新增信息、起止状态、可见角色、空间/轴线、声音、时长 | 结构校验加具体连续性检查 |
| 资产引用 | entity ID、基础形象/造型 ID、采用版本、实际媒体地址或哈希、引用角色 | 查实际采用素材；头像不能替代人物基础形象 |
| 人工改动 | 修改来源、字段锁、理由、版本、影响范围 | 局部重规划不得覆盖锁定项 |
| 画格与执行 | shot ID、画格时刻、批次映射、模型参数 | 网页、CLI 和实际请求使用同一冻结方案 |

规则检查负责资产存在、时长能力、覆盖、版本和锁；创作评审负责切镜必要性、信息顺序和表演可读性。后者必须给出镜头与原文证据，不能用单个“导演评分”代替用户判断。

## 5. 自定义导演如何介入

导演简报支持整集、组、镜头三个作用域。可填写视点、节奏、镜头偏好、情绪、禁用表现和声音策略；镜头参数支持直接编辑。

建议界面操作：

1. **自动提案**：输出可编辑分镜表和各组导演理由。
2. **导演修改**：例如“留在母亲脸上听完台词”“先不要露出签名栏”“此镜固定机位”。将其落成字段，显示自然语言要求的解析结果。
3. **锁定选择**：锁定指定镜头、台词时序、资产或构图，其他字段仍可改。
4. **局部重导**：只重做选中组或镜头，展示前后差异、相邻连续性变化和失效素材。原结果保留。
5. **预演后采用**：播放带时长的静态分镜；需要时加临时对白。采用版本进入执行，用户显式授权的自动模式可自动通过机械校验，但仍保留完整记录。

冲突不静默降级：用户锁定 20 秒长镜，而模型只支持 15 秒时，明确列出换模型、缩短表演、改为两个有理由的镜头等方案。不能暗中改成两个 10 秒镜头。

## 6. E2 示例：母亲为何拦住莉娅

根据截图原文：莉娅伸手拿羊皮纸；女人挡住；女人说签字才能得到暖屋和饭；莉娅看向小男孩及车厢里不回应的孩子，无言。

导演任务：让观众从“她为什么阻止救人”转为理解“她在生存与代价之间被迫选择”。以下是候选方案，不代表已采用或已生成：

| 镜头 | 画面与声音 | 切镜理由 |
| --- | --- | --- |
| A | 同框中景交代莉娅、女人和纸的位置；莉娅伸手，女人挡住。固定机位可成立 | 先让阻挡动作和人物关系读得懂，避免手部特写造成空间误解 |
| B | 母亲较近景，抱着孩子说原文台词，给表演足够时间 | 让观众理解动机，而不把女人拍成单纯阻挠者 |
| C | 沿莉娅的视线看到车厢中不回应的孩子；是否单独切出怀中小孩取决于 B 的可读性 | 对照“眼前温饱”和“失去回应的代价”；不重复对白 |
| D | 回到莉娅，眼神停住、没有回答 | 落在无法轻易作答的情绪，而非补旁白解释 |

这里列四镜只是一个候选，不是规则：若 B 已清楚包含莉娅的观察和沉默，可合为三镜；如果空间不清楚，应修构图或增加必要覆盖。是否增加纸面插入镜，取决于前组是否已交代关键字迹。不得为凑格重复揭示，也不得把空白签名栏画成签过字。

实际秒数需结合完整台词试读、动作和全片预算确定，本表不编造最终时长。连续性需锁定母亲抱孩子、纸的位置、莉娅未拿到纸、车厢孩子没有回应。诺尔若出现，保留原文手势与无对白设定。

## 7. 导演提示词草案

下面是统一导演服务的创作指令草案，必须配合结构化输出和校验；不能直接替换一段 prompt 后宣称链路已修复。

```text
你负责将已确认剧本设计为可拍摄、可剪辑的镜头方案。
输入包含完整剧本及版本、已采用人物基础形象与场景道具目录、
用户导演简报、锁定字段、前后组状态、目标时长和模型能力。

先识别每段戏的目标、阻力、转折和观众认知变化，据此组织叙事组。
对每组确定视点、信息揭示顺序和情绪落点，再设计镜头覆盖。
每个切镜说明新增的信息、空间、表演或节奏作用；无理由则不增加。
不按原文段落数、字数、固定秒数或画格数量决定镜头数。

每镜给出可见起始状态、主体动作、可见结束状态、景别构图、
人物站位与视线、摄影机位置和运动、光源、对白/声音时间安排。
静态画格只描述一个时刻；运动写入动作轨迹。固定机位是合法选择。
二维风格使用适用的构图与视野语言，不强填虚构物理摄影参数。

保持源事件、说话人和每句原文对白，不新增事实或替角色解释心理。
一个事件可由多个镜头覆盖，但对白只发声一次；允许有明确时间映射的画外音。
身份引用使用已采用基础形象及明确造型版本，不用头像替代，不自动重造角色。
保持持物、人物数量、轴线、视线、光源和动作阶段的连续性。

严格保留用户锁定项。遇到时长、资产或能力冲突，返回具体冲突和可选修订，
不默默删台词、改变剧情或用平均分配时长掩盖问题。
局部修订只修改指定范围，同时检查与相邻镜头的衔接。
返回既定结构化合同；原文事实、导演选择和待解决问题分别标记。
```

脚本生成器值得继承的是图像/运动分离、逐镜可读表格和具体表达；不照搬其“对白尽量短”、通常 2–5 秒、强制运镜和微细节要求。这些默认值可能删改原文、破坏长表演或给 2D 画面强塞不适用的摄影参数。

## 8. 实施与验收顺序

**P0：统一规划。** 以主线导演合同为基础，让画布规划调用同一导演服务；移除固定四镜前提；人物绑定采用基础形象。保留旧方案读取，但旧方案不能伪装成新版导演审核通过。验收包括三镜、五镜、长对白、一个镜头多个画格及缺失基础形象等用例。

**P1：编辑与执行一致。** 网页/CLI 共用修订接口，支持导演简报和锁定、版本冲突检查、实际请求快照。验收：用户改镜头后保存、刷新、CLI 读取及执行参数一致；锁定项在局部重导后不变。

**P2：局部修复成为操作。** 提供改构图、换参考、拆/合镜头、局部重导及预演。按依赖标记素材过期而不删除历史。验收：只重做目标组所需任务，相邻衔接可核查，无关组不重新付费。

**E2 最终验收。** 新导演方案在原画布可见，逐镜展示用途、动作、声音、时长、实际基础形象引用；用户修改能保存并进入请求；通过官方画布 CLI 完成组分镜、组视频和整集合成，并播放检查明显遗漏与连续性。当前研究文档不等同于完成这些验收。
