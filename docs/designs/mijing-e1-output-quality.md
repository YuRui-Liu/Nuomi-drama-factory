# 密境山海 E1：从链路完成到成片质量合格

日期：2026-10-08。技能：gstack-office-hours。模式：Builder（依据已有制作目标，不重新询问商业定位）。状态：用户已确认修复生产链路，实施中；具体进展与待验证项见验收报告。设计获批不代表成片通过。

## 问题与证据

用户要求修复验收记录中的问题，并明确指出字幕过大、对白挤满画面、站位与朝向不一致、远景人脸劣化。此前验证证明视频可以生成和播放，不能证明镜头语言和观看质量合格。现有 E1 应视为测试样片，不能标记成片质量验收通过。

- 已证实：`src/novelvideo/export/episode_export.py:build_srt_content` 将 `entry.segment.dialogue` 整段放入一个镜头时间块，没有逐句声学时间。
- 已证实：`src/novelvideo/task_backend/runners/video.py` 使用 `FontSize=18,MarginV=24` 烧录 SRT，没有显式 ASS 画布与输出像素比例。字号参数不是输出像素值；必须以真实渲染验证，不凭数字判断大小。FFmpeg 官方说明：https://www.ffmpeg.org/ffmpeg-filters.html#subtitles-1。
- 已证实：`narrative_group_video.py` 中摄影检查由 `cinematography_review_required` 控制，调用 `_advisory_cinematography_review`。技术上可用与视觉上合格目前未明确分离。
- 已证实：`shot_continuity/visual_review.py` 只有 blocking、lighting、camera、cut 四类问题，缺少独立的人脸可读性与身份劣化分类。已存在首中尾抽帧、边界比较和内容缓存，应扩展而非另建一套审核系统。
- 尚待对帧定位：用户截图能证明字幕遮挡及远景脸部异常风险，但不能单凭两个静帧认定具体哪个切点越轴。必须回查相邻视频、原分镜、镜头运动和参考资产，区分真实移动、合法反打与无依据的位置变化。

## 目标与约束

目标是让创作者在正常软件流程内得到可观看、可校正、可重复导出的成片。字幕、人物与空间检查也可成为已有视频的后期校正工具，但本轮不扩大为通用剪辑器。

- 沿用当前分支及独立项目，不覆盖旧工程或他人改动。生产数据通过既有用户入口操作。
- 保留已付费视频、图片、配乐及版本。字幕修正只重新合成；视觉重做限定缺陷镜头所在叙事组，组内恢复复用合格片段。
- 预算延续人民币100元、RunningHub单独不设上限；账单不完整不得当作零成本。减少无依据重复生成。
- 100元按本次E1从最初实测至修复结束的人民币计费累计计算，不在修复时重置；剩余额度为100元减已有人民币支出及待结算预留。提交前核对已有回执、已知估算上界和本次费用上界；无法证明仍在额度内时暂停新增人民币付费生成，继续本地字幕/代码修复和核账。RunningHub遵循用户明确的独立预算例外。
- 用户此前要求不再反复确认；本设计采用保守可逆默认，明确记录假设，不声称用户已审定新的每个数值。
- 不用“保持一致”“高清脸”替代可检查的事实；不把代码字段相等当作生成图像实际一致。

## 前提与方案取舍

前提：画面有内容不等于质量通过；字幕计时必须以实际声音为准；同一场景的世界位置与屏幕左右是不同概念；超分不能保证恢复不存在的人脸身份细节。

1. 仅改字号和增强提示词：最省事，但无法解决对白时序和跨镜错误，不采用。
2. 复用现有生产链，补齐逐句字幕、连续性事实、实际输出质量证据与局部修复：推荐，兼顾当前E1修复与后续可靠性。
3. 整集推倒重生成或另建全功能剪辑台：成本与回归范围大，丢失当前可用素材，本轮不采用。

## 推荐设计

### 一、字幕：独立的对白时间轴与明确画布样式

- 使用统一字幕事件：台词ID、说话人、文本、起止时间、来源（实际对齐/人工校正/估算）、审核状态、源音频指纹。SRT、烧录、预览读取同一事件集。
- 台词按真实说话轮次分条，长句按语义短语拆分；禁止把双方问答同时叠在一个时间块。保留原对白，不自动改写或漏句。
- H3原声不能拿计划时长冒充实际发声时间。优先复用供应商可用时间戳；不存在则对现有原声做一次缓存的对齐，先确认本地依赖/模型可用性，再选实现，不预设已安装ASR。识别只辅助定位，以原台词为校对依据。低置信度、漏说、多说、音画不符标为待校对并提供逐句时间编辑；不能静默按字数平均后标记精确。临时估算允许预览，不可自动进入质量合格版。
- 区分时间对齐错误与源内容错误：实际说了但时间错误可人工校正；漏说、多说、错说不能靠移动字幕解决。源内容错误保持待审，经现有有记录的台词修订流程确认可接受内容，或局部修复对应音视频，再重新对齐核验。未实际发声的台词不能硬贴在静默时间段进入已验收版。默认保留原剧本，通过局部修复达到一致；修复前可保留测试预览。
- 合成时以最终采用的视频帧时间轴重映射字幕，包括裁剪、转码和组拼接；全部事件满足0≤开始<结束≤成片时长，默认不重叠。超界报可解释问题，不只截断掩盖累积漂移。
- 输出显式ASS画布，例如720×1280对应PlayResX/Y；建议初始字体32px、细黑描边约1.5px、白字、底部居中、左右各8%安全边距、底边约10%留白，最多2行，每行初始约16个汉字并以实际字宽收敛。1080×1920同比缩放。上述是本产品竖屏预设，不宣称是抖音统一硬性规范；平台遮挡区可配置。
- 横屏单独预设，不复用竖屏绝对位置。预览、SRT与烧录可分别保存，字幕样式可调；超长内容拆条，不无限缩字号、不扩大到人物胸脸。
- 校验样例：用户截图中的“我看错了”“为什么”“怕你觉得我又在逞强”“那就一起看”必须按实际原声依次出现。每个镜头同时显示的说话轮次≤1，无对白时消失。

### 二、站位朝向：分镜出图前约束，分镜图上审核

2026-10-09 用户纠正：站位应从分镜出图上注意，不能把视频 QC 作为主要解决环节。实施优先级据此调整，上游约束和分镜审核是主路径，视频检查只发现生成过程中新增的偏移。

- 在已有导演/连续性模型内整理场景锚点、角色世界位置、面向目标、视线对象、移动起终点、道具归属、镜头轴线、机位及切换意图；未知字段保持未知，不能编造用于通过校验。
- 出图提示词必须保留当前定帧的站位、身体朝向与视线，不能在过滤未来动作时一起删除。分批出图保留相邻镜头的冻结空间上下文；单格修复继承被修复版本的空间约束，不读取新计划冒充旧来源。
- 在分镜图审核中对照这些事实检查人物位置、相互面对关系和机位；发现源图错误，先修分镜再生成视频。远景中需要读表情的镜头应先调整景别或构图。
- 分镜与H3共用已采纳事实，按镜头筛选可见人物/生物参考；已逃走的异兽不能继续以“all relevant”进入后镜。
- 合法反打可能改变屏幕左右；不能以“左右必须固定”禁止正常摄影。只有有证据的跨轴、无移动过程的瞬移、错误面对对象等才报错。用上镜末帧、下镜首帧及各自上下文解释问题。
- 复用已有首中尾和边界审查；针对用户指出的动作段增加必要关键时刻，而非对整集无限抽帧。缺帧、接口失效、判断不确定属于“待审”，不是通过，也不是需要购买重生成。
- 明确三种状态：生成完成、质量待审、已验收。缺陷不删除素材。可以导出有明确标识的测试预览；正式采用需修复或有记录的人工处置，不让一次模型意见自动触发整集重买。

### 三、远景脸部：画面责任与局部修复

- 远景允许自然细节不足，但不能出现显眼的五官漂移、融化、脸型突然变化。若台词或情绪必须靠表情表达，规划应选择能承载该信息的景别，不能要求极小人脸完成细腻表演。
- 审核同时看全帧与来自原始帧的人脸区域，区域仅作检查不生成新证据。区分符合景深的虚化、合理遮挡与畸变；检测置信度不足标待审。具体脸部尺寸阈值先在E1实际分辨率上测量，不虚构通用阈值。
- 修复次序：核对角色参考与原始分镜→必要时改成可控景别/机位或修复首帧→仅重做受影响片段并沿用同组其他已付费结果。无须承担表情的建立镜头可保留背侧面远景，但不得为了规避质量检查擅改表演意图。
- 通用人脸增强会改变身份和动画风格，不默认启用；如使用，须与角色参考及前后帧比较，验证没有闪烁和身份漂移。

### 四、验收报告其余问题全部进入闭环

历史已修复项只做受影响回归，不重建功能；“历史待验证”不得自动算完成。建立问题ID、证据、修复位置、回归结果、当前状态五列清单。

| 范围 | 修复/验证要求 |
|---|---|
| 中文项目名 | 显示名与稳定内部标识分离，旧路由与目录不随改名改变；旧项目回退显示现有名称 |
| 模型/费用提示 | 提交前显示实际模型、渠道、计费单位；估算未知明确写未知，不将订阅或RH币混成人民币 |
| 创作画风与制作画风 | 生图前明确实际生效画风，发现不一致给可执行的应用入口；不偷偷覆盖用户显式制作选择 |
| 角色基础图与本集身份 | 生成前列出有效引用与缺失原因，必需引用/声音设计缺失时可直接修正；保留既有刷新修复 |
| 创作审查反复退回 | 复用同一历史问题ID与处置证据，区分结构与对白职责；新的真实结构缺陷仍能重新打开，不禁用QC |
| 超长镜头/起始帧提前动作 | 原有时长门禁回归，加动作初始状态检查；不允许“能提交”替代镜头负载合理 |
| 无关参考污染 | 镜头级参考筛选，明确出场/离场时间和角色身份；审核实际画面 |
| 成片进入配乐 | 合成页提供“进入配乐台”，绑定现有成片不可变版本而非再次上传；新成片不能静默替换旧配乐源 |
| 音乐时长略短 | 采用时提示实际时长，提供按源长度放入/显式循环/末尾留白；毫秒误差与真实不足区分，不能默认循环抢拍 |
| 下载 | 为SRT/ZIP/配乐版提供可重试下载入口及正确文件名/类型；接口成功与浏览器成功保存分别验收 |
| 费用回执缺失 | 保留unknown，按原任务ID补查去重，不以补查触发重生成 |
| 类型检查/恢复 | 收集当前错误归属，修复本轮相关项，报告其余真实阻塞；恢复不重复付费的回归保留 |
| 音乐人声状态/TTS旁支 | 未听辨的纯音乐不标已确认无人声；外部TTS独立列未覆盖，不能冒充本集H3原声验收 |

## 实施顺序及交付

1. 固定现有E1输入、音视频和报告证据；把“链路完成”与“质量通过”分开。整理全量问题状态矩阵。
2. 先修字幕事件与渲染，用同一原片输出新版本，避免视频生成消耗。输出原/新版同时间画面对照及逐句字幕检查结果。
3. 定位站位和脸部缺陷的镜头、时间点和源图，补连续性与脸部回归，再通过正常入口局部修复，不改生产数据库掩盖结果。
4. 修复报告其余交接、入口和反馈问题，复核字幕、合成与配乐源版本关系；替换视频后只重算受影响字幕、配乐时间和混音。
5. 交付新版成片、原片保留、问题清单与回归证据。软件成功状态、自动检查结果、实际观看结果分别报告。

## 验收标准

- 720×1280及1080×1920字幕渲染截图均符合预设安全区；长中文、标点、双人问答、横屏、字体缺失都有回归。
- 对本集10句对白逐句检查实际入出点，默认允许误差目标≤200ms；达不到则人工校正，不把估算作为通过。文本无漏句/重复/多轮同屏，末条不越片尾。
- 对全部8镜与7个相邻切点明确记录站位和朝向检查，其中跨场切点不要求空间连续；有意的反打/运动能解释，不能从静帧编造运动。
- 每个可见主要人物的实际视频帧检查脸部畸变与时序稳定，低细节远景不误判为身份确定；问题帧有定位和修复后对照。
- 字幕重导出不调用视频生成；局部重做不重买已完成无变更片段；原成片与旧配乐版本可恢复。
- 自动回归、实际播放、人工审片三个证据层分别列出。模型不确定/未检查不得标为质量合格。

## 风险与尚待调查

实际语音对齐能力未在仓库中确认，需要先验证依赖与供应商输出；不能先承诺全自动逐字准确。具体站位错误与脸部缺陷尚未完成逐帧归因，不能预先断言都来自提示词。测试数据中的实际时长漂移须同时核对视频时间基和字幕映射，不能只用片尾截断处理。大规模并行未提交改动需要保留，避免回退他人工作。
