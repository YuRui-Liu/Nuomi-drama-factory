# 分镜管线复验后的修复

## 问题与范围

第 1 集实际重生成发现：旧导演组没有启用分镜图片合同，视频规划只看到文本和图片摘要；出图请求遗漏活动风格快照；头像引用被描述为完整身份参考。第 8 组出现重复笔记本和额外手，第 5 组出现脸部出框与道具漂移。

本轮沿用现有按叙事组生产、冻结图片和多模态规划能力，修复其入口连接。不另建提示词库，不恢复已经取消采用的服装图，不将生成成功当作质量合格。

## 实现

- 旧导演组再次正式出图时自动启用分镜图片合同，实际新图登记为可追踪来源，视频阶段使用冻结的图像字节。旧的切图重试保持原合同，不能伪造历史来源。
- 排队请求冻结当前有效风格快照，避免出图丢失 image projection。
- 引用映射从稳定槽位获取角色名，支持名字含下划线；头像仅负责脸部，身份状态图负责脸和服装，不再混同。
- 导演规划和修复规则补齐单镜职责、主动作、接触与持物、表情可见、出入画和跨镜连续性。
- 多模态视频规划以实际首帧确定物体位置、持有人、尺度与人数，禁止用复制道具满足冲突文本；保留矛盾证据。提升策略版本，使旧文本规划缓存失效。
- 身份生成和 QC 不再把定角的综合 identity_anchors 当作当前服装要求。实际案例包含“胸袋露出折叠地图”，但常服并无该道具要求；面部、发型、体型和特征仍使用专门字段。
- QC 保留实际拒绝证据，并在界面显示具体的状态矛盾。岑砚、居民乙原图在当前规则下复检通过，资产变为可用的 provisional 状态，当前方案的 21 个引用绑定已刷新。
- 实际任务暴露新版图片来源读取 task_id 而执行器注入 __run_task_id 的问题；优先使用执行器任务 ID，保留兼容字段。对应回归测试覆盖两种封装。

## 参考与改编边界

参考 [zenstory-ai/drama-skills 的分镜方法](https://github.com/zenstory-ai/drama-skills/blob/main/skills/short-drama-storyboard/SKILL.md)：单镜起点、主动作与终点分开；冻结帧只投影起点；引用按身份、造型、地理和尺度分别说明用途。本项目独立实现提示约束，沿用自己的组、镜头、资产与任务契约。参考项目不是本次生成效果的证明。

## 验证

自动化覆盖旧组重新出图后的合同、风格传递、头像/状态图职责及来源追踪。真实生成重点复验第 8 组；实际多模态观察与最终视频分别检查，明确区分新图登记成功、提示规划读图成功和视频质量合格。
