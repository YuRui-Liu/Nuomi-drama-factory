# 剧情驱动的人物选角

本功能将原文依据、造型方案、头像候选和最终采用分开。生成候选不会替换角色当前头像；只有用户确认定角，头像与对应的视觉设定才一起生效。

## 使用流程

1. 在真实项目的「资产中心 → 角色 → 视觉设定」中进入剧情选角，选择基础形象或具体身份阶段。
2. 主动重新选角，核对原文依据及出处。简介、旧提示词和默认年龄不自动升级为剧本事实。资料不足或事实冲突会显示原因。
3. 比较三套造型方案。原文明示的年龄、物种和美貌等约束必须保留；设计解释与自由选择单独标注。职业、善恶或悲惨经历不能凭空变成五官、伤疤或残疾。
4. 选择方案并生成候选。生成使用提交时的方案、风格、模型和原文版本快照，费用沿用项目现有模型计费记录。
5. 将候选与当前头像对照，查看事实符合度、设计落实度及人物辨识度三个检查维度。检查失败可以单独重试，无需重画。
6. 确认定角后，当前头像和视觉设定共同更新。存在偏差、不可判断、未检查或检查失败时，需要逐项确认相应提示并填写采用原因。

界面只展示模型辅助判断，不提供颜值评分。未检查、检查失败和不可判断都不等于通过。没有可用的已确认对照人物时，也不宣称已经验证全体角色的辨识度。

## 旧角色与身份阶段

打开页面、查看候选和生成新候选均不改变旧角色当前图。旧角色需要主动重新选角。基础形象与身份阶段使用不同草案、候选和采用记录。

启用剧情选角后，旧头像上传、历史恢复及画布推送不能绕过定角流程替换该头像。全身身份图和服装仍可正常编辑，但实际文件路径若与受保护头像发生碰撞会拒绝写入或删除。两个身份的名称规范化后共用同一头像路径时，须先解决名称冲突。

## 费用与重试

- 重新选角会调用文本模型，生成候选会调用所选图像模型，检查会调用已配置的图像检查模型。
- 候选生成与检查是独立任务。重试检查不会重新生成图片。
- 同一次请求用幂等键去重；服务无法确认先前提交结果时，不盲目再次调用付费提供方。
- 原文、方案或项目风格变化后，旧候选会标记过期。过期、归属不符、图片缺失或内容校验失败不能通过填写原因强行采用。

## 数据与恢复

项目注册表中的 `state_dir` 与 `output_dir` 可以不同，不能互相推导。候选元数据位于 `state_dir/casting_candidates.json`，采用日志位于 `state_dir/casting_adoptions.json`；视觉工作区位于 `output_dir/state/character_visual_workspaces.json`。

采用事务在项目锁内同步执行。日志先持久化旧状态与新目标，再发布图片、视觉设定、工作流和身份阶段引用，最后标记完成。中途进程退出后，下一次相关读取或写入会恢复未完成事务。已完成事务保留新版本；当前图链接解析为不可变版本，避免浏览器读到采用过程中的临时文件。

不要手工删除候选图片、改写采用日志或直接修改当前头像文件来解决错误。出现来源校验、路径冲突或版本冲突时，先处理具体原因，再从页面刷新并重新提交。

## 接口

基础路径为 `/api/v1/projects/{project}/characters/{name}/casting`，身份阶段通过 `identity_id` 查询参数选择。

| 操作 | 方法与后缀 |
| --- | --- |
| 查看档案与当前版本 | `GET` 基础路径 |
| 重新选角 | `POST /recast` |
| 修改或选择方案 | `PATCH` 基础路径 |
| 查看候选 | `GET /candidates` |
| 生成候选 | `POST /candidates` |
| 独立检查候选 | `POST /candidates/{candidate_id}/review` |
| 确认定角 | `POST /candidates/{candidate_id}/adopt` |

采用请求必须携带当前方案版本和检查尝试版本。候选响应的 `adoption_requirements` 给出服务端要求确认的提示及是否需要原因；前端不能自行推定检查通过。

真实项目 `shanhai_shiyi` 首轮四角色选角未通过服务端校验：步知遥、桑禾、闻照在事实引用验证阶段停止；朏朏在三提案结构重复与经历细节验证阶段停止。文本路由为 `codex / gpt-5.6-sol`，本轮五次调用的费用条目为 `unpriced`（没有匹配价格规则），不能当作零费用。尚未调用图像生成或采用任何候选。

真实候选对照及用户视觉验收尚未完成。自动测试结果不代表生成质量已经获得用户认可；后续补充候选、模型、费用和实际反馈。
