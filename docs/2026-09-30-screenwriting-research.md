# 剧本创作与导演转译调研

调研日期：2026-09-30。用户已选择方案 B：补齐单集戏剧设计与导演转译方法，先用 E1 做质量对照，再决定软件接入。用户新增要求：剧本正文符合小云雀官方展示的标准剧本格式。

本文保存研究结果及后续验证约定，不代表软件功能已实现，也不代表新剧本已经定稿。本次没有进行跨产品同题生成盲测。GitHub 星数为调研时页面约数，不是质量排名。“hu ggingfields”暂按 Higgsfield 理解。

## 1. 研究结论

当前流程能组织生成、资产绑定、分镜和合成，但技术成功不等于戏剧成立。主要改进方向是：在视频生成之前明确人物欲望与阻力、行动造成的变化、观众获得信息的顺序，以及本集承诺与回报；然后把这些意图落实到表演、声音和镜头关系。

不能仅靠加入“强钩子、电影感、情绪张力”等词，也不能把每集强制套成固定秒数反转。安静场景可以承担关系、期待、余波和空间感，不应一律删掉。

### 可直接研究的方法材料

- [场景工艺 Skill](https://github.com/jtydhr88/screenwriting-skills/blob/main/plugins/screenwriting/skills/sw-scene-craft/SKILL.md)：识别场景目的、冲突、行动与反应、价值变化。采用其中的分析方法，不机械要求每场都剧烈反转。

- [Higgsfield 剧本到分镜指南](https://higgsfield.ai/blog/script-to-ai-storyboard-shot-list)：在昂贵的视频生成前，通过关联分镜明确意图、节奏和连续性。

## 3. 当前实现与 E1 的证据

### 代码层面

- `src/novelvideo/script_creation/prompts.py` 已有钩子、情绪曲线、人物弧光等要求，不是完全缺少创作指导。
- 默认 `CRAFT_BY_KIND` 中，正文加载场景工艺和语言编辑；已有 `short-drama-rhythm.md` 未直接列入默认阶段映射。
- `src/novelvideo/agent_teams/adapters.py` 的自定义团队方法可以替换默认指导，因此不能只根据默认映射断言某次任务完全没用节奏方法。后续接入前应核对实际任务方法快照。
- `src/novelvideo/director_plan/prompts.py` 强调按原文顺序完整覆盖、不改对白、物理动作和资产连续性。这些约束需要保留，但平淡的上游正文无法只靠下游运镜补救。
- `DirectorShotIntent` 有叙事目的、观众注意力、情绪效果、连续性策略。字段存在和非空校验不能证明戏剧质量；也尚未完成这些字段跨所有下游转换的逐项保真审计。

### E1 实际导演规划

| 叙事组 | 内容摘要 | 创作诊断 |
| --- | --- | --- |
| 1—3 | 水源异常、限制取水、有限净水分配 | 有生活压力与利益冲突，可更集中地呈现具体人物承担的代价 |
| 4—6 | 听广播、再辨尾音、判断与暗号有关 | 连续辨认信息，人物处境与关系的变化相对弱；需检查是否可以合并重复等待 |
| 7—8 | 查看管线、暂不处置、安排后续检查 | 谨慎符合人物逻辑，但持续暂缓决定可能削弱推进力 |

以上是对实际规划的创作判断，不是跨产品性能测试。现有规划并非毫无冲突，例如限水与居民需求、是否关闭广播均有分歧。问题是多段情绪集中在不安、等待、怀疑、未决，落差与行动后果不足。

## 4. 已选择的方案 B

先交付可阅读的 E1 对照样稿，验证质量差异后再设计软件接入。保留现有已认可的交互，不把本次研究变成 UI 重做。

| 阶段 | 输出 | 验收问题 |
| --- | --- | --- |
| 故事定位 | 人物欲望、代价、关系、类型期待 | 为什么观众关心这个人？ |
| 单集设计 | 节拍表、信息释放、本集回报、集尾压力 | 这集改变了什么？留下的问题为什么有分量？ |
| 剧本正文 | 小云雀示例结构的分场剧本 | 人物是否通过行动推动变化？对白是否存在具体目的？ |
| 导演转译 | 关联镜头表、表演、声音与剪辑意图 | 剧本的关键情绪是否转成可见或可听的表达？ |
| 生成前验收 | 对照阅读，必要时低成本分镜预演 | 不依赖精美画面，这段戏是否仍成立？ |

### E1 对照交付约定

1. 保存现有版本作为基线，不覆盖原稿或已生成视频。
2. 给出完整单集节拍对照，指出合并、保留、改写的原因。
3. 优先展示开场与广播关键场景的正文对照，再形成完整正文。
4. 区分表达改进与剧情事实变化；新增关系、事件、角色能力或未来揭示必须显式标注，不能悄悄成为原作事实。
5. 给出对应分镜，检查人物行动、信息差、反应、声音和剪辑如何接续。
6. 用户认可创作质量后再进入软件实现与正式生成。

用户选择 B 是方法路线，不等于选定“爽剧”或某种情绪风格。悬疑压迫、人物抉择是研究建议，尚不是用户确认的类型偏好。对照稿可以先保持原项目基调，避免擅自转换题材。

### 成本与边界

- 先文本、后画面；先局部比较、后整集生成。避免用视频反复抽卡弥补剧本问题。
- 建议首轮采用一轮评审加一次定点改写，不默认无限循环或完整多 Agent 编剧室。
- 画幅保持 16:9；角色身份、造型、声音及场景上下文来自已确认的人物表、场景表等资料。
- 道具以剧本创作道具表及用户明确新增为依据，不自动膨胀资产。场景优先复用，必要时建立变体。
- 正文定稿后导演层保持忠实；若发现必须重写剧情，应回到正文提出修改，不通过视频提示词偷改。

## 5. 小云雀标准剧本格式

依据：[小云雀官方产品手册](https://xyq.jianying.com/tutorials/web-manual)，短剧 Agent → 常见问题 → Q1“剧本格式有什么要求？”，核查日期 2026-09-30。

官方给出的是标准格式示例，不是完整的机器解析语法。可确认的结构包括：集数及场号、以“场景”标明地点和时间、以“人物”列出人物、以 △ 区分动作描述，以及带人物名称的对白和 OS。本文不把官网没说明的分隔符、编码或附加字段宣称为官方硬性要求。

下面是按该结构编写的项目格式示例，内容为原创排版示意，不是官方原文，也不是已批准的 E1 改写：

```text
第一集 1-1
场景：折湾站水箱区 夜
人物：岑砚，居民甲

△ 居民甲举起水杯。杯底浮着细小的絮状物。
△ 岑砚按住他的手腕，把杯子缓缓压低。

居民甲：今晚就剩这点水了。
岑砚（压低声音）：先放下。

第一集 1-2
场景：折湾站广播间 夜
人物：岑砚

△ 广播响起，岑砚停在开关前，手指悬着。
```

项目补充约定（不是小云雀官方额外要求）：

- 场号唯一且连续，采用集号-场号；切换时间或物理空间时明确分场。
- 人物和场景名称与资产表统一；别称通过映射处理，不靠生成模型自行猜测。
- △ 段落写可看见或听见的内容，心理活动若必须表达，应明确采用表演、对白或 OS；不把无法拍摄的解释冒充动作。
- 普通对白采用“人物：内容”；必要语气放在人物后的括号内。OS 单独标记，不能因名字出现便认定人物在场、不能把 OS 当口型对白。
- 画外声、广播声、旁白须明确标注来源并与出镜人物分开；具体内部类型及导出写法应在实现时做兼容验证，不宣称官网给出了完整枚举。
- 创作分析、情绪节拍、钩子说明、审稿意见不混入供导入的正文。
- 运镜、时长、资产 ID、首尾状态、参考图及供应商参数放在独立分镜／制作数据中，保持正文可读。
- 研究文档保存为 Markdown；未来正文导出可提供 TXT/DOCX。当前仅核实官方文档和约定格式，未进行小云雀真实上传解析验收。
