# 端到端创作管线：把决策逐层交接

这页适用于从素材导入走到可观看成片的项目。它描述“信息如何交接”，不是规定所有项目都必须使用同一模型、供应商或制作顺序；低成本试片可以跳过某些步骤，长篇项目则应保留可回溯的中间产物。

## 适用场景

- 新项目需要建立从原文到成片的共同工作语言。
- 某一步改动后，下游不断返工，团队不清楚哪个版本才是有效输入。
- 要定位“文本没问题但画面不对”或“素材都在但无法合成”的断点。

## 核心观点

每一层只做一种转换，并交付能被下一层核对的结果：原文变成结构化故事，故事变成剧集与 Beat，Beat 变成剧本和分镜，分镜变成生产资产，资产变成声音/视频，最后才是合成导出。上游的稳定标识（项目、集数、Beat、角色、场景）比文件名更重要。

把“创作决策”和“模型执行”分开：模型可以提出候选，导演或编剧确认采用；失败时优先回到最近一个仍然正确的层，而不是全链路重跑。相关实现边界可对照[生产管线总览](../system-map.md)。

## 判断标准

一项交接可通过以下标准才算完成：

- **可读**：下一岗位无需猜测意图，能看到目的、约束和例外。
- **可追溯**：能反查来源文本、版本和生成任务。
- **可复用**：角色、场景、道具和音色不靠手工复制到每个镜头。
- **可失败**：外部模型超时、额度不足或结果不合格时，状态明确且不会误发布半成品。
- **可验收**：每层有少量具体检查，不把问题推迟到最终视频才发现。

## 推荐工作流

1. [小说导入](../pipelines/01-ingest.md)：保留原始文本和导入 revision，标记章节、人物、地点及不确定信息。
2. [剧集图谱](../pipelines/02-episode-graph.md)：确定集目标、Beat 顺序、冲突升级和跨集钩子。
3. [生产资产](../pipelines/03-production-assets.md)：建立角色、场景、道具的参考与采用状态；不合格候选留在草稿区。
4. [剧本与语义](../pipelines/04-screenplay.md)：把 Beat 翻成动作、对白、旁白和声音意图，避免把镜头术语混入角色台词。
5. [分镜与图像](../pipelines/05-storyboard.md)：按镜头生成或挑选画面，绑定参考图和构图目的。
6. [声音与音频](../pipelines/06-audio.md)及[视频生成](../pipelines/07-video.md)：先验证对白可听、动作可读，再扩展镜头运动和氛围。
7. [合成与导出](../pipelines/08-compose-export.md)：统一画幅、时长、音频采样和字幕，生成可回看的版本并记录采用的中间产物。

返工时只回退到第一个不满足验收的交接点。例如角色脸型漂移应回到资产参考或镜头提示，而不是重新导入小说；Beat 因果错误才回到剧集图谱。

## 正反例

**正例**：编剧改了第 3 集 Beat 2 的结尾，系统保留新 revision；分镜只重做受影响镜头，配音任务按新剧本重新排队，导出页显示使用的 revision。团队能说明“为什么重做”和“哪些素材仍可复用”。

**反例**：成员直接替换 `final.mp4`，没有更新脚本或任务状态。下一次合成又使用旧对白，页面缓存还显示旧缩略图，最后只能靠人工逐个文件比对。

## 常见失败

- 把生成文件路径当作业务身份，移动文件后上下游全部失联。
- 没有区分草稿、已采用和已发布，失败产物被后续步骤误用。
- 任务完成只看状态，不检查实际媒体是否存在、可读且对应当前 revision。
- 同时修改文本、角色和分镜，返工后无法定位真正原因。
- 将供应商特性写进创作规则，导致换工具就要重写整个流程。

## 软件入口

- 按阶段从[项目与小说](../product/01-project-and-novel.md)一路进入[合成与导出](../product/06-compose-and-export.md)，先确认用户操作和阶段产出。
- 项目创建、导入和任务状态：见[启动与本地开发](../start-software.md)。
- 资产采用、参考图和版本复查：从[生产资产管线](../pipelines/03-production-assets.md)进入对应项目页面。
- 分镜、音频、视频与导出：分别使用[分镜与图像](../pipelines/05-storyboard.md)、[声音与音频](../pipelines/06-audio.md)、[视频生成](../pipelines/07-video.md)、[合成与导出](../pipelines/08-compose-export.md)中的入口和验收点。

## 检查清单

- [ ] 当前 revision、项目、集数和 Beat 标识在所有中间产物中一致。
- [ ] 每层交付都写明了输入、采用结果、失败原因和下一步。
- [ ] 草稿与已采用资产分开，失败任务不会被自动当成可用结果。
- [ ] 我能定位最近一个正确的交接点，并只重跑受影响的下游。
- [ ] 导出前已按当前剧本 revision 复查画面、对白、音频和字幕。
