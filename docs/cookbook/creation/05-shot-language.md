# 镜头语言：把叙事意图变成可执行镜头

- **所属**：创作方法 · 05 镜头语言

- **下游**：[分镜与图像](../pipelines/05-storyboard.md) · [视频生成](../pipelines/07-video.md)
- **产品入口**：[剧本与分镜](../product/04-screenplay-and-storyboard.md)；页面源码为 `frontend/src/routes/_app/projects.$project/episodes.$episode/beats.lazy.tsx`

## 适用场景

适合把一段剧本、一个 DramaticBeat 或一组动作拆成可拍摄、可生成、可验收的镜头。尤其适合出现「画面好看但不知道在讲什么」、镜头数量失控、生成提示词互相冲突时使用。

## 核心观点

镜头先回答「观众此刻需要看到什么」，再决定景别、角度和运动。每个镜头至少写清三件事：镜头目的、主体与动作、与前后镜头的关系。景别是信息量控制，调度是视线和空间关系控制，不应只当作风格标签。

## 判断标准

- **镜头目的**：能用一个动词描述，如建立、揭示、跟随、反应、对照或收束。
- **景别**：近景服务表情和细节，中景服务人物关系，全景服务空间和行动；选景别时能说明舍弃了什么信息。
- **调度**：主体从哪里进入、朝哪里移动、视线指向哪里、镜头为何跟随或停下，都有明确答案。
- **可生成性**：主体、动作、时间、地点和关键资产没有互相冲突；一镜只承担一个主要动作或信息转折。

## 推荐工作流

1. 从剧本事实提取「必须看见」和「必须听见」，不要先写画面形容词。
2. 为每个镜头写一句目的，再选能承载目的的景别和机位。
3. 在俯视或平面草图上标出人物、道具、运动方向和视线，检查轴线与入出画。
4. 将动作拆成起势、变化、结果三个节点；必要时用反应镜头补足因果。
5. 把镜头写入 ShotPlan，再进入[分镜与图像](../pipelines/05-storyboard.md)生成草图和首帧；完成后由[视频生成](../pipelines/07-video.md)验证运动可延续性。

## 正反例

正例：目的「揭示门外有人」；先用中景看角色停下，再切门把手近景，最后用过肩镜头让门外身影进入画面。每一镜只推进一个信息。

反例：「电影感、震撼、镜头快速推进，角色又哭又笑并拿刀奔跑」。它没有目的优先级，动作、情绪和运动互相抢占生成预算。

## 常见失败

- 景别写得很完整，却没有主体动作，结果所有镜头都像静态海报。
- 用推拉摇移替代调度设计，导致人物移动方向和视线方向在相邻镜头中反复翻转。
- 一个镜头同时要求交代空间、表情、道具细节和剧情转折，首帧无法验证重点。
- 只改提示词不改 ShotPlan，重生成后仍重复同一结构性问题。

## 检查清单

- [ ] 每个镜头都有一个可复述的镜头目的。
- [ ] 景别、角度和运动分别说明了它们要传递的信息。
- [ ] 主体动作、视线、入画和出画方向与前后镜头一致。
- [ ] 关键角色、道具和场景资产已对应到项目中的 canonical 资产。
- [ ] 草图阶段已验证构图，未把所有问题推迟到视频生成阶段。
