# 创作复盘：把一次成片变成下一次的输入

- **所属**：创作方法 · 08 复盘模板
- **相关技术页**：[质量门禁](07-quality-gates.md) · [共享系统地图](../system-map.md)
- **产品入口**：[项目与小说](../product/01-project-and-novel.md) · [设置与任务中心](../product/07-settings-and-tasks.md)

## 适用场景

每集或每轮生成结束后使用。模板用于记录可复现事实、判断依据和下一轮动作，不用于替团队补写不存在的数据，也不把个人偏好伪装成系统指标。

## 核心观点

复盘要把「发生了什么」与「下次怎么改」分开。先锁定 revision、任务、素材和返工点，再归纳模式；没有证据的地方保留空白，注明待补来源。

## 判断标准

- 事实项能回指任务记录、文件、时间码、版本或审阅者。
- 结论只覆盖本次样本，不把单集现象推广成系统规律。
- 改进行动有负责人、触发条件和验收方式；没有负责人就不算行动项。
- 能区分输入问题、创作决策问题、工具问题和验收问题。

## 推荐工作流

1. 导出或抄录本次使用的剧本、资产、镜头、音频、视频和合成 revision。
2. 按时间线记录首次发现、影响范围、临时处理和最终处理。
3. 将问题归类到[质量门禁](07-quality-gates.md)的阶段，寻找最早可退回点。
4. 从重复出现且证据充分的问题中挑选 1～3 个改进行动。
5. 下一轮开始前回看行动项，只更新「已验证」或「仍待验证」状态。

## 正反例

正例：写明「第 3 集 r2，00:41 处角色持物从左手跳到右手；影响镜头 12–14；由镜头组修正动作状态卡，下一轮顺剪前复核」。

反例：「这集节奏不好，模型不稳定」。它没有时间码、对象、证据或可执行的修复边界。

## 常见失败

- 只记录最终成片观感，不保留失败候选和退回节点，无法定位最早错误。
- 用平均耗时、成功率等数字填满模板，但没有说明统计范围和来源。
- 一次复盘列出过多行动项，下一轮没有任何一项完成验证。
- 把工具偶发失败直接归因为创作方案，忽略输入版本和重试上下文。

## 软件入口

- 从项目概览确认剧集与项目范围；界面入口以当前项目导航为准。
- 从任务中心复制任务类型、状态、错误和时间信息，实现入口为 `frontend/src/routes/_app/projects.$project/tasks.tsx`。
- 需要追踪具体产物时，回到[分镜与图像](../pipelines/05-storyboard.md)、[声音与音频](../pipelines/06-audio.md)、[视频生成](../pipelines/07-video.md)和[合成与导出](../pipelines/08-compose-export.md)。

## 检查清单

- [ ] 已填写项目、剧集、日期、参与者和本次 revision 范围。
- [ ] 每个问题都有对象、证据位置、影响范围和发现时间。
- [ ] 未知数据保持空白，并标注待补来源，没有编造数字。
- [ ] 每个改进行动都有负责人、截止条件和验收方式。
- [ ] 已选出下一轮开始前必须验证的 1～3 项行动。
