# Toonflow 长漫剧制作设计规格

日期：2026-10-27。状态：分节设计已确认，等待书面规格审阅。本文只定义设计，不表示相关能力已经实现或通过实际生成验证。

## 后续确认的完整管线补充

本文件下方保留早期设计背景；阶段顺序、资产和验收范围以最新[制作阶段契约](../packages/skills/nuomiSkills/references/productionStages.md)为准，软件执行依据[公开操作协议](../packages/skills/nuomiSkills/references/toonflowOperations.md)。六项契约为“阶段输入／Skill 职责／节点操作／成果／确认条件／返修路径”。

正式主线补齐为：立意 → 全剧规划 → 分集剧本 → 必要资产设计与采用 → 全景切片与打光 → 按复杂度进行 3D 导演 → 独立正式分镜 → 独立配音 → H3 规划及视频 → 合成与验收。配音可在对白和音色采用后提前执行，实际时长回馈镜头规划。

用户在画布审阅成果、在专属工作台编辑、在资产库管理跨集／跨作品可复用资产。全局素材库可复用，但必须补齐作品管理、资产本体关系与固定版本采用。人物基础设计包含白底三视图及脸部特写；全景切片机位不包含位置移动；复杂空间、人物调度和运镜必须经 3D 导演，简单特写需记录跳过依据。

当前已验证部分图片、音色、配音生成，旧 E1 缺少完整资产设计、导演、分镜和制作画布，不能作为正式管线验收。旧素材与任务保留为早期试制，不自动入库或采用。下文“当前没有进行付费生成验证”为早期记录，不代表从未试制；这些局部试制也不证明 H3 全模式可用。

nuomi-skills 的方法文件不等于运行时接入完成。Codex 必须能通过真实公开操作完成整条管线，不能用技能文档、代码存在、手工改内部文件或任务成功回执替代验收证据。

## 目标与首个闭环

以当前 Toonflow 为基座，Agent/Skill 为制作核心，画布展示可审阅、编辑和采用的成果。整体同时支持长篇连载和单集长时长；首轮从一句话创意开始，完成连续两集短集成片，包含独立对白、基础音轨和字幕，验证跨集角色、音色与资产复用。

首轮范围包括题材立意、全剧设定与分集规划、两集剧本、资产与音色、分镜与 H3 规划、媒体生成、成片合成、局部返修和任务恢复。发布材料、平台发布、完整剪辑软件和全剧自动批量制作不属于本轮。

硬性验收要求：外部 Codex 必须能通过公开工具完成 E1（E01，第一集）的全流程操作与验收，不依赖用户手工点击工作台、搬运素材或修改文件。E1 是第一道端到端验收关卡；通过后继续 E2，验证跨集复用，不取消既定两集闭环。

整体规格作为实施边界，后续实现计划按依赖拆成阶段；每个阶段完成相应能力及验证后再推进。实际作品的集长、画幅、风格、集数与算力预算是制作时的输入，不在平台规格中写死。

## 制作主线与层级

题材立意 → 全剧设定与分集规划 → 分集剧本 → 角色／场景／音色资产 → 分镜与导演方案 → 生成片段 → 单集合成。

- 作品层保存采用的立意、世界观、人物关系、共用资产与音色。
- 篇章层保存主线、人物成长和分集规划；简单作品可省略篇章层。
- 集层保存剧本、场景、镜头、配音、视频与成片记录。
- 生成段是模型执行单位，与剧情镜头分别关联；一个镜头可以拆成多个生成段。

采用内容是下游依据。跨集使用稳定角色身份及固定资产、音色版本，不以候选列表的最新结果自动替换已采用内容。

## Agent、Skill 与业务操作

Agent 识别作品和集数，读取采用记录，按阶段加载 Skill，提出可审阅方案，获得批准后调用业务操作。Skill 承载立意、长篇规划、剧本、资产、音色、导演及合成方法，避免把所有规则塞入同一个长提示词。

工作台按钮与 Agent 调用同一套业务能力，读写同一份制作状态。文件与业务操作负责结构校验、任务状态和持久化，不能仅靠 Skill 文本保证约束。画布节点引用成果及其版本，不能另存一份独立的采用状态。

当前 workflow 的 Seedance 强制路由需按明确目标模型分流，保留原有能力，增加 H3 专用规划规则。没有可执行的已选模型时报告能力问题，不静默换模型。

用户采用关键阶段确认方式：立意与规划、剧本、角色与音色、生成方案均需确认；已批准的相同方案或批次直接执行。创作确认、算力授权和成果采用分别记录。方案变化或重试可能产生新消耗时核对原授权范围。

## Codex 可操作性与 E1 验收

### 同一条公开操作链

外部 Codex 是一等操作者，可直接调用 Toonflow MCP；不要求先转交内置 Agent。沿用现有 getAppState、画布能力发现、getNodeTools／nodeTools、应用操作及文件资源入口，具体名称和参数通过实时 schema 发现。以下为必须覆盖的业务能力，不是假定现有工具已经全部具备。

| 阶段 | Codex 必须能够完成的操作 | 可读取的结果 |
| --- | --- | --- |
| 定位与准备 | 定位或打开指定项目，发现插件、模型、音色和合成能力，确定 E1 目标 | 项目／画布标识、真实可用能力、具体缺项 |
| 立意与规划 | 保存简报、生成三个方向、编辑／局部重做、依据用户确认采用，生成全剧与分集规划 | 候选正文、版本、采用结果及来源 |
| 剧本与资产 | 创建和修改 E1 剧本，生成或绑定角色、场景及音色，试听／预览后执行采用 | 实际媒体、对白及角色映射、固定资产版本 |
| 独立配音 | 按角色和原文逐句生成、查询、读取结果、局部重做及采用 | 音频文件、实际时长、台词与音色版本 |
| H3 规划 | 规划模式、拆段、绑定首尾帧或参考，读取中文方案与执行文件 | 单次合法时长、素材绑定、模式匹配与阻塞原因 |
| 生成与恢复 | 批量提交已授权任务，查询／等待、恢复、取消及按需重试 | 供应商任务编号、真实终态、输出路径、错误原因 |
| 成片 | 排列采用片段，合成独立对白、基础音轨和字幕，生成及读取成片 | 可播放视频、合成清单、字幕和音轨依据 |
| 验收与返修 | 读取媒体证据、定位问题、修订对应业务对象并重做受影响结果 | 验收记录、证据引用、修订前后版本及最终交付 |

所有必要操作均有结构化输入、明确返回值及可读取的错误；不能只存在于 Vue 按钮事件中。前端允许保持打开以支持当前实时画布工具，但 Codex 能通过工具完成导航、选择和操作，不以人工点选作为流程依赖。需要界面连接的工具必须显式报告连接要求；长任务及采用记录持久化，界面关闭或重连不丢失制作进度。

Codex 必须能发现和读取对应 Skill、制作状态与可追溯文件；不能靠绕过公开接口直接改画布 JSON、数据库或内部状态来完成验收。大视频通过文件资源或受控媒体读取入口访问，不把现有 workspaceFiles 的 20 MiB Base64 限制当作成片读取方案。

### 确认无需用户操作界面

沿用已确认的关键阶段审批。Codex 在对话中展示实质方案、请求必要确认，然后通过公开业务操作记录确认与采用；用户不需要另去界面再次点击。确认记录关联具体版本和授权范围。用户授权 Codex 代为评价并采用某批成果时可以按范围执行，不能把一般制作授权视为无限制花费或伪造人工试听。

### E1 验收证据与通过条件

E1 必须从一句话创意开始，最终产出真实可播放的第一集视频。验收通过公开产品能力及必要人工操作式验证完成，不新增测试脚本、断言模块或测试专用导出。

- 可读取性：Codex 可获得实际视频、音频、字幕、时间线和采用记录。仅有路径、任务成功回执或文件存在不能算媒体验收通过。
- 技术检查：通过可调用的产品媒体能力读取时长、画幅、编码和音轨信息；核对各 H3 提交不超过 15 秒、输出可解码、字幕处于有效时间范围、所有素材来自采用版本。
- 内容检查：支持 Codex 获取逐镜头及衔接位置的可视证据、完整对白音频的听取或分析依据、实际语音与原文的对照结果；检查漏句、截断、重复人声、明显身份与画面衔接问题。自动转写仅是证据之一，不等于音色、表演及视听质量已通过。
- 可修复性：发现问题后能定位具体片段／对白，完成局部返修并重新合成；不能要求用户手工下载、剪接或替换文件。
- 可恢复性：中断后按任务编号读取状态并继续，不因超时或重连重复生成。
- 交付：保存成片及验收记录，列出检查项、实际证据、发现的问题、修复情况、未验证项和用户确认依据。验收记录是制作成果文件，不是自检程序。

实现必须补齐缺失的媒体读取、分析和合成公开能力，使 Codex 可以实际完成上述检查。若运行环境无法读取声音或视频，必须报告具体能力缺口，E1 不得标记通过；不能将所有媒体检查转交用户并称为“Codex 完成验收”。审美取舍与关键阶段确认仍尊重用户决定，Codex 不伪称人类已试听或审阅。

## 成果画布与工作台

采用“成果节点＋专属工作台”。画布显示成果、简明状态和关联，打开节点进入编辑与审阅界面。默认状态包括待确认、制作中、待处理、已采用。

用户明确要求减少过程细节：界面不提供高级详情展开区，不展示提示词原文、工作流参数、帧数、任务日志等实现内容。这些记录持久化到文件以便追溯，供 Agent 排查及返修使用。界面保留必要的创作选择、时长、素材、算力信息与可操作的错误说明。

H3 工作台按片段组织，显示预览、中文导演描述、使用素材、时长和状态。规划器推荐生成方式，用户可调整。生成前展示任务清单；不把内部校验步骤逐项暴露为操作步骤。此前浏览器草图中的提示词面板和技术检查列表不进入最终产品。

## 题材立意

参考 Nuomi 当前 IdeationWorkspace 与 IdeaDirections 的交互，采用“题材创意 → 立意方向”两步结构。

- 创作简报可保存，支持用户自写立意。
- 一次生成三个方向，左侧切换候选，右侧查看内容。
- 内容包括一句话立意、主角与核心冲突、故事看点、人物最终抉择。
- 支持编辑、保存、仅重做当前方向；切换查看不改变采用结果。
- 未保存修改离开时提供保存、放弃和继续编辑选择；生成失败保留简报与旧候选。
- 采用方向后进入全剧设定及首批分集规划，经确认后制作 E01、E02，不直接跳到 E01 制作。

## MiniMax H3 规划与适配

H3 规划器将采用的素材、提示词、镜头内容、对白及时间要求转成 H3 导演格式。允许在保留剧情、对白与顺序的前提下拆段、分配时长，不擅自新增剧情或替换资产。

规划输出包括中文审阅方案、模式、素材绑定、执行提示词及 timeline_data 等参数。RunningHub 适配器负责素材上传、任务提交、状态查询、结果下载。指定工作流 ID 为 2114738928094892033，新版图来自仓库 runnninghub/MiniMax H3 导演台全能工作流_api.json。

| 模式 | 素材与语义 | 官方基础模型族 |
| --- | --- | --- |
| T2VA | 从文字生成完整视听过程 | FL2VA |
| I2VA | 指定首帧，动作从首帧发展 | FL2VA |
| FL2VA | 指定首尾帧，生成连接过程 | FL2VA |
| L2VA | 指定尾帧，动作收束至尾帧 | FL2VA |
| Ref2VA | 图片、视频、音频分别提供主体或结构参考 | Ref2VA |

基础四种模式采用 integrated_multimodal_description、overall_soundscape、non_diegetic_music；有关键帧时附加对应时间对齐指令。全参考采用 subject_definitions、summary、retention_analysis、detailed_description、overall_soundscape、non_diegetic_music，引用标签绑定真实素材。

描述使用英文，对白及画面文字保留原语言。中文对白逐句使用 `<d>[Chinese] 原文</d>`，标签外明确稳定说话人、画内／画外及发声时间；不得只描述张嘴动作或同时禁止生成对白。独立配音不替代生成阶段的中文声画约束，后期仍需按实际原生对白节奏对齐，不能保证换声后天然口型一致。规划使用明确动作、构图、运镜和时间安排，保持说话人一致；原始对白独立保留，格式转换不改变其内容。Ref2VA 中音色参考与音频直接复用是不同用途，不混用。

视频制作采用一次批次预检、按账号额度并发执行、一次集中审阅；不反复确认已采用输入，不为正常镜头做多轮抽帧 QC。技术检查自动完成，只有异常镜头深入检查；新语言方案先验证一个实际对白镜头再放行同批，失败不自动付费重试。

### 时长与衔接硬约束

- 单次 RunningHub 提交的 H3 生成总时长不超过 15 秒；包含多个段时同时校验各段与任务合计。
- 官方公开生成范围为 4–15 秒。实际合法帧数取决于节点实现；必须先计算有效帧数再校验时长，不能单看 durationSec。需要比最低生成时长更短的剪辑时，可从完整有效素材选取，但不得截断对白。
- 超限内容拆成独立任务再合成。保留对白、剧情和顺序，不通过截断、强制加速规避上限。
- 有前段尾帧依赖时，等待真实结果采用后继续；场景切换允许直接切镜，不强制接帧。
- 全参考素材限制按模型及工作流实际支持的交集执行。官方上限为九张图片、三段视频、三段音频、混合最多十二个文件；视频与音频各有单段 2–15 秒及对应总时长不超过 15 秒限制。

### 已发现的接入风险与放行条件

新版 JSON 当前有效链路含 Ref2VA 权重及名称为 FL2V 的加速 LoRA。仅改 task_type 不能证明首尾帧模式可用。实施时须核对节点实际实现、权重及 LoRA 兼容性，各模式通过真实验证后才允许执行。

示例时间轴写 10 秒＋5 秒，但保存帧数为 243＋124，24 FPS 下共约 15.29 秒；不得直接复制示例时长与帧数。Nuomi 的帧数换算同样只能作为参考，需与新版节点校对。

当前没有进行付费生成验证；模式兼容性、结果时长和音频行为属于集成验收门槛，不能宣称已接通。

## 音色、独立配音与合成

默认采用独立配音，但后续 H3 视频必须开启原生声音（`generateAudio: true`），保留原视频、背景音与音效，不因使用独立配音而静音生成。后期仅分离、替换原对白；无法干净分离时保留原文件并记录限制，不整轨静音。现有无音轨视频保留，不自动付费重生成。角色工作台支持音色设计、导入参考录音、克隆配音试听与采用。参考音频克隆不等同于训练独立声音模型。

按定稿对白及说话人生成配音，支持逐句试听、采用、重做。采用音色跨集复用，每次配音记录实际使用的音色版本。优先依据配音实际时长规划视频片段和对白安排。

合成使用采用的视频、独立对白、基础音轨与字幕。字幕文本来自定稿对白，时间依据实际配音；不同音轨避免重复人声。含原生对白的视频需处理后再合成，不能把原始混音与独立配音直接叠加。若当前环境无法在保留所需环境声的同时处理原生人声，明确阻塞原因，不静默丢失声音或声称分离成功。

首轮提供必要的顺序剪接、音轨混合与字幕合成，不扩展成完整剪辑软件。参考 OpenMontage 的阶段成果交接、片段顺序合成和跨片段声音连续性方法，不迁移其整套平台、岗位体系或无关发布流程。

## 持久化、恢复与局部返修

制作文件保存在当前项目工作区。至少记录稳定对象标识、版本、来源与依赖、采用记录、任务及尝试编号、供应商任务编号、实际输入参数、素材路径和输出。引用采用版本，候选及旧输出保留。凭据使用既有配置入口，不写入成果或追溯文件。

提交前记录本次任务意图，获得供应商任务编号后持久化。重开项目恢复查询；提交结果不明确时先查原任务，无法确定时标记待处理，不自动重复付费提交。已提交不代表已完成，下载或保存失败不能报告制作成功。

修改上游时根据版本依赖标记受影响成果；不自动重做整集。修改一句对白，先重做对应配音并检查时长、字幕和相关视频；需要视频返修时提出具体方案。修改角色或音色同样只标记实际依赖的成果。旧成片可保留并标记依据旧版本，避免与新候选混淆。

遵循仓库规范：前端复用 useWorkspaceFiles，磁盘操作使用 @toonflow/file，完整快照显式原子写入；异步制作固定项目目录，防止切换项目后写错位置。输入结构、路径边界、文件冲突与保存错误属于运行时业务校验，必须保留。

插件专属组件、提示词和业务逻辑放所属插件；跨插件共享业务放 packages/nodeShared；packages/nodeScaffold 仅提供通用基础能力。沿用当前 Bun、TypeScript、Express、Vue 技术栈，不为本需求迁入 Python 服务或新增通用编排框架。

## 验收与实施顺序

后续计划按以下依赖推进：

1. 统一制作对象、采用版本、文件追溯与共用业务操作，形成 Agent/Skill 入口。
2. 题材立意工作台及全剧／分集规划、剧本成果。
3. 角色、场景、音色资产与独立配音。
4. H3 规划器及 RunningHub 五种模式的真实能力核验与适配。
5. 片段生成、两集成片合成、局部返修及恢复验收。

每个阶段同步提供 Codex 可发现的公开操作与结果读取能力，不先完成仅能点击的界面、再把自动化留作后续。阶段 5 先由 Codex 走通 E1 全链路并提交验收证据，再推进 E2 跨集复用验收。

首个闭环验收必须实际完成连续两集可播放成片，检查人物与音色复用、对白完整、字幕时间和无重复人声；验证一次局部返修不会无关重做，以及任务恢复不会重复提交。每次 H3 提交满足 15 秒上限。用户对成果的采用不能由“工具返回成功”替代。

开发阶段只执行已有类型检查、构建和必要手动验证；不新增测试模块、自检脚本、测试依赖或 CI 测试入口。路由变更后运行既有路由生成命令，不手工维护 router.ts。配置验证使用临时目录。编译通过与实际功能验证分别报告，付费验证仅在对应生成方案获得授权后执行。
