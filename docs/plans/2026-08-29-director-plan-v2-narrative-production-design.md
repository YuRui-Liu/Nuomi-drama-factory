# DirectorPlan v2：叙事规划、生成批次、H3 视频与风格快照设计

> 日期：2026-08-29
> 状态：待实现
> 适用范围：剧集导演台、叙事组工作台、宫格图生成、MiniMax H3 视频生成、扩展风格服务

## 1. 背景与问题

当前链路把三种不同概念混在同一层：

1. 剧情语义上的叙事组；
2. 图片模型的一次宫格生成批次；
3. 视频模型的一次生成片段。

旧实现按场景连续性贪心聚合最多 9 个 Beat。由于实际 Beat 常缺少分组代码读取的场景字段，分组会退化为固定每 9 个 Beat 一组。旧 Beat 又基本等同于剧本文本行，而不是可拍摄的导演镜头，因此出现以下问题：

- 单一字幕、动作或转场被误当成独立叙事组；
- 一个叙事组内可能包含多个目标和情绪转折；
- 1～2 个有效镜头仍被强制生成 2×2 四宫格；
- 图片批次、视频段和叙事结构相互牵制；
- H3 提示词逐 Beat 优化，调用多、慢且缺少整集连续性；
- 项目风格以扁平提示词重复注入，可能覆盖导演镜头并造成风格漂移。

DirectorPlan v2 将语义规划、图片批次和视频片段拆为独立层级，并通过不可变版本保证可回退、可审核和可重复生成。

## 2. 目标与非目标

### 2.1 目标

- 一次整集导演调用生成语义正确、可拍摄的叙事组和 Shot。
- NarrativeGroup、GenerationBatch、VideoSegment 各自承担单一职责。
- 支持完整校验、局部修复、人工审核和版本回退。
- 图片宫格数量与实际 Shot 数匹配，不留空格和白边。
- H3 以整集上下文规划提示词，但每个 VideoSegment 独立生成视频。
- 风格在导演、图片和视频链路中一致，同时不覆盖明确镜头语言。
- 尽可能复用旧素材，但不把错误风格素材标记为正式完成品。

### 2.2 非目标

- 不保留旧 Beat 作为新导演规划的权威语义单元。
- 不让图片生成批次跨越叙事组。
- 不用额外 AI 生成转场视频。
- 不允许 Shot、GenerationBatch 或 VideoSegment 任意覆盖叙事组风格。
- 不在视觉风格变更时修改角色、场景、道具的语义身份。

## 3. 核心领域模型

```text
Episode
└─ DirectorPlanRevision
   ├─ StyleSnapshot（项目默认）
   ├─ Scene[]
   ├─ NarrativeGroup[]
   │  ├─ StyleSnapshotRef（可选覆盖）
   │  ├─ Shot[]
   │  ├─ GenerationBatch[]
   │  └─ VideoSegment[]
   └─ AssetMigrationReport
```

### 3.1 DirectorPlanRevision

DirectorPlan 是整集导演结果的不可变版本。新导演、修改会影响镜头语言的风格、或人工确认后的结构重排，都创建新 revision。旧 revision 和旧素材保留，可随时恢复。

主要字段：

- `revision_id`、`episode_id`、`status`；
- `source_script_hash`、`director_model`、`prompt_version`；
- `project_style_snapshot_id`；
- `scenes`、`narrative_groups`；
- `validation_report`、`migration_report`；
- `created_at`、`activated_at`。

状态至少包括：`draft`、`validating`、`review_required`、`active`、`superseded`、`failed`。

### 3.2 NarrativeGroup

叙事组是一个完整的叙事动作单元，必须表达同一个目标、动作推进或可见转折。它不是模型调用批次。

主要字段：

- 稳定 `group_id`；
- 原文范围 `source_span_ids`；
- 场景与时间锚点；
- `objective`、`visible_turn`、`relation_to_previous`；
- 1～5 个 Shot，目标为 2～4 个；
- 可选叙事组风格覆盖引用。

### 3.3 Shot

Shot 是可独立呈现的导演镜头，包含：

- 原文证据引用；
- 主体、动作、景别、机位、构图和运动；
- `visible_start_state` 与 `visible_end_state`；
- 精确对白引用，不由 LLM 改写对白；
- 预估时长、连续性锚点和资产引用。

### 3.4 GenerationBatch

GenerationBatch 只描述一次图片模型调用。它不得跨叙事组，且不改变 Shot 语义。

默认布局：

| Shot 数 | 布局 |
|---:|---|
| 1 | 单图 |
| 2 | 二联画 |
| 3 | 三联画 |
| 4 | 2×2 |
| 5 | 3 + 2 两个批次 |

任何布局都不得创建空白格。

### 3.5 VideoSegment

VideoSegment 是一次真实视频模型调用。默认一个 Shot 对应一个 VideoSegment；只有明确的连续动作、相同主体与空间、且中间不可合理硬切时，才允许多个 Shot 合成一个 Segment。

每个 Segment 独立调用 RunningHub/MiniMax。叙事组预览视频由本地确定性合成产生，不作为付费模型的源输出。

## 4. 整集导演规划

### 4.1 输入

主导演 LLM 每集只执行一次结构化调用，输入包括：

- 带稳定 source ID 的完整剧本；
- 与本集相关的角色、场景、道具圣经；
- 项目基调、画幅和平台约束；
- DirectorPlan 的结构化输出协议；
- 项目 `StyleSnapshot.director` 投影；
- MiniMax H3 等下游模型的必要约束，但不要求主导演输出最终模型提示词。

DeepSeek 通道不使用 `tool_choice`。优先使用 `response_format/json_schema`，不支持时退化为 `json_object`，再由本地验证器校验。

### 4.2 叙事组划分

采用“确定性硬边界 + LLM 场内语义分组 + 本地验证”的混合策略。

硬边界包括：

- 场景、地点或明确时间切换；
- 闪回、梦境、监控画面等叙事层切换；
- 无法保持人物和空间连续性的段落。

场景内部在以下位置建立语义边界：

- 当前目标或动作完成；
- 新信息改变人物决策；
- 情绪、权力或关系发生可见转折；
- 叙事焦点主体改变；
- 悬念、揭示或钩子落点成立。

每个组必须满足：一个主要目标、一个动作推进、一个可见结果或转折。组内 1～5 个 Shot，超过上限必须拆分。

### 4.3 验证与局部修复

本地验证覆盖：

- 原文范围完整、顺序一致、无重叠和缺失；
- 所有 ID 引用有效；
- NarrativeGroup 不跨硬边界；
- Shot 数量和可拍摄性满足要求；
- 每个动作具有节奏或身体力度，以及可见结束状态；
- 对白引用与原文一致；
- GenerationBatch 和 VideoSegment 不跨叙事组；
- 时长、人物、场景和道具连续性合法。

主结果校验失败时，只将失败组及必要邻接上下文提交局部修复，最多两次。修复仍失败则保持当前 active revision 不变，并进入人工审核。

## 5. 图片生成与宫格切分

图片生成使用 GenerationBatch 的 Shot 数决定布局，不再固定 2×2。目标画幅（如 9:16）是每个切分后画面的画幅，而不是强迫整张宫格画布也使用同一画幅。

### 5.1 画布与分辨率

- 根据布局、单格目标画幅和模型可用分辨率计算整张宫格画布。
- 使用混合策略选择最接近且像素充足的模型尺寸。
- 高分辨率模型只改变渲染质量，不改变 NarrativeGroup 或 Shot 数量。
- 分辨率选择同时受模型尺寸白名单、单格最低像素和最大成本约束。

### 5.2 无白边切分

服务端采用混合切分：

1. 用预期坐标计算理论分隔线；
2. 在邻域检测亮色或低纹理分隔带；
3. 找到分隔带时沿其中心切分；
4. 每格向内安全裁切少量像素；
5. 按目标画幅执行居中或主体感知裁切；
6. 检测边缘残留白边，必要时再次内缩；
7. 记录切分参数和质量报告，确保可重复。

## 6. H3 视频提示词与执行

### 6.1 整集 Prompt Pack

H3 提示词规划采用整集一次调用，输出全部 VideoSegment 的结构化 `H3DirectorPlan`。这样可以利用整集上下文保持人物、动作、视线、节奏和镜头递进一致。

LLM 不直接输出不可校验的最终长提示词。本地现有 H3 编译器继续负责：

- 官方格式编译；
- 字段级质量校验；
- 模型安全约束；
- 最终 prompt manifest 和版本记录。

单个 Segment 校验失败时，仅修复该 Segment，最多两次。缓存以 Segment、导演版本、风格哈希和 H3 提示词版本为键。

只有用户进入单 Segment 编辑时才创建持久编辑会话，不预先为整集所有 Segment 创建会话。

### 6.2 视频执行

- 一个 VideoSegment 对应一个 RunningHub/MiniMax 任务。
- Segment 内可通过 H3 `[Shot N]` 表达真正连续的多镜头动作。
- 不再把整个叙事组强制塞进一次远程视频时间线。
- 各 Segment 成功后，本地按 DirectorPlan 时序合成叙事组和整集预览。
- 单个任务失败可以独立重试，不影响已完成 Segment。

### 6.3 音频与时序

音频模式采用“项目默认 + VideoSegment 覆盖”：

- 有对白：先生成或复用外部 TTS，锁定真实时长，再生成 H3 Prompt 和视频；
- 无对白：默认使用 H3 原声；
- 默认不让 H3 生成非叙事性音乐，`non_diegetic_music=N/A`；
- 保留环境声和动作音效；
- 整集统一使用项目 BGM。

### 6.4 转场

默认硬切，并根据叙事关系确定性选择少量转场：

- 因果、递进、连续动作：硬切或动作匹配切；
- 对比：明确硬切；
- 蒙太奇：按节奏硬切；
- 时间跳跃：叠化或淡入淡出；
- 对白与环境连续：允许声音先入或延出，即 J-cut/L-cut。

不额外调用 AI 生成转场视频。

## 7. 风格服务整合

### 7.1 覆盖层级

风格层级为：

```text
项目默认风格
└─ NarrativeGroup 显式覆盖（可选）
   ├─ Shot 继承
   ├─ GenerationBatch 继承
   └─ VideoSegment 继承
```

叙事组覆盖适用于闪回、梦境、监控画面等需要明确视觉区分的段落。下游对象不得独立覆盖，以避免同组风格漂移。

### 7.2 不可变 StyleSnapshot

DirectorPlan 创建时冻结风格快照：

```json
{
  "style_id": "anime",
  "style_version": 3,
  "catalog_hash": "...",
  "style_hash": "...",
  "projections": {
    "director": "...",
    "image": "...",
    "video": "...",
    "panel_tag": "..."
  }
}
```

风格库后来发生修改时，已激活 DirectorPlan 不会被隐式改变。

### 7.3 分层投影

- `director`：媒介、构图倾向和可执行约束，不注入图片模型专用渲染术语。
- `image`：GenerationBatch 使用的完整图片投影，只注入一次。
- `panel_tag`：单格使用的短标签，避免每格重复完整风格造成过度风格化。
- `video`：H3 可表达的媒介、材质、色彩和光线连续性；不包含图片负面词，也不覆盖 Shot 镜头设计。

冲突优先级：

```text
Shot 明确镜头设计 > 风格镜头倾向 > 模型默认行为
```

TTS、对白、环境声音和 BGM 不接受视觉风格注入。

### 7.4 修改风格

用户修改项目或叙事组风格时提供两条路径：

1. **仅换画风**：保留叙事组、Shot、VideoSegment 和时序结构，只使视觉素材及相关缓存失效；
2. **按新风格重新导演**：创建新的 DirectorPlan revision，旧版本和素材保留。

### 7.5 资产和缓存

- 角色、场景、道具的语义身份全局共享。
- 身份图、场景图、道具图等视觉锚点按 `style_hash` 保存不同风格版本。
- `style_hash` 一致时可自动复用为正式素材。
- `style_hash` 不一致时只能作为内容参考，必须重新渲染。
- 图片和视频缓存键必须包含 `style_hash`。
- 单纯换画风不使剧本、叙事组和 Shot 语义缓存失效。

### 7.6 对扩展风格服务原方案的调整

原方案中的 18 个只读扩展风格、三组 UI、项目默认风格、六类片段和去重逻辑继续保留。新增或调整：

- StyleService 返回结构化片段，而非只有扁平 `style_instructions`；
- 新增服务端 `StyleResolver` 和 `StyleSnapshot`；
- 正式制片链路由服务端统一解析，前端不拼接生产提示词；
- 自由画布 ImageGenNode 可继续使用轻量拼接；
- Style API 暴露版本、目录哈希和各用途投影；
- 生产任务 manifest 记录快照 ID 与哈希。

## 8. 旧资产迁移

重新导演后执行相似度迁移，但不删除旧素材：

- 高置信度：自动匹配并应用；
- 中置信度：进入审核队列；
- 低置信度：保持未匹配。

匹配依据包括原文范围、主体、场景、动作、镜头语义和风格哈希。即使语义高度相似，只要风格哈希不同，旧视觉素材也只能成为参考图，不能直接成为正式产物。

迁移报告必须能解释每项自动匹配的依据，并允许人工撤销。

## 9. 前端审核工作流

导演台提供“重新导演分镜”入口和真实阶段日志：

1. 读取并锁定剧本版本；
2. 整集导演规划；
3. 结构验证；
4. 局部修复；
5. 生成批次和视频段规划；
6. 旧资产相似度迁移；
7. 等待审核或激活。

审核界面同时展示旧版与新版叙事组，支持：

- 拆分、合并和重排叙事组；
- 在相邻组之间移动 Shot；
- 编辑 Shot 可见起止状态和导演参数；
- 查看资产迁移的自动、待审和未匹配状态；
- 选择立即激活、审核后激活或放弃新版；
- 恢复任意旧 revision。

风格变更时显示“仅换画风”和“按新风格重新导演”两种清晰操作，不把两者混成一次不可逆生成。

## 10. 错误处理、性能与可观测性

- 普通整集导演规划目标在 90 秒内完成，硬超时 180 秒。
- 正常路径只有一次整集导演调用；只有失败组或失败 Segment 进行局部修复。
- 任务进度必须对应真实阶段，不得长期停留在 1%。
- 每次 LLM 和提供商调用记录模型、请求类型、耗时、重试、响应状态和结构化错误码，不记录密钥。
- GRSAI、DeepSeek、RunningHub 等传输错误与内容质量错误必须区分。
- 单 Segment、单 GenerationBatch 失败可独立重试，不使整个 DirectorPlan 失效。
- 当前 active revision 在新版本完整通过验证并由用户选择激活前保持可用。

## 11. 验收标准

### 11.1 结构正确性

- 原剧本 source spans 100% 覆盖且无重叠。
- 叙事组不再按固定 9 Beat 分桶。
- 每个组表达一个目标、动作推进和可见转折。
- 每组 1～5 个 Shot，默认集中在 2～4 个。
- GenerationBatch 和 VideoSegment 均不跨组。

### 11.2 图片链路

- 1、2、3、4 个 Shot 分别产生单图、二联、三联和四宫格。
- 5 个 Shot 产生 3+2 两批，不出现空白格。
- 切分结果符合目标画幅，边缘无可见白边残留。
- 模型和 1K/2K/4K 选择不会改变分镜结构。

### 11.3 视频链路

- 整集 H3 Prompt Pack 一次生成，失败 Segment 局部修复。
- 每个 VideoSegment 独立产生真实 RunningHub/MiniMax 任务。
- 有对白 Segment 先锁定 TTS 时长；无对白 Segment 默认使用 H3 原声。
- 提示词质量失败不会误发起付费视频请求。
- 叙事组与整集预览可由成功 Segment 本地确定性合成。

### 11.4 风格链路

- 同一 DirectorPlan revision 的风格快照不可变。
- 项目默认与叙事组覆盖正确继承到图片和视频。
- Shot 镜头设计不会被风格相机倾向覆盖。
- 不同 `style_hash` 的视觉资产不会被误判为正式可复用。

### 11.5 验证方式

- 单元测试覆盖分组规则、布局、切分、StyleResolver、缓存键和 H3 编译器。
- 契约测试覆盖整集导演 JSON、局部修复、Style API 和任务 manifest。
- 使用真实 DeepSeek、GRSAI 与 RunningHub/MiniMax 执行小规模 smoke test，不以 mock 代替最终链路验证。

## 12. 分阶段实施

### M1：核心导演模型

- DirectorPlan revision、NarrativeGroup、Shot 数据模型；
- 整集导演调用、验证和局部修复；
- GenerationBatch 与 VideoSegment 独立规划；
- 兼容读取旧项目，不立即删除旧 Beat 数据。

### M2：审核与迁移

- 新旧版本对比界面；
- 拆分、合并、移动和重排；
- 资产相似度迁移与解释报告；
- revision 激活和回退。

### M3：生产生成链路

- 动态宫格布局和无白边切分；
- 整集 H3 Prompt Pack 与单 Segment 真实生成；
- StyleSnapshot 全链路投影；
- 本地预览合成、音频策略和确定性转场。
