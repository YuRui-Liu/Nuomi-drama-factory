# Current Main 吸收方案补充决策 V2

> 与 `2026-08-30-current-main-script-semantics-absorption-addendum.md` 一并执行。本文记录后续连续拍板的产品决策；如与旧计划冲突，以本文为准。

## 1. 四阶段短剧制作链

剧集制作页调整为：

1. `剧本校对`：编辑原文、解析场次、识别动作/对白/出场和剧本事实；不改写剧情。
2. `导演拆解`：生成带证据的 DramaticBeat，可合并、拆分和调整来源范围。
3. `镜头设计`：生成 ShotPlan、连续性约束和 1～4 镜头 NarrativeGroupPlan。
4. `成片合成`：组图、拆格、修复、H3 视频、声音、QC 和交付。

原“脚本预览”和“生成脚本”退出产品模型；动作分别为 `解析场次`、`生成拆解`、`生成分镜`。统计改为 `原文行数 · 场次数 · 戏剧节拍数 · 镜头数 · 叙事组数`。

## 2. 角色视觉三步链

1. `剧本事实`：只展示带来源依据的叙事事实。
2. `视觉提案`：根据人物小传、时代地域和项目风格生成三套低成本文字方向，标注为创意设计。
3. `身份资产`：选择/编辑提案形成 VisualBible 后，再生成身份候选、身份锚点和正/侧/背三视图。

资产中心使用 `剧本事实`、`视觉提案`、`身份锚点`、`状态资源` 四区。“自动提取”改为“解析资产”。空槽首个 QC 通过结果可暂用；后续候选不能自动覆盖；主角/常驻角色最终身份必须人工确认。

## 3. DramaticBeat 混合解析

采用“确定性场次解析 + AI 语义分组 + 证据校验”：

- 确定性识别场次标题、内外景、地点时间、动作、角色名、对白、括号指示和特殊标记。
- AI 只在完整 Scene 内分析目标、阻碍、动作、反应、信息揭示、情绪/权力变化、转折和结果。
- 每个 Beat 保存 scene/source span、参与角色、目标/阻碍、动作/反应、转折/结果、情绪变化、对白线索、时长和必须表现内容。
- 严格区分 `script_fact` 与 `director_interpretation`。
- 校验失败阻断镜头设计，禁止回退逐行模式。

## 4. 导演意图驱动镜头设计

镜头链为 `DramaticBeat -> DirectorShotIntent -> ShotPlan`。每个镜头必须先有叙事用途。ShotPlan 保存来源、目的、主体动作、表演、景别角度、构图机位、运动、对白/声音、时长、连续性、资产需求、画幅、视频模式建议和必须表现内容，不保存最终图片长提示词。

不按每个 Beat 或每句对白机械一对一生成镜头。确认后再按共享角色状态、场景状态、光线时间、连续动作/视线和参考图组织 1～4 镜头叙事组。

## 5. 证据化资产需求

导演拆解只产生 `AssetRequirement`：资产类别、规范实体、所需状态、剧本依据、使用范围、连续性、重要度、已有匹配和是否新建。

- 剧情阶段/地点标签不等于视觉状态。
- “广播站时期”在外观未变化时不得建立 CharacterState。
- 服装、年龄、伤势、污损、淋湿、伪装、变身或剧情性发型/体型变化才建立状态。
- 图片模型和图源只在资产中心真正出图时出现。

## 6. 依赖感知失效

依赖链为 `ScriptRevision -> Scene -> DramaticBeat -> ShotPlan -> NarrativeGroupPlan -> GenerationAttempt -> 媒体`。每个派生对象记录来源版本、source span、输入摘要哈希和过期原因。

- 剧本修改只使相关范围过期，其他场次保持有效。
- 旧媒体不删除，只标记基于旧版本。
- 不自动调用模型重建；用户确认后才创建新 attempt。
- 用户可保留并重新绑定旧结果，但必须记录理由和新来源关系。
- 严格模式存在过期关键链路时禁止交付。

## 7. 验收补充

| 场景 | 必须结果 |
|---|---|
| 剧集制作页 | 仅显示剧本校对、导演拆解、镜头设计、成片合成四阶段 |
| Beat 生成 | 确定性解析，AI 分组且每个 Beat 可追溯原文 |
| 镜头生成 | 每个 Shot 有 DirectorShotIntent，不按 Beat/对白机械一对一 |
| 角色视觉 | 剧本事实、视觉提案、VisualBible 和身份资产严格分层 |
| “广播站时期”等标签 | 无可见外观变化时不得建立 CharacterState |
| 剧本局部修改 | 只使相关下游对象过期，不自动删除或重新付费生成 |
| 严格模式 | 过期关键链路或未确认关键身份必须阻断交付 |
