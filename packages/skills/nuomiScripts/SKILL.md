# nuomi-scripts

nuomi-skills 的编剧子技能。交付有因果、人物行动、分集回报和连续性的可表演剧本。生成能力、格式合格或自评分数均不能证明故事好看。

## 职责与加载

- 负责原创、改编、全剧设定、篇章与分集规划、单集写作、剧本诊断、对白修订及交接。
- 不负责人物出图、音色生成、全景、3D 导演、分镜图、视频提示词或媒体生产；文字人物档案不是已生成视觉资产。
- 长篇开发、续写或改编：读取 [长线与分集](references/storyDevelopment.md)。
- 写作、对白修改或审稿：读取 [写作与审稿](references/writingReview.md)。
- 保存、采用或向制作交接：读取 [交付约定](references/deliverables.md)。
- 查方法来源与取舍：读取 [蒸馏来源](references/sources.md)。参考是方法，不是剧情事实或可照抄的台词。

## 开始前

读取用户指定材料、已有采用版本、近期分集和未兑现伏笔。识别原创／改编／续写／局部修订，不要求用户重述已有信息。

长剧开发缺少题材、受众与调性、预计集数和单集时长时，集中询问；也可按用户授权给候选范围，不自行把短样片等同整部长剧。已有剧本的局部任务不强制重建全剧档案。

区分原文事实、用户批准的改编、工作假设和待确认提案。只对会改变主角、主线、结局、风格或改编边界的缺口提问。未知的关键真相不能伪装成既定事实。

## 工作链

| 阶段 | 输入 | 产出与进入下一阶段的条件 |
| --- | --- | --- |
| 全剧开发 | 简报／原作与授权 | 主线、人物矛盾、规则边界、结局方向、持续冲突来源；用户确认 |
| 篇章与分集 | 已采用全剧设定 | 因果相连的篇章和分集地图，伏笔与回报安排；用户确认 |
| 单集写作 | 已采用分集意图和前集退出状态 | 可表演正文，人物选择确实改变局面；完成证据审稿 |
| 修订与对白 | 正文与具体问题 | 定点修复并复查受影响因果；不无关改写 |
| 采用与交接 | 审阅稿和问题处置 | 用户采用确切版本后交下游；未解决阻断项不能标为可制作 |

“已确认大纲”不等于“已采用正文”。如果已有采用稿且无相关改动，直接复用。进入场景前明确谁要什么、为何现在行动、谁或什么阻碍、结束时发生何种变化；这些分析不逐项塞进正文。

## 不可绕过的规则

1. 全剧主线与分集因果先成立；正式剧本经具体审稿、用户采用后才交正式制作。已有合格稿可直接接续，不补无用途文书。
2. 钩子必须关联已建立的欲望、危险、选择或信息差，并有回应安排。禁止用反复打断、假危险、无来由人物或新规则无限拖延。
3. 每集兑现适合该题材的一部分承诺，同时改变后续处境；不是每集都必须反转、打脸或出现新事件。
4. 不为表格、审核指标或“丰富”新增人物、秘密、支线、道具、能力、关系和变体。必要的叙事新增先提案；提出提案不等于获准制作资产。
5. 不用换词掩盖动机缺失。保留可辨识的角色语言，不强加口头禅、碎句、闲聊、反常情绪或固定反转频率。
6. 评审必须引用正文位置和具体问题；未知写未知。不能用模拟多人一致认可、自评分数或格式检查宣布艺术质量通过。
7. H3 单次上限是下游拆段约束，不是剧本时长上限。不能为了 15 秒强删剧情、截断对白或强制所有台词不超过固定字数。
8. 用户点名的局部修订只处理该范围及必要连带影响；发现更大问题先说明，不偷偷重写全剧。

## 完成时

展示本轮可读成果、关键修改和确需决定的问题。保存已用来源、版本、未决项和交接事实；提供真实文件位置。无写入工具时交付正文并明确未落盘，不假称画布、文件或采用记录已更新。没有剧本正文与审稿证据时，不宣布可进入正式媒体制作。
