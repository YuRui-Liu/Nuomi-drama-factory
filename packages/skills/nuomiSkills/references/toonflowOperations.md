# Toonflow 公开操作协议

本文件将制作方法接到软件操作。源代码存在只说明候选能力，实时 schema 可发现才说明当前可调用，真实操作回执与成果回读才说明已执行。

## 操作闭环

1. 通过 `getAppState` 定位页面、作品目录和画布。多页面明确 connectionId；跨异步操作固定作品绑定，不随用户切换写入另一作品。
2. 读取制作记录与已采用版本，再发现画布节点、端口及操作。复用已有节点和成功任务，不因“继续”重新创建。
3. 使用 `getCanvas`、`findCanvasNodes`、`getCanvasNodes`、`getCanvasEdges`、`getNodeTools` 获取真实类型、状态和函数 schema；分页和截断必须补齐。参数以现场 schema 为准。
4. 使用公开 `addCanvas`／`switchCanvas`／`addNode` 及 `nodeTools` 操作工作台对应业务。创建节点后发现函数，再写正文或配置；不假定 addNode 能写任意 data。服务端业务可通过明确目录执行，不要求用户操作页面。
5. 按端口实际类型接入采用素材。画布业务连线只表示真实输入；阶段依赖、审批、版本追溯由制作记录保存，不能把概念流程连成错误媒体输入。
6. 保存后回读正文、配置、输出和版本；实际媒体用公开资源读取。布局展示阶段成果与必要状态，不堆叠执行日志。需要页面截图时用浏览器观察核对可见结果。
7. 通过公开采用操作记录用户确认所指的版本。候选生成成功不自动采用，保存文件也不代表画布或资产库已呈现。

禁止直接改画布 JSON、数据库或内部状态完成产品验收。公开操作缺失时，记录缺失业务动作及阻塞阶段；不能让 Skill 编造接口，也不能用 Markdown 节点冒充可操作的导演台或资产库。

## 画布分区与返修

- 按剧本与规划、角色／场景／道具资产、分镜与首帧、视频与声音、成片划分可辨认区域；每区按集号、镜号排列。同镜头的当前采用成果与正在处理的返修候选紧邻，分镜返修和视频返修分别放在对应阶段。
- 操作前通过公开接口分页读取画布、节点、尺寸、位置、绑定和连线，再根据制作成果采用记录、任务状态及用户明确决定判断状态。生成成功、节点位置及名称中的“最终”不代表采用；证据不足的节点放待确认区域，不能覆盖或擅自归档。
- 优先查找和复用已有节点；需要同时审阅当前成果和返修候选时，才在该镜头旁新增必要节点。标题使用集号、镜号、成果类型和简明状态；作品级资产保留真实身份，不虚构镜号。执行日志、提示词和任务过程保存在已有成果或任务中，不堆成画布节点。
- 返修采用后，确认新旧节点和成果版本，再将旧展示节点移到主要工作区外、可按原镜头定位的历史区域。保留历史节点、文件和已有连线；历史记录按需查看，不自动删除或重做。失败或拒绝的候选保留记录并归入历史或待确认。
- 按节点实际尺寸和既有占用位置安排各区域及返修空间，避免重叠；真实输入才连接，不创建表示概念阶段的媒体连线。不以全图 `arrangeCanvas` 代替阶段／镜号布局；当前公开操作未证明支持新建或调整分组，不猜测分组接口。
- 整理现有画布时先保存节点 ID、原位置、名称、父子关系、绑定和完整连线，以及目标位置和判断依据；通过公开 `moveNodes`／必要时 `renameNodes` 分批操作，每批最多 64 个。分组子节点无法确认坐标语义时留在原处。每批前复核作品、画布与被操作节点；并发变化或失败时停止、回读并记录完成范围，必要时按原位置恢复，不盲目重试。
- 等待保存后重新读取并核对节点 ID、绑定、连线 ID 和端点，再在画布上查看区域和至少一个返修镜头。无法读取、保存或确认时报告未验证项，不宣布整理成功；这些操作不改变成果采用状态或触发媒体生成。

## 当前可复用入口与边界

以下依据当前源码，运行时仍须发现。不要把本表当工具已连接或已通过验收。

| 入口／代码证据 | 用途与限制 |
| --- | --- |
| `productionRead`、`productionExecute`：apps/server/src/utils/mcp/tools.ts | 读制作修订、保存和采用；按 schema 传 expectedRevision／expectedAdoption，冲突先重读，不盲覆盖。通用修订存储不自动提供所有专属工作台。 |
| `productionTask`：同上 | prepare 固定输入，submit 按授权提交，read／refresh 查询原任务，cancel 按实际能力取消。缺远端编号且结果不明时不重提。 |
| `productionMedia`：同上 | 读取实际图片和音频；视频通过现有 FFmpeg 能力提帧与音轨。客户端无法感知返回媒体时记录未验证，不伪造视听评价。 |
| `listAppOperations` → `appOperation`：utils/mcp/operations.ts | 发现插件、供应商和全局素材文件操作。资产业务使用 `listAssetCatalog` / `executeAssetCatalog`，不要用普通素材文件覆盖版本。 |
| 画布与 `getNodeTools` → `nodeTools` | 正文、图片、音频和视频挂载、生成配置及执行；只使用实际公布的节点函数，引用必须来自真实存在文件。 |
| packages/nodes/director3dNode、imageNode 的全景实现 | 有可复用软件代码。必须核查是否公开摆位、运动、切片导出等完整操作；源码或可点击界面不等于 Codex 已可操作。 |

候选素材可按作品归属保存为未采用版本，供资产库审阅；正式复用前必须确认采用，保留稳定资产版本和来源。若只有文件接口而无对应业务语义，停在“候选成果已生成、资产采用能力待补”，不把文件复制当正式资产采用。

## 作品与资产版本

先读取资产目录修订及作品，按当前工作目录调用 `saveWork` 登记或更新作品名称。`saveVersion` 从该作品实际媒体文件保存候选版本：传作品 ID、类型、必要性、来源路径和资产关系；修订同一资产时带原 assetId。人物／场景变体必须引用一个已采用基础资产版本，音色用 voiceOf 指向已采用人物。不要把镜头、剧本或导演预演塞进资产图谱。

`adoptVersion` 记录用户或实际委托的采用证据，不把“生成成功”当采用。`useVersion` 给目标作品固定具体 assetId/version；新候选或新采用版本不自动替换旧作品引用。每次写入带最新 expectedRevision；冲突先重读，绝不盲目重试。具体字段以实时操作 schema 为准。

画布 `remote-productionNode` 的 `node:bindProduction` 绑定单一制作记录修订，expectedRef 防止覆盖其他绑定；`node:readProduction` 回读正文、采用状态和上游变化。工作台编辑保存新修订，不能复制出第二份主剧本。节点显示候选或已采用，并不代替真实媒体成果。

立意节点 `remote-ideaNode` 的 `node:bindIdeas` 接收已有创意简报及最多三个已保存立意候选，`node:readIdeas` 回读候选和采用状态。Agent 根据用户创意生成三种方向并先通过 production 保存，再绑定节点供用户编辑和采用；用户已有明确立意时可直接填写，不强制生成三个方向。生成候选不自动采用，局部重做只修改目标候选。

案例手法节点 `remote-techniqueNode` 的 `node:bindTechnique` 绑定已有手法成果，`node:readTechnique` 回读成果；`node:searchTechniques` 搜索手法与案例，`node:readTechniqueCase` 读取案例及其来源提示词。用户未指定时，根据剧情、镜头目的与模式、时长提出推荐并说明原因，取得确认后采用；用户指定手法视为授权采用。选定案例原文通过手法成果 `casePrompts` 保存来源快照；Agent 先实际读取该案例及手法，结合当前剧本、人物、镜头、素材和有效时长提炼可执行的英文动作与运镜，写入生成段 `techniquePrompt`，不得照搬案例人物、对白或事件。保留原始 `technique: {ref, snapshot}` 及依赖，在 H3 画面描述中原样包含 `Camera direction (<id>@<revision>): <techniquePrompt>`。检查首尾帧对齐、镜头标签、参考素材、对白和时间线符合 H3 官方模式，核对英文描述忠实于手法及当前镜头；仅字符或字段检查不能保证语义及生成效果。将手法节点连接制作成果节点时明确选定目标生成段并填写英文描述。模式和时长不兼容时调整方案，不强行套用。下游过期时先重新确认，不自动重跑付费生成。

3D 导演使用 `node:readDirector` 取得模型 version，`node:saveDirectorPlan` 保存场景及方案，`node:exportDirector` 导出构图或预演。新方案保留历史，保存后重新取得 version；旧 version 不用于再次导出。图片节点的 `node:panoramaView` 提供 open/read/set/export，当前公开 set 仅含 yaw/pitch/FOV，不含相机平移、roll 或重新打光；后两者缺口不能标成已支持。

生成节点若已有任务接口则复用同一业务任务，不再从另一入口提交第二次。供应商状态不明先查询原编号；已完成但下载失败只恢复下载。付费重做必须属于实际批准范围。

图片生成节点提供 `node:bindProductionTask`：taskId 必须属于当前作品，expectedTaskId 为现有绑定或 null；读取真实任务后显示固定输入和实际输出，不提交任务。已绑定节点的普通生成入口停用；新方案创建新任务和节点。先通过 `productionTask` 查询或提交，再同步原绑定；不要另外调用 generateImage。

普通图片生成节点的风格选择由 `node:getConfig` 返回可用 ID，使用 `node:setStyle({id})` 选择预设、`projectDefault` 或 `none`，不触发生成。作品默认风格会固定所选版本及内容；若默认版本变化，应重新选择。节点已绑定制作任务时，以采用的图片方案风格快照为准，不可直接更改节点风格；不要同时连接风格节点并在普通节点重复选择风格。

风格节点 `remote-styleNode` 可浏览 Nuomi 基础与扩展风格，并通过 `node:bindStyle` 绑定版本、`node:readStyle` 读取风格及默认值。使用 `productionRead({action:"readDefaultStyle"})` 获取作品默认风格；通过 `productionExecute` 保存 `style` 候选、采用修订，再以 `setDefaultStyle` 和 `expectedDefault` 显式设为默认。直接指定的镜头覆盖使用另一个已采用风格；不混合默认风格和覆盖风格。未采用风格的旧作品维持原行为。

作品已有默认风格后，正式 `imagePlan`、`asset`、分镜逐镜及 H3 逐段都必须携带 `style: {ref, mode, snapshot}`，其中 `snapshot` 是所引用风格的完整 content，`mode` 为 `default` 或 `override`；同一 `ref` 同时写入成果 dependencies。图像使用已采用 `imagePlan` 作为任务 plan，其 target 为 `{kind:"asset", role, identityId}` 或 `{kind:"storyboardShot", storyboard, shotId}`；后者的 `storyboard` 是实际分镜草案的固定修订（可未采用），且镜头 ID 必须属于该修订。分镜草案改变后方案过期，避免以未出图而不可采用的分镜形成循环依赖。prompt 须与任务请求完全相同。图片沿用原始风格快照的提示词校验；H3 保留原始 `style` 快照及引用，另在每个生成段的 `stylePrompt` 写与快照正向风格和避免项语义一致的英文描述，并在画面描述字段原样包含 `Visual style (<id>@<revision>): <stylePrompt>`。Agent 应核对英文描述与原始风格一致，不能仅凭语言字符检查断定翻译正确。历史方案仍可读取，重新提交时须保存并采用包含英文描述的新修订。保存后回读快照、英文描述与最终提示词；默认风格变化或采用版本变化时仅更新受影响方案，不重提既有任务。

H3 绑定风格时，其首尾帧和角色图片成果也必须记录相同的风格修订。旧图片不能仅凭补写风格字段就声称已统一；先集中审阅实际画面，对不符合所选风格的镜头准备局部返修，复用其余素材。文字快照和输入校验不能保证模型生成结果一致。

图片节点 `node:prepareInpaint` 使用归一化多边形选区保存真实原图、红色引导图、透明蒙版和重绘草稿，不提交生成。先检查选区及投影，再以原图、引导图的固定顺序准备制作任务。重绘草稿绑定完成任务时验证参考路径并复用远端结果，通过本地蒙版合成保留选区外像素；重复绑定复用已保存合成，不能再次收费。这里不是供应商原生 mask 控制，选区内几何仍需实际检查。局部保护成功不代表修复内容合格；门外全景 v3 已出现保护区零变化但墙体仍悬空的反例。

导演 `exportDirector` 的 panorama 模式接受固定 camera 位置和 aspect=2，导出完整球面几何底图并排除人偶，用于约束全景美术生成。该图不是已采用场景资产。全景节点处于画布视口外时预览会惰性加载；先 `fitCanvas({nodeIds})`，再 open/read，ready=true 后设置和导出。图片节点连接来源只保留来源关系，还须通过 setImage 明确挂载真实文件。

长预演视频通过 `exportDirector({kind:"video", ..., backgroundRequestId})` 启动，使用固定请求编号；调用立即返回，随后用 `directorVideoExportStatus({requestId, action:"read"})` 查询实际进度和结果。相同编号与输入重复调用只返回原记录，不重复录制；更换输入须新编号。`action:"cancel"` 取消本地录制。页面关闭或重载会中断，恢复时先检查记录和实际画布输出，不把 `running` 当完成。录制期间保持页面可见；该机制不绕过媒体生成授权，也不是可跨页面重启续录的服务端任务。

`storyboard` 成果绑定已采用剧本，逐镜记录 sourceShotIds、dialogueIds、预计时长、景别与调度依据。复杂调度和非特写镜头必须保存真实导演构图／预演路径及方案版本；只有简单特写可记录 direct reason。正式分镜采用前每个镜头必须已有实际 image。productionNode 的分镜工作台编辑同一修订，保存为新候选；草案时长不冒充最终成片时长。

## 阶段回执

每次执行记录：作品／集、阶段、输入采用版本、操作对象、实际公开调用、输出文件与节点、任务编号、确认依据、尚未验证项、受影响下游。文件保留详情，画布只显示用户需要审阅的成果和简明状态。

恢复时读取上述记录及真实任务状态，再决定下一步。上一轮对话里的“完成”、现存路径、旧任务成功或 Skill 文本均不能代替当前成果证据。

## 本套件交付状态

nuomi-scripts 已有编剧方法文件，本父 Skill 已定义全管线阶段与软件操作方法。这里尚未证明套件被运行时自动加载，未证明全部专属工作台和业务操作已接通，也未完成正式 E1。

此前部分图片、音色及独立配音真实生成，只能证明对应局部能力。正式制作仍须补齐画布成果组织、完整资产设计与管理、全景／导演／分镜操作以及端到端验收证据。
