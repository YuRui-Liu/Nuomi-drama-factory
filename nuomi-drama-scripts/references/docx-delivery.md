# DOCX 交付

## 输入

E001-E030 单集 Markdown、project.yaml、审查报告、版权/合规台账、DOCX 模板和渲染工具。

## 必须规则

- DOCX 只能从 Markdown 源编译，不能成为第二正文源。
- 编译前检查集数连续、单集契约通过、P0/P1 清零、权利/合规状态允许。
- 编译后执行 OOXML 结构审计，并生成 PDF/PNG 逐页检查布局。
- 全部证据齐全才标记 `ready`；否则标记 `needs_review` 或 `blocked`。

## 交付字段

DOCX 文件、PDF/PNG 检查件、结构审计日志、渲染日志、源版本、交付状态和失败原因。

## 阻断条件

缺任一集、时长或场景协议错误、P0/P1 未处理、版权/合规阻断、渲染失败或工具不可用。

## 自检问题

- DOCX 的正文是否能逐字追溯到 Markdown？
- 是否误把未渲染文件标为最终交付？
- 单集和批量交付是否遵守各自协议？
